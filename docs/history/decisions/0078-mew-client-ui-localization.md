## 배경

mew의 클라이언트 문구와 일부 날짜 표기가 한국어에 고정돼 있어, 영어·중국어(간체)·일본어 사용자에게 같은 UI를 제공할 수 없다. 서버 데이터와 문서 내용은 사용자가 입력한 원문이므로 번역 대상이 아니다.

## 선택지

1. i18next 같은 외부 런타임을 추가한다 — 완성된 생태계가 있지만 현재 필요한 기능에 비해 번들·의존성이 늘어난다.
2. 클라이언트에 작은 타입 안전 카탈로그와 React 컨텍스트를 둔다 — 언어 선택·보간·날짜 포맷에 충분하며 외부 의존성이 없다.
3. 브라우저 자동 번역에 맡긴다 — UI의 접근성 레이블·동적 문구·날짜 규칙을 통제할 수 없다.

## 결정

`src/i18n.tsx`를 클라이언트 UI 번역의 단일 진입점으로 둔다. 지원 locale은 `ko`, `en`, `zh-CN`, `ja`이며, 번역 키는 화면 의미를 나타내는 영문 dot notation으로 작성한다. `I18nProvider`는 `mew:locale`의 사용자 선택을 우선하고, 첫 방문에는 브라우저 언어를 협상한 뒤 한국어를 폴백으로 쓴다.

컴포넌트는 `useI18n()`의 `t()`와 `formatDate()`만 사용한다. 새 UI 문구는 반드시 네 카탈로그에 함께 추가한다. 번역하지 않은 기존 문구는 전환 작업 동안 한국어 원문으로 남기되, 새 기능에서 하드코딩하지 않는다. 사용자 문서·파일명·에이전트 출력·서버 오류의 원문은 번역하지 않는다.

언어 선택은 사용자별 브라우저 설정이며 서버 계정·협업 상태와 동기화하지 않는다. 선택이 바뀌면 `html[lang]`도 함께 갱신한다.

## 개발 지침

- 화면에 새 텍스트(UI 본문, 버튼·메뉴 이름, placeholder, `title`, `aria-label`, 빈 상태·오류 안내)를 추가할 때는 같은 변경에서 `src/i18n.tsx`의 `ko`·`en`·`zh-CN`·`ja` 카탈로그를 모두 갱신하고 `t()`로 렌더링한다.
- 날짜·시간은 문자열을 조합하거나 locale을 고정하지 않고 `useI18n()`의 `formatDate()`를 사용한다.
- 테스트용 기대 문구, 코드 주석, 사용자가 작성한 파일 내용과 서버가 받은 원문은 UI 번역 대상이 아니다.
- 카탈로그에 없는 문구를 한국어 리터럴로 새로 넣어서는 안 된다. 번역 키와 네 언어 번역이 준비될 때까지 해당 UI 변경은 완료가 아니다.

## 근거

이 방식은 현재 React 단일 클라이언트에 필요한 범위를 정확히 다루며, 런타임 번역 파일 로딩 실패나 새 외부 의존성 없이 점진적으로 92개 UI 소스 파일을 옮길 수 있다. semantic key는 한국어 원문을 키로 삼는 방식보다 원문 교정과 번역 검수를 독립시킨다.
