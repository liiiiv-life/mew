## 배경

에이전트 창([ADR 0034](0034-mew-agent-panel-acp-reintroduction.md)·[0046](0046-mew-agent-panel-tabs-one-session-per-tab.md))은 사람이 붙들고 있는 대화다. 탭 하나가 세션 하나이고, 창을 보고 있는 사람이 프롬프트를 어디에 넣을지 매번 고른다. 역할이 다른 일(문서 정리·코드 수정·조사)을 나눠 시키려면 사람이 탭을 여러 개 열고 머릿속으로 배분해야 했고, 그 배분 규칙은 어디에도 남지 않았다.

또 하나: 창을 닫으면 그 대화의 큐를 미는 주체가 사라진다. "시켜 놓고 자리를 뜬다"가 성립하지 않는 것은 [ADR 0048](0048-mew-agent-supervisor-process.md)이 이미 지적한 문제다.

## 결정

에이전트셋 = (에이전트 런타임 + 모델 + 역할) 묶음 하나. 셋들을 그리드로 늘어놓고, 입력줄 하나에서 일을 던지면 라우터 셋이 어디로 갈지 정한다.

```
입력줄 하나 ──▶ 라우터 셋(판정 전용) ──▶ 대상 셋의 큐 ──▶ ACP 세션 ── 어댑터 ── CLI
     └── @지목이 있으면 라우터를 건너뛴다 ──────────▶
```

- 역할(role)은 시스템 프롬프트다. ACP에는 시스템 프롬프트 필드가 없어서 그 세션의 첫 프롬프트 머리말로 붙인다(`agentSetRunner.#compose`). 같은 세션이 이어지는 동안 문맥에 남는다
- 라우터는 지울 수 없고 역할도 고칠 수 없다. 이 셋의 일은 판정 하나뿐이라, 역할을 손대는 순간 판정 형식이 깨지고 라우팅이 조용히 망가진다. 바꿀 수 있는 것은 어떤 에이전트·어떤 모델로 판정할지뿐이다(서버가 저장값을 덮어써 강제한다 — `normalizeSets`)
- 판정 결과는 id 또는 이름으로 읽는다(`pickSet`). 모델이 id 대신 이름을 답하는 일이 잦고, 군말을 붙이면 결론은 마지막 줄에 있다. 아무것도 못 고르면 그 작업은 라우팅 실패로 남는다 — 임의의 셋으로 흘려보내지 않는다
- 큐와 수명의 주인은 서버다. 창은 구경창이고, WS(`/api/agentset/ws`)는 상태를 흘릴 뿐 세션을 만들지 않는다. 창을 닫아도 일은 계속 돈다
- 세션은 첫 작업에 뜬다(지연 시작), 10분 놀면 꺼진다. 셋을 20개 만들어 두어도 램은 실제로 일하는 만큼만 든다

### 왜 에이전트 창을 확장하지 않았나

에이전트 창은 "대화 하나를 사람이 끌고 간다"는 전제 위에 있다(탭=세션, 창이 붙어야 이벤트가 흐름). 셋은 반대로 "사람이 안 봐도 굴러간다"가 전제다. 같은 창에 얹으면 탭의 뜻이 둘로 갈린다 — 별도 창으로 둔다.

### ADR 0048과의 관계

0048(감독 프로세스)은 아직 구현되지 않았다(2026-08-12 기준 `server/agentHost.ts` 없음). 그래서 셋 러너도 지금은 mew 프로세스 안에 산다 — mew를 재시작하면 돌던 셋 작업이 죽고 작업 이력도 사라진다. 0048을 구현할 때 에이전트 창의 세션과 함께 감독 밖으로 나가야 한다. 이 문서는 0048을 뒤집지 않는다, 같은 방향의 미완이다.

### 보안

셋도 결국 Bash를 쓰는 에이전트다. WS·REST 모두 터미널과 같은 게이트(`authorizeTmux`, owner/manager)를 쓴다. 무인으로 임의 프롬프트가 도는 표면이라는 점에서 예약 작업(`schedules.ts`)과 같은 급이고, 권한 모드 기본값은 [ADR 0037](0037-mew-agent-bypass-permissions-default.md)과 같은 `bypassPermissions`다. 격리를 늘리지 않는다 — OS 층 격리는 여전히 없다([ADR 0044](0044-mew-agent-cli-tool-parity.md)).

## 결과

- 역할별 분업이 창 밖으로 나왔다. 배분 규칙이 사람 머릿속이 아니라 셋의 `role` 문자열에 남는다
- 라우터가 한 번 더 도는 만큼 첫 응답이 느려진다(판정 턴 하나). 급하면 `@이름`으로 건너뛴다
- 작업 이력은 메모리에만 있다(셋당 50개). 영속이 필요해지면 `<DATA_DIR>/agent-sets/<id>.jsonl`이 다음 단계다
- 되돌리려면 창(`AgentSetPanel`)과 서버 3파일(`agentSets.ts`·`agentSetRunner.ts`·`agentSetWs.ts`)을 지우면 된다. 에이전트 창은 건드리지 않았다 — 공유하는 것은 `AgentSession`과 런타임 등록표뿐이다
