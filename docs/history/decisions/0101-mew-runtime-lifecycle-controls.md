## 배경

런타임 선택 목록에는 설치 버튼, 각 런타임 톱니바퀴에는 실행 파일·env 설정만 있어 설치·인증·제거의
책임 위치가 갈렸다. 특히 API 키와 계정 로그아웃은 공급자별 CLI 계약을 따라야 하므로 브라우저가 임의
명령이나 시크릿 경로를 받으면 안 된다.

## 결정

- 각 런타임의 톱니바퀴 설정은 설치·제거·로그인·로그아웃을 함께 제공한다.
- `server/agentRuntimes.ts` 등록표가 각 동작의 고정 spawn spec을 소유한다. HTTP는 runtime id와 정해진
  action만 받고 명령·인자·경로를 받지 않는다.
- 제거는 등록표가 안전한 역설치 명령을 선언한 런타임에서만 노출한다. 설치 방법이 공급자 스크립트라
  안전한 제거 계약이 없는 런타임은 제거 불가 사유를 표시하고 임의 파일 삭제를 하지 않는다.
- 로그인은 기존 ACP/CLI 인증 계약을 그대로 중계한다. 로그아웃은 등록표에 선언된 비대화형 CLI 명령만
  실행하며, Mew가 토큰·API 키를 읽거나 직접 지우지 않는다.
- 설치·제거·로그아웃은 manager·owner만 실행하며, 제거와 로그아웃은 확인 뒤 실행한다.

## 근거

런타임 등록표 밖의 패키지 관리자·인증 저장소를 추측해 삭제하면 운영체제·설치 방식에 따라 다른 파일을
손상시킬 수 있다. 등록된 역설치와 CLI 로그아웃만 실행하면 기존 셸 권한 경계 안에서 명령 주입·시크릿
노출 없이 수명주기 조작을 한 곳에 모을 수 있다.
