## 배경

Mew에는 오른쪽에 붙는 에이전트 패널과 일반 tmux 터미널 패널이 따로 있었다. 그러나 Claude Code와
Antigravity는 이미 에이전트 탭 안에서 `TmuxTerminal`을 사용하므로, 같은 탭·패널·크기 조절·모바일
전면 상태를 두 벌로 유지할 이유가 줄었다. 사용자는 AI 채팅과 셸을 작업 단위 탭으로 섞어 두고 하나의
패널에서 전환하기를 원한다.

## 선택지

1. 두 보조 패널을 유지하고 서로 이동 버튼만 둔다 — 저장 상태·단축키·모바일 스택과 탭 모델이 계속 갈린다.
2. 일반 터미널 세션 목록을 에이전트 패널 안에 중첩한다 — 패널 안에 탭 줄이 두 벌 생기고 한 탭의 의미가 표면마다 달라진다.
3. 일반 tmux 셸을 새 탭 런타임으로 추가하고 독립 터미널 패널을 없앤다 — 모든 대화·TUI·셸이 같은 탭 수명주기를 쓴다.

## 결정

3번을 채택한다.

- 사용자 표기는 **터미널•에이전트패널**이다. 헤더 메뉴·플로팅 핸들·닫기 접근성 이름도 이 이름을 쓴다.
- 새 탭 런타임 목록에 `tmux 터미널`을 추가한다. 선택하면 탭 cwd에서 일반 셸을 여는 탭별 전용 tmux
  세션을 만들고 기존 `TmuxTerminal`로 붙는다.
- 탭 하나는 ACP 세션, 공식 에이전트 TUI, 일반 tmux 셸 중 정확히 하나를 소유한다. 패널을 닫아도 세션은
  남고 탭의 `×`를 눌렀을 때만 해당 ACP 감독 또는 전용 tmux를 종료한다.
- 일반 셸도 terminal 표면이므로 에이전트셋과 무인 예약 작업 대상에는 들어가지 않는다. 설치·인증 UI도
  제공하지 않으며 서버에 이미 필요한 tmux와 로그인 셸을 사용한다.
- 독립 `TmuxTerminalPanel` 보조 패널, 헤더의 별도 터미널 항목, 플로팅 핸들의 별도 터미널 항목과
  `terminal` 모바일 패널 상태를 제거한다. 기존 터미널 단축키는 통합 패널 토글로 이어져 근육 기억을 보존한다.
- 계정 원장이나 브라우저에 남은 옛 `tmuxOpen=true`는 통합 패널을 여는 신호로 한 번 호환한다. 기존 일반
  이름의 tmux 세션은 자동 종료하거나 새 탭으로 추측 이관하지 않는다.
- 에디터의 `Ctrl+L` 참조 대상은 `agent` 하나로 합치고, 활성 탭이 tmux이면 그 터미널이 받는다. 터미널
  내부의 Esc는 TUI·셸에 전달하며 패널 닫기로 소비하지 않는다.

## 근거

이미 검증된 탭별 숨김 tmux와 `TmuxTerminal`을 재사용하므로 새 터미널 프로토콜이나 두 겹 탭 UI가
필요 없다. 패널 상태가 하나가 되면 데스크톱 폭, 모바일 전면 순서, 탭 이동, 닫기와 참조 전달도 같은
규칙을 공유한다. 기존 세션을 자동 이관하지 않는 이유는 계정별 에이전트 탭 원장과 서버 전역 tmux 이름
사이에 소유자를 안전하게 대응시킬 정보가 없기 때문이다.

## 결과

- 옛 독립 터미널 패널을 그대로 되살리는 것은 재시도 금지가 아니다. 다만 다시 분리하려면 통합 탭에서
  해결할 수 없는 서로 다른 수명주기나 동시 표시 요구를 근거로 새 결정을 쓴다.
- 독립 패널에서 만들었던 일반 이름의 tmux 세션은 서버에 남을 수 있지만 통합 탭 목록에는 나타나지 않는다.
