## 배경

팀원이 내부 브라우저를 열 때 서버 Chromium의 새 창·팝업이 서버 사용자의 작업을 가린다. 기존 창 모드는 Google 로그인 성공을 확인한 실행 방식이므로 기본값을 일괄 헤드리스로 바꾸지 않는다.

## 결정

- Linux/WSL의 일반 서버 브라우저가 창 모드이면 프로필별 전용 Xvfb에서 실행한다. `MEW_BROWSER_DISPLAY=desktop`으로 기존 실제 디스플레이를 명시 선택할 수 있다. 기본값은 `virtual`이다.
- Chromium 직접 실행·CDP 연결·sandbox·프로필·DOM 중계는 유지한다. X11을 명시하여 상속된 Wayland 환경으로 실제 데스크톱에 연결하지 않는다.
- 가상 디스플레이는 동적 번호·임시 인증 쿠키·TCP 수신 금지를 사용하고, 해당 Chromium 종료 뒤 함께 정리한다. 시작 실패 시 실제 데스크톱이나 헤드리스로 몰래 전환하지 않는다.
- `MEW_BROWSER_HEADLESS=1`은 계속 GUI 없는 실행을 선택한다. macOS/Windows와 호스트 제한 검증 helper는 이 Linux 전용 변경 범위 밖이다.
- 실행 설정과 검증 한계는 [프로젝트 브라우저 계약](../../guides/browser.md)에 기록한다.

## 근거

탭 생성의 비활성화 옵션이나 창 최소화만으로는 사이트 팝업과 OS의 창 활성화를 모두 차단할 수 없다. 가상 디스플레이로 분리하면 사이트의 원래 팝업 동작을 유지하면서 서버 데스크톱과 분리할 수 있다. Xvfb 설치가 추가로 필요하며 실제 공급자 로그인 성공은 별도 사용자 확인 대상이다.
