## 배경

[ADR 0048](0048-mew-agent-supervisor-process.md)은 브라우저나 mew가 닫혀도 진행 중인 턴을 끝내고,
붙은 창 없이 30분이 지나기 전에 다시 붙으면 감독 메모리의 이벤트를 replay하도록 했다.
하지만 30분 유휴 종료 후에는 같은 탭을 다시 열어도 새 ACP 세션이 만들어져, 탭 목록은
남아 있는데 대화만 사라졌다. 탭은 채팅방처럼 오래 남아야 하며, 유휴 정리는 프로세스 수명만 끝내야 한다.

## 선택지

1. 감독을 종료하지 않는다 — 복원은 단순하지만 탭 수만큼 ACP/CLI 프로세스와 메모리가 무기한 남는다.
2. 브라우저 전사 캐시만 그린다 — 화면은 남지만 새 에이전트가 이전 대화 문맥을 가지지 못한다.
3. 탭이 마지막 ACP 세션 ID를 기억하고 새 감독이 자동 `session/load`한다 — 유휴 자원은 정리하면서
   화면과 에이전트 문맥을 함께 복원한다.

## 결정

3번을 채택한다.

- `mew:agent-tabs`의 탭은 `runtime+cwd`별 마지막 ACP 세션 ID를 저장한다. 런타임이나 cwd를 갈아타다
  돌아와도 각 조합의 대화를 이어야 하기 때문이다.
- 브라우저는 WS 접속에 저장된 세션 ID를 `resume` 힌트로 보낸다. 같은 `runtime+tab+cwd`의 감독이
  살아 있으면 힌트를 무시하고 감독의 현재 세션을 기준으로 삼는다.
- 감독이 없어 새로 뜨는 경우에만 ACP 핸드셰이크 후 힌트의 세션을 `session/load`한다. 전사 재생이
  끝난 뒤 브라우저를 붙여, 중간에 만든 빈 세션이 화면의 기준이 되지 않게 한다.
- 살아 있던 감독의 메모리 replay와 ACP `session/load` 전사는 이벤트 형식이 다르다. 자동 복원 replay는
  `restored` 표식을 보내 브라우저 캐시와 합치지 않고 교체한다. 안 그러면 같은 대화가 두 번 그려진다.
- 탭을 명시적으로 닫거나 현재 탭에서 새 세션을 시작하면 저장된 포인터와 브라우저 전사 캐시를
  함께 지운다. 사용자가 의도한 새 대화가 자동 resume로 되살아나면 안 된다.
- 백엔드가 `session/load` capability를 광고하지 않거나 기록이 삭제·손상되어 불러오지 못하면 탭 자체를
  못 열게 하지 않고 새 세션으로 폴백한다.

## 근거

탭 목록은 이미 브라우저에 지속되고 ACP 백엔드는 전사를 디스크에 저장한다. 두 개를 세션 ID 하나로 다시
연결하면 별도 서버 전사 DB나 무기한 감독 프로세스 없이도 채팅방과 같은 수명을 만든다. 브라우저 이벤트 캐시는
서버가 뜨기 전 첫 화면을 즉시 그리는 가속일 뿐이고, 실제 복원의 기준은 ACP `session/load`다.

## 결과

- 30분 유휴 시한은 그대로라 놀고 있는 프로세스는 정리된다.
- 다시 연 탭은 새 감독·ACP 프로세스를 띄우는 비용과 `session/load` 시간을 한 번 낸다.
- 탭 지속 정보가 브라우저 로컬 상태이므로 다른 브라우저·기기에는 탭 목록과 세션 포인터가 자동 동기화되지 않는다.
