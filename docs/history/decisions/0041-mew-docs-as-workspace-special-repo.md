## 배경

mew는 워크스페이스 최상위 폴더 하나를 프로젝트 하나로 보고 전부 프로젝트 탭에 세운다. docs도 그중
하나였다 — 이름만 `DEFAULT_PROJECT`로 특별했을 뿐, 목록·격자 팝업·개명·삭제 대상에 함께 서 있었다.

그런데 docs는 다른 레포와 성격이 다르다. 워크스페이스마다 하나뿐이고, 제품이 아니라 그 워크스페이스
전체의 SSoT이며, 다른 워크스페이스로 옮겨 갈 때 통째로 따라가야 한다. 프로젝트 목록에 섞여 있으면
"프로젝트 여럿 중 하나"로 보여 이 성격이 드러나지 않는다.

## 결정

docs를 프로젝트에서 빼고 워크스페이스에 하나뿐인 특별 레포로 만든다. 위치는 `<워크스페이스>/.mew/docs`.

- `listProjects()`가 docs를 걸러내고 `isValidProjectName('docs')`는 false — 같은 이름의 프로젝트를
  만들 수 없다(만들면 이름이 겹쳐 가려진다). 점으로 시작하는 `.mew`는 애초에 프로젝트 이름 규칙에 걸리지 않는다
- 내부 식별자 `docs`는 그대로 둔다. 경로만 `projectRoot('docs')`에서 `.mew/docs`로 꺾는다.
  문서·트리·검색·협업 방 키(`프로젝트:경로`)·git·명령어 버튼·`.data/` 키가 전부 프로젝트 이름으로
  도는 구조라, 이름을 바꾸면 열려 있는 방과 저장된 상태가 통째로 어긋난다
- 폴더가 없으면 서버가 빈 폴더로 만든다(`ensureDocsRoot`) — 새 워크스페이스는 빈 docs로 시작한다
- 탭은 프로젝트 탭 줄 맨 왼쪽 고정 탭 하나. 끌 수 없고 순서를 바꿀 수 없고 이름이 없으며
  (아이콘 `i:notes` 고정) 프로젝트 격자 팝업에 나오지 않는다
- 폴더 통째로 가져오기/내보내기만 있다(owner 전용). 가져오기는 기존 내용을 전부 지우므로 경고 확인을
  한 번 더 받는다. 내보내기는 대상 폴더 아래 `docs`로 복사하고 같은 이름이 있으면 거부한다
- 폴더 고르기는 네이티브 대화상자가 아니라 서버가 목록을 내려주는 컴포넌트다
  (`GET /api/fs/dirs`, owner 전용 — 워크스페이스 경계 밖을 그대로 보여준다)
- 각 레포 `AGENTS.md`가 가리키는 경로는 `../.mew/docs`, 워크스페이스 루트에서는 `.mew/docs`

## 근거

- 하나뿐인 것을 여럿 중 하나처럼 두면 생기지 않아야 할 동작(개명·삭제·둘 만들기)이 API 표면에 남는다.
  프로젝트에서 빼면 그 표면 자체가 사라진다
- `.mew` 아래로 넣으면 워크스페이스 최상위가 제품 레포만 남아 목록이 곧 프로젝트 목록이 된다.
  워크스페이스를 바꿔 끼울 때도 `.mew` 하나만 보면 그 워크스페이스의 mew 상태가 전부 거기 있다
- 이름이 아니라 경로만 특별 취급한 것은 뒤집기 가장 싼 선택이다 — 내부 식별자를 바꾸는 개편은
  협업 방·저장된 탭·git 처리까지 한꺼번에 건드려야 한다

## 결과

- 옛 `<워크스페이스>/docs`는 디스크에서 `.mew/docs`로 옮겼다(git 히스토리 그대로)
- 레포 문서의 `../docs/...` 링크를 `../.mew/docs/...`로 일괄 수정했다
- 게스트는 docs 탭을 늘 보지만, 안에 보이는 것은 전과 같이 `guestAccess.ts`의 경로 규칙이 정한다
  (규칙이 없으면 빈 트리)
