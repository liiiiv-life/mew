## 배경

루트 프로젝트를 전환하면 `switchWorkspace()`가 이전 작업 경로의 에이전트 감독과 직접 소유 세션을 종료했다. 화면에서 다른 프로젝트를 여는 행동이 진행 중인 작업과 예약 전송까지 끊어, 독립 감독의 목적과 맞지 않았다.

## 결정

- 루트 프로젝트 전환은 트리 감시자와 협업 방만 정리한다. 에이전트 감독·에이전트셋 세션은 종료하지 않는다.
- 에이전트 탭 UI는 계속 루트 프로젝트별로 분리한다. 전환한 화면은 새 루트의 탭만 연결하지만, 이전 루트의 감독은 자신의 고정 cwd에서 백그라운드 작업과 큐를 계속 처리한다.
- mew 서버 종료도 독립 감독을 종료하지 않는다. 서버가 다시 뜨면 같은 소켓에 재연결할 수 있고, 예약 전송은 데이터 파일을 읽어 만료된 항목을 실행한다.
- 탭을 명시적으로 닫는 `close_session`만 해당 탭의 감독을 종료한다.

## 근거

감독은 이미 mew와 다른 프로세스 그룹에서 실행되고 cwd를 생성 시점에 고정한다. 따라서 활성 루트 변경은 감독의 파일 접근을 바꾸지 않는다. UI 연결만 끊으면 유휴 정책은 유지하면서 작업의 연속성을 보장한다.

## 결과

프로젝트를 전환한 뒤 이전 에이전트 탭을 다시 열면, 진행 중이거나 완료된 대화가 감독 replay/세션 복원으로 이어진다. 명시적으로 탭을 닫지 않은 오래된 유휴 감독은 기존 유휴 정책에 따라 종료될 수 있다.
