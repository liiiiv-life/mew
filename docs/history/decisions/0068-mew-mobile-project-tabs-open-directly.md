- 결정자: 송상훈 (지시)

## 배경

모바일의 비활성 프로젝트 탭은 아이콘만 보여서, 첫 클릭에는 프로젝트를 열지 않고 이름과 명령어 버튼을 담은
`ProjectPeek` 이름표를 띄웠다. 같은 탭이나 이름표를 다시 눌러야 실제 프로젝트가 열렸다. 이 보호 단계는 프로젝트
전환이라는 기본 동작에 클릭을 하나 더 요구했고, 사용자가 탭을 눌렀는데 이동하지 않는 지연으로 느껴졌다.

## 선택지

1. 2단계 전환 유지 — 프로젝트 이름을 먼저 확인할 수 있지만 모든 모바일 전환에 추가 클릭이 필요하다.
2. 한 번에 전환 — 잘못 누를 가능성은 남지만 탭의 기본 동작이 데스크톱과 같고 즉시 반응한다.

## 결정

모바일과 데스크톱 모두 프로젝트 탭을 한 번 누르면 즉시 해당 프로젝트를 연다. 비활성 모바일 탭의 첫 클릭을
가로채던 `ProjectPeek` 컴포넌트와 이름·명령어 이름표를 삭제한다. 활성 프로젝트의 명령어 버튼과 탭 길게 누르기·
끌기·우클릭 동작은 유지한다.

이름표를 앞세운 동일한 2단계 전환은 **재시도하지 않는다**. 모바일 아이콘의 발견성이 다시 문제가 되면 프로젝트
전환을 막지 않는 방식으로 해결한다.

## 근거

- 탭은 누르면 화면이 바뀐다는 기대가 강해서 확인 이름표보다 즉시 전환이 예측 가능하다.
- 현재 프로젝트는 모바일에서도 이름이 펼쳐지므로 전환 직후 어느 프로젝트인지 확인할 수 있다.
- 명령어 버튼은 활성 탭에서 그대로 접근할 수 있어 이름표 제거가 명령 실행 기능을 없애지 않는다.

## 결과

- 비활성 프로젝트의 명령어를 프로젝트 전환 없이 이름표에서 실행하던 보조 경로는 제거된다.
