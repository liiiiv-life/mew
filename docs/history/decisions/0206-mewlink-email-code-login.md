- 관련 결정: [0195](0195-mew-account-based-p2p-remote-access.md), [0203](0203-mewlink-workers-p2p-ui.md) — 중앙 인증·로컬 인가·작업 데이터 직결 경계 유지

## 배경

사용자는 OAuth 외에 이메일 로그인을 요구했다. 기존 선택 이메일 OIDC만으로는 중앙 화면에서 이메일을 입력하고 로그인할 수 없다.

## 선택지

1. 외부 이메일 OIDC만 유지 — 제공자 설치·설정이 필요하며 요청한 직접 입력 흐름을 제공하지 않는다.
2. 중앙에 비밀번호를 저장 — 비밀번호 재설정·유출 대응 등 별도 자격증명 수명 관리가 필요하다.
3. 이메일 소유를 일회용 코드로 확인 — 메일 발송 설정은 필요하지만 중앙에 비밀번호를 저장하지 않는다.

## 결정

3번을 기본으로 구현한다. Cloudflare Email Service의 Workers binding으로 로그인 코드를 발송하며 사용자가 발송 도메인을 활성화하고 배포한다. 실제 메일이나 외부 계정 설정을 자동 검증으로 변경하지 않는다.

- 중앙 origin에서 이메일 입력·코드 확인을 수행한다. 코드는 짧은 만료·일회용 소비·시도 제한을 적용하고 브라우저의 Secure·HttpOnly 호스트 전용 challenge 쿠키에 결합한다. D1에는 challenge·코드의 해시만 저장하며 코드·세션·메일 본문을 로그에 남기지 않는다.
- 검증 성공 후에만 중앙 계정과 기존 중앙 세션을 만들고 첫 유저이름 설정을 이어간다. 이메일 주소만으로 OAuth 또는 기존 로컬 mew 계정에 연결하거나 권한을 승격하지 않는다.
- 직접 이메일 계정의 신원 namespace는 OAuth/OIDC와 분리한다. 이메일 대소문자 정규화 기준은 현재 구현 계약에 기록하며 Gmail의 점·플러스 등 제공자별 별칭을 임의로 합치지 않는다.
- 메일 실패·과도한 재요청·코드 오류·만료는 복구 가능한 오류로 끝낸다. 설정 없는 발송이나 개발 환경의 성공을 실서비스 메일 전달 성공으로 표현하지 않는다.

## 근거

이메일 소유 확인으로 사용자 요구를 충족하면서 비밀번호 저장·재설정 경로를 추가하지 않는다. 계정 자동 병합을 피하고 불변 내부 ID 기반 기기·멤버·P2P 인증 경계를 유지한다. 발송 API는 [Cloudflare Workers Email API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/)를 따른다. 세부 화면·제한·설정·검증은 [원격 접속 계약](../../development/remote-access.md)이 소유한다.
