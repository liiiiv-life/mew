## 배경

[ADR 0131](0131-mew-repository-docs-hierarchy.md)로 mew의 실행 안내와 상세 참조를 나눴다.
사용자가 이 구조를 전체 제품·프로젝트로 확대하고, 루트 SSoT에 있던 프로젝트 전용 내용도 각 소유 프로젝트로 옮기도록 요청했다.

## 선택지

1. 제품 정의·운영은 중앙, 코드 계약만 프로젝트에 유지 — 한 제품의 정보가 두 위치에 계속 나뉜다.
2. 모든 문서와 ADR을 각 레포로 이동 — 공통 결정과 프로젝트 간 영향을 한곳에서 찾기 어렵다.
3. 프로젝트 전용 문서는 소유 프로젝트, 공통 지식과 ADR은 중앙 — 사실별 소유자를 유지하면서 탐색 경로를 짧게 만든다.

## 결정

3번을 채택한다. 문서를 두는 기준은 코드 결합 여부보다 **내용의 소유 프로젝트**다.

- `<프로젝트>/README.md`는 무엇인지, 실행·필수 설정·검증 명령, 작업 불변식, 상세 문서 인덱스를 담는다.
- `<프로젝트>/docs/MOC.md`에서 필요한 분야만 고른다. 제품 정의·로드맵·스펙·리서치·사용법·개발 계약·운영·진행 작업은 해당 프로젝트 `docs/`의 단일 기준본에 둔다.
- README가 짧고 상세 문서가 없으면 빈 `docs/`를 만들지 않는다. 상세 내용이 생길 때 위 구조를 적용한다.
- 공유 서비스도 소유 프로젝트가 있으면 그 프로젝트에 문서를 둔다. med-gen·AI/TTS 등은 여러 소비자가 사용한다는 이유로 중앙에 사본을 만들지 않는다. 소비자 문서는 소유자의 기준본으로 연결한다.
- ADR 원본과 ADR 스코프 지도는 모두 `.mew/docs/decisions/`에 유지한다. 프로젝트에 ADR을 만들거나 복제하지 않는다. 기존 결정 본문은 유지하며 이관에 필요한 링크만 보정한다.
- 루트 `.mew/docs/`는 회사·브랜드·공통 서비스 인벤토리·여러 프로젝트에 걸친 정책·개발 환경·지원사업·행사·공통 참고·불변 archives를 맡는다. 지원사업 제출본이나 행사 기록에 제품이 등장해도 그 기록의 소유자는 바뀌지 않는다.
- 루트 `AGENTS.md` → 중앙의 짧은 공통 규칙 → 소유 프로젝트 README → 필요한 docs 문서 및 중앙의 관련 ADR 순서로 읽는다. 전체 제품·ADR·history를 재귀 로드하지 않는다.
- 코드와 문서 변경이 함께 필요하면 프로젝트 docs까지 한 작업에서 갱신한다. 기술 결정은 중앙 ADR, 포트·도메인·계정 변경은 중앙 서비스 인벤토리도 갱신한다.
- 중앙의 제품·프로젝트 지도와 레포 인벤토리는 상세 본문을 복제하지 않고 각 프로젝트로 연결한다. 이관 시 상대 링크·문서 지도·기계 판독용 문서 경계 목록을 함께 갱신한다.
- 기존 연구 원문·응답·첨부자료는 보존하고 `History / raw`로 탐색 범위를 구분한다. `archives/`는 이동·수정하지 않는다. 파일 이동을 이유로 현재 사실의 검토일을 새로 찍지 않는다.
- 프로젝트 `docs/`의 Markdown을 허용하고, 그 밖에는 기존 네 파일명만 허용한다. 검사기는 등록한 경계 안의 링크·MOC 도달성을 검사하며 다른 레포가 없는 중앙 CI에서는 외부 경계를 명시적으로 건너뛴다. 워크스페이스 검사는 실제 대상 존재까지 확인한다.

## 근거

제품을 읽거나 구현하는 작업은 그 프로젝트의 README에서 충분한 맥락을 찾을 수 있어야 한다.
단일 정보 원천은 모든 본문이 같은 Git 저장소에 있어야 한다는 뜻이 아니라, 각 사실의 기준본과 소유자가 하나라는 뜻이다.
공통 규칙과 ADR을 중앙에 유지하면 프로젝트 간 일관성과 결정의 계보도 보존된다.

## 이관 결과

- 중앙의 프로젝트 전용 문서·연구 응답·첨부자료 102개를 소유 프로젝트로 이동했다. 실행과 상세 인덱스는 10개 프로젝트의 README + docs 구조로 연결했다. 상세 내용이 없는 QR·간트 도구는 README를 진입점으로 유지한다.
- 워크스페이스 루트에 남아 있던 옛 mew README 사본은 mew의 History / raw에 보존하고, 루트 README는 전체 프로젝트 진입점으로 바꿨다.
- 중앙의 기존 archives와 ADR 원본 위치는 유지했다. 이동한 본문의 링크와 코드에 적힌 문서 경로를 보정하고, 연구 첨부자료는 바이트를 변경하지 않았다.
- 문서 경계 검사기는 등록 프로젝트 존재·README 인덱스·MOC 도달성·Markdown 및 HTML 첨부 링크를 확인한다. 중앙만 checkout한 CI와 전체 워크스페이스를 각각 검사한다.
