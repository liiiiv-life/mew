## 배경

0081의 사이드바는 Documents와 현재 루트를 각각 누르면 활성 프로젝트를 바꾸는 가상 폴더로
표시했다. 따라서 루트 내용을 보려면 프로젝트 이름으로 한 번 더 들어가야 했고, Documents도
파일시스템의 다른 폴더처럼 펼쳐 보는 감각과 달랐다. 하위 프로젝트 판정도 Git 저장소 여부를
사용했지만, 이 워크스페이스에서 프로젝트 경계는 명령·설정이 놓이는 `.mew` 폴더다.

## 결정

- 탐색기 최상단에는 접고 펼칠 수 있는 **Documents**를 둔다. 펼치면 그 실제 폴더의 내용이 바로
  아래에 보인다.
- Documents 다음에는 현재 루트의 실제 항목을 프로젝트 이름으로 감싸지 않고 곧바로 둔다. 따라서
  Documents는 다른 폴더보다 위에 있고, 루트의 프로젝트 폴더는 일반 폴더와 같은 목록에서 그 아래에
  놓인다.
- 루트의 직계 폴더 안에 `.mew`가 있으면 하위 프로젝트로 표시하고, 그 폴더의 명령 메뉴를 붙인다.
  `.git` 유무는 이 UI 판정에 사용하지 않는다. 중첩 `.mew` 탐지는 여전히 범위 밖이다.
- 편집 탭·저장·협업의 내부 프로젝트 식별자(`docs`, `.workspace`)는 유지한다. 한 트리로 보이는 것은
  탐색 UI만의 배치이며, Documents 항목을 열 때에만 해당 식별자로 편집 스코프를 전환한다.

## 결과

Documents와 루트가 모두 폴더처럼 탐색되면서도, 문서 위치와 루트 내용이 중복 표시되지 않는다.
Git 초기화 전인 프로젝트도 `.mew`만 있으면 같은 방식으로 프로젝트로 드러난다.
