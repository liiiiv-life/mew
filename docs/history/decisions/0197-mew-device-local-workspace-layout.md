## 배경

PC와 모바일 또는 서로 다른 PC에서 같은 계정의 배치가 마지막 저장값으로 덮이면 화면 크기와 작업 방식에 맞춰 조절한 위치·크기를 잃는다. 사용자는 기기별 배치 기억과 PC 메모·태스크의 팝업 표시를 요청했다.

## 선택지

1. 계정의 마지막 배치만 복원한다 — 새 기기에서 이어가기 쉽지만 기기별 배치가 서로 덮인다.
2. 브라우저별 배치를 먼저 복원하고 계정 원장은 초기값으로 사용한다 — 기기별 기억을 유지하고 새 기기도 기존 작업에서 시작한다.

## 결정

2번을 채택한다.

- 도킹 트리·비율·탭 배정, 문서 탭·분할·활성 문서, 보조 패널 여닫힘은 브라우저 로컬의 계정·루트 프로젝트 키로 저장하고 복원 시 우선한다.
- 로컬 기록이 없는 기기는 기존 계정 원장을 초기값으로 사용한다. 서버 원장 저장은 호환·새 기기 초기화를 위해 유지하며 기존 기기의 로컬 배치를 덮지 않는다.
- 에이전트·터미널의 실행 세션과 계정 탭 목록, 파일 트리·기능·Git 상태의 기존 소유권은 유지한다. 위치 변경이나 팝업 전환으로 실행 세션을 종료하지 않는다.
- 메모·태스크의 PC 표시 방식과 팝업 크기·위치는 브라우저에 기억한다. 모바일은 전면 패널 계약을 유지하고 PC 팝업 좌표를 덮지 않는다.
- 별도 하드웨어 식별자를 수집하지 않는다. 브라우저 프로필/사이트 저장 공간이 기기의 경계이며 삭제하면 해당 기억도 초기화된다. IP는 배치 저장 키로 사용하지 않는다.

## 근거

배치는 화면과 입력 방식에 의존한다. 기존 계정 원장의 초기 복원을 유지하면서 로컬 우선순위를 적용하면 서버에 기기 등록이나 추가 개인정보를 도입하지 않고 요청한 독립적인 기억을 제공한다.

현행 구현·검증은 [Mew UI 계약](../../development/ui-contracts.md#작업-패널-배치)을 따른다.
