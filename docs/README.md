# 문서 작성과 탐색

mew의 기준 문서는 이 `docs/`에 둔다. 공통 소유권과 중앙 결정 기록은 [워크스페이스 지침](../../AGENTS.md)을 따른다. [ADR 0199](../../.mew/docs/decisions/0199-mew-description-discovery.md)에 따라 mew에서는 MOC를 통한 AI 탐색과 새 문서의 MOC 등록 의무를 description 탐색으로 대체한다.

## 필요한 문서 찾기

프로젝트 README·지침과 [실행·검증 규칙](development/getting-started.md)을 먼저 읽는다. 이후 문서 경로와 YAML 프론트매터 `description`만 훑어 필요한 current 문서 본문을 선택한다. description은 탐색 힌트이며 정확한 사실·상태·계약은 선택한 본문에서 확인한다. 문서 본문·history·연구 원문을 통째로 로드하지 않는다.

저장소 루트에서 아래 명령은 본문을 출력하지 않고 경로와 description을 동적으로 나열한다. 별도 목록 파일의 관리나 색인이 필요 없다.

```bash
node server/document-descriptions.ts
node server/document-descriptions.ts --check --all
```

기본 목록은 `history/`·`archives/`·숨김 경로·심볼릭 링크를 제외한다. 과거 근거가 필요할 때만 `--all`로 history 설명을 포함한다. archives는 항상 읽기 전용이며 목록에서도 제외한다. 설명이 없는 문서·빈 문자열·잘못된 YAML·옛 `desc` 키는 검사 오류다.

## 문서 배치

| 내용 | 기준 위치 |
| --- | --- |
| 사용자 설치·조작 | `guides/` |
| 기능별 요구사항·상세 동작·확인 기준 | `features/`의 해당 기능 파일 |
| 공유 구현·저장·통신·UI·검증 계약 | `development/` |
| 설정·환경변수·외부 도구 연결 | `configuration/` |
| 서버 설치·배포 | `deployment/` |
| 반복 운영·접근·복구 | `operations/` |
| 태스크 제목·완료·태그·기간 | `tasks/`의 개별 작업 파일 |
| 설계·조사·구현 및 적용 검증 기록 | `work/` |
| 비교·실측·연구 원문 | `research/` |
| 대체된 구현·제거된 기능·이전 계약 | `history/` |

작업 기록의 검증 성공과 실제 운영 적용은 구분한다. 완료 여부나 현재 계약을 제목·수정일만으로 추정하지 않는다. 대체된 구현 기록은 현재 기준본을 확인한 뒤 `history/`로 옮기며, 원문과 미검증 조건을 보존한다. 들어오는 링크를 보정하고 중앙 ADR·외부 링크가 사용하는 기존 경로는 필요하면 짧은 이동 안내로 유지한다. 연구 원문은 `research/`에서 보존하되, 이전 구현에 대한 연구는 문서 홈에서 History / raw로 구분한다.

## description 작성

모든 docs Markdown의 첫 YAML 블록에 비어 있지 않은 문자열 `description`을 쓴다. 대상 기능·계약·문제와 문서가 다루는 범위를 1~2문장으로 적는다. 제목만 반복하거나 본문 전체를 복제하지 않는다. 미구현 계획·이전 계약·이동 안내·연구 결과는 그 성격을 명시해 현재 구현과 구분한다. 필드 이름은 `description`으로 통일한다.

새 문서나 상세 본문을 작성할 때 설명을 함께 쓴다. 태스크 패널에서 제목만 추가한 문서는 `태스크: 제목`으로 시작하며 제목을 바꾸면 자동 기본 설명도 따라간다. 직접 다듬은 설명은 패널이 덮어쓰지 않는다. 본문 범위·상태가 바뀌면 작성자가 설명도 갱신한다.

## 소유권과 갱신

기능 전용 요구사항·상세 명세는 해당 기능 파일이 소유하고, 여러 기능이 공유하는 개발 계약·사용법·운영은 기존 소유 문서에 둔다. 코드·기능·운영 변경과 소유 문서 갱신은 같은 작업에서 한다. 중앙 ADR은 복제하지 않는다. 시크릿과 임시 디버깅 로그를 문서에 쓰지 않는다.

새 문서를 만들거나 옮길 때 MOC에 등록할 필요는 없다. 실제로 존재하는 들어오는 링크는 이동·개명과 함께 보정한다. 기존 MOC·대표 문서는 Documents·기능 화면과 이전 링크의 호환을 위해 보존한다. MOC의 링크 목록은 모든 파일을 망라하는 필수 인덱스가 아니다. history의 원래 본문·연구 결과는 보존하고 archives는 수정하지 않는다.
