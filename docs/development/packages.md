# 공용 패키지

[문서 지도](../MOC.md) · [이 분야](MOC.md) · [설치·실행](../guides/getting-started-ko.md)

재사용 가능한 부분은 `packages/*`의 소스 패키지로 분리되어 있다 (빌드 없음 — vite·node가 소스를 직접 소비). 컴포넌트는 fetch 경로·인증을 모르고, 호스트 앱이 `api` prop으로 서버 연동을 주입한다 (앱 쪽 구현은 `src/api/client.ts`).

공용 화면 문구는 `@mew/ui/i18n-core`의 `uiText`와 `@mew/ui/i18n`의 `useUiLocale`로 번역한다. 호스트는 `setUiLocale`로 언어를 전달하며, Mew는 기존 `I18nProvider`와 연결한다. 편집기·모바일 보조키·터미널·단축키 오류·확인창이 같은 언어를 사용한다. Node에서 사용하는 유틸은 React를 불러오지 않는 `i18n-core` 진입점을 사용한다. 사전·구독·검증 기준은 [UI 번역 계약](ui-contracts.md#ui-번역)을 따른다.

- `@mew/editor` — TipTap 마크다운 에디터(`Editor`). frontmatter 패널·표·링크/멘션 툴팁· 미디어 업로드 포함. `EditorApi`(fetchFile·uploadAsset·fetchLinkPreview) 주입. fuzzy 검색·frontmatter 유틸도 여기서 export. `@`**·**`/` **입력 감지는** `keydown`**이 아니라** `onUpdate`**/**`onSelectionUpdate`**(트랜잭션 기반)로 한다** — keydown 스페이스 트리거는 모바일에서 조용히 실패한다(`SlashMenu.tsx`가 현재 구현).
  - **왼쪽 거터의 줄 번호가 드래그 핸들을 대신한다.** 번호는 호버와 상관없이 늘 떠 있고(`LineFocus`의 `data-mew-line-numbers`), 핸들 엘리먼트는 그 숫자 위에 포개지는 **투명한 손잡이**다(클릭=블록 선택). 블록 이동은 **0.7초 동안 움직이지 않고 누른 뒤**에만 시작한다. 그 전에 드래그를 시작하면 이동으로 승격되지 않고 기존 드래그/스크롤 제스처로 끝까지 처리한다. 밝기 3단: 평소 → 지금 잡히는 줄(`mew-line--hover`, DragHandle의 `onNodeChange`가 붙임) → 커서가 있는 줄(`mew-line--focus`, `editor/lineFocus.ts`의 장식).
  - 세는 단위는 핸들이 잡는 단위와 같아야 한다 — **최상위 블록 하나가 한 줄, 리스트는 항목이 한 줄**이고 `ul`/`ol` 자체는 줄이 아니다. 목록 padding은 한 단 24px이며 `LineFocus`가 `listLevel`로 계산한 `--mew-list-depth`를 번호 장식에 전달한다. CSS의 `li[data-mew-line-numbers]::before`는 깊이만큼 들여쓰기를 되돌려 모든 중첩 단계의 줄번호를 같은 거터에 맞춘다. JS의 투명 손잡이도 한 단 24px을 써야 숫자 위에 남는다 — 한쪽만 고치지 말 것.
  - 번호 값은 블록·목록 항목의 **Markdown 원본 시작 줄**이다. 원문을 현재 스키마로 정규화한 내용이 편집 문서와 같으면 원본의 빈 줄·soft break를 유지하고, 편집 직후 원문 prop이 뒤처지면 현재 문서 전체의 저장 직렬화 결과로 계산한다. frontmatter 줄 수를 더하며, 속성만 바뀌어도 본문 변경 없이 거터를 갱신한다. 번호 장식은 문서·원문·오프셋별로 재사용해 커서 이동마다 원문을 다시 파싱하지 않는다.
  - 저장에서 제외되는 마지막 빈 입력 문단에는 마지막 내용 줄에서 두 줄 뒤의 다음 블록 시작 번호를 표시한다(빈 문서는 본문 첫 줄). 중간 빈 문단은 저장되는 `<br/>`를 기준으로 계산한다. CSS 블록 순번으로 대체하지 않는다. 회귀 검증은 `packages/editor/src/editor/lineFocus.test.ts`와 실제 PC·모바일 편집기의 `server/editor-line-numbers-ui.test.ts`가 맡는다.
  - 표 스크롤 컨테이너의 왼쪽 끝은 본문 시작선에 맞추고 내부 표 앞에 여백을 두지 않는다. 줄번호는 컨테이너 바깥 왼쪽 거터에 표시하며 가로 스크롤에도 고정한다. `.tableWrapper`는 `position: static`을 유지하고 줄번호의 위치 기준은 `.tiptap`이다. 음수 왼쪽 margin과 이를 상쇄하는 padding으로 거터를 스크롤 영역에 넣지 않는다.
  - `EditorHandle`과 호스트 `CodePaneHandle`은 `getViewAnchor`·`restoreViewAnchor`로 원문 줄번호와 스크롤 영역 내 높이를 전달한다. Hotview는 거터의 원문 매핑을 재사용하고 Plain은 CodeMirror 문서 줄을 사용한다. `EditorPane`이 모드 변경 직전 앵커를 잡고 기존 MutationObserver·ResizeObserver 복원 경로에서 적용한다. 포커스를 강제로 가져오거나 본문을 저장하지 않으며, 사용자 입력·문서 전환·10초 상한에서 복원을 해제한다.
  - `showMobileKeyBar`(기본 `true`)로 호스트가 보조키 표시를 제한할 수 있다. 실제 표시는 모바일 폭·에디터 포커스도 필요하며, `false`로 바뀌면 Ctrl·Shift 토글과 보조키용 커서 하단 여백을 해제한다. 공통 메모는 소프트 키보드가 열린 동안에만 허용하고 일반 문서 에디터는 기존 표시 조건을 유지한다.
- `@mew/shortcuts` — 단축키 바인딩.
- `@mew/tmux-term` — 터미널 본문(xterm.js)과 서버 (`@mew/tmux-term/server`: `createTmuxManager`·`createTmuxRouter`·`attachTmuxWebSocket`, cwd 파라미터)을 제공한다. Mew의 주 UI는 `AgentPanel` 안의 `TmuxTerminal`이며 패키지의 범용 `TmuxTerminalPanel`은 현재 보조패널로 마운트하지 않는다. 버튼 줄 오른쪽 도구는 **전부 아이콘 하나**다(맨 아래 · 키보드 잠금 · 선택 모드 · 복사). 에디터에서 누른 Ctrl+L의 `경로:줄` 참조는 호스트 앱이 `mew:insert-ref`로 보내며 선택한 패널의 활성 탭 하나만 받는다.
  - \*\*\[맨 아래\]\*\*는 올라간 스크롤을 **누가 들고 있는지**에 따라 셋을 다 한다: ① xterm 자체 스크롤백이면 `scrollToBottom` ② tmux copy-mode(마우스를 안 쓰는 프로그램)면 WebSocket `exitCopyMode` → 서버가 `tmux copy-mode -q`(멱등. PTY에 `q`·Esc를 쏘면 모드가 아닐 때 TUI에 오입력된다) ③ **앱이 직접 스크롤하는 경우**(Claude Code처럼 마우스를 잡는 TUI) — tmux는 휠을 앱에 넘겼을 뿐이라 ①②가 통하지 않는다. 이때는 SGR 휠 아래를 한 번에 몰아 보내 앱 스스로 최신까지 내려가게 한다.
  - **\[키보드 잠금\]**(자물쇠)은 모바일 소프트 키보드가 뜨지 않게 한다 — 터미널의 보조 textarea와 하단 입력칸에 `inputMode='none'`을 건다. 포커스는 살아 있어 붙여넣기·하드웨어 키보드·명령어 버튼은 그대로 쓴다. 세션이 아니라 브라우저 설정이라 `localStorage: mew:tmux-keyboard-lock`에 남는다.
  - 터미널 세션·에이전트 탭의 전송 성공 입력은 각각 브라우저에 최근 100개까지 보관한다. 추가로 [브라우저 저장 계약](browser-storage.md)의 전체 용량·7일 보관 기간을 따르며, 미전송 초안은 자동 정리에서 제외한다. 입력칸의 첫 줄에서 `↑`, 마지막 줄에서 `↓`를 누르면 셸처럼 이전·다음 항목을 불러오며, 여러 줄 안에서는 본래 커서 이동을 유지한다.
  - 터미널 입력 영역은 에이전트 composer와 같은 색상 토큰을 사용한다. 도구 줄·입력 영역 바탕은 `surface-deep`, 테두리 없는 입력칸은 `surface`, 글자는 `ink`, 힌트는 `ink-muted`다. 전송 버튼은 32px 정사각형·`accent` 배경과 `ink-on-accent` 위쪽 화살표로 표시하며 접근성 이름과 Ctrl+Enter 툴팁을 유지한다. 셸 입력의 고정폭 글꼴과 자동 높이·전송 동작은 유지한다.
  - 하단 입력칸은 내용에 따라 자동으로 늘어나되 32\~160px 범위를 지킨다. 숨겨진 패널에서 `scrollHeight`가 0으로 측정돼도 32px 아래로 줄이지 않는다.
  - 하단 입력 힌트는 `TmuxTerminal`·`TmuxTerminalPanel`의 `inputPlaceholder` prop으로 호스트가 번역해서 전달한다. Mew는 ACP 입력칸과 같은 `common.textInput` 번역을 사용한다.
- `@mew/mobile-keys` — 모바일 키보드 보조키 바(`MobileKeyBar`). 에디터·터미널이 공용으로 쓴다. 바 높이는 고정하지 않고 버튼 24px·위아래 여백 각 4px·상단 테두리를 포함한 내용 높이에 맞춰 세로 넘침을 막는다. 필요한 가로 스크롤은 유지한다. 에디터 바는 화면 하단 고정, **터미널 바는 명령 도구 줄과 텍스트 입력칸 사이, 입력칸 바로 위의 레이아웃 공간을 차지**해 입력칸을 덮지 않는다. 터미널은 `stretch`와 `extraKeys`로 **Esc · Tab · Ctrl · Shift · ← · ↑ · ↓ · → · Home · End · ^C** 11개 키를 한 줄에 균등 배치한다. `Home`·`End`는 터미널에 줄 처음/끝 키를 보내며 Ctrl/Shift 조합 후 토글을 해제한다. `^C`는 Ctrl+C를 보내 실행 중인 프로그램에 중단을 요청한다. 초안은 전송·삭제하지 않고 기존 입력 포커스와 키보드 잠금·이력 방향키 동작을 유지한다. 에디터는 추가 키·균등 배치를 요청하지 않아 기존 구성을 유지한다. 고정 바는 `z-20`이다 — 전체 화면 오버레이(사이드바·채팅·에이전트· 터미널)가 `z-30`이라 그 아래로 깔려야 한다.\*\* 같은 `z-30`으로 두면 DOM 순서상 편집 칸이 사이드바보다 뒤라 보조키가 열린 사이드바 위에 떠 버린다. `onComment`를 주면 댓글 아이콘이 붙는다(폰에는 Alt+Shift+C가 없다) — 앵커는 호스트(`EditorPane.startComment`)가 만든다. `onCodeBlock`·`onTable`을 주면 코드블럭·표 아이콘이 붙는다 — 에디터만 넘기고(터미널은 대상이 없다) 코드블럭은 커서 문단 toggle, 표는 슬래시 메뉴 '표'와 같은 3×3 삽입이다. `onUndo`·`onRedo`는 되돌리기·다시 실행 아이콘이다 — Ctrl+Z/Y 단축키와 같은 경로(`runUndoRedoKeepingView`)라 커서가 바뀐 자리로 옮겨진다. 읽기 전용일 때는 에디터가 이 넷을 모두 감춘다. 보조키 바는 문서가 짧아도 화면 맨 아래에 고정되고, 모바일 키보드가 열린 때는 그 바로 위에 붙는다. 스와이프 전환은 제공하지 않는다.
- `@mew/ui` — 인라인 색상 선택기 `ColorPicker`([색상 입력 계약](ui-contracts.md#테마색과-파생-액센트)), 자체 단일 선택 필드 `SelectField`([드롭다운 계약](ui-contracts.md#드롭다운과-선택-컴포넌트)), 의존성 없는 공용 조각: `ConfirmDialog`(네이티브 confirm 대체 — 전체화면이 풀리지 않게), `useToast`(답을 받을 필요가 없는 짧은 안내 — 화면 아래 알약 하나, 2.6초 뒤 저절로 사라지고 `pointer-events-none`이라 아무것도 가로채지 않는다. **오버레이 스택에 등록하지 않는다** — 등록하면 안드로이드 뒤로가기가 토스트를 닫는 데 쓰인다), `pathDrag`([사이드바 항목 끌어놓기](../guides/editor.md#사이드바-항목-끌어놓기)), `useDragReorder`(줄 안 재정렬 + 줄 **바깥**에 놓을 때를 알리는 `onDragMove`/`onDrop` — 문서 탭 끌어서 화면 분할이 이걸 쓴다. 모바일은 0.35초 길게 누른 뒤 집히고, `immediateMouseDrag`를 쓰는 문서·에이전트·터미널·브라우저 작업 탭은 마우스로 바로 끌 수 있다. 기본 모드의 마우스는 0.5초 길게 누른 뒤 집히며 그전에 끌면 훅이 `scrollLeft`를 민다. 터치는 길게 누르기 전에 움직이면 기본 스크롤을 유지한다. 잡은 탭의 시각적 복사본이 포인터를 따라 움직이고 원래 탭은 빈 자리 표시를 남긴다. 복사본은 본문 호스트에 붙여 탭 줄 밖에서도 보이고 접근성·포인터 입력에서는 제외한다. 메뉴가 있는 터치 길게 누르기는 실제 이동부터 복사본을 표시한다. 놓기·취소·Esc·blur·창 크기 변경·화면 숨김·언마운트 때 복사본을 제거한다), `useOverlayDismiss`([닫기 규칙](ui-contracts.md)).


터미널 보조키 검증: `node --test server/terminal-keybar-ui.test.ts`. 실제 xterm·TmuxTerminal과 격리 WebSocket 기록으로 키 시퀀스·Ctrl/Shift 해제·초안/포커스 유지, 320/390/767px 양 테마에서 입력칸 위 한 줄 배치·가로/세로 넘침 없음·버튼과 세로 여백 수용 여부·데스크톱 숨김을 검사한다. 실제 셸 프로세스는 실행하지 않는다.
