# 오버레이와 탭 단축키 계약

## 디자인 지침: 여백과 정보 밀도

**여백은 내용을 돋보이게 하고 관계를 명확히 하는 만큼 사용한다. 화면의 여유로움은 빈 공간의 크기보다 정돈된 배치와 일관된 간격에서 만든다.** Mew의 작업 UI는 가독성·조작 편의와 함께, 한 화면에서 보고 다룰 수 있는 정보와 작업 영역을 우선한다.

- 패널·설정·팝업·툴바는 콘텐츠에 맞는 간결한 패딩과 간격을 기본으로 한다. 장식적인 바깥 여백, 중첩 컨테이너의 누적 패딩, 불필요한 최소 높이로 화면을 부풀리지 않는다.
- 관련 항목은 가깝게 묶고 그룹 사이에만 구분에 필요한 간격을 둔다. 위계는 정렬·글자 크기와 굵기·색상으로도 표현하며, 모든 구분을 큰 여백에 맡기지 않는다.
- 넓은 화면의 추가 공간은 본문·목록·작업 영역에 배분한다. 모바일과 좁은 패널에서는 과도한 여백 때문에 주요 조작이 화면 밖으로 밀리거나 불필요한 스크롤이 생기지 않게 한다.
- 원격 데스크톱은 실제 원격 화면의 가시 면적을 우선한다. 연결·설정 화면과 조작 도구도 같은 밀도 원칙을 적용하고, 큰 안내 카드나 빈 영역이 작업 화면을 잠식하지 않게 한다. 영상 비율 유지에 필요한 레터박스는 장식 여백과 구분한다.
- 밀도를 높일 때도 읽기 편한 글자와 행간, 클릭·터치 영역, 포커스 표시, 기기 안전 영역은 유지한다. 먼저 컨테이너 여백과 중복 공간을 줄이고, 내용을 잘라내거나 조작 대상을 지나치게 작게 만들지 않는다.

`impeccable` 등 디자인 스킬을 사용할 때도 이 프로젝트의 작업 중심 밀도 기준을 우선한다. 검토 시에는 같은 화면 크기에서 핵심 내용과 조작이 얼마나 잘 보이는지, 여백이 실제로 구분과 사용성을 돕는지 확인한다.

## 드롭다운과 선택 컴포넌트

앱이 소유하는 드롭다운·선택 목록은 **반드시 자체 컴포넌트**로 구현한다. OS/브라우저 기본 `<select>`·`<datalist>` 팝업은 신규·수정 UI에 사용하지 않는다. CSS `appearance: none`이나 색상만 적용한 네이티브 선택기도 해당한다. 모바일이라는 이유로 네이티브 목록으로 전환하지 않는다. 이 규칙은 사용자 요청으로 정했으며 명시적인 변경 요청 전 예외를 추가하지 않는다.

먼저 `packages/ui`와 기존 제품 컴포넌트를 확인해 적합한 자체 컴포넌트를 재사용한다. 없거나 접근성·기능 요구를 충족하지 못하면 공용 자체 컴포넌트를 만들어 사용한다. 일반 단일 선택에는 `@mew/ui`의 `SelectField`(`packages/ui/src/select-field.tsx`)를 사용한다. 모델 검색·런타임 설치 등 별도 기능이 있는 기존 자체 선택기는 해당 기능의 구현을 유지한다.

- 트리거와 목록은 앱 테마를 따른다. 선택·비활성 상태를 표시하고 긴 문구·모바일 너비에서도 화면 밖으로 넘치지 않는다. 목록은 portal로 부모의 overflow를 벗어나며 visual viewport의 여유 공간에 따라 위·아래로 배치하고 내부 스크롤한다.
- `combobox`·`listbox`·`option` 역할, 접근성 이름, 선택/펼침/활성 항목 연결을 제공한다. `SelectField`는 트리거에 포커스를 유지하고 방향키·Home/End·문자 검색·Enter/Space 확정·Tab 이동을 지원한다. 탐색만으로 값을 저장하지 않는다.
- 바깥 누름과 공통 `useOverlayDismiss`의 Esc·뒤로가기는 목록 한 겹만 닫는다. 모달 안에서도 목록이 먼저 닫히고 원래 설정창·포커스를 유지한다. 비활성화·저장 중에는 목록을 닫고 입력을 막는다.
- 에이전트 기본 지침의 커밋 방식·응답 언어·답변 길이는 이 공용 필드를 사용한다. 기존 즉시 저장·충돌 안내·재조회·사용자 정의 값 보존을 유지한다. `server/agent-guidance-ui.test.ts`에서 네이티브 select 없음, 키보드·모바일 터치 선택, 저장 중 포커스, 충돌 복구, Esc 우선 닫기와 목록 경계를 검사한다.
- 설정창의 언어와 UI·Markdown·Mono 글꼴도 `SelectField`를 사용한다. 글꼴은 `editable` 모드로 추천 목록과 직접 입력을 함께 제공하며 네이티브 `datalist`를 사용하지 않는다. 입력 중 공백·커서 이동·IME를 보존하고, 방향키로 활성화한 항목만 Enter로 선택한다. 입력·선택은 기존 변경 콜백을 사용하며 저장·초기화는 호출부가 소유한다. `server/theme-color-ui.test.ts`에서 언어 변경, 사용자 글꼴 저장·복원·초기화, 키보드·터치·Esc·뒤로가기와 320/390/1100px 양 테마 목록 경계를 검사한다.
- 계정 추가·계정별 역할·파일 권한·경로 범위, 에이전트셋 런타임, 예약 작업의 실행 주기·런타임·프로젝트, PDF 확대·펜 굵기, 원격 데스크톱 공유 화면·핫키 보조키, 모바일 편집 칸 선택도 이 필드를 사용한다. 서버 요청·저장 값·권한 경계는 각 호출부가 유지하며, 선택 목록 탐색만으로 저장하거나 폼을 제출하지 않는다.
- `compact`는 좁은 도구 줄의 필드 높이·글자 크기를 줄이며 coarse pointer에서는 터치 영역을 확보한다. `className`은 바깥 필드 너비·배치를, `id`는 기존 label 연결을 지정한다. 목록은 기본적으로 body에 portal하고, 전체화면·inert 경계가 있는 화면은 `portalContainer`에 해당 화면 루트를 넘긴다. PDF 전체화면은 PDF 루트, 원격 데스크톱은 원격 화면 루트를 사용해 목록이 전체화면 밖이나 입력 차단된 영역에 표시되지 않게 한다.
- `server/account-access-ui.test.ts`, `server/git-ai-commit-ui.test.ts`, `server/schedule-ui.test.ts`, `server/pdf-viewer-ui.test.ts`, `server/remote-desktop-ui.test.ts`, `server/workspace-switch-ui.test.ts`에서 각 화면의 선택 결과·모바일 경계·닫기 동작을 확인한다. 외부 웹사이트의 네이티브 선택 요소를 원격으로 조작하는 `server/browser-dom.ts`와 그 외부 페이지 fixture는 앱 UI 생성 코드가 아니므로 유지한다.

## 테마색과 파생 액센트

색상 입력은 `@mew/ui`의 `ColorPicker`(`packages/ui/src/color-picker.tsx`)를 사용한다. `value`·`defaultValue`는 불투명 6자리 HEX이며 `onChange`는 유효한 소문자 HEX만 전달한다. 저장·테마 파생은 호출부가 소유하고, 라벨은 호출부에서 번역해 전달한다. OS 색상 창 대신 필드 아래에 색상 영역과 색조·채도·밝기 슬라이더를 펼친다. 인라인 배치로 설정 스크롤 영역과 모바일 너비를 따르며 별도 portal·모달을 만들지 않는다.

색상 영역은 pointer capture로 마우스·터치 드래그와 경계 밖 좌표 보정을 처리한다. 같은 값을 접근성 이름·현재 값이 있는 세 range 슬라이더로 키보드 조절할 수 있다. 검정·회색에서도 조절 중인 색조·채도는 유지한다. 불완전 HEX는 저장하지 않고 blur·Esc 시 복원한다. `useOverlayDismiss`는 선택기 또는 HEX 편집 중 Esc·뒤로가기를 먼저 처리해 설정창을 유지하며, 닫기 후 색상 버튼으로 포커스를 돌린다. 바깥 누름으로도 접고 비활성 상태에서는 입력을 막는다.

화면 설정은 `src/utils/theme-color.ts`의 테마색 HEX 하나만 저장하고, 파생 토큰은 저장하지 않는다. `mew:theme-color`가 없을 때만 이전 `mew:accent-color` 객체의 `accent`를 읽는다. 잘못된 값은 기본 `#4432a8`로 복구하고 저장 실패 시 현재 화면에서 계속 사용할 수 있다. 예전 객체는 보존하지만 새 값이 우선하며 이전 `accentStrong`·`link`는 적용하지 않는다.

원본 색을 흰색 또는 검정과 sRGB 채널 단위로 혼합하여 상대 휘도를 맞춘다. 다크의 액센트/강한 액센트 목표 휘도는 0.35/0.50, 라이트는 0.10/0.055다. 극단적인 밝기·무채색도 같은 기준으로 보정하므로 직접 고른 색은 색 계열의 기준이며 화면의 액센트 HEX와 같지 않을 수 있다. `--color-link`는 액센트와 같고, `--color-ink-on-accent`는 다크에서 `#171717`, 라이트에서 흰색이다. 본문·패널·raised 배경의 액센트 글자와 솔리드 액센트/강한 액센트 버튼 글자는 4.5:1 이상 대비를 유지한다. 삭제 버튼·오류 알림은 별도 `--color-ink-on-danger`를 사용한다.

`src/main.tsx`에서 첫 React 렌더 전에 저장된 색을 적용하며, App은 테마색 또는 라이트/다크 모드 변경 시 네 토큰을 함께 갱신한다. `src/index.css`의 초기 기본값도 같은 파생 결과와 일치해야 한다. HEX 입력 중 미완성 값은 적용하지 않고 포커스가 나가거나 Escape를 누르면 마지막 유효한 값으로 되돌린다. 색상 선택·초기화는 즉시 적용한다. 네 언어에서 색상 입력은 하나만 표시한다.

검증: `src/utils/theme-color.test.ts`는 이전 설정 이관·유효성·저장 실패·모드 전환·기본 CSS 일치와 RGB 색상 격자/무채색의 대비·밝기 순서를 검사한다. `server/theme-color-ui.test.ts`는 실제 설정 컴포넌트로 HEX/선택기 입력·마우스/터치 드래그·키보드 슬라이더·무채색 편집·Esc/뒤로가기/바깥 누름·초기화·모드 전환·새로고침 복원·불완전 입력 복구·버튼 hover·삭제 버튼 글자색·320/390/1100px 양 테마를 검사한다.

## 에디터 본문 로딩

`useTabs`의 일시적인 `Tab.loading`은 저장 상태와 별개로 파일 본문 요청을 나타낸다. 새 파일·복원 탭·캐시 재검증에 설정하며 전체 본문 성공(빈 문자열 포함) 또는 실패 시 해제한다. 큰 파일의 앵커 미리보기만 받은 동안은 유지한다. 탭 저장 원장에는 기록하지 않으며, 자체 뷰어가 스트리밍하는 바이너리 미디어에는 설정하지 않는다.

`EditorPane`은 활성 탭이 로딩 중일 때 `DockInlineBody`에 `aria-busy`를 설정하고 본문·툴바·상태줄을 검정 50% 덮개와 중앙 스피너로 덮는다. 아래 영역은 `inert`, 편집기는 읽기 전용으로 처리한다. 탭 바와 다른 패널은 계속 사용할 수 있다. 로딩 인디케이터의 `role="status"`는 기존 `common.loading` 번역을 사용하고, 모션 감소 설정에서는 회전하지 않는다.

검증: `server/editor-pane-ui.test.ts`는 실제 편집기와 지연 파일 응답으로 1100px 다크·390px 라이트에서 덮개 경계·입력 차단·캐시 본문·모션 감소·연속 파일 전환·빈 문서·실패 후 해제를 확인한다. 기존 협업 편집기 오류 복구와 워크스페이스 전환 검증은 각각 `server/editor-collab-ui.test.ts`, `server/workspace-switch-ui.test.ts`가 담당한다.

## 작업 패널 배치

메뉴·독의 기능 화면은 App 소유 작업 패널이며, 미저장 확인·커밋 상세만 공통 `ConfirmDialog`·`DialogFrame`을 사용한다. 기능 트리·상세·인라인 요청·대화 연결의 기준본은 [기능 기반 개발](../specs/feature-development.md)이다.

원격 데스크톱은 [ADR 0136](../../../.mew/docs/decisions/0136-mew-native-remote-desktop-webrtc.md)의 독립적인 화면 오버레이다. 모바일에서는 독을 남기고 브라우저 전체화면에서만 독을 숨긴다. 도킹·패널 복원에 포함하지 않는다. 공통 Esc·뒤로가기 스택을 사용하고, 닫기·백그라운드 전환은 영상과 입력을 종료한다. 조이스틱·뷰 조작 계약은 [원격 데스크톱](remote-desktop.md)에 둔다.

[ADR 0134](../../../.mew/docs/decisions/0134-mew-dockable-workspace-panels.md)에 따라 에디터·에이전트·일반 터미널·웹 브라우저·Git은 `DockWorkspace`의 공통 분할 영역을 사용한다. Git 추가는 [ADR 0135](../../../.mew/docs/decisions/0135-mew-git-workspace-panel.md)를 따른다. 파일 트리 사이드바·멤버 채팅·Android는 기존 보조창을 유지한다.

- 상단 손잡이는 패널 전체를 옮긴다. 마우스로 탭을 끌면 탭 하나를 분리한다. 같은 종류의 탭바 전체(탭 사이·빈 공간·양 끝 포함)에 놓으면 합친다. 탭바의 실제 DOM 영역을 본문 가장자리 분할보다 먼저 판정하며, 탭 아이템을 직접 맞출 필요는 없다. 본문 중앙에는 합치고 가장자리에는 새 칸을 만든다. 다른 종류와는 나란히 배치한다. 드롭 전에 실제로 붙을 영역을 표시하며 Esc는 드래그를 취소한다. 드래그 중 탭 순서가 바뀌어 DOM 노드가 이동하면 커밋 직후 pointer capture를 복구해 탭바 밖에서도 이동·드롭을 이어 받는다.
- 문서·에이전트·터미널·브라우저 탭의 공통 `useDragReorder`는 잡은 탭을 포인터와 같은 거리만큼 움직이는 복사본으로 보여준다. 탭 크기는 유지하고 위로 8px 들어 올리되 화면 위쪽을 넘지 않는다. 원본 탭은 크기를 유지한 빈 자리로 남겨 재정렬 좌표가 흔들리지 않게 한다. 복사본은 가로 스크롤 영역에 잘리지 않고, `aria-hidden`·`inert`·`pointer-events: none`으로 탭 탐색과 분할 드롭 판정에 끼어들지 않는다. 가로 가장자리 자동 스크롤 중에도 포인터를 따라가며 종료·취소 시 원본 표시와 캡처를 복구한다. 즉시 마우스 드래그·모바일 길게 누르기·메뉴·줄 스크롤의 기존 판정은 유지한다. `server/tab-reorder-ui.test.ts`는 실제 Chromium에서 양 입력의 추적·슬롯 표시·재정렬 뒤 드롭 식별자·클릭 억제·Esc/터치 취소·자동 스크롤·언마운트 정리를 검사하며 기존 `dockWorkspaceUi.test.ts`로 분할·합치기를 함께 확인한다.
- 데스크톱(768px 이상)에서 문서·에이전트·터미널·브라우저 **탭 자체를 더블클릭**하면 해당 패널의 탭 바와 본문을 사이드바를 포함한 `.mew-workspace-content` 전체로 확대하고 다시 더블클릭하거나 Esc를 누르면 원래 분할로 돌아온다. 프로젝트 헤더는 영역 밖에 남고 선택한 패널의 탭 바만 작업 영역 맨 위에 전체 너비로 표시한다. 나머지 패널은 세로 분할의 중간 탭 바까지 숨기고 `inert`로 키보드 접근도 막는다. 플로팅 독은 그보다 위에 남는다. 탭 바 빈 공간·손잡이·닫기/추가 버튼·탭 이름 입력란은 확대 트리거가 아니다.
- 확대는 `DockWorkspace`의 임시 그룹 상태이며 저장된 분할 트리·비율·탭 배정을 수정하지 않는다. 확대 중 다른 패널 탭은 보이지 않으며, 복귀 후 탭을 선택하거나 독으로 다른 패널을 조작한다. 탭·손잡이 드래그, 확대 패널 닫기/마지막 탭 제거, 모바일 전환 시 해제한다. 확대 중 분할 경계선은 숨기고 복귀 시 원래 위치로 돌려놓는다. 프로젝트 전환·새로고침 후 확대 상태는 복원하지 않는다.
- 확대 시 선택한 `DockPanel`을 작업 영역 전체로 넓히며, 도구 본문은 기존 `DockBody`를 확대된 탭 바 아래에 배치한다. 문서 본문·에이전트 선택기/초기 상태는 기존 소유자 아래의 `DockInlineBody`에서 부모 크기를 따라 늘어난다. 편집기·ACP·tmux·브라우저를 재마운트하지 않는다. 가려진 다른 인라인 본문은 `inert`와 숨김 처리하고, 도구 본문은 기존 활성 탭 표시 조건에 확대 대상을 더한다. 확대 중 `+`로 연 에이전트 선택기도 확대 영역에서 조작한다. 문서 미리보기 탭의 더블클릭 고정은 확대와 함께 유지한다. 에이전트·터미널 탭 이름 변경은 데스크톱에서 F2, 모바일에서 기존 제목 더블탭을 사용한다.
- 확대 상태는 공통 `useOverlayDismiss` 스택에 등록한다. Esc·뒤로가기는 확대 한 겹만 해제하며 패널 자체를 닫지 않는다. 나중에 열린 팝업·모달은 먼저 닫히고 IME 조합 중 Esc는 가로채지 않는다. 브라우저 복제 iframe 안의 Esc도 확대 중에만 이 스택으로 전달하고 처리되면 원격 사이트에 중복 전달하지 않는다.
- 탭 포커스의 `Shift+Enter`는 확대·복귀의 키보드 대안이며 키 반복은 무시한다. 확대 중에는 선택한 패널의 탭만 키보드로 탐색할 수 있다. 독의 패널 선택은 `DockHandle.restore()`로 확대를 해제한 뒤 기존 탐색 동작을 수행하므로 사이드바·다른 종류의 도구가 가려진 상태로 남지 않는다.
- 브라우저는 좌우로만 붙인다. 세로 분할 안의 칸을 대상으로 삼아도 해당 세로 분할 전체의 옆에 붙이며, 브라우저 위아래에 다른 패널을 붙이는 동작도 허용하지 않는다.
- 경계선을 끌거나 키보드 화살표로 분할 비율을 조절한다. 배치·비율·탭 배정·패널별 활성 탭은 루트 프로젝트의 계정 `workspaceUi.dock`에 버전 1로 저장한다. 기존 에디터 분할은 최초 배치에 반영하고 터미널 열림 상태는 `chrome.terminalOpen`으로 분리한다.
  - 경계선은 주 포인터의 왼쪽 누름에서 pointer capture를 얻고, iframe 위에서도 같은 포인터의 이동·놓기를 이어 받는다. `pointerup`은 마지막 위치를 반영하고 캡처를 해제하며 `pointercancel`·`lostpointercapture`는 조절을 끝낸다. 전역 window 이동 리스너에 의존하지 않는다. 패널 비율은 로컬에서 즉시 변경하고, 내부 브라우저 viewport 동기화 응답을 기다리지 않는다.
- `DockPanel`과 탭별 `DockBody`는 같은 DOM 호스트에 유지하고 위치만 바꾼다. 분할 나무를 바꿀 때 ACP·tmux·브라우저 본문을 다시 마운트하지 않는다. 에이전트·셸 탭 원장은 `AgentPanel` 컨트롤러 하나가 저장한다. 숨김은 탭 종료가 아니다.
- 모바일에서는 전면 종류 하나만 표시한다. 768px 미만에서는 공통 `DockGrip`을 렌더하지 않아 에디터·에이전트·터미널·브라우저·Git의 패널 이동 손잡이와 그 자리 여백을 없앤다. 데스크톱으로 넓히면 손잡이를 복원한다. 에이전트·터미널·브라우저의 분리된 탭은 종류별 한 줄로 모으며 데스크톱 배정은 보존한다. 문서 편집 칸이 여럿이면 상단 선택기로 전환한다. 패널 전면 상태와 뒤로가기는 기존 공통 스택을 따른다.
- 마지막 탭을 옮긴 기존 패널은 기본 패널을 포함해 자동으로 접힌다. 다른 패널에 탭이 남아 있을 때 빈 기본 패널이나 새 탭 버튼만 있는 칸을 남기지 않는다. 처음 여는 종류에 탭이 전혀 없을 때의 새 탭 화면은 유지한다.
- 패널의 닫기 버튼은 기본·분리 여부와 관계없이 누른 패널 하나만 닫는다. 같은 종류의 남은 패널이 있으면 탭을 그쪽으로 옮기고, 남은 패널의 활성 탭은 유지한다. 마지막 패널이면 탭을 기본 그룹에 보존하고 해당 종류를 접는다. 닫은 패널의 분할은 저장된 배치에서도 제거하며 남은 패널이 빈자리를 채운다. 다시 열 때는 보존된 탭을 한 패널로 열고 닫았던 빈 분할을 복구하지 않는다. 탭 닫기는 기존 세션 종료 계약을 따른다. 모바일의 종류별 전면 전환과 전체 표시 토글은 기존 동작을 유지한다.
- 브라우저 탭바(독립 `/browser` 포함)는 에이전트·터미널과 같은 36px 높이·깊은 배경·활성 탭 배경·간격·드래그 강조를 사용한다. 탭 제목은 최대 9rem에서 줄이고 탭 자체는 축소하지 않아 가로로 스크롤한다. 탭 닫기는 16px 버튼이다. 브라우저의 새 탭은 마지막 탭 바로 뒤의 36px 너비 버튼과 14px SVG `+`이며 Git은 현재 프로젝트 하나만 사용하므로 추가 버튼을 두지 않는다. 패널 닫기는 오른쪽에 고정한 24px 버튼과 14px SVG `×`로 표시한다. 마지막 브라우저 탭도 닫을 수 있으며, 탭이 없으면 패널 안에 주소·바로가기 시작 화면을 표시한다. `+`로 만든 빈 탭은 주소를 열기 전까지 서버 세션 없이 도킹·선택·닫기를 지원한다.

검증은 `dockWorkspaceUi.test.ts`의 탭바 빈 공간 합치기·빈 기본/분리 패널 접기·개별 기본/분리 패널 닫기·빈자리 확장·재열기/새로고침·초안/마운트 보존 검사, `dock-layout.test.ts`의 트리·브라우저 제약·복원 검사와 실제 React 패널을 올린 격리 브라우저에서 수행한다. 드래그 분리·합치기, 경계 크기 조절, 저장 복원, 모바일 전환, 초안·마운트 유지가 대상이다. 실행 중인 Mew 서버에 빌드 결과를 반영하지 않는다.
크기 조절은 서버 통신 없는 중첩 iframe 위로 포인터를 한 번에 옮기는 재현 테스트로 확인하며, 놓기·취소 뒤 정지와 키보드 조절도 검사한다.
`dock-maximize-ui.test.ts`는 실제 문서·에이전트·터미널·브라우저 탭과 세션 전송 대역을 격리해 확대 범위, 세로 분할 탭 바·프로젝트 탭·독의 hit test, 원래 비율 복귀, 탭이 있는 패널의 Esc 복귀·팝업 우선 닫기, 저장 미변경, 초안·마운트 보존, F2 이름 변경, 탭 전환·드래그·닫기·마지막 문서 탭 제거와 모바일 무동작을 확인한다. `browser-dom-scroll.test.ts`는 복제 iframe 안에서 확대 중 Esc를 호스트가 처리하고 일반 상태에서는 원격 사이트에 전달하는지 확인한다.

## Git 저장소 탭

`git-panel.tsx`는 현재 프로젝트 루트(`.workspace`, 빈 상대경로) 하나를 바로 연다. 저장소 탭·탭 바·선택기·중첩 탐색은 없다. 사용자 요청으로 단일 현재 프로젝트 탭 바를 제거했으며 요청 전 재도입하지 않는다. `DockBody`의 상단 여백은 0이며 커밋 작성부터 표시한다. GitHub 로그인·닫기·데스크톱 이동 손잡이는 작성 영역 아래 조작 줄에 합치고, 상세·diff에서는 기존 뒤로가기 줄에 표시한다. 로딩·저장소 없는 상태에도 이 조작은 제공한다. Git은 탭 더블클릭 확대 대상에서 제외한다. `restoreGitPanel`은 기존 Documents·하위 저장소 탭과 활성 선택을 현재 루트 하나로 정규화한다. `workspaceUi.git`는 그 식별자, `workspaceUi.chrome.gitOpen`은 열림 상태, `workspaceUi.dock`은 배치를 소유한다. 루트 전환은 계정 UI 로딩을 기다린 뒤 새 프로젝트 화면을 마운트한다.

`GitWorkbench`는 `DockBody` 아래에서 이동·숨김 동안 마운트를 유지한다. 패널 닫기와 `Ctrl+W`는 Git 패널을 접고, 다시 열면 상세·커밋 초안을 유지한다. 초안은 영구 저장하지 않는다. 이전·다음 탭 신호는 무시한다. 기존 저장 탭 식별자는 도킹 배치 호환에만 사용한다. 모바일 전면·Esc·뒤로가기는 공통 패널 등록표를 사용한다. 커밋 우클릭 메뉴는 패널보다 먼저 닫는다.

기본 화면은 작성 영역·변경 파일·커밋 기록 순서이며 초기 높이는 약 30:50:20이다. 작성 영역은 위쪽 구간의 37.5%로 시작하고 CSS 세로 resize로 설명 공간을 조절한다. 제목 오른쪽에 커밋 버튼, 아래에 설명과 AI 자동 커밋 버튼을 둔다. 파일별/전체 체크박스의 선택은 패널 메모리에서만 유지하며 새 파일은 자동 선택하지 않는다. `GitWorkbench`가 작성·변경사항 구간의 비율(기본 80%, 범위 15–85%)을 메모리에 보관하고 상세 화면에서도 기본 목록 DOM을 숨겨 유지하므로 두 목록의 스크롤을 보존한다. 각 목록은 독립 스크롤·overscroll containment를 사용한다. 경계는 pointer capture로 마우스·터치 드래그를 처리하고 놓기·취소·capture 해제 시 종료한다. 키보드 위/아래는 5%씩, Home/End는 양 끝으로 조절하며 접근성 separator 값도 갱신한다. 커밋 행은 28px, 그래프 레인 간격은 10px이며 상대 시간은 `relativeCommitTime`에서 가장 큰 단위 하나로 계산한다. 작업트리 diff에서 돌아오면 기본 화면의 선택·초안·스크롤을 복원한다. 커밋 POST는 명시적 `files` 목록을 요구한다. 서버는 현재 변경 목록과 정확히 일치하는 경로만 허용하고 이름 변경의 이전 경로도 포함한다. 새 파일을 index에 등록한 뒤 literal pathspec과 `git commit --only`를 사용하므로 선택하지 않은 staged 파일을 커밋하지 않는다. 미추적 폴더도 파일별로 나열한다.

저장소 상태를 먼저 조회하며 루트가 저장소가 아니면 빈 상태를 표시하고 로그·작업트리 요청을 보내지 않는다. 재시도로 Git 초기화 이후 상태를 갱신할 수 있다. 저장소 목록 API는 각 요청 스코프의 루트만 확인한다. 경로 기반 커밋 조회 등 다른 Git API는 기존 소비자와 권한 경계를 유지한다. 사용법·제거 이유·재도입 조건은 [Git 사용법](../guides/projects.md#git-작업-패널)과 [ADR 0160](../../../.mew/docs/decisions/0160-mew-git-current-project-only.md)을 따른다.

검증: `server/git-panel-ui.test.ts`는 실제 React·격리 Chromium에서 현재 루트 직접 열기·탭 바/상단 예약 공간 없음·변경 파일 즉시 표시·독립 스크롤·분할 드래그/키보드·320px 한 줄 커밋·직접 diff 복귀·옛 저장소 탭 정리·도킹 이동·닫기/재열기·초안 유지·모바일·단축키·저장소 없는 상태를 확인한다. `git-panel-state.test.ts`는 저장 상태 이행, `server/gitWorkbench.test.ts`는 실제 임시 저장소로 중첩 제외·프로젝트 전환·상위 저장소 fallback 금지와 기존 Git 작업을 검사한다.

## 플로팅 핸들과 상단 메뉴

독 이동 손잡이의 hover 툴팁은 사용자 요청으로 제거했으며 요청 전 재도입하지 않는다. 손잡이의 접근성 이름(`aria-label`)과 이동 조작은 유지한다.

`MobileDock`는 모든 화면 크기에서 표시한다. 768px 미만에서는 다음 모바일 배치를 사용한다. 기본 순서는 `sidebar, editor, agent, terminal, git, browser, features, desktop, rag`이며 기능 권한으로 보이는 항목을 거른다. 화면 양옆·맨 아래에 붙는 직사각형 바이며 높이는 48px + 하단 safe-area다. 둥근 외곽선과 선택 아이콘의 배경은 없애고 위쪽 1px 구분선만 둔다. 선택된 아이콘은 밝은 글자색과 굵은 선으로 표시한다. 아이콘은 가로로 균등 배치하고 터치 높이는 44px이며 너비는 화면에 맞춰 균등 분배한다(320px에서 9개를 표시할 때 약 34.2px). z-index는 40으로 메뉴·모달보다 낮다. 작업 본문·모바일 고정 패널은 하단 48px + safe-area를 비워 입력부를 가리지 않는다. 일반 뮤캣의 바닥은 독 위로 올라가 아이콘과 겹치지 않으며 거대 휴식 고양이는 기존 화면 범위를 유지한다.

768px 이상에서는 하단 중앙에 완전히 둥근 캡슐형 플로팅 독을 표시한다. 배경은 테마 surface 색의 78% 불투명도와 16px backdrop blur를 사용한다. 본문 공간을 예약하지 않고 z-index 40으로 띄운다. 왼쪽의 작은 점 손잡이를 잡으면 대기 없이 독 전체를 옮긴다. 아이콘의 선택·길게 눌러 재정렬과 별개의 제스처이며 패널 전환을 발생시키지 않는다. 손잡이에 초점을 두고 방향키로 8px, Shift+방향키로 32px 이동할 수 있다. 위치는 `mew:desktop-dock-position`에 저장하고 저장 실패 시 현재 화면에서 계속 작동한다. Esc·pointer cancel·capture 해제·blur·화면 숨김·창 크기 변경은 진행 중 이동을 되돌린다. 독 크기·창 크기 변경 시 화면 가장자리 8px 안쪽으로 표시 위치를 보정하며 모바일에서는 저장 위치를 적용하지 않는다. 원격 뷰어에서도 같은 독을 portal하고 브라우저 전체화면에서는 숨긴다. 데스크톱 독 버튼은 해당 패널의 열림 상태를 토글하며 다른 패널은 유지한다. 열림 상태는 `aria-pressed`로 제공하고 열린 패널 모두에 옅은 `surface-raised` 배경을 표시한다. 현재 작업 포커스를 가진 패널 하나는 `aria-current`와 더 진한 `surface-hover` 배경·밝고 굵은 아이콘으로 구분한다. 두 종류의 하이라이트 모두 클릭하면 해당 패널을 닫고 배경을 없앤다. 닫힌 아이콘은 hover해도 배경 하이라이트를 만들지 않고 글자색으로 반응한다. `useFocusedWorkspacePanel`은 패널의 `data-workspace-panel` 경계에서 pointerdown·focusin과 iframe 진입 시 window blur 뒤 활성 요소를 추적한다. 탭·본문·키보드 이동 모두 갱신하며, 독·공통 도구 조작은 마지막 작업 포커스를 유지한다. 닫힌 패널은 하이라이트에서 제외하며 단순 열림 순서로 포커스를 추정하지 않는다. 에디터는 모든 편집 칸을 숨기거나 다시 표시하며 탭·본문·분할 배치와 마운트를 보존한다. 에디터 숨김은 현재 앱 메모리에서만 유지하고 모바일에는 적용하지 않는다. 파일 열기 등 에디터 전면 요청은 숨김을 해제한다.

모바일 독 선택은 공통 `openWorkspacePanel` 또는 `showMobileEditor`로 전면만 전환하고, 같은 버튼을 다시 눌러도 닫지 않는다. 데스크톱에서는 열린 패널을 `closeWorkspacePanel`로 닫고 닫힌 패널을 연다. 기능 패널 닫기는 `featureCloseRef`의 미저장 확인을 거친다. 스와이프는 포커스 기록 대신 **실제 모바일 전면 패널**을 기준으로 동작한다. 좌→우는 -1, 우→좌는 +1이며 40px 이상, 가로 이동이 세로의 1.5배를 넘을 때 한 번 실행한다. `adjacentDockPanel`은 표시 중인 독 순서의 바로 옆 항목만 선택하며 양 끝에서 순환하지 않는다. 패널 내부의 탭·사이드바 뷰는 건드리지 않는다. 탭 우선 이동과 `mobileTabNavigationRef` 연결은 사용자 요청으로 제거했으며 요청 전 재도입하지 않는다. 독에 없는 채팅·Android에서는 독 버튼으로 대상 패널을 선택한다.

`desktop` 항목은 `caps.desktop`이 있을 때만 표시하고 기존 저장 순서에 없으면 맨 뒤에 보충한다. 모바일 선택·스와이프는 독립 전체화면 뷰어를 열고, 데스크톱 버튼은 뷰어를 켜거나 끈다. 작업 패널 스택은 유지하고 뷰어 닫기 뒤 이전 전면 패널로 돌아온다. 원격 뷰어의 모달·배경 inert·연결 종료 계약은 유지한다. 독은 뷰어 내부 호스트로 portal하여 계속 사용할 수 있고, 다른 패널 선택·스와이프는 뷰어와 연결을 닫는다. 브라우저 전체화면에서는 독·예약 공간을 숨기고 해제 시 복원한다. 8개 아이콘은 좌우 여백 6px와 항목 간격 0으로 320px 폭에서도 줄바꿈·가로 넘침 없이 표시한다. 위아래 여백은 각각 1px·2px이며 별도로 하단 safe-area를 더한다.

`features`는 현재 루트 프로젝트와 `caps.agent`가 있을 때 표시한다. 기본 위치는 원격 데스크톱 바로 왼쪽이며 기존 저장값에 없으면 `desktop` 앞에 보충해 이전 항목들의 상대 순서를 유지한다. 모바일 버튼·스와이프와 메뉴는 `openWorkspacePanel('features')`로 같은 패널을 열며, 데스크톱 독 버튼은 열기·닫기를 토글한다. `features`도 공통 전면 스택·dismissal 등록표에 참여하며 모바일 독의 선택 표시는 전면 패널을, 데스크톱은 현재 작업 포커스를 따른다. 모바일에서 다른 패널로 전환해도 컴포넌트를 유지하여 선택·초안을 보존한다. 닫기·Esc·뒤로가기·전체 패널 닫기는 `requestCloseRef`를 통해 미저장 확인을 거친다. 데스크톱은 오른쪽 붙임 패널이며 패널 폭 640px 미만에서는 목록·상세를 교대로 표시한다. 기능 전체 팝업은 사용자 요청으로 제거했으며 요청 전 재도입하지 않는다.

450ms 정지 후 길게 누르기를 재정렬로 승격하고, 그 전에 10px 움직이면 길게 누르기를 취소한다. PC·모바일 모두 잡은 아이콘의 복사본을 포인터와 같은 거리만큼 이동시키고 8px 들어 올려 표시한다. 원래 버튼은 아이콘을 숨긴 빈 자리 표시로 남기며, 변형되지 않은 버튼 슬롯의 가로 중심과 포인터의 거리를 기준으로 순서를 미리 보여준다. 독 위아래로 벗어나거나 양 끝을 넘어도 가장 가까운 슬롯으로 이동하고, 같은 슬롯 안의 작은 움직임으로 순서가 반복해서 뒤집히지 않는다. 놓을 때 `mew:mobile-dock-order`에 저장한다. 저장값은 중복·미등록 ID를 제거하고 누락된 기본 항목을 보충하며, 권한으로 숨긴 항목의 순서도 보존한다. 저장 실패 시 현재 화면에서 계속 작동한다. 취소·추가 터치·Esc·blur·화면 숨김·창 크기 변경·portal 호스트/권한 항목 변경은 미리보기를 되돌리고 포인터 캡처를 해제한다. 재정렬 중 Esc는 패널 닫기로 전달하지 않으며 재정렬과 스와이프 뒤 합성 클릭은 실행하지 않는다. 버튼 접근성 이름·독 안내는 네 언어를 지원하며 `Alt+좌우` 재정렬과 Enter 선택을 제공한다.

독 아이콘은 공통 `HoverTipLayer`와 `data-tip`으로 마우스 호버 즉시 이름을 표시한다. 터치 탭은 아이콘 위치와 관계없이 독보다 8px 위, 화면 중앙에 같은 이름의 작은 토스트를 500ms 표시한다. 연속 탭은 이전 토스트를 교체하고 시간을 다시 센다. 스와이프·재정렬·취소에는 표시하지 않으며 키보드로 독을 숨기거나 화면을 떠나면 정리한다. 토스트는 포커스를 옮기거나 포인터 입력을 가로채지 않는다.

`useMobileKeyboard`는 입력 초점과 visual viewport 축소(150px 초과)를 함께 확인한다. 레이아웃 뷰포트도 줄어드는 브라우저를 위해 키보드 전 높이를 기억하고 너비 변경 시 갱신한다. 키보드 동안 독과 예약 공간을 숨긴다. 확대 제스처는 키보드 판정에서 제외한다. 기존 모바일 플로팅 핸들과 왼쪽 사이드바 버튼은 독으로 대체했고 사용자 요청 전 재도입하지 않는다.

검증: `mobile-dock.test.ts`는 기존 순서 복원·기능/원격 데스크톱 항목 보충·패널 경계를, `server/mobile-dock-ui.test.ts`는 Chromium의 마우스 툴팁·터치 토스트 위치/500ms 종료/연속 탭 갱신과 실제 터치의 선택·양방향 스와이프·포인터 추적/빈 자리/독 바깥 이동·순서 저장·취소·키보드 재정렬·키보드 viewport 축소·권한 필터·320/390/767px 양 테마와 데스크톱 표시·반투명 캡슐·마우스 길게 눌러 순서 이동/저장/Esc 취소·손잡이 이동·위치 복원·키보드 이동·Esc 취소·창 축소 경계·모바일 전환을 검사한다. `server/workspace-switch-ui.test.ts`는 실제 App의 데스크톱 독 토글·열림 상태와 포커스 표시의 양 테마 배경 강도·닫기 후 하이라이트 해제·본문 클릭/키보드/iframe 포커스·에디터 숨김/복원·기능 초안 닫기 확인·모바일 재선택 유지·탭 선택 유지·인접 패널 전환과 원격 데스크톱 버튼과 기능 버튼/스와이프 진입·초안 유지·Esc/뒤로가기 미저장 확인·독 위 배치를 실제 기능 컴포넌트로 확인한다(원격 전송은 fixture로 대체). 실기기의 키보드 애니메이션·안전 영역 동작은 별도 확인 대상이다.

데스크톱의 `FabMenu`는 실제 pointerType으로 입력을 구분한다. 마우스 왼쪽 버튼은 8px 이동부터 대기 없이 위치를 변경하며, 클릭은 메뉴를 연다. 마우스 위치 이동은 방향 명령을 실행하지 않는다. 터치는 기존 방향 선택과 350ms 길게 누른 뒤 이동을 유지한다. 위치 고정 시 입력 종류에 관계없이 위치 변경을 막고, 터치 방향 선택과 메뉴 버튼은 계속 사용할 수 있다.

위치와 고정은 기기 설정으로 `mew:floating-handle-position`·`mew:floating-handle-locked`에 저장한다. 저장소가 막혀도 현재 화면에서는 이동·고정이 작동한다. 열린 메뉴는 화면 안으로 보정하되 저장 위치는 바꾸지 않는다. 키보드 회피도 고정 여부와 무관하게 적용한다. 메뉴는 공통 오버레이 닫기 스택을 사용하고 숨긴 버튼은 키보드 탐색에서 제외한다. 아이콘 설명은 `HoverTipLayer`의 `data-tip`으로 즉시 표시한다.

`HeaderMenu`는 768px 이상에서 번역된 메뉴 이름과 36px 높이 버튼을 표시한다. 앱 헤더는 같은 구간에서 48px 높이와 넓은 도구 여백을 쓴다. 작은 화면은 40px 헤더와 아이콘 버튼을 유지한다. 열린 메뉴는 `z-index: 1050`으로 플로팅 핸들·도킹 경계·브라우저 팝업보다 앞에 표시한다. 메뉴에서 여는 대화상자는 메뉴를 닫은 뒤 표시한다.

로그인 사용자는 햄버거 바로 왼쪽의 `ActiveSessionsButton`에서 활성 브라우저 세션 수와 사용자별 목록을 확인한다. 팝업은 화면 너비 안에서 줄바꿈하고 긴 목록은 내부 스크롤한다. 연결 중에는 `—`를 표시하고 이전 목록을 비운다. 신원·접속 수·권한의 기준은 [presence 계약](collaboration.md#활성-mew-세션-presence)을 따른다.

검증: `server/fab-menu-ui.test.ts`에서 실제 Chromium의 마우스 즉시 이동·클릭·고정 복원·툴팁·키보드와 터치 방향 선택·길게 누르기·반응형 메뉴를 확인한다.

## 겹친 창과 크기 조절 경계

데스크톱 `DockBody`는 자체 z-index를 만들지 않는다. 본문 안에서 열린 메뉴·팝업이 낮은 부모 레이어에 갇혀 형제 크기 조절 경계(`z-index: 40`) 뒤로 내려가는 것을 방지한다. 본문 사각형은 헤더·경계 영역을 제외하므로 기존 본문 배치와 드래그 캡처는 유지한다. 모바일의 패널 전면 순서용 레이어는 유지한다.

터미널 명령어 버튼 편집창은 `document.body`로 portal하며 전체 화면 배경이 뒤쪽 패널과 경계의 포인터 입력을 가로막는다. 다른 팝업도 자기 영역에서는 뒤쪽 경계 대신 포인터 입력을 받아야 한다. 전체 화면 모달은 배경까지 가로막고, 작은 메뉴는 덮고 있는 영역에서 가로막는다. 커서 모양만 숨기고 뒤쪽 리사이즈가 계속 작동하도록 구현하지 않는다.

검증: `server/overlay-layer-ui.test.ts`에서 메뉴와 핸들을 겹치고, 본문 안 팝업·실제 터미널 버튼 편집창을 크기 조절 경계와 겹쳐 `elementFromPoint`·실제 커서·드래그 차단을 확인한다. 창을 닫으면 다시 크기 조절할 수 있어야 한다.

## 사이드바 터치 메뉴와 이동

`useTreeTouchGesture`는 실제 포인터 종류로 터치와 마우스를 구분한다. 터치가 시작되면 해당 항목의 네이티브 `draggable`을 끄고, 브라우저의 이른 `dragstart`·`contextmenu`가 길게 누르기 메뉴를 선점하지 못하게 한다. 마우스를 다시 누르면 네이티브 드래그를 복구한다.

- 500ms부터 1000ms 전까지 손을 떼면 항목 메뉴를 연다. 1000ms까지 유지하면 이동 모드로 전환하며 원본 항목·파일명 미리보기를 강조한다. 이동 모드에서도 실제로 끌기 전에는 파일을 옮기지 않는다.
- 이동 모드 전에 12px 이상 움직이면 길게 누르기를 취소하고 기본 스크롤을 유지한다. 이동 중에는 비수동 터치 리스너로 스크롤을 막고 목록 가장자리에서 자동 스크롤한다.
- 터치 드래그도 기존 `dragstart`·`dragover`·`drop`·`dragend` 처리와 경로 MIME을 공유한다. 메뉴·이동 뒤 합성 클릭은 무시하지만 다음 의도적인 탭은 바로 받는다. 터치 취소·멀티터치·Esc·포커스 상실·화면 숨김·언마운트 때 타이머·미리보기·스크롤 저장 잠금을 해제한다.

검증: `server/sidebar-touch-ui.test.ts`는 격리 Chromium의 실제 터치 이벤트로 탭·메뉴·이동·정지 유지·취소·스크롤·외부 드롭 대상·후속 클릭 차단과 같은 기기의 마우스 입력 복귀를 확인한다. iOS·Android 실기기 검증을 대신하지 않는다.

## 사이드바 상단 생성 버튼

`useSidebarCreate`는 편집기의 활성 문서와 별도로 사이드바에서 마지막 선택한 디렉터리·트리 범위를 기억한다. 폴더는 자기 경로, 파일은 부모 경로다. 루트·Documents를 구분하고 작업 루트가 바뀌면 선택과 대기 요청을 지운다. 하위 프로젝트는 클릭 시 독립 프로젝트 탭을 여는 진입점으로, 현재 트리의 생성 대상으로 선택하지 않는다. 상단 `SidebarCreateButtons`는 파일·폴더 생성 요청을 선택 범위 하나에만 전달하며 게스트에게는 표시하지 않는다.

생성은 `FileTree.startCreate`의 기존 인라인 이름 입력·검증·API를 공유한다. 버튼 클릭 자체로 임의 이름의 파일을 저장하지 않는다. 닫힌 Documents는 먼저 펼치고, 수신한 요청은 한 번 소비한 뒤 제거하여 다시 펼칠 때 입력이 재등장하지 않게 한다. 하위 프로젝트의 파일·폴더 생성은 그 프로젝트 탭에서 루트 생성 도구를 사용한다. Documents 생성은 Documents API 스코프를 유지한다.

## 텍스트 선택

`src/index.css`의 base 레이어에서 앱 UI는 기본적으로 텍스트 선택과 iOS 길게 누르기 callout을 막는다. 제목·안내·탭·메뉴·도구 버튼·포털의 설명도 같은 기본값을 따른다. 모든 자손에 `user-select: none`을 강제하지 않고 `body`의 기본값과 본문별 예외로 관리한다.

- 입력칸·textarea·편집 가능한 본문, 읽기 전용을 포함한 Hotview(`.tiptap`)·CodeMirror(`.cm-content`)·PDF 텍스트 레이어는 선택과 복사를 유지한다. `pre`·`code`의 출력·명령과 `role="alert"` 오류도 선택 가능하다.
- 에이전트 질문·답변·생각·작업 내용, 채팅·댓글, 진단 오류, 시트·읽기 전용 DB 셀, Git 커밋 본문 등 복사할 실제 내용에는 `select-text`를 붙인다. `select-all`을 쓰는 인증 코드도 기존 전체 선택을 유지한다. 알림용 `ConfirmDialog`는 메시지를 선택할 수 있고, 확인·취소 버튼은 선택되지 않는다.
- 선택 가능한 본문 안에서도 일반 버튼·label·summary는 선택을 막는다. 접히는 에이전트 버블·오류 버튼의 본문만 `select-text`로 다시 허용하며, 선택 중에는 펼치기·오류 상세 열기를 실행하지 않는다. 명시적인 `select-none`(줄 번호 등)은 그대로 유효하다.
- 새로운 복사 대상은 내용의 가장 작은 컨테이너에 `select-text`를 붙인다. 화면 전체를 예외로 두거나 색상·제목 태그만으로 선택 여부를 정하지 않는다. 기본 포커스·편집·스크롤·클립보드 동작을 JavaScript로 일괄 차단하지 않는다.

검증: `server/text-selection-ui.test.ts`에서 데스크톱·모바일 폭의 UI 비선택, 중첩된 본문·버튼 예외, 읽기 전용 본문·진단 복사, 입력 선택·편집, 포털·실제 오류 버튼과 공용 오류 대화상자를 검사한다. 모바일 사이드바 길게 누르기는 `server/sidebar-touch-ui.test.ts`를 함께 실행한다.

## 화면 문구

화면에는 항목 이름, 현재 상태, 선택에 필요한 차이, 다음 행동만 표시한다. 버튼이나 입력란의 이름으로 충분하면 별도 설명을 붙이지 않는다. 화면에서 이미 알 수 있는 동작을 되풀이하는 상시 사용법·단축키 안내 문구를 추가하지 않는다. 사용자 요청으로 제거한 안내는 표현을 바꾸거나 다른 위치로 옮겨 재도입하지 않는다. `~하면 ~에 저장됩니다` 같은 문장을 짧게 바꾸는 데 그치지 않고, 사용자가 알아야 할 내용인지 먼저 판단한다.

서버·CLI·등록표·저장 파일 경로·통신 방식 등 구현 설명과 이를 위한 고정 안내 영역은 다시 추가하지 않는다. 구현과 운영 정보는 해당 개발·설정 문서에 둔다. 삭제·덮어쓰기 범위, 실행 종료 여부, 적용 시점, 입력 제한, 비용 구분, 오류 해결 방법은 필요한 위치에 남긴다. 기능이나 오류 원인을 숨기기 위한 문구 삭제는 하지 않는다.

- 기능 패널: 에이전트셋 아래의 “항목을 수정하고 적용하면…” 같은 작업 방식·단축키 설명은 표시하지 않는다. 에이전트셋이 없어 작업할 수 없는 경우의 설정 안내처럼 실제로 필요한 상태 안내만 해당 상황에 표시한다.
- 화면 설정: 테마·언어·색상 선택을 다시 설명하지 않는다. 글꼴 입력 조건은 짧게 표시한다.
- 브라우저: 서버 실행·로그인 상태 관리 문구와 고정 영문 배지를 두지 않는다. 로딩은 인디케이터만, 오류·중요 안내는 패널 하단 `BrowserNotice` 토스트로 표시한다. 주소창 아래 상태 안내줄은 재도입하지 않는다. 토스트는 페이지 높이를 바꾸거나 모바일 뒤로가기 스택을 소비하지 않는다. 자동 숨김·재연결 동작은 [브라우저 안내](../guides/browser.md#브라우저-창)를 따른다.
- 에이전트 설정: 설치 상태와 가능한 작업을 표시한다. 지원하지 않는 삭제·로그아웃 명령의 구현 사유를 설명하지 않는다. 설정 적용 시점과 키 변경 방법은 유지한다.
- 계정·구독: 계정·플랜·실제 제한과 재조회 동작을 표시한다. 무료 플랜을 설명하는 중복 문단이나 공급자 조회 방식에 대한 원문 메모는 표시하지 않는다. API 사용 요금 구분은 유지하고, 같은 계정인지 확인하는 안내는 구독 창 안에 둔다.
- 명령·예약: 실행 폴더, 실행할 내용, 시각, 완료 후 터미널 종료 여부를 표시한다. 설정 파일 위치나 crontab 실행 구조는 설명하지 않는다.
- 문서 도구: 가져오기·내보내기 메뉴의 반복 설명을 없애고, 덮어쓰기 경고는 폴더 선택·확인 단계에 둔다. 링크 제목의 편집 불가와 DB 참조의 읽기 전용 여부는 짧은 표시로 구분한다.

설명을 제거하면 빈 상자·구분선·여백도 함께 정리한다. 번역을 사용하는 화면은 네 언어를 함께 갱신하고, 없어진 문구의 번역 키도 삭제한다. 키보드 포커스·입력 이름·상태 알림은 유지한다. 에이전트 로그인 화면의 세부 기준은 [표시 기준](../specs/agent-panel.md#로그인-화면)을 따른다.

## UI 번역

- 앱의 언어 선택은 기존 `I18nProvider`가 관리하며, 초기 저장 언어와 변경값을 `@mew/ui/i18n-core`의 `setUiLocale`에도 즉시 전달한다. 앱의 `t()` 키와 공용 패키지의 `uiText()`는 같은 한국어·영어·중국어 간체·일본어 설정을 따른다.
- 공용 문구의 기준본은 `packages/ui/src/ui-messages.ts`다. 한국어 원문을 키로 사용하고 영어·중국어·일본어를 모두 등록한다. 로딩·빈 상태·오류 폴백·버튼·도움말·접근성 이름을 포함한다. 새 원문을 UI에 직접 넣지 않고 기존 앱 키 또는 공용 사전에 등록한다. 개수·경로·이름은 자리표시자로 전달하고 문장 단위를 번역한다.
- React 표면은 `@mew/ui/i18n`의 `useUiLocale()`로 변경을 구독한다. 모듈 초기화 때 번역 결과를 고정하지 않는다. React 밖의 유틸은 호출 시 언어를 읽고, DOM 노드 뷰는 `subscribeUiLocale()`를 구독한 뒤 파괴 시 해제한다. CodeMirror 검색은 언어 compartment만 재설정하고 Markdown 렌더 캐시는 언어도 키에 포함한다. 언어 전환을 위해 편집기·터미널을 재마운트하거나 초안·검색어·문서를 비우지 않는다.
- 요일·달력·시각은 선택 언어의 `Intl` 형식을 사용한다. 사용자 문서·파일명·프로젝트명·대화·명령 출력·외부 시스템의 원문을 번역하려고 치환하지 않는다. 한국어 슬래시 검색 별칭, 기존 탭 이름 호환값, Markdown 제목 파싱 별칭은 데이터 계약으로 보존한다.
- 검증: `packages/ui/src/i18n.test.ts`는 네 언어·자리표시자·구독 정리를, `src/ui-localization.test.ts`는 UI 소스의 한국어 리터럴 누락과 언어별 Markdown 캐시·시간 표시를 검사한다. `server/i18n-ui.test.ts`는 격리 Chromium의 데스크톱·모바일에서 네 언어 전환, 에이전트 히스토리·현재 대화 새로고침, CodeMirror 찾기, 코드 복사, 공용 확인창과 초안·검색어·본문 보존을 검사한다.

## 오버레이 닫기 규칙 (`useOverlayDismiss`)

**팝업·모달·드롭다운을 새로 만들면 반드시** `useOverlayDismiss(onClose)`**를 부른다.** 열려 있는 오버레이를 앱 전체에서 하나의 스택으로 모아, Esc와 **안드로이드 하드웨어 뒤로가기**가 언제나 *가장 나중에 열린 것 하나만* 닫게 한다. 등록하지 않은 팝업 위에서 뒤로가기를 누르면 그 팝업 대신 뒤에 있는 터미널·사이드바가 닫히거나 페이지를 떠난다.

- App이 상태를 소유하는 보조 패널(사이드바·채팅·터미널·에이전트 패널·브라우저·Git·Android·기능)은 `utils/mobile-panel-stack.ts`의 공통 스택 하나가 전면 순서와 닫기 순서를 함께 소유한다. 모바일에서 뒤에 열린 패널을 다시 선택하면 닫지 않고 전면으로 옮기며, 전면 패널을 다시 선택할 때만 닫는다. `hooks/use-panel-dismissals.ts`도 이 전면 패널 하나만 오버레이로 등록하므로 Esc·뒤로가기와 z-index가 어긋나지 않는다. 새 보조 패널은 `WORKSPACE_PANEL_IDS`와 `App.tsx`의 open/setter 등록표에 추가하고 공통 open/close/toggle/layer 함수를 사용한다(빠진 등록은 타입 검사로 막힌다). 모달·팝업·드롭다운은 각 컴포넌트가 직접 등록한다. 모바일은 루트 프로젝트별로 **마지막 전면 창**도 이 기기 브라우저에 기억하므로, 새로고침·재시작 뒤에도 열린 창 중 마지막으로 보던 창이 다시 전면에 온다.
- 모바일에서 사이드바·채팅·터미널·에이전트 패널에서 파일을 열면, 그 창을 닫고 선택한 파일의 편집 칸을 바로 드러낸다. 데스크톱의 나란한 패널 배치는 유지한다.
- 뒤로가기 대응은 History에 더미 항목(가드)을 하나 얹어 두는 방식이다. 겹쳐 있어도 가드는 하나뿐이고, 한 겹 닫힐 때마다 다시 얹는다. UI로 닫혔을 땐 `history.back()`으로 걷어 스택을 맞춘다.
- 오버레이마다 각자 keydown 리스너를 달면 안 된다 — capture 단계에서 `stopPropagation`을 해도 같은 노드(window)에 붙은 다른 리스너는 그대로 실행돼, 겹친 팝업이 Esc 한 번에 전부 닫힌다.
- `escapePhase: 'bubble'`은 사이드바·터미널 패널처럼 **콘텐츠를 감싸고만 있는** 오버레이용이다. 안쪽(에디터 슬래시 메뉴, 파일 이름 바꾸기)이 Esc를 먼저 쓰고 `stopPropagation` 하면 패널은 닫히지 않는다. 기본값 `'capture'`는 다이얼로그용 — 아래 에디터·터미널이 손대기 전에 가로챈다.
- `closeOnEscape`는 Esc를 삼킬지 판단한다. 터미널을 품은 오버레이는 `outsideTerminal`(`src/utils/terminalFocus.ts`)을 넘겨 vim 등의 Esc를 양보한다. 뒤로가기에는 영향이 없다.
- `closeOnBack`은 모바일 뒤로가기를 콘텐츠가 먼저 처리할 때 쓴다. `false`를 반환하면 창을 유지하고 History 가드를 다시 얹어 연속 입력도 처리한다. 브라우저는 App의 전면 패널 등록에서 선택된 탭의 `canGoBack`을 확인해 서버 뒤로가기를 보내며, 기록이 없으면 패널을 닫는다. 독립 `/browser`는 같은 옵션으로 직접 등록한다. 별도 popstate 리스너나 두 번째 패널 등록을 추가하지 않으므로 위에 열린 모달·메뉴의 우선순위가 유지된다. Esc·바깥 클릭·닫기 버튼에는 이 콜백을 적용하지 않는다.
- `outside: () => 요소`를 주면 **그 요소 바깥을 눌러도 닫힌다**(맨 위 하나만, Esc와 같은 규칙). 터치 화면에는 Esc 키가 없으므로 **닫기 버튼이 없는 팝업은 이걸 주지 않으면 빠져나갈 길이 없다**.판단은 전파가 아니라 `contains()` 위치로 한다 — 안쪽에서 `stopPropagation`을 해도 capture는 이미 지나간 뒤다. 사이드바처럼 바깥 클릭으로 닫히면 안 되는 오버레이는 그냥 안 주면 된다.

에디터의 멘션·슬래시 메뉴와 링크/표 툴팁은 **일부러 등록하지 않았다.** 타이핑·선택에 따라 수시로 떴다 사라져서 그때마다 History를 밀고 당기면 브라우저 pushState 제한에 걸린다. 이들의 Esc는 `Editor.tsx`의 ProseMirror `handleKeyDown`이 직접 처리한다.

## 포커스 기반 탭 단축키

`Ctrl+W`(기본 `closeTab`)는 App이 조합을 한 번만 판정한 뒤, `@mew/shortcuts`의 `dispatchFocusedShortcut`으로 **포커스된 표면**에 전달한다. 터미널·에이전트 패널·브라우저처럼 자기 탭을 소유하는 창은 루트 ref와 `useFocusedShortcutScope(ref, { closeTab })`만 등록한다. 이 계약 덕분에 새 탭 창을 추가해도 App의 단축키 조건문을 고치지 않는다.

- 실제로 닫을 탭이 있을 때만 `preventDefault()`로 브라우저의 `Ctrl+W`보다 먼저 처리한다. 마지막 내부 브라우저 탭과 주소를 열기 전의 빈 탭도 닫을 수 있다. 탭이 없는 시작 화면에서는 브라우저 기본 탭 닫기를 양보하며, 다른 표면의 탭으로 새지 않는다.
- 등록된 창이 없고 편집기의 초점 칸에 활성 문서가 있을 때만 그 문서 탭을 닫는다. 터미널의 탭 닫기는 기존 `×` 버튼과 같은 경로로 해당 셸 세션을 종료한다.

## 계정 관리 권한 표

계정과 guest는 행, 기능은 열이다. 계정 열과 머리글을 고정하고 작은 화면에서는 표 안에서 가로 스크롤한다. 체크는 서버 저장 성공 후 갱신하며 실패는 선택 가능한 오류 메시지로 알린다. 파일 권한은 같은 창의 파일·폴더 탭에서 계정별 상속/차단/열람/수정을 지정하고 실제 적용 결과를 함께 표시한다. 사이드바의 guest 권한 조작은 제거한다. [서버 권한 계약](access-control.md)을 따른다.


## 하위 프로젝트 탭 진입

[ADR 0158](../../../.mew/docs/decisions/0158-mew-subprojects-open-root-tabs.md)에 따라 직계 프로젝트는 Documents 뒤의 `SubprojectLink`, 중첩 프로젝트는 `FileTree`의 같은 링크로 표시한다. `onOpenProject`가 지정된 트리는 프로젝트를 펼치거나 내부를 지연 로드하지 않는다. 일반 폴더·Documents는 기존 탐색을 유지한다. `visibleOpenDirectories`의 프로젝트 경계 옵션과 직접 로드 가드가 옛 펼침·자식 캐시 및 파일 위치 표시로 인한 내부 로드를 막는다.

`App.openSidebarProject`는 현재 루트와 트리 스코프를 `POST /api/subprojects/open?project=<scope>`의 `{ path, workspace }`로 전달한다. 서버는 owner·출발 루트 일치·실제 하위 폴더·`.mew` 디렉터리·파일 열람 권한을 검사하고 기존 `switchWorkspace`를 호출한다. 출발 루트가 바뀌었으면 409이며 링크·상위 탈출·일반 폴더는 거부한다. Documents 안의 프로젝트도 해당 스코프의 경로로 푼다.

응답은 기존 `applyWorkspace`로 반영하여 계정별 탭 목록과 루트별 UI를 복원한다. 성공한 절대경로만 기억하고 중복 경로는 하나로 합친다. 전환 요청은 공통 ref로 중복 실행을 막는다. `expandedSubprojects` 저장 필드는 옛 상태 읽기 호환용으로 남고 새 저장값은 빈 배열이며, 인라인 프로젝트 트리·명령 메뉴는 복원하지 않는다.

검증: `server/subproject-tabs.test.ts`는 실제 HTTP의 역할·경로·출발 루트·Documents 스코프와 전환 결과를, `server/subprojects-ui.test.ts`는 격리 Chromium의 클릭·터치·키보드·권한 비활성·탭 재사용·옛 펼침 무시를 검사한다. `src/utils/treePersistence.test.ts`는 프로젝트 경계 아래 지연 로드 제외를 검사한다. 서버 재시작·배포 없이 검증한다.


## 루트 프로젝트 탭 그룹

`RootProjectTabs`는 `shared/project-tab-groups.ts`의 `ProjectTabLayout`(`paths`, `groups`)을 사용한다. 그룹은 `{id, paths, collapsed}`이며 중첩하지 않는다. 전체 `paths`가 표시 순서의 기준이고 그룹 멤버는 연속하게 정규화한다. 같은 경로는 한 그룹에만 속하며, 닫힌 경로·중복·잘못된 ID를 제거하고 2개 미만 그룹은 해제한다. 그룹 만들기·이동은 탭 배치만 변경하고 루트 전환·파일 이동 API를 호출하지 않는다. 기존 루트 전환·계정 소유권 결정 안의 UI 확장이다.

`use-project-tab-gesture.ts`는 마우스·펜과 실제 터치를 지원한다. 500ms 이상 1000ms 미만에 놓으면 아이콘 선택, 1000ms 유지하면 이동 모드다. 이동 전 10px 이상 움직이면 제스처를 취소해 기본 터치 스크롤을 허용한다. 터치는 비수동 touchmove 리스너로 이동 모드에서만 스크롤을 막는다. 이동 중 탭 줄 양끝에서는 가로 자동 스크롤한다. 놓는 시점의 좌표로 드롭 대상을 다시 판정하며 hover는 저장하지 않는다. 놓기 후 클릭, Esc, blur, 숨김, touchcancel, 추가 손가락, unmount를 처리해 실수로 프로젝트가 전환되지 않도록 한다.

드롭은 탭 중앙 25–75%의 그룹 미리보기와 양끝 삽입선을 구분한다. 그룹 머리말은 해당 그룹 추가 대상이고, 그룹 외곽 6px 여백은 그룹 밖 삽입 대상이다. 별도의 이동 중 `그룹 밖으로` 대상은 독립 탭을 맨 뒤에 둔다. 접힌 그룹에 추가하면 펼친다. 키보드는 Alt+좌우로 삽입, Alt+Shift+좌우로 그룹, Alt+아래로 그룹 밖 이동을 제공한다. 활성 프로젝트 표시·닫기 버튼·아이콘 선택은 유지하며, 아이콘 선택기는 `DialogFrame`으로 공통 닫기와 포커스 복원을 따른다.

계정의 기존 `GET/PUT /api/user-ui/root-projects`에 선택적 `groups`를 추가한다(owner 전용). 서버는 경로 검증 후 같은 정규화 함수를 적용한다. 그룹이 없는 기존 원장은 독립 탭으로 읽힌다. App은 서버 상태를 받은 뒤에만 저장하며 연속 저장을 직렬화해 빠른 이동 요청의 역전을 막는다. 브라우저 사본은 기존 경로·아이콘 키와 `mew:root-project-groups`를 사용한다. 폴더를 새로 열면 독립 탭으로 추가하며 기존 그룹은 유지한다. 다른 기기의 실시간 갱신은 기존과 같이 제공하지 않고 다음 복원 때 읽는다.

검증: `project-tab-groups.test.ts`는 중앙 경계·그룹 생성·추가·그룹 간 이동·내부 정렬·해제·오래된 상태 정리를, `userUiState.test.ts`는 계정별 저장을 검사한다. `server/project-tab-groups-ui.test.ts`는 실제 React와 격리 Chromium에서 데스크톱·모바일의 미리보기/드롭·접힘 그룹 추가·정렬·해제·복원·취소·아이콘 선택·키보드·일반 가로 스크롤을 검사한다.


## 세션 복원·복귀 중 전체 화면 로딩

Mew에 다시 들어와 계정·작업 화면을 복원하거나, 숨겨졌던 페이지로 복귀·bfcache 복원·presence 재연결 후 상태를 재검증할 때 캐시된 화면을 유지하면서 중앙 로딩 인디케이터만 표시한다. 검정 덮개 없이 `pointer-events: none`인 비모달 상태 표시를 사용해 헤더·독·패널의 클릭·터치·키보드 조작과 기존 포커스를 유지한다. `ProjectLoadingOverlay` 하나에 프로젝트 전환과 세션 갱신 상태를 합치며, 스피너는 라이트·다크 테마의 본문색을 따른다. 기존 `common.loading` 번역과 모션 감소 설정을 따른다.

`useRefreshTasks`는 명시적으로 등록된 복원 요청을 개별 토큰으로 추적한다. App의 인증·현재 workspace·계정별 workspace/루트 탭·첫 단계 트리 조회, AgentPanel의 계정 탭 복원, useTabs의 복원 활성 문서 본문·열린 파일 권한 재검증이 대상이다. 동시 요청은 마지막 요청의 성공·실패까지 기다리고 언마운트한 소유자의 완료는 상태를 갱신하지 않는다. 사용자 파일 열기의 본문 로딩은 에디터 패널 표시를 유지하며, 일반 tree 변경 신호·자동저장·활동 heartbeat·에이전트 턴/스트리밍·비활성 문서의 지연 로드는 전체 화면 로딩을 만들지 않는다.

`usePresence`는 숨김→표시 또는 bfcache의 `pageshow.persisted` 복귀 때 열린 소켓이 있으면 기존 권한 재검증과 workspace 조회를 실행한다. 끊어진 소켓은 기존 재연결 경로를 따른다. 주기적인 활동 보고는 복귀 갱신을 발생시키지 않는다. 이 표시는 요청의 진행 상태이며 모든 스트리밍 연결이 준비됐다는 의미는 아니다.

검증: `server/workspace-switch-ui.test.ts`는 지연 응답으로 최초 복원, 캐시 본문 재조회, visibility/bfcache 복귀와 presence 재연결, 동시 인증·트리·파일 권한 조회, 실패 후 해제, 일반 tree 알림의 비차단을 검사한다. 1100px 다크·390px 라이트의 중앙 인디케이터·투명 배경·클릭/터치와 키보드 조작 유지·모션 감소도 확인한다.

## 루트 프로젝트 빠른 전환

[ADR 0086](../../../.mew/docs/decisions/0086-mew-root-project-spa-handoff-and-cache.md)의 단일 활성 서버 루트·SPA 전환과 [ADR 0092](../../../.mew/docs/decisions/0092-mew-agent-survives-root-project-switch.md)의 에이전트 작업 유지 계약 안에서 대기를 줄인다. 실제 폴더·파일을 읽기 위해 비활성 루트를 미리 전환하지 않는다.

- `switchingRootProject`가 참인 동안 `ProjectLoadingOverlay`로 중앙 인디케이터를 표시한다. 루트 탭 전환·하위 프로젝트 열기 모두 같은 상태를 쓰며, 기존 `finally`에서 전환 상태를 해제하며, 이어지는 세션 복원 요청이 있으면 전체 화면 로딩은 계속 유지한다. 화면을 어둡게 덮거나 입력을 가로채지 않으며, 클릭·터치·키보드 조작을 계속 허용한다. 인디케이터는 요청 완료·실패에 따라 자동으로 사라진다. 스크린 리더에는 번역된 로딩 상태를 알리고 모션 감소 설정에서는 회전하지 않는다. 탭바 문구는 전환 상태를 더 분명히 알리기 위해 제거했으며, 사용자 요청 전에는 다시 도입하지 않는다.
- `App.openRootProject`는 절대 루트를 명시하는 계정 UI 조회와, 에이전트/터미널 사용 시 해당 루트의 에이전트 탭 조회를 전환 POST와 병렬로 시작한다. 최초 복원·캐시 만료 때 UI 조회는 진행 중인 같은 요청을 재사용한다. `AgentPanel.preparedTabs`는 해당 전환에서 시작한 promise만 받아 초기 조회를 중복하지 않으며, 세션 점유 재조회는 기존처럼 서버를 읽는다. 다른 사용자의 전환·하위 프로젝트 진입·최초 화면에는 기존 조회를 사용한다.
- `WorkspaceSnapshotCache`는 로그인된 `EditorApp` 인스턴스 안에서만 유지한다. 화면 상태는 최대 12개 루트·1MiB, 첫 단계 트리는 최대 24개 루트/스코프 항목·1MiB다. 각 스냅샷은 기록 후 60초까지 사용하며 항목·바이트 한도를 넘으면 LRU 순서로 버린다. 큰 항목은 캐시하지 않는다. 새 localStorage 원장이나 서버 캐시는 만들지 않는다. 권한 변경 시 두 캐시를 비우고, 계정 변경은 App 인스턴스를 교체한다.
- 서버가 전환을 확인하면 해당 루트의 캐시된 UI·첫 단계 트리를 즉시 반영한다. 첫 단계 트리는 항상 백그라운드로 다시 읽고, 변경 신호로 읽은 결과도 캐시에 반영한다. 직접 전환 중 들어온 presence 알림은 모아 POST가 끝난 뒤 현재 루트를 한 번 확인하며, 이전 조회 응답은 순서 번호로 폐기한다. POST 응답과 알림 조회에서 같은 `path`·`docsPath`를 받은 경우 재초기화하지 않는다. Documents 경로가 바뀌면 트리 캐시를 비우고 새 조회를 시작한다. 처음 루트를 알기 전에는 인증된 사용자의 트리·프로젝트 목록 중복 조회를 만들지 않는다.
- 500ms UI 저장 대기가 끝나기 전에 루트를 떠나면 마지막 스냅샷을 그 **이전 루트**에 저장한다. 계정 UI PUT은 직렬화하고, 계정 App이 사라진 뒤에는 대기 중 쓰기를 보내지 않는다. 캐시와 진행 중 GET이 겹치면 더 최신인 로컬 스냅샷을 유지한다.
- `useTabs`는 저장된 모든 편집 칸·탭 껍데기를 한 번의 상태 갱신으로 만든다. 이전 루트의 동명 탭을 조회해 복원을 건너뛰지 않는다. 루트를 바꿀 때 이전 Documents 등 다른 API 스코프의 메모리 상태도 제거해 새 루트에 저장하지 않는다. 본문은 기존 계정/루트별 캐시로 채우고 각 칸의 활성 탭만 최신 본문을 요청한다. 복원 전에는 옛 루트의 본문을 새 탭 아래에 표시하지 않는다.
- 트리·본문·문서 규칙 응답은 전환 세대가 일치할 때만 적용한다. 빠른 A→B→A 전환에서도 늦은 옛 응답이 현재 본문이나 캐시를 덮지 않는다. 전환 실패는 현재 루트·화면을 유지한다.

검증: `workspace-snapshot-cache.test.ts`는 재사용·진행 요청 합치기·LRU/바이트/만료·실패 재시도·권한 무효화를 검사한다. `server/workspace-switch-ui.test.ts`는 실제 App·useTabs·FileTree·프로젝트 탭·도킹을 격리 Chromium에 올리고 네트워크 응답을 통제해, POST 완료 전 메타데이터 요청 시작, warm 복귀의 추가 UI GET 0회, 트리/본문 갱신 대기 중 캐시 표시, 중복 알림, 직전 탭 닫기 저장, Documents 스코프 격리, 오래된 본문 응답 폐기와 전환 실패를 검사한다. 이 테스트는 다른 패널과 편집기 렌더러를 대체하므로 실제 서버·대형 편집기·에이전트 재연결 전체 지연의 측정값으로 해석하지 않는다. `server/agent-command-ui.test.ts`는 실제 AgentPanel의 일반 초기 조회와 준비된 조회 재사용을 각각 확인한다.

RAG 패널은 공통 모바일 전면 스택·Esc/뒤로가기·계정별 열림 복원을 사용한다. 독 기본 맨 끝과 데스크톱 메뉴에서 열며 프로젝트 전환 시 이전 검색 결과를 폐기한다. 상세 범위는 [검색 설정](../configuration/search.md)을 따른다.

## 프로젝트 추가·서버 파일 탐색 공통 UI

`OpenProjectDialog`와 `ServerFileExplorer`는 `src/components/file-browser.tsx`의 `FileBrowserHeader`, `FileBrowser`, `FileBrowserEntry`를 공유한다. 프로젝트 추가 창의 기존 디자인을 기준으로 `DialogFrame` 크기, 주소 입력·홈/상위 버튼, 이름 필터, 36px 목록 행, Git 표시, 로딩·빈 목록·오류 재시도, 하단 경로를 통일한다. 필터는 현재 조회 결과를 대상으로 하며 경로를 다시 읽으면 초기화한다. 경로 자동완성은 서버 파일 탐색기에서 켜고 늦게 도착한 이전 입력의 응답은 무시한다. 프로젝트 추가의 최초 포커스는 `FileBrowserHeader` 제목에 두고 `FileBrowser.autoFocusPath=false`로 주소창 자동 포커스를 끈다. 서버 파일 탐색기는 기존 주소창 포커스를 유지한다.

API 목록 조회와 작업 후 갱신은 호출한 컴포넌트가 소유하고, 공통 파일 조작은 `useExternalFileActions`가 맡는다. 프로젝트 추가는 폴더만 표시하고 폴더 클릭으로 이동하며 생성/Git 작업·프로젝트 열기 버튼을 슬롯으로 넣는다. 맨 위 즐겨찾기는 공통 탐색 컴포넌트가 렌더한다. 서버 탐색기는 같은 행 컴포넌트로 하위 트리를 지연 로드하고 파일 열기·우클릭 작업을 연결한다. 프로젝트 생성/Git 작업은 owner 전용이며, 즐겨찾기 및 그 안의 클라우드 기본 항목은 `serverFiles` 권한으로 제공한다. 루트 경로 전환·닫기 이후의 이전 목록/하위 폴더 응답은 반영하지 않는다.

두 창 모두 `DialogFrame`의 Tab 포커스 제한·호출 컨트롤 복원을 사용한다. 서버 탐색기의 이름 변경·삭제 확인은 탐색기 위의 독립 대화상자이며, Esc는 전면 확인창 또는 항목 메뉴부터 닫는다. 회귀 검증은 `server/project-dialog-ui.test.ts`에서 데스크톱/모바일·밝은/어두운 테마, 프로젝트 생성/Git 작업, 서버 트리 지연 조회·필터·개명·복사/붙여넣기·외부 파일 열기를 확인한다.

### 없는 프로젝트 경로 확인·생성

`listEntries`는 ENOENT일 때 부모 방향으로 `lstat`·`stat`를 확인해 가장 가까운 기존 디렉터리와 처음 없는 이름을 구한다. `GET /api/fs/entries`는 실제 누락에만 404와 `{code: "MISSING_DIRECTORY", missing: {path, existingPath, missingName}}`을 반환한다. 파일·권한 오류·깨진 심볼릭 링크는 생성 대상으로 분류하지 않는다. 클라이언트의 `MissingDirectoryError`로 이 응답을 구분하며, 오류 문자열을 파싱하지 않는다.

`OpenProjectDialog`는 사용자가 이동한 경로가 없으면 공통 `ConfirmDialog`에 번역된 질문과 전체 생성 경로를 표시한다. 취소는 입력 경로를 유지하고, 확인 후에만 owner 전용 `POST /api/fs/directory` `{path}`를 호출한다. 서버는 경로를 다시 검사하고 `mkdir({recursive: true})`로 중간 폴더를 만든다. 이미 만들어진 디렉터리는 성공으로 처리하고 파일을 덮어쓰지 않는다. 생성 후 그 위치를 탐색하지만 프로젝트를 자동으로 열지 않는다. 요청 순서 번호로 닫기·다른 경로 이동 뒤 도착한 조회/생성 결과를 무시하고, 생성 중 이동·닫기·중복 실행을 막는다. 기본 경로의 최초 조회 실패에는 확인창을 자동으로 띄우지 않는다.

검증: `server/fsBrowse.test.ts`의 중첩 경로·무쓰기 조회·기존 디렉터리 경합·파일/권한/깨진 링크 구분, `server/access-policy.test.ts`의 실제 HTTP 메타데이터·owner 생성 권한, `server/project-dialog-ui.test.ts`의 생성 확인·취소·실패 재시도·번역을 사용한다.

### 파일 탐색 즐겨찾기 저장·감지

공통 `FileBrowserFavorites`는 제목 아래·주소창 위에 접힌 자체 드롭다운으로 위치한다. 이동과 제거가 서로 다른 버튼인 복합 목록이므로 단일 선택 `SelectField` 대신 같은 공통 즐겨찾기 컴포넌트 안의 `FavoritesDropdown`을 사용한다. 목록은 가장 가까운 `DialogFrame` 안으로 portal하여 모달 포커스 경계에 포함하고, fixed 위치를 visual viewport에 맞춰 위/아래로 보정한다. 최대 280px 안에서 스크롤하며 Tab·방향키·Home/End 탐색, Enter/Space 실행, `useOverlayDismiss`의 Esc·뒤로가기, 포커스 복원을 지원한다. 바깥 누름은 목록만 닫고 아래 조작으로 이어지지 않는다. 현재 폴더 추가·새로고침은 닫힌 상태에서도 보인다. `GET /api/fs/favorites`는 서버 OS의 기본 폴더와 로그인 계정의 변경값을 합친 `{ folders: [{path, name, kind, account?, provider?}] }`를 반환한다. `PUT /api/fs/favorites`는 `{path, favorite: boolean}`으로 경로 하나만 변경하고 `{ok: true}`를 반환한다. 두 API는 `requireFeature('serverFiles')`를 사용하고 요청 계정만 읽고 쓴다. owner 전용 `/fs/cloud-storage`의 기존 권한은 그대로다.

저장 위치는 기존 `DATA_DIR/user-ui-state.json`의 계정별 `fileFavorites: {added, hidden}`이다. 프로젝트 루트와 무관하며 다른 계정의 경로나 원장의 기존 탭·작업 화면 값을 덮어쓰지 않는다. 경로별 변경을 읽기·수정·원자 저장하여 서로 다른 경로를 추가한 동시 창의 변경을 보존한다. 기본 항목을 제거하면 `hidden`에 남겨 다음 감지에서 복구하지 않는다. 추가와 숨김 목록은 각각 최대 200개, 경로는 절대경로·4096자 이하이며 추가 시 실경로·디렉터리·접근 가능 여부를 확인한다. 삭제되거나 연결이 끊긴 경로도 즐겨찾기에서 제거할 수 있다.

`server/file-favorites.ts`는 홈 기본 폴더, macOS iCloud·File Provider 폴더, WSL C 드라이브와 Windows 프로필 기본 폴더 및 OneDrive 폴더 백업 위치를 얕게 확인한다. 공통 클라우드 감지는 `server/cloud-storage.ts`를 재사용하고 실경로로 중복 제거한다. WSL은 환경변수 또는 Linux 커널의 Microsoft 식별자로 판별해 서비스 실행 시에도 감지한다. 브라우저 OS는 감지에 사용하지 않는다. `/fs/entries`의 `canonicalPath`로 현재 폴더의 즐겨찾기 여부를 판단하여 심볼릭 링크로 들어온 경우에도 같은 폴더로 인식한다. 사용자 지정 경로는 OS가 접근 가능한 폴더를 직접 추가할 수 있다. 감지·저장 실패를 목록 오류와 분리하며 기존 즐겨찾기는 유지한다.

검증: `server/file-favorites.test.ts`의 macOS/WSL 가상 디렉터리·계정 저장, `server/access-policy.test.ts`의 기능 권한·계정 격리, `server/project-dialog-ui.test.ts`의 두 창 간 즐겨찾기 공유·기본값 제거 유지·저장 실패와 모바일 배치를 확인한다.

### 파일 작업 우클릭 메뉴

사이드바 `FileTree`, 프로젝트 추가, 서버 파일 탐색기는 `FileActionMenu`를 공유한다. 메뉴와 visual viewport의 실측 크기로 위치를 맞추고, 모바일에서는 표시 중인 하단 독의 위쪽 경계와 4px 간격을 유지한다. 안전 영역을 포함한 독 높이를 반영하며 공간이 부족하면 메뉴 안에서 스크롤한다. 화면 회전·viewport 이동/크기 변경·메뉴/독 크기 변경 시 다시 배치하고, 독이 숨겨졌거나 데스크톱이면 viewport 전체를 사용한다. Esc·뒤로가기는 전면 메뉴부터 닫는다. 메뉴 바깥 누름은 메뉴만 닫고 아래 파일/폴더 클릭으로 이어지지 않는다. 사이드바의 생성·복제·Git·하위 프로젝트 작업과 권한 조건은 기존 호출부가 유지한다.

두 서버 경로 탐색기의 `useExternalFileActions`는 `/api/fs` 작업, 이름 변경 입력·삭제 확인, 오류, 중복 실행 방지, 임시 복사/잘라내기 상태를 공유한다. 붙여넣기 목적지는 폴더 자체 또는 파일의 부모 폴더이며, 클립보드가 없으면 메뉴를 비활성화한다. 잘라내기 성공 시에만 클립보드를 비우고 원본/대상 디렉터리 및 열린 파일 경로를 갱신한다. 절대경로 클립보드는 두 탐색기 사이에서 메모리로 유지하며, 프로젝트 상대경로·파일 권한을 사용하는 사이드바의 클립보드/API와 섞지 않는다.

폴더 메뉴의 **즐겨찾기로 추가**는 기존 `setFileFavorite(path, true)`를 호출한다. 성공 이벤트 `mew:file-favorites-changed`를 받은 상단 즐겨찾기는 서버 저장값을 다시 읽으며 실패 시 목록을 바꾸지 않는다. 파일에는 즐겨찾기 항목이 없다. 공통 목록 행은 모바일 길게 누르기로도 메뉴를 열며, 움직임은 길게 누르기를 취소하고 메뉴를 연 뒤의 클릭은 폴더 이동/파일 열기로 이어지지 않는다.

`server/project-dialog-ui.test.ts`는 두 탐색기의 메뉴·즐겨찾기 즉시 반영·파일 부모로 붙여넣기·잘라내기와 양쪽 목록 갱신·삭제 확인·모바일 길게 누르기를 검증한다. 사이드바 회귀는 `server/sidebar-touch-ui.test.ts`, `server/sidebar-create-ui.test.ts`, `server/subprojects-ui.test.ts`가 맡는다. 터치 테스트는 하단 독과의 비겹침, 안전 여백 변경, 가로 회전 후 내부 스크롤과 마지막 항목의 클릭 가능 여부, 독 숨김·데스크톱 전환 후 경계 복원도 확인한다.
