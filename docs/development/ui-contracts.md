# 오버레이와 탭 단축키 계약

[문서 지도](../MOC.md) · [이 분야](MOC.md) · [설치·실행](../../README.md)

## 작업 패널 배치

원격 데스크톱은 [ADR 0136](../../../.mew/docs/decisions/0136-mew-native-remote-desktop-webrtc.md)의 독립적인 전체 화면 오버레이다. 도킹·패널 복원에 포함하지 않는다. 공통 Esc·뒤로가기 스택을 사용하고, 닫기·백그라운드 전환은 영상과 입력을 종료한다. 조이스틱·뷰 조작 계약은 [원격 데스크톱](remote-desktop.md)에 둔다.

[ADR 0134](../../../.mew/docs/decisions/0134-mew-dockable-workspace-panels.md)에 따라 에디터·에이전트·일반 터미널·웹 브라우저·Git은 `DockWorkspace`의 공통 분할 영역을 사용한다. Git 추가는 [ADR 0135](../../../.mew/docs/decisions/0135-mew-git-workspace-panel.md)를 따른다. 파일 트리 사이드바·멤버 채팅·Android는 기존 보조창을 유지한다.

- 상단 손잡이는 패널 전체를 옮긴다. 마우스로 탭을 끌면 탭 하나를 분리한다. 같은 종류의 탭바 전체(탭 사이·빈 공간·양 끝 포함)에 놓으면 합친다. 탭바의 실제 DOM 영역을 본문 가장자리 분할보다 먼저 판정하며, 탭 아이템을 직접 맞출 필요는 없다. 본문 중앙에는 합치고 가장자리에는 새 칸을 만든다. 다른 종류와는 나란히 배치한다. 드롭 전에 실제로 붙을 영역을 표시하며 Esc는 드래그를 취소한다. 드래그 중 탭 순서가 바뀌어 DOM 노드가 이동하면 커밋 직후 pointer capture를 복구해 탭바 밖에서도 이동·드롭을 이어 받는다.
- 브라우저는 좌우로만 붙인다. 세로 분할 안의 칸을 대상으로 삼아도 해당 세로 분할 전체의 옆에 붙이며, 브라우저 위아래에 다른 패널을 붙이는 동작도 허용하지 않는다.
- 경계선을 끌거나 키보드 화살표로 분할 비율을 조절한다. 배치·비율·탭 배정·패널별 활성 탭은 루트 프로젝트의 계정 `workspaceUi.dock`에 버전 1로 저장한다. 기존 에디터 분할은 최초 배치에 반영하고 터미널 열림 상태는 `chrome.terminalOpen`으로 분리한다.
  - 경계선은 주 포인터의 왼쪽 누름에서 pointer capture를 얻고, iframe 위에서도 같은 포인터의 이동·놓기를 이어 받는다. `pointerup`은 마지막 위치를 반영하고 캡처를 해제하며 `pointercancel`·`lostpointercapture`는 조절을 끝낸다. 전역 window 이동 리스너에 의존하지 않는다. 패널 비율은 로컬에서 즉시 변경하고, 내부 브라우저 viewport 동기화 응답을 기다리지 않는다.
- `DockPanel`과 탭별 `DockBody`는 같은 DOM 호스트에 유지하고 위치만 바꾼다. 분할 나무를 바꿀 때 ACP·tmux·브라우저 본문을 다시 마운트하지 않는다. 에이전트·셸 탭 원장은 `AgentPanel` 컨트롤러 하나가 저장한다. 숨김은 탭 종료가 아니다.
- 모바일에서는 전면 종류 하나만 표시한다. 에이전트·터미널·브라우저·Git의 분리된 탭은 종류별 한 줄로 모으며 데스크톱 배정은 보존한다. 문서 편집 칸이 여럿이면 상단 선택기로 전환한다. 패널 전면 상태와 뒤로가기는 기존 공통 스택을 따른다.
- 마지막 탭을 옮긴 기존 패널은 기본 패널을 포함해 자동으로 접힌다. 다른 패널에 탭이 남아 있을 때 빈 기본 패널이나 새 탭 버튼만 있는 칸을 남기지 않는다. 처음 여는 종류에 탭이 전혀 없을 때의 새 탭 화면은 유지한다.
- 패널의 닫기 버튼은 기본·분리 여부와 관계없이 누른 패널 하나만 닫는다. 같은 종류의 남은 패널이 있으면 탭을 그쪽으로 옮기고, 남은 패널의 활성 탭은 유지한다. 마지막 패널이면 탭을 기본 그룹에 보존하고 해당 종류를 접는다. 닫은 패널의 분할은 저장된 배치에서도 제거하며 남은 패널이 빈자리를 채운다. 다시 열 때는 보존된 탭을 한 패널로 열고 닫았던 빈 분할을 복구하지 않는다. 탭 닫기는 기존 세션 종료 계약을 따른다. 모바일의 종류별 전면 전환과 전체 표시 토글은 기존 동작을 유지한다.
- 브라우저 탭바(독립 `/browser` 포함)와 Git 탭바는 에이전트·터미널과 같은 36px 높이·깊은 배경·활성 탭 배경·간격·드래그 강조를 사용한다. 탭 제목은 최대 9rem에서 줄이고 탭 자체는 축소하지 않아 가로로 스크롤한다. 탭 닫기는 16px 버튼, 새 탭은 마지막 탭 바로 뒤의 36px 너비 버튼과 14px SVG `+`, 패널 닫기는 오른쪽에 고정한 24px 버튼과 14px SVG `×`로 표시한다. 마지막 브라우저 탭도 닫을 수 있으며, 탭이 없으면 패널 안에 주소·바로가기 시작 화면을 표시한다. `+`로 만든 빈 탭은 주소를 열기 전까지 서버 세션 없이 도킹·선택·닫기를 지원한다.

검증은 `dockWorkspaceUi.test.ts`의 탭바 빈 공간 합치기·빈 기본/분리 패널 접기·개별 기본/분리 패널 닫기·빈자리 확장·재열기/새로고침·초안/마운트 보존 검사, `dock-layout.test.ts`의 트리·브라우저 제약·복원 검사와 실제 React 패널을 올린 격리 브라우저에서 수행한다. 드래그 분리·합치기, 경계 크기 조절, 저장 복원, 모바일 전환, 초안·마운트 유지가 대상이다. 실행 중인 Mew 서버에 빌드 결과를 반영하지 않는다.
크기 조절은 서버 통신 없는 중첩 iframe 위로 포인터를 한 번에 옮기는 재현 테스트로 확인하며, 놓기·취소 뒤 정지와 키보드 조절도 검사한다.

## Git 저장소 탭

`git-panel.tsx`는 저장소 스코프·상대 경로를 식별자로 사용하며 같은 저장소를 중복해서 열지 않는다. 파일 편집기 탭과 섞지 않는다. `workspaceUi.git`는 탭 목록·순서·활성 ID, `workspaceUi.chrome.gitOpen`은 열림 상태, `workspaceUi.dock`은 배치·그룹별 활성 탭을 소유한다. `git-panel-state.ts`는 복원할 스코프·경로를 검사하고 오래된 표시 이름과 중복을 정리한다. 루트 전환 시 계정 UI 로딩을 먼저 대기해 이전 루트의 탭을 새 루트에 기록하지 않는다.

각 저장소의 `GitWorkbench`는 `DockBody` 아래에서 이동·숨김 동안 마운트를 유지한다. 저장소 선택기는 첫 진입·`+`·그래프의 뒤로가기에서 보이고, 고르기 전에는 저장되는 가상 탭을 만들지 않는다. 탭의 마지막 `×`는 빈 저장소 선택기로 돌아가며, 패널 닫기는 탭·커밋 초안을 유지한다. 초안은 서버/브라우저 저장소에 영구 저장하지 않는다. 사용자 동작·초기화 경계는 [Git 사용법](../guides/projects.md#git-작업-패널)을 따른다.

`Ctrl+W`는 탭바·선택기·본문 각각의 포커스 범위에서 처리한다. 플로팅 핸들의 이전/다음 신호는 현재 Git 그룹에 전달한다. 모바일 전면·닫기는 `WORKSPACE_PANEL_IDS`와 App의 공통 등록표를 사용한다. 커밋 우클릭 메뉴는 공통 오버레이 스택에서 패널보다 먼저 닫는다.

검증: `server/git-panel-ui.test.ts`는 실제 React 패널과 격리 Chromium에서 저장소 선택·탭 중복 방지·분리/합치기·닫기/재열기·초안 유지·복원·모바일·포커스 단축키를 검사한다. Git 응답만 대체하며 실제 저장소를 변경하지 않는다. `git-panel-state.test.ts`는 잘못된 저장 상태, `mobile-panel-stack.test.ts`는 Git의 공통 전면 복원을 검사한다.

## 플로팅 핸들과 상단 메뉴

`FabMenu`는 실제 pointerType으로 입력을 구분한다. 마우스 왼쪽 버튼은 8px 이동부터 대기 없이 위치를 변경하며, 클릭은 메뉴를 연다. 마우스 위치 이동은 방향 명령을 실행하지 않는다. 터치는 기존 방향 선택과 350ms 길게 누른 뒤 이동을 유지한다. 위치 고정 시 입력 종류에 관계없이 위치 변경을 막고, 터치 방향 선택과 메뉴 버튼은 계속 사용할 수 있다.

위치와 고정은 기기 설정으로 `mew:floating-handle-position`·`mew:floating-handle-locked`에 저장한다. 저장소가 막혀도 현재 화면에서는 이동·고정이 작동한다. 열린 메뉴는 화면 안으로 보정하되 저장 위치는 바꾸지 않는다. 키보드 회피도 고정 여부와 무관하게 적용한다. 메뉴는 공통 오버레이 닫기 스택을 사용하고 숨긴 버튼은 키보드 탐색에서 제외한다. 아이콘 설명은 `HoverTipLayer`의 `data-tip`으로 즉시 표시한다.

`HeaderMenu`는 768px 이상에서 번역된 메뉴 이름과 36px 높이 버튼을 표시한다. 앱 헤더는 같은 구간에서 48px 높이와 넓은 도구 여백을 쓴다. 작은 화면은 40px 헤더와 아이콘 버튼을 유지한다. 열린 메뉴는 `z-index: 1050`으로 플로팅 핸들·도킹 경계·브라우저 팝업보다 앞에 표시한다. 메뉴에서 여는 대화상자는 메뉴를 닫은 뒤 표시한다.

로그인 사용자는 햄버거 바로 왼쪽의 `ActiveSessionsButton`에서 활성 브라우저 세션 수와 사용자별 목록을 확인한다. 팝업은 화면 너비 안에서 줄바꿈하고 긴 목록은 내부 스크롤한다. 연결 중에는 `—`를 표시하고 이전 목록을 비운다. 신원·접속 수·권한의 기준은 [presence 계약](collaboration.md#활성-mew-세션-presence)을 따른다.

검증: `server/fab-menu-ui.test.ts`에서 실제 Chromium의 마우스 즉시 이동·클릭·고정 복원·툴팁·키보드와 터치 방향 선택·길게 누르기·반응형 메뉴를 확인한다.

## 겹친 창과 크기 조절 경계

데스크톱 `DockBody`는 자체 z-index를 만들지 않는다. 본문 안에서 열린 메뉴·팝업이 낮은 부모 레이어에 갇혀 형제 크기 조절 경계(`z-index: 40`) 뒤로 내려가는 것을 방지한다. 본문 사각형은 헤더·경계 영역을 제외하므로 기존 본문 배치와 드래그 캡처는 유지한다. 모바일의 패널 전면 순서용 레이어는 유지한다.

터미널 명령어 버튼 편집창은 `document.body`로 portal하며 전체 화면 배경이 뒤쪽 패널과 경계의 포인터 입력을 가로막는다. 다른 팝업도 자기 영역에서는 뒤쪽 경계 대신 포인터 입력을 받아야 한다. 전체 화면 모달은 배경까지 가로막고, 작은 메뉴는 덮고 있는 영역에서 가로막는다. 커서 모양만 숨기고 뒤쪽 리사이즈가 계속 작동하도록 구현하지 않는다.

검증: `server/overlay-layer-ui.test.ts`에서 메뉴와 핸들을 겹치고, 본문 안 팝업·실제 터미널 버튼 편집창을 크기 조절 경계와 겹쳐 `elementFromPoint`·실제 커서·드래그 차단을 확인한다. 창을 닫으면 다시 크기 조절할 수 있어야 한다.

## 사이드바 터치 메뉴와 이동

`useTreeTouchGesture`는 실제 포인터 종류로 터치와 마우스를 구분한다. 터치가 시작되면 해당 항목의 네이티브 `draggable`을 끄고, 브라우저의 이른 `dragstart`·`contextmenu`가 길게 누르기 메뉴를 선점하지 못하게 한다. 마우스를 다시 누르면 네이티브 드래그를 복구한다.

- 500ms부터 1000ms 전까지 손을 떼면 항목 메뉴를 연다. 1000ms까지 유지하면 이동 모드로 전환하며 원본 항목·파일명 미리보기를 강조한다. 이동 모드에서도 실제로 끌기 전에는 파일을 옮기지 않는다.
- 이동 모드 전에 12px 이상 움직이면 길게 누르기를 취소하고 기본 스크롤을 유지한다. 이동 중에는 비수동 터치 리스너로 스크롤을 막고 목록 가장자리에서 자동 스크롤한다.
- 터치 드래그도 기존 `dragstart`·`dragover`·`drop`·`dragend` 처리와 경로 MIME을 공유한다. 메뉴·이동 뒤 합성 클릭은 무시하지만 다음 의도적인 탭은 바로 받는다. 터치 취소·멀티터치·Esc·포커스 상실·화면 숨김·언마운트 때 타이머·미리보기·스크롤 저장 잠금을 해제한다.

검증: `server/sidebar-touch-ui.test.ts`는 격리 Chromium의 실제 터치 이벤트로 탭·메뉴·이동·정지 유지·취소·스크롤·외부 드롭 대상·후속 클릭 차단과 같은 기기의 마우스 입력 복귀를 확인한다. iOS·Android 실기기 검증을 대신하지 않는다.

## 사이드바 상단 생성 버튼

`useSidebarCreate`는 편집기의 활성 문서와 별도로 사이드바에서 마지막 선택한 디렉터리·트리 범위를 기억한다. 폴더는 자기 경로, 파일은 부모 경로다. 루트·Documents를 구분하고 작업 루트가 바뀌면 선택과 대기 요청을 지운다. 하위 프로젝트는 클릭 시 독립 프로젝트 탭을 여는 진입점으로, 현재 트리의 생성 대상으로 선택하지 않는다. 상단 `SidebarCreateButtons`는 파일·폴더 생성 요청을 선택 범위 하나에만 전달하며 게스트에게는 표시하지 않는다.

생성은 `FileTree.startCreate`의 기존 인라인 이름 입력·검증·API를 공유한다. 버튼 클릭 자체로 임의 이름의 파일을 저장하지 않는다. 닫힌 Documents는 먼저 펼치고, 수신한 요청은 한 번 소비한 뒤 제거하여 다시 펼칠 때 입력이 재등장하지 않게 한다. 하위 프로젝트의 파일·폴더 생성은 그 프로젝트 탭에서 루트 생성 도구를 사용한다. Documents 생성은 Documents API 스코프를 유지한다.

## 텍스트 선택

`src/index.css`의 base 레이어에서 앱 UI는 기본적으로 텍스트 선택과 iOS 길게 누르기 callout을 막는다. 제목·안내·탭·메뉴·도구 버튼·포털의 설명도 같은 기본값을 따른다. 모든 자손에 `user-select: none`을 강제하지 않고 `body`의 기본값과 본문별 예외로 관리한다.

- 입력칸·textarea·편집 가능한 본문, 읽기 전용을 포함한 Hotview(`.tiptap`)·CodeMirror(`.cm-content`)·PDF 텍스트 레이어는 선택과 복사를 유지한다. `pre`·`code`의 출력·명령과 `role="alert"` 오류도 선택 가능하다.
- 에이전트 질문·답변·생각·작업 내용, 채팅·댓글, 진단 오류, 시트·읽기 전용 DB 셀, Git 커밋 본문 등 복사할 실제 내용에는 `select-text`를 붙인다. `select-all`을 쓰는 인증 코드도 기존 전체 선택을 유지한다. 알림용 `ConfirmDialog`는 메시지를 선택할 수 있고, 확인·취소 버튼은 선택되지 않는다.
- 선택 가능한 본문 안에서도 일반 버튼·label·summary는 선택을 막는다. 접히는 에이전트 버블·오류 버튼의 본문만 `select-text`로 다시 허용하며, 선택 중에는 펼치기·오류 상세 열기를 실행하지 않는다. 명시적인 `select-none`(줄 번호 등)은 그대로 유효하다.
- 새로운 복사 대상은 내용의 가장 작은 컨테이너에 `select-text`를 붙인다. 화면 전체를 예외로 두거나 색상·제목 태그만으로 선택 여부를 정하지 않는다. 기본 포커스·편집·스크롤·클립보드 동작을 JavaScript로 일괄 차단하지 않는다.

검증: `server/text-selection-ui.test.ts`에서 데스크톱·모바일 폭의 UI 비선택, 중첩된 본문·버튼 예외, 읽기 전용 본문·진단 복사, 입력 선택·편집, 포털·실제 오류 버튼과 공용 오류 대화상자를 검사한다. 모바일 사이드바 길게 누르기는 `server/sidebar-touch-ui.test.ts`를 함께 실행한다.

## 화면 문구

화면에는 항목 이름, 현재 상태, 선택에 필요한 차이, 다음 행동만 표시한다. 버튼이나 입력란의 이름으로 충분하면 별도 설명을 붙이지 않는다. `~하면 ~에 저장됩니다` 같은 문장을 짧게 바꾸는 데 그치지 않고, 사용자가 알아야 할 내용인지 먼저 판단한다.

서버·CLI·등록표·저장 파일 경로·통신 방식 등 구현 설명과 이를 위한 고정 안내 영역은 다시 추가하지 않는다. 구현과 운영 정보는 해당 개발·설정 문서에 둔다. 삭제·덮어쓰기 범위, 실행 종료 여부, 적용 시점, 입력 제한, 비용 구분, 오류 해결 방법은 필요한 위치에 남긴다. 기능이나 오류 원인을 숨기기 위한 문구 삭제는 하지 않는다.

- 화면 설정: 테마·언어·색상 선택을 다시 설명하지 않는다. 글꼴 입력 조건은 짧게 표시한다.
- 브라우저: 서버 실행·로그인 상태 관리 문구와 고정 영문 배지를 두지 않는다. 로딩은 인디케이터만, 오류·중요 안내는 패널 하단 `BrowserNotice` 토스트로 표시한다. 주소창 아래 상태 안내줄은 재도입하지 않는다. 토스트는 페이지 높이를 바꾸거나 모바일 뒤로가기 스택을 소비하지 않는다. 자동 숨김·재연결 동작은 [브라우저 안내](../guides/browser.md#브라우저-창)를 따른다.
- 에이전트 설정: 설치 상태와 가능한 작업을 표시한다. 지원하지 않는 삭제·로그아웃 명령의 구현 사유를 설명하지 않는다. 설정 적용 시점과 키 변경 방법은 유지한다.
- 계정·구독: 계정·플랜·실제 제한과 재조회 동작을 표시한다. 무료 플랜을 설명하는 중복 문단이나 공급자 조회 방식에 대한 원문 메모는 표시하지 않는다. API 사용 요금 구분은 유지하고, 같은 계정인지 확인하는 안내는 구독 창 안에 둔다.
- 명령·예약: 실행 폴더, 실행할 내용, 시각, 완료 후 터미널 종료 여부를 표시한다. 설정 파일 위치나 crontab 실행 구조는 설명하지 않는다.
- 문서 도구: 가져오기·내보내기 메뉴의 반복 설명을 없애고, 덮어쓰기 경고는 폴더 선택·확인 단계에 둔다. 링크 제목의 편집 불가와 DB 참조의 읽기 전용 여부는 짧은 표시로 구분한다.

설명을 제거하면 빈 상자·구분선·여백도 함께 정리한다. 번역을 사용하는 화면은 네 언어를 함께 갱신하고, 없어진 문구의 번역 키도 삭제한다. 키보드 포커스·입력 이름·상태 알림은 유지한다. 에이전트 로그인 화면의 세부 기준은 [표시 기준](../specs/agent-panel.md#로그인-화면)을 따른다.

## 오버레이 닫기 규칙 (`useOverlayDismiss`)

**팝업·모달·드롭다운을 새로 만들면 반드시** `useOverlayDismiss(onClose)`**를 부른다.** 열려 있는 오버레이를 앱 전체에서 하나의 스택으로 모아, Esc와 **안드로이드 하드웨어 뒤로가기**가 언제나 *가장 나중에 열린 것 하나만* 닫게 한다. 등록하지 않은 팝업 위에서 뒤로가기를 누르면 그 팝업 대신 뒤에 있는 터미널·사이드바가 닫히거나 페이지를 떠난다.

- App이 상태를 소유하는 보조 패널(사이드바·채팅·터미널·에이전트 패널·브라우저·Git·Android)은 `utils/mobile-panel-stack.ts`의 공통 스택 하나가 전면 순서와 닫기 순서를 함께 소유한다. 모바일에서 뒤에 열린 패널을 다시 선택하면 닫지 않고 전면으로 옮기며, 전면 패널을 다시 선택할 때만 닫는다. `hooks/use-panel-dismissals.ts`도 이 전면 패널 하나만 오버레이로 등록하므로 Esc·뒤로가기와 z-index가 어긋나지 않는다. 새 보조 패널은 `WORKSPACE_PANEL_IDS`와 `App.tsx`의 open/setter 등록표에 추가하고 공통 open/close/toggle/layer 함수를 사용한다(빠진 등록은 타입 검사로 막힌다). 모달·팝업·드롭다운은 각 컴포넌트가 직접 등록한다. 모바일은 루트 프로젝트별로 **마지막 전면 창**도 이 기기 브라우저에 기억하므로, 새로고침·재시작 뒤에도 열린 창 중 마지막으로 보던 창이 다시 전면에 온다.
- 모바일에서 사이드바·채팅·터미널·에이전트 패널에서 파일을 열면, 그 창을 닫고 선택한 파일의 편집 칸을 바로 드러낸다. 데스크톱의 나란한 패널 배치는 유지한다.
- 뒤로가기 대응은 History에 더미 항목(가드)을 하나 얹어 두는 방식이다. 겹쳐 있어도 가드는 하나뿐이고, 한 겹 닫힐 때마다 다시 얹는다. UI로 닫혔을 땐 `history.back()`으로 걷어 스택을 맞춘다.
- 오버레이마다 각자 keydown 리스너를 달면 안 된다 — capture 단계에서 `stopPropagation`을 해도 같은 노드(window)에 붙은 다른 리스너는 그대로 실행돼, 겹친 팝업이 Esc 한 번에 전부 닫힌다.
- `escapePhase: 'bubble'`은 사이드바·터미널 패널처럼 **콘텐츠를 감싸고만 있는** 오버레이용이다. 안쪽(에디터 슬래시 메뉴, 파일 이름 바꾸기)이 Esc를 먼저 쓰고 `stopPropagation` 하면 패널은 닫히지 않는다. 기본값 `'capture'`는 다이얼로그용 — 아래 에디터·터미널이 손대기 전에 가로챈다.
- `closeOnEscape`는 Esc를 삼킬지 판단한다. 터미널을 품은 오버레이는 `outsideTerminal`(`src/utils/terminalFocus.ts`)을 넘겨 vim 등의 Esc를 양보한다. 뒤로가기에는 영향이 없다.
- `closeOnBack`은 모바일 뒤로가기를 콘텐츠가 먼저 처리할 때 쓴다. `false`를 반환하면 창을 유지하고 History 가드를 다시 얹어 연속 입력도 처리한다. 브라우저는 App의 전면 패널 등록에서 선택된 탭의 `canGoBack`을 확인해 서버 뒤로가기를 보내며, 기록이 없으면 패널을 닫는다. 독립 `/browser`는 같은 옵션으로 직접 등록한다. 별도 popstate 리스너나 두 번째 패널 등록을 추가하지 않으므로 위에 열린 모달·메뉴의 우선순위가 유지된다. Esc·바깥 클릭·닫기 버튼에는 이 콜백을 적용하지 않는다.
- `outside: () => 요소`를 주면 **그 요소 바깥을 눌러도 닫힌다**(맨 위 하나만, Esc와 같은 규칙). 터치 화면에는 Esc 키가 없으므로 **닫기 버튼이 없는 팝업은 이걸 주지 않으면 빠져나갈 길이 없다**.판단은 전파가 아니라 `contains()` 위치로 한다 — 안쪽에서 `stopPropagation`을 해도 capture는 이미 지나간 뒤다. 사이드바처럼 바깥 클릭으로 닫히면 안 되는 오버레이는 그냥 안 주면 된다.

에디터의 멘션·슬래시 메뉴와 링크/표 툴팁은 **일부러 등록하지 않았다.** 타이핑·선택에 따라 수시로 떴다 사라져서 그때마다 History를 밀고 당기면 브라우저 pushState 제한에 걸린다. 이들의 Esc는 `Editor.tsx`의 ProseMirror `handleKeyDown`이 직접 처리한다.

## 포커스 기반 탭 단축키

`Ctrl+W`(기본 `closeTab`)는 App이 조합을 한 번만 판정한 뒤, `@mew/shortcuts`의 `dispatchFocusedShortcut`으로 **포커스된 표면**에 전달한다. 터미널·에이전트 패널·브라우저처럼 자기 탭을 소유하는 창은 루트 ref와 `useFocusedShortcutScope(ref, { closeTab })`만 등록한다. 이 계약 덕분에 새 탭 창을 추가해도 App의 단축키 조건문을 고치지 않는다.

- 실제로 닫을 탭이 있을 때만 `preventDefault()`로 브라우저의 `Ctrl+W`보다 먼저 처리한다. 마지막 내부 브라우저 탭과 주소를 열기 전의 빈 탭도 닫을 수 있다. 탭이 없는 시작 화면에서는 브라우저 기본 탭 닫기를 양보하며, 다른 표면의 탭으로 새지 않는다.
- 등록된 창이 없고 편집기의 초점 칸에 활성 문서가 있을 때만 그 문서 탭을 닫는다. 터미널의 탭 닫기는 기존 `×` 버튼과 같은 경로로 해당 셸 세션을 종료한다.

## 계정 관리 권한 표

계정과 guest는 행, 기능은 열이다. 계정 열과 머리글을 고정하고 작은 화면에서는 표 안에서 가로 스크롤한다. 체크는 서버 저장 성공 후 갱신하며 실패는 선택 가능한 오류 메시지로 알린다. 파일 권한은 같은 창의 파일·폴더 탭에서 계정별 상속/차단/열람/수정을 지정하고 실제 적용 결과를 함께 표시한다. 사이드바의 guest 권한 조작은 제거한다. [서버 권한 계약](access-control.md)을 따른다.


## 하위 프로젝트 탭 진입

[ADR 0158](../../../.mew/docs/decisions/0158-mew-subprojects-open-root-tabs.md)에 따라 직계 프로젝트는 Documents 뒤의 `SubprojectLink`, 중첩 프로젝트는 `FileTree`의 같은 링크로 표시한다. `onOpenProject`가 지정된 트리는 프로젝트를 펼치거나 내부를 지연 로드하지 않는다. 일반 폴더·Documents는 기존 탐색을 유지한다. `visibleOpenDirectories`의 프로젝트 경계 옵션과 직접 로드 가드가 옛 펼침·자식 캐시 및 파일 위치 표시로 인한 내부 로드를 막는다.

`App.openSidebarProject`는 현재 루트와 트리 스코프를 `POST /api/subprojects/open?project=<scope>`의 `{ path, workspace }`로 전달한다. 서버는 owner·출발 루트 일치·실제 하위 폴더·`.mew` 디렉터리·파일 열람 권한을 검사하고 기존 `switchWorkspace`를 호출한다. 출발 루트가 바뀌었으면 409이며 링크·상위 탈출·일반 폴더는 거부한다. Documents 안의 프로젝트도 해당 스코프의 경로로 푼다.

응답은 기존 `applyWorkspace`로 반영하여 계정별 탭 목록과 루트별 UI를 복원한다. 성공한 절대경로만 기억하고 중복 경로는 하나로 합친다. 전환 요청은 공통 ref로 중복 실행을 막는다. `expandedSubprojects` 저장 필드는 옛 상태 읽기 호환용으로 남고 새 저장값은 빈 배열이며, 인라인 프로젝트 트리·명령 메뉴는 복원하지 않는다.

검증: `server/subproject-tabs.test.ts`는 실제 HTTP의 역할·경로·출발 루트·Documents 스코프와 전환 결과를, `server/subprojects-ui.test.ts`는 격리 Chromium의 클릭·터치·키보드·권한 비활성·탭 재사용·옛 펼침 무시를 검사한다. `src/utils/treePersistence.test.ts`는 프로젝트 경계 아래 지연 로드 제외를 검사한다. 서버 재시작·배포 없이 검증한다.


## 루트 프로젝트 탭 그룹

`RootProjectTabs`는 `shared/project-tab-groups.ts`의 `ProjectTabLayout`(`paths`, `groups`)을 사용한다. 그룹은 `{id, paths, collapsed}`이며 중첩하지 않는다. 전체 `paths`가 표시 순서의 기준이고 그룹 멤버는 연속하게 정규화한다. 같은 경로는 한 그룹에만 속하며, 닫힌 경로·중복·잘못된 ID를 제거하고 2개 미만 그룹은 해제한다. 그룹 만들기·이동은 탭 배치만 변경하고 루트 전환·파일 이동 API를 호출하지 않는다. 기존 루트 전환·계정 소유권 결정 안의 UI 확장이다.

`use-project-tab-gesture.ts`는 마우스·펜과 실제 터치를 지원한다. 500ms 이상 1000ms 미만에 놓으면 아이콘 선택, 1000ms 유지하면 이동 모드다. 이동 전 10px 이상 움직이면 제스처를 취소해 기본 터치 스크롤을 허용한다. 터치는 비수동 touchmove 리스너로 이동 모드에서만 스크롤을 막는다. 이동 중 탭 줄 양끝에서는 가로 자동 스크롤한다. 놓는 시점의 좌표로 드롭 대상을 다시 판정하며 hover는 저장하지 않는다. 놓기 후 클릭, Esc, blur, 숨김, touchcancel, 추가 손가락, unmount를 처리해 실수로 프로젝트가 전환되지 않도록 한다.

드롭은 탭 중앙 25–75%의 그룹 미리보기와 양끝 삽입선을 구분한다. 그룹 머리말은 해당 그룹 추가 대상이고, 그룹 외곽 6px 여백은 그룹 밖 삽입 대상이다. 별도의 이동 중 `그룹 밖으로` 대상은 독립 탭을 맨 뒤에 둔다. 접힌 그룹에 추가하면 펼친다. 키보드는 Alt+좌우로 삽입, Alt+Shift+좌우로 그룹, Alt+아래로 그룹 밖 이동을 제공한다. 활성 프로젝트 표시·닫기 버튼·아이콘 선택은 유지하며, 아이콘 선택기는 `DialogFrame`으로 공통 닫기와 포커스 복원을 따른다.

계정의 기존 `GET/PUT /api/user-ui/root-projects`에 선택적 `groups`를 추가한다(owner 전용). 서버는 경로 검증 후 같은 정규화 함수를 적용한다. 그룹이 없는 기존 원장은 독립 탭으로 읽힌다. App은 서버 상태를 받은 뒤에만 저장하며 연속 저장을 직렬화해 빠른 이동 요청의 역전을 막는다. 브라우저 사본은 기존 경로·아이콘 키와 `mew:root-project-groups`를 사용한다. 폴더를 새로 열면 독립 탭으로 추가하며 기존 그룹은 유지한다. 다른 기기의 실시간 갱신은 기존과 같이 제공하지 않고 다음 복원 때 읽는다.

검증: `project-tab-groups.test.ts`는 중앙 경계·그룹 생성·추가·그룹 간 이동·내부 정렬·해제·오래된 상태 정리를, `userUiState.test.ts`는 계정별 저장을 검사한다. `server/project-tab-groups-ui.test.ts`는 실제 React와 격리 Chromium에서 데스크톱·모바일의 미리보기/드롭·접힘 그룹 추가·정렬·해제·복원·취소·아이콘 선택·키보드·일반 가로 스크롤을 검사한다.


## 루트 프로젝트 빠른 전환

[ADR 0086](../../../.mew/docs/decisions/0086-mew-root-project-spa-handoff-and-cache.md)의 단일 활성 서버 루트·SPA 전환과 [ADR 0092](../../../.mew/docs/decisions/0092-mew-agent-survives-root-project-switch.md)의 에이전트 작업 유지 계약 안에서 대기를 줄인다. 실제 폴더·파일을 읽기 위해 비활성 루트를 미리 전환하지 않는다.

- `App.openRootProject`는 절대 루트를 명시하는 계정 UI 조회와, 에이전트/터미널 사용 시 해당 루트의 에이전트 탭 조회를 전환 POST와 병렬로 시작한다. 최초 복원·캐시 만료 때 UI 조회는 진행 중인 같은 요청을 재사용한다. `AgentPanel.preparedTabs`는 해당 전환에서 시작한 promise만 받아 초기 조회를 중복하지 않으며, 세션 점유 재조회는 기존처럼 서버를 읽는다. 다른 사용자의 전환·하위 프로젝트 진입·최초 화면에는 기존 조회를 사용한다.
- `WorkspaceSnapshotCache`는 로그인된 `EditorApp` 인스턴스 안에서만 유지한다. 화면 상태는 최대 12개 루트·1MiB, 첫 단계 트리는 최대 24개 루트/스코프 항목·1MiB다. 각 스냅샷은 기록 후 60초까지 사용하며 항목·바이트 한도를 넘으면 LRU 순서로 버린다. 큰 항목은 캐시하지 않는다. 새 localStorage 원장이나 서버 캐시는 만들지 않는다. 권한 변경 시 두 캐시를 비우고, 계정 변경은 App 인스턴스를 교체한다.
- 서버가 전환을 확인하면 해당 루트의 캐시된 UI·첫 단계 트리를 즉시 반영한다. 첫 단계 트리는 항상 백그라운드로 다시 읽고, 변경 신호로 읽은 결과도 캐시에 반영한다. 직접 전환 중 들어온 presence 알림은 모아 POST가 끝난 뒤 현재 루트를 한 번 확인하며, 이전 조회 응답은 순서 번호로 폐기한다. POST 응답과 알림 조회에서 같은 `path`·`docsPath`를 받은 경우 재초기화하지 않는다. Documents 경로가 바뀌면 트리 캐시를 비우고 새 조회를 시작한다. 처음 루트를 알기 전에는 인증된 사용자의 트리·프로젝트 목록 중복 조회를 만들지 않는다.
- 500ms UI 저장 대기가 끝나기 전에 루트를 떠나면 마지막 스냅샷을 그 **이전 루트**에 저장한다. 계정 UI PUT은 직렬화하고, 계정 App이 사라진 뒤에는 대기 중 쓰기를 보내지 않는다. 캐시와 진행 중 GET이 겹치면 더 최신인 로컬 스냅샷을 유지한다.
- `useTabs`는 저장된 모든 편집 칸·탭 껍데기를 한 번의 상태 갱신으로 만든다. 이전 루트의 동명 탭을 조회해 복원을 건너뛰지 않는다. 루트를 바꿀 때 이전 Documents 등 다른 API 스코프의 메모리 상태도 제거해 새 루트에 저장하지 않는다. 본문은 기존 계정/루트별 캐시로 채우고 각 칸의 활성 탭만 최신 본문을 요청한다. 복원 전에는 옛 루트의 본문을 새 탭 아래에 표시하지 않는다.
- 트리·본문·문서 규칙 응답은 전환 세대가 일치할 때만 적용한다. 빠른 A→B→A 전환에서도 늦은 옛 응답이 현재 본문이나 캐시를 덮지 않는다. 전환 실패는 현재 루트·화면을 유지한다.

검증: `workspace-snapshot-cache.test.ts`는 재사용·진행 요청 합치기·LRU/바이트/만료·실패 재시도·권한 무효화를 검사한다. `server/workspace-switch-ui.test.ts`는 실제 App·useTabs·FileTree·프로젝트 탭·도킹을 격리 Chromium에 올리고 네트워크 응답을 통제해, POST 완료 전 메타데이터 요청 시작, warm 복귀의 추가 UI GET 0회, 트리/본문 갱신 대기 중 캐시 표시, 중복 알림, 직전 탭 닫기 저장, Documents 스코프 격리, 오래된 본문 응답 폐기와 전환 실패를 검사한다. 이 테스트는 다른 패널과 편집기 렌더러를 대체하므로 실제 서버·대형 편집기·에이전트 재연결 전체 지연의 측정값으로 해석하지 않는다. `server/agent-command-ui.test.ts`는 실제 AgentPanel의 일반 초기 조회와 준비된 조회 재사용을 각각 확인한다.
