## Mewlink 로컬 로그인

기기 주소는 중앙 로그인 없이 연결하지만 mew 로그인 전에는 일반 guest 기능·파일 공유 권한을 적용하지 않는다. dispatcher가 정적 UI·인증·Mewlink 접근 요청 API만 허용하고 업무 HTTP·WS를 차단한다. 로컬 비밀번호 세션 또는 owner 승인·본인 연결을 마친 외부 신원을 확인한 뒤 기존 역할·기능·파일·작업 루트의 권한을 적용한다. 중앙 등록 계정·주소·연결 subject는 로컬 권한이 아니다. 임시 비밀번호·만료·로그아웃·계정 삭제·역할과 파일 규칙 변경은 접속 중에도 검사하며 이전 인증의 요청·WS를 종료한다. 비밀번호 변경 요구는 비밀번호 로그인에 적용하며 외부 인증의 프로필 수정으로 이를 지우지 않는다. 상세 전송과 세션 보관은 [원격 접속 계약](remote-access.md)을 따른다.

owner의 **계정 관리 → Mewlink 계정 접근**에서 검증된 신원 요청을 승인하면 비밀번호 없는 member를 즉시 등록한다. 기존 이메일 사용자는 같은 접속의 검증된 Mewlink 신원과 완료된 비밀번호 로그인으로 본인 계정에 연결할 수 있다. 이 연결은 새 계정이나 권한을 만들지 않으며 이메일 계정의 기존 권한을 사용한다. 역할·기능·경로 권한은 동일한 로컬 사용자 ID에 귀속한다. 새 외부 사용자는 승인 전에는 권한이 없고 기본 역할은 member다. 연결 해제는 개인 설정·로컬 비밀번호를 삭제하지 않으며 외부 로그인만 회수한다. 외부 연결은 승인 당시의 연결 ID와 사용자 ID에 고정하여 해제 후 재연결이나 다른 사용자 연결로 기존 세션을 되살리지 않는다.

## 관리 화면과 기본값

공통 모달의 헤더는 제목·계정 수·추가/닫기 아이콘으로 구성하며 계정 추가 폼과 권한 안내는 필요할 때 펼친다. 프로필 사진을 누르면 계정 제어 팝업에서 역할 변경·삭제를 수행한다. 삭제는 팝업 내 확인을 거치고 실패하면 재시도한다.

계정 추가의 역할, 계정 행과 사진 팝업의 역할, 파일 경로 범위와 경로별 권한은 공통 `SelectField`를 사용한다. 네이티브 팝업 없이 키보드·터치로 선택하며 표의 스크롤 영역 밖으로 목록을 띄운다. 역할·파일 권한 저장 중 필드를 비활성화하고 기존 저장 실패 안내·재조회·서버 권한 검사를 유지한다.

owner의 **계정 관리 → 기능 권한**은 계정을 열, 역할·기능을 행으로 표시한다. 기능·파일 권한 표의 계정 머리글에는 저장된 프로필 사진을 표시하고, 사진이 없거나 읽기에 실패하면 사람 아이콘을 표시한다. guest는 그룹 아이콘을 유지하며 머리글을 누르면 이름·이메일을 확인한다. owner 전용 `/api/admin/access`와 기능 권한 저장 응답은 계정별 `avatarDataUrl`을 포함한다. 기능은 파일 열람·수정, 에이전트, 터미널, 원격 데스크톱, localhost 앱 접속, Android, 서버 파일 탐색기, Git, 데이터베이스, 공동 편집·댓글, 채팅, 시스템 관리, 예약 작업이다. 역할은 기본값이고 체크 변경은 계정별 덮어쓰기다. 초기화하면 해당 역할 기본값을 다시 따른다. 마지막 owner는 강등하거나 삭제할 수 없으며 현재 로그인한 본인도 삭제할 수 없다. 계정 관리와 워크스페이스 관리 등 owner 전용 관리 기능은 기능 표로 위임하지 않는다.

owner·manager는 기본적으로 모든 기능을 사용한다. member는 파일 열람·수정, 데이터베이스, 공동 편집·댓글, 채팅을 사용한다. guest는 파일 열람·수정만 조절하며 나머지는 로그인 계정 전용이다. 임시 비밀번호 미변경 상태는 모두 차단한다. 터미널형 에이전트는 에이전트와 터미널 기능을 모두 요구한다.

**파일·폴더 권한**에서 워크스페이스 또는 Documents를 고르고 탐색하거나 상대경로를 입력한다. 각 계정의 규칙은 상속·차단·열람·수정이며 실제 적용 결과를 함께 표시한다. 기능의 파일 열람·수정 토글은 상한이다. 가장 구체적인 파일/폴더 규칙이 우선하고 수정은 열람을 포함한다. 규칙이 없으면 로그인 계정은 허용, guest는 차단한다. 사이드바에는 권한 변경 버튼을 두지 않는다.

## 저장과 경로

owner 전용 `DELETE /api/admin/users/:accountId`는 존재하지 않는 계정에 404, 본인·마지막 owner 삭제에 400을 반환한다. 삭제 시 비밀번호·일반/신뢰 브라우저 세션·Mewlink 연결/승인 요청과 모든 워크스페이스의 파일 규칙·계정별 기능 덮어쓰기를 제거하고 접근 변경을 알린다. 등록된 제공자의 Git 연결도 제거하며 진행 중인 GitHub 로그인 작업은 계정 생성 시각을 대조해 삭제·재등록 뒤 도착한 토큰을 저장하지 않는다. 개인 설정·프로젝트 파일·작업 기록은 보존한다. 같은 ID 재등록으로 과거 세션·권한·외부 Git 자격증명이 복원되어서는 안 된다.

- `shared/access-policy.ts`: 기능 목록·역할 기본값·공유 자료형.
- `server/access-policy.ts`: 실제 판정과 `MEW_DATA_DIR/access-policy.json`의 원자적 저장(0600). 기능은 계정 이메일/guest별, 파일 규칙은 실제 워크스페이스 루트별로 저장한다.
- `server/access-routes.ts`: owner 전용 `/api/admin/access`, `/feature`, `/path`. 파일 변경 요청은 열었던 workspace 식별자를 보내고 루트가 바뀌었으면 409로 거부한다.
- 기존 `guest-access.json`은 신규 정책 파일이 없을 때 현재 워크스페이스에 한 번 가져온다. 다음 권한 저장에 함께 기록한다. 옛 `/api/guest-access` 변경 API는 410이다.
- Documents·하위 프로젝트·루트 별칭과 심볼릭 링크는 실제 경로로 판정하므로 다른 별칭으로 제한을 우회할 수 없다. 워크스페이스 밖과 차단 경로는 거부한다. 재귀 이동·복사·삭제에서 디렉터리 심볼릭 링크를 만나면 거부하여 범위 탈출과 순환을 막는다.

일반 파일 경계는 `.data`라는 폴더 이름뿐 아니라 실제 `DATA_DIR`과 모든 하위를 항상 거부한다. `MEW_DATA_DIR`로 이름을 바꾸거나 기본 XDG 데이터 폴더가 워크스페이스 안에 있어도 적용하며, 파일·폴더 심볼릭 링크와 아직 생성하지 않은 하위 경로도 실제 부모 경로로 검사한다. owner나 명시적 파일 허용 규칙으로 이 차단을 해제할 수 없다. 프로젝트 목록·트리·카탈로그에도 해당 경로를 표시하지 않는다.

Git·DB·태스크·기능 목록 등 프로젝트 전체 권한을 요구하는 API는 데이터 폴더가 포함되어 있으면 현재 `serverFiles` 권한도 요구한다. 이 권한은 이미 별도 서버 파일 탐색기로 OS 파일에 접근할 수 있는 범위이며 owner·manager의 기본값이다. 따라서 Mew 저장소 안에 기존 `.data/`가 있어도 이 계정의 정상 프로젝트 작업을 일괄 차단하지 않는다. 역할 이름만으로 예외를 주지 않으며, `serverFiles`를 회수하거나 명시적 파일 권한을 제한하면 해당 검사도 그대로 적용한다. 일반 파일 API의 데이터 경로 차단은 계속 유지한다.

## 서버 경계

`server/reqAuth.ts`의 기능 미들웨어와 WS authorize가 실제 경계다. 트리·검색은 허용된 항목만 반환하고 원문·다운로드·PDF·이력·댓글·표 너비·첨부도 파일 권한을 검사한다. 폴더 이동·삭제·복사는 하위 차단 규칙까지 검사한다. 업로드는 multipart 파싱 후 목적지를 다시 검사하며 문서 제목 변경의 링크 전파도 수정 가능한 파일에만 적용한다.

guest의 `PUT /api/file`은 기존 파일 본문만 수정한다. 존재하지 않는 경로를 생성하지 않으며, 생성 플래그 없는 파일 핸들로 열어 검사와 쓰기 사이의 삭제를 파일 생성으로 바꾸지 않는다. `/api/raw`·`/api/asset`·서버 파일 탐색기의 `/api/fs/raw`는 CSP sandbox로 스크립트 실행을 막아 HTML·SVG 등 사용자 파일이 Mew origin의 권한으로 실행되지 않게 한다.

터미널·에이전트·공동 편집·DB·presence·live WebSocket은 브라우저가 보낸 `Origin`의 스킴·호스트·포트를 요청 origin과 대조한다. 같은 호스트의 다른 포트·하위 도메인, `null`·잘못된 Origin은 거부한다. Origin 없는 비브라우저 클라이언트는 호환을 유지하며, 브라우저의 WebSocket은 Origin을 보내므로 이 예외로 다른 origin의 페이지가 쿠키 인증을 사용할 수 없다. 중앙 origin을 쓰는 Mewlink는 서버가 검증해 연결한 살아 있는 P2P context만 예외로 허용하고 기존 인증·기능·회수 검사는 그대로 적용한다. 운영 서버와 개발 서버에 같은 정책을 적용한다.

첨부 `/api/asset`은 UUID만 안다고 볼 수 없다. 해당 `.mew/assets/` 파일에 열람 권한이 있어야 하며 응답은 캐시하지 않는다. guest에게 문서를 공유할 때 첨부 경로도 따로 허용한다. 프론트매터 공유 선택 목록(`/api/frontmatter-options`)은 조회에 프로젝트 전체 열람 권한, 추가·삭제에 로그인과 프로젝트 전체 수정 권한을 요구한다. Git·DB 관리처럼 프로젝트 전체 자료를 반환하는 기능은 해당 프로젝트에 부분 파일 제한이 있으면 차단한다. DB는 라우터가 실제로 사용하는 프로젝트 스코프도 다시 검사한다.

로그인 영상 화면은 인증 작업의 `agent` 또는 GitHub 연결의 `git`/`filesWrite` 권한을 확인한다. 별도 일반 브라우저 권한은 요구하지 않는다.

파일 규칙은 **mew 파일 API**에 적용된다. 에이전트·터미널·원격 데스크톱·서버 파일 탐색기 등 서버 제어 기능은 OS 권한으로 동작하며 파일 규칙으로 샌드박싱되지 않는다. 이 기능을 허용한 계정에 파일 규칙으로 비밀을 숨길 수 있다고 가정하지 않는다. 계정 관리에 이 설명을 표시한다.

## 외부 디버거

[외부 DAP 디버거](../features/터미널·에이전트·자동화/외부%20DAP%20디버거.md)는 owner·manager의 터미널 기능 권한과 현재 프로젝트 전체 파일 읽기·수정 권한을 요구한다. 어댑터 설치·실행과 디버깅 대상은 서버 OS 권한으로 동작하며 파일 ACL의 샌드박스가 아니다. 모든 디버거 HTTP 요청에 권한을 검사하고 실행 중 세션도 정책 변경 및 5초 주기 검사로 재검증한다. 계정·프로젝트·세션 불일치 요청은 실행하지 않는다. 독립 세션·자식 연결·스레드와 중단 revision별 참조를 대조하고 메모리·값 쓰기에도 같은 권한을 적용한다. 내부 DOM 브라우저를 제거했으므로 일반 Mew 브라우저 탭을 선택하는 분석 연결은 제공하지 않는다. 외부 DAP 디버거와 분석 파일 가져오기는 유지한다.

선택적 `mew-debugger` 에이전트 MCP에는 디버거 권한에 더해 `agent` 기능과 계정·프로젝트별 `agentBridge` 활성화를 요구한다. 계정·프로젝트에 고정한 비공개 Unix 소켓에서 매 호출 및 정책 변경·5초 주기로 재검사하며 공유 해제·권한 회수·프로젝트 변경에서 연결을 닫는다. 명령은 정확한 세션·연결·중단 revision을 요구하고 HTTP와 같은 허용 목록을 사용한다. 도구 설치·임의 DAP/CDP·다른 계정의 대상은 노출하지 않는다.

## 접속 중 권한 변경

저장 시 `accessChanges`가 기존 연결을 재검증한다. 에이전트·터미널·공동 편집·원격 화면·브라우저 소켓은 권한 없는 연결을 끊고 입출력에서도 검사한다. DB 구독은 기능과 프로젝트 접근을 검사한다. 유휴 소켓 인증은 5초 간격으로 재확인한다. localhost 프리뷰 토큰은 원래 인증 세션과 현재 `portPreview` 권한에 결합하며 요청·열린 소켓을 재검증한다. 옛 `browser` 덮어쓰기는 `portPreview`로 읽어 이관하고 다음 권한 저장에서 새 키로 기록한다.

presence는 내용 없는 `permissions` 신호를 보내고 클라이언트는 `/auth/me`, 트리, 열린 파일 권한을 다시 읽는다. 권한 없는 창과 파일은 닫고 수정만 회수된 파일은 읽기 전용으로 바꾼다. 본문 캐시를 폐기하며 재접속 때도 재검증한다. 이미 사용자가 내려받은 데이터와 서버에 실행 중인 프로세스를 소급 삭제하거나 종료하지는 않는다.

## 검증

`server/access-policy.test.ts`는 기능 독립 허용·거부, 계정 관리 권한, guest 이관, 상속·명시 차단, 별칭·심볼릭 링크, HTTP·검색·협업 권한 회수, 마지막 owner, 워크스페이스 변경을 검증한다. `server/account-access-ui.test.ts`는 실제 관리 컴포넌트의 저장·실패 복원·역할 기본값 복귀·파일 규칙과 데스크톱/모바일 표를 검증한다. 테스트는 임시 데이터 디렉터리를 사용한다.

`server/server-data-path.test.ts`는 워크스페이스 안에 둔 임의 이름의 데이터 폴더와 파일·폴더 별칭을 일반 파일 GET·PUT, ACL, 트리·카탈로그에서 차단하고 안전한 형제 경로는 유지하는지 검사한다. 서버 파일 권한을 가진 계정의 Git·태스크·기능 목록 접근과 권한 회수·파일 규칙 적용도 검사한다. `server/websocket-origin.test.ts`는 WebSocket 종류별 다른 포트·스킴·Origin 거부와 같은 origin·비브라우저 호환, 검증된 P2P context의 수명을 검사한다. 이 보안 fixture는 PTY 생성을 금지한다.

## 태스크 패널

객체 목록 `/api/task-list`는 로그인과 현재 루트 전체 열람 권한을 요구하며 쓰기는 전체 편집 권한도 검사한다. 요청 루트·계정과 현재 세션을 대조해 전환 직전의 요청이 다른 프로젝트·계정에 저장되지 않게 한다. 읽기만 허용된 계정은 목록을 조회할 수 있다. [입력·저장 계약](task-list.md)을 따른다.

## 뮤펫 전역 스킨

`/api/mewpet/skins`의 목록·이미지 읽기는 내장 스킨과 같은 공개 표시 데이터이며 모든 역할에서 허용한다. 추가·수정·삭제는 인스턴스 전역 변경이라 owner 전용이다. 활성 프로젝트나 Documents 파일 ACL로 전역 스킨을 필터하지 않는다. 서버는 이미지 실제 형식·크기·프레임 수와 manifest를 검사하고 폴더 밖 경로·심볼릭 링크를 거부한다. 이미지 하나당 4MiB·스킨 합계 24MiB·최대 16개 동작의 업로드로 제한하며 실패 시 기존 정상 파일을 보존한다. 같은 서버의 다른 계정·프로젝트에서도 스킨 목록은 공유하지만 선택 취향은 기존 브라우저 범위에 둔다.
