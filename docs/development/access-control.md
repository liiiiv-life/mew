# 계정별 기능·파일 권한

상위: [개발 계약](MOC.md). 정책: [SECURITY](../../SECURITY.md), 결정: [ADR 0150](../../../.mew/docs/decisions/0150-mew-account-feature-and-file-permissions.md).

## 관리 화면과 기본값

owner의 **계정 관리 → 기능 권한**은 계정·guest를 행, 기능을 열로 표시한다. 기능은 파일 열람·수정, 에이전트, 터미널, 원격 데스크톱, 내부 브라우저, Android, 서버 파일 탐색기, Git, 데이터베이스, 공동 편집·댓글, 채팅, 시스템 관리, 예약 작업이다. 역할은 기본값이고 체크 변경은 계정별 덮어쓰기다. 초기화하면 해당 역할 기본값을 다시 따른다. 마지막 owner는 강등할 수 없다. 계정 관리와 워크스페이스 관리 등 owner 전용 관리 기능은 기능 표로 위임하지 않는다.

owner·manager는 기본적으로 모든 기능을 사용한다. member는 파일 열람·수정, 데이터베이스, 공동 편집·댓글, 채팅을 사용한다. guest는 파일 열람·수정만 조절하며 나머지는 로그인 계정 전용이다. 임시 비밀번호 미변경 상태는 모두 차단한다. 터미널형 에이전트는 에이전트와 터미널 기능을 모두 요구한다.

**파일·폴더 권한**에서 워크스페이스 또는 Documents를 고르고 탐색하거나 상대경로를 입력한다. 각 계정의 규칙은 상속·차단·열람·수정이며 실제 적용 결과를 함께 표시한다. 기능의 파일 열람·수정 토글은 상한이다. 가장 구체적인 파일/폴더 규칙이 우선하고 수정은 열람을 포함한다. 규칙이 없으면 로그인 계정은 허용, guest는 차단한다. 사이드바에는 권한 변경 버튼을 두지 않는다.

## 저장과 경로

- `shared/access-policy.ts`: 기능 목록·역할 기본값·공유 자료형.
- `server/access-policy.ts`: 실제 판정과 `MEW_DATA_DIR/access-policy.json`의 원자적 저장(0600). 기능은 계정 이메일/guest별, 파일 규칙은 실제 워크스페이스 루트별로 저장한다.
- `server/access-routes.ts`: owner 전용 `/api/admin/access`, `/feature`, `/path`. 파일 변경 요청은 열었던 workspace 식별자를 보내고 루트가 바뀌었으면 409로 거부한다.
- 기존 `guest-access.json`은 신규 정책 파일이 없을 때 현재 워크스페이스에 한 번 가져온다. 다음 권한 저장에 함께 기록한다. 옛 `/api/guest-access` 변경 API는 410이다.
- Documents·하위 프로젝트·루트 별칭과 심볼릭 링크는 실제 경로로 판정하므로 다른 별칭으로 제한을 우회할 수 없다. 워크스페이스 밖과 차단 경로는 거부한다. 재귀 이동·복사·삭제에서 디렉터리 심볼릭 링크를 만나면 거부하여 범위 탈출과 순환을 막는다.

## 서버 경계

`server/reqAuth.ts`의 기능 미들웨어와 WS authorize가 실제 경계다. 트리·검색은 허용된 항목만 반환하고 원문·다운로드·PDF·이력·댓글·표 너비·첨부도 파일 권한을 검사한다. 폴더 이동·삭제·복사는 하위 차단 규칙까지 검사한다. 업로드는 multipart 파싱 후 목적지를 다시 검사하며 문서 제목 변경의 링크 전파도 수정 가능한 파일에만 적용한다.

첨부 `/api/asset`은 UUID만 안다고 볼 수 없다. 해당 `.mew/assets/` 파일에 열람 권한이 있어야 하며 응답은 캐시하지 않는다. guest에게 문서를 공유할 때 첨부 경로도 따로 허용한다. Git·DB·RAG 관리처럼 프로젝트 전체 자료를 반환하는 기능은 해당 프로젝트에 부분 파일 제한이 있으면 차단한다. DB는 라우터가 실제로 사용하는 프로젝트 스코프도 다시 검사한다.

파일 규칙은 **mew 파일 API**에 적용된다. 에이전트·터미널·원격 데스크톱·서버 파일 탐색기 등 서버 제어 기능은 OS 권한으로 동작하며 파일 규칙으로 샌드박싱되지 않는다. 이 기능을 허용한 계정에 파일 규칙으로 비밀을 숨길 수 있다고 가정하지 않는다. 계정 관리에 이 설명을 표시한다.

## 접속 중 권한 변경

저장 시 `accessChanges`가 기존 연결을 재검증한다. 에이전트·터미널·공동 편집·원격 화면·브라우저 소켓은 권한 없는 연결을 끊고 입출력에서도 검사한다. DB 구독은 기능과 프로젝트 접근을 검사한다. 유휴 소켓 인증은 5초 간격으로 재확인한다. 브라우저 프록시 서명 세션은 정책 변경 시 폐기한다.

presence는 내용 없는 `permissions` 신호를 보내고 클라이언트는 `/auth/me`, 트리, 열린 파일 권한을 다시 읽는다. 권한 없는 창과 파일은 닫고 수정만 회수된 파일은 읽기 전용으로 바꾼다. 본문 캐시를 폐기하며 재접속 때도 재검증한다. 이미 사용자가 내려받은 데이터와 서버에 실행 중인 프로세스를 소급 삭제하거나 종료하지는 않는다.

## 검증

`server/access-policy.test.ts`는 기능 독립 허용·거부, 계정 관리 권한, guest 이관, 상속·명시 차단, 별칭·심볼릭 링크, HTTP·검색·협업 권한 회수, 마지막 owner, 워크스페이스 변경을 검증한다. `server/account-access-ui.test.ts`는 실제 관리 컴포넌트의 저장·실패 복원·역할 기본값 복귀·파일 규칙과 데스크톱/모바일 표를 검증한다. 테스트는 임시 데이터 디렉터리를 사용한다.
