# 태스크 패널

[개발 지도](MOC.md) · [기능](../features/%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%C2%B7%ED%8C%8C%EC%9D%BC%C2%B7%EA%B2%80%EC%83%89/%ED%83%9C%EC%8A%A4%ED%81%AC%20%ED%8C%A8%EB%84%90%C2%B7%EB%AA%A9%EB%A1%9D%C2%B7%EB%8B%AC%EB%A0%A5%C2%B7%EA%B0%84%ED%8A%B8.md) · [사용법](../guides/projects.md#태스크)

## 입력과 패널

- 메모와 독립된 `tasks` 도킹 패널이며 현재 루트 프로젝트의 태스크를 관리한다. 항목은 `{id, text, done, tags?, startDate?, date?, path?}` 객체다. 모든 항목은 같은 단계이며 태그·날짜는 선택 속성이다. 우선순위는 제공하지 않는다.
- 마지막 입력칸은 새 항목 초안이다. 비어 있고 포커스가 없을 때는 문구·체크박스 대신 가로 중앙의 + 아이콘만 표시하며 행을 클릭하거나 Tab으로 진입하면 기존 입력칸에서 작성한다. Enter 또는 포커스 이동으로 객체를 만들며 Enter 이후 같은 입력칸에서 다음 항목을 이어 쓴다. 기존 항목의 Enter는 커서/선택 위치에서 내용을 나누고 원래 항목 ID를 유지한다. 오른쪽 내용에는 새 ID를 부여한다. Shift+Enter는 같은 항목 안의 줄바꿈이다.
- 여러 줄 붙여넣기는 줄마다 객체를 만든다. 기존 항목에 붙이면 첫 줄은 원래 ID를 유지한다. 빈 항목의 Backspace는 해당 객체를 삭제한다. 삭제 버튼·빈 항목 Backspace로 객체를 삭제한 뒤 다른 항목이나 새 입력칸에 자동 포커스하지 않아 모바일 키보드를 새로 열지 않는다. 첫 항목은 삭제 버튼으로 지울 수 있다. 커서가 처음/끝에 있을 때 위/아래 화살표로 인접 항목을 이동한다. IME 조합 중 Enter는 태스크를 만들거나 나누지 않는다.
- 체크박스는 해당 객체의 완료만 바꾸며 저장 순서는 유지한다. 기본 필터에서는 완료 즉시 숨기고, 완료 항목을 표시하면 취소선으로 표시하고 바로 수정할 수 있다. 목록·달력 항목의 삭제 아이콘은 기본 상태와 hover에서 숨긴다. 항목을 왼쪽으로 스와이프하면 오른쪽에 삭제 아이콘을 표시하며, 아이콘을 눌러야 객체를 삭제한다. 오른쪽 스와이프·바깥 클릭·Esc·보기 전환으로 닫고 한 번에 한 항목만 연다. 세로 이동·포인터 취소는 삭제를 열지 않으며 체크박스 순서 이동·태그 가로 스크롤은 기존 조작을 유지한다. 키보드에서는 항목 안에서 Alt+Delete로 아이콘을 열고 포커스한 뒤 Enter/Space로 삭제한다. 읽기 전용에서는 스와이프 삭제를 제공하지 않는다.
- 체크박스 영역을 6px 이상 끌면 순서 이동으로 전환하며 짧은 클릭/탭은 완료 체크를 유지한다. 포인터를 따라가는 항목 복사본과 삽입선을 표시하고 가장자리에서 본문을 자동 스크롤한다. 다른 항목의 중앙을 넘을 때마다 화면 순서를 즉시 바꾸며 주변 행은 탭·독과 같은 재배열 애니메이션으로 이동한다. 미리보기 순서는 패널 내부에만 유지하고 드롭 때 최신 객체에 최종 위치를 적용해 자동 저장한다. 취소하면 원래 순서로 돌아가며, 외부에서 구조가 바뀌면 이동을 취소한다. 체크 상태·본문·ID는 유지하며 드래그 뒤 합성 클릭을 차단한다. Esc·pointercancel·capture 해제·창 크기 변경·blur·화면 숨김은 이동을 취소하며 Esc가 패널 닫기로 전달되지 않는다. 입력칸과 일반 본문에서는 기존 스크롤·텍스트 선택을 유지한다.
- 체크박스에 포커스한 상태의 Alt+위/아래로도 이동한다. 드래그 중·취소·키보드 이동 때 주변 행은 공통 `useReorderAnimation`의 180ms 곡선을 사용하고 `prefers-reduced-motion`에서는 애니메이션을 생략한다.
- 저장 중 상태는 타이틀바의 태스크 제목 바로 오른쪽에 표시한다. 좁은 화면에서 제목이 아이콘으로 축약돼도 상태 표시를 유지하며 보기 탭 앞에서 남은 너비에 맞춰 말줄임한다.
- 36px 공통 헤더·DockGrip·확대/복원·분할 경계·독·모바일 전면 스택·Esc/뒤로가기를 공유한다. 열림 상태는 계정별 `chrome.tasksOpen`, 위치는 `tasks` dock kind로 복원한다. 모바일에서는 입력칸을 자동 포커스하지 않는다.

## 항목 우클릭 메뉴

- 목록·달력 항목과 간트 이름·막대를 우클릭하거나 항목 안에서 Shift+F10/메뉴 키를 누르면 공용 아이콘 메뉴를 연다. 문서 열기·일정 편집·완료 전환·태스크 삭제를 제공하며 메뉴의 완료 체크 상태는 현재 객체를 따른다.
- 문서가 연결되고 파일 열기 콜백이 있을 때만 문서 열기를 표시한다. 읽기 전용에서는 문서 열기만 제공하고 날짜·완료·삭제 조작은 숨긴다. 날짜 수정은 목록·달력의 기존 기간 팝오버 또는 간트 편집 카드를 연다. 삭제는 같은 객체와 연결 문서의 기존 삭제 경로를 사용한다.
- 모든 메뉴 항목에는 기존 아이콘 세트의 아이콘과 번역된 이름을 함께 표시한다. 메뉴는 portal로 열고 실측 크기를 사용해 visual viewport와 모바일 독 위에 배치한다. 방향키·Home/End로 이동하고 Enter/Space로 실행한다. Esc·Tab·뒤로가기·바깥 누름으로 닫으며 키보드 닫기는 호출한 요소로 포커스를 복원한다. 바깥 누름은 메뉴만 닫고 아래 항목의 동작으로 이어지지 않는다. 삭제는 다른 입력칸에 포커스하지 않는다.

## 내부 문서 링크

- 태스크마다 루트 프로젝트의 `docs/tasks/<태스크 제목>.md` 파일이 연결된다. 목록·달력에서 날짜 버튼 오른쪽 문서 아이콘을 누르면 App의 파일 열기를 통해 실제 Markdown 문서를 연다. 간트 편집 카드에서도 같은 파일을 열 수 있으며 읽기 전용 계정에도 문서 열기를 제공한다.
- 연결 파일이 설정된 Documents 폴더 안에 있으면 Documents 스코프와 폴더 상대 경로로 연다. Docs에서 직접 열었을 때와 같은 탭을 재사용하며, Documents 폴더 밖의 파일은 루트 프로젝트 스코프로 연다.
- 목록·달력의 문서 아이콘은 본문 첫 줄·날짜 버튼의 세로 중심에 맞춘다. 터치 입력에서는 32px 버튼 영역을 유지하면서 위아래 2px 음수 여백으로 28px 행 기준에 정렬한다.
- `path`는 서버가 실제 파일명으로 계산한 루트 상대 경로다. API 입력의 경로를 저장·삭제 대상으로 신뢰하지 않는다. 제목을 수정하면 프론트매터 `title`과 파일명을 함께 변경한다. 외부에서 `title`을 수정해도 쓰기 권한 조회 때 파일명을 맞추며 ID·본문·사용자 속성을 보존한다. 파일명만 외부에서 바꾸면 읽기 조회에는 그 경로를 반환하고 쓰기 권한 조회/저장 때 `title` 기준 이름으로 다시 맞춘다.
- 2026-10-06 사용자 요청으로 제목의 `@파일명` 참조 자동완성·링크 버튼을 제거했다. 제목을 문서 제목 그대로 쓰기 위한 변경이며 별도 요청 없이 재도입하지 않는다. 기존 제목의 Markdown 링크 문자열은 보존한다.

## 태그와 필터

- 목록·달력·간트에서 완료 항목을 기본적으로 숨긴다. 헤더 아래 필터 줄의 **완료된 항목 보기** 체크박스를 켜면 완료 항목도 표시한다. 태그가 없어도 이 필터는 제공하며 읽기 전용에서도 조작할 수 있다. 선택은 보기 전환 동안 유지하고 패널을 다시 마운트하면 숨김으로 초기화한다. 태그 필터와 AND로 결합하고 달력 날짜별 개수·간트 범위에도 반영한다. 숨긴 완료 항목은 편집·추가·재배열로 삭제하지 않으며 필터 변경만으로 저장하지 않는다.

- 새 태스크·기존 태스크·달력 일정·간트 편집 카드에서 제목 왼쪽에 태그가 없으면 회색 `태그` 칩을 표시하고 이 칩을 누르면 검색 가능한 다중 선택 팝업을 연다. 태그가 있으면 기존 태그 이름을 눌러 같은 팝업을 열며 별도 + 버튼은 표시하지 않는다. 선택한 칩을 팝업 위치와 닫은 뒤 포커스 복원의 기준으로 사용하며 마지막 태그가 제거되면 회색 칩으로 이어진다. 기존 태그를 검색해 선택/해제하고 새 이름은 + 후보로 만든다. 선택 후 팝업을 유지하며 제목은 변경하지 않는다.
- 팝업 상단 검색창은 돋보기 아이콘과 번역된 `태그 검색` placeholder를 표시한다. 테마의 raised 배경·strong 테두리로 목록과 구분하며 PC 32px/터치 36px 높이, 포커스 시 accent 테두리를 사용한다. 목록 스크롤 중에도 상단에 고정하며 모바일에서는 자동 포커스 없이 검색 가능함을 보여준다.
- 검색은 이름 부분 일치이며 방향키·Enter와 클릭·터치로 선택한다. Esc·뒤로가기·바깥 클릭·포커스 이탈은 팝업 한 겹만 닫는다. 화면 경계와 visual viewport를 따르며 모바일에서 검색창을 자동 포커스하지 않는다. 읽기 전용에서는 추가·삭제 조작을 숨긴다.
- 이름은 Unicode NFC·소문자로 정규화하며 문자·숫자·밑줄·하이픈을 허용한다. 한 이름은 64자, 항목당 최대 100개이고 중복은 저장하지 않는다. 제목 입력·붙여넣기의 `#` 토큰은 태그로 추출하지 않고 제목에 그대로 보존한다. 2026-10-06 제목/속성 분리 요청에 따라 인라인 해시태그 입력을 제거했으며 별도 요청 없이 재도입하지 않는다.
- 본문·필터 칩 모두 태그 이름의 오른쪽 여백을 2px로 둔다. 본문 삭제 버튼은 12px 아이콘을 왼쪽에 정렬하고 PC·터치 모두 너비를 18px로 맞춰 이름 왼쪽과 아이콘 오른쪽의 바깥 여백을 각각 6px로 통일한다. 세로 터치 여백은 유지한다.
- 태그 선택 목록의 기존 항목 오른쪽 ×는 **태그 전체 삭제**다. 누르면 루트 프로젝트의 모든 태스크(완료·필터로 숨겨진 항목 포함)에서 해당 태그만 제거하고 저장된 태그 목록·지정 색상·작성 중 새 항목의 태그에서도 제거한다. 활성 태그 필터는 해제해 빈 필터에 갇히지 않게 한다. 다른 태그·내용·기간·완료·순서와 Markdown 본문/사용자 속성은 유지한다. 검색 중 새 이름 후보에는 전체 삭제 버튼을 표시하지 않으며 읽기 전용에서는 전체 삭제를 제공하지 않는다. 개별 칩의 ×와 선택 목록 체크 해제는 기존처럼 해당 태스크만 변경한다.
- 태그 선택 목록의 색 동그라미는 태그 선택과 분리된 버튼이다. 누르면 16색(4×4) 팔레트를 열어 같은 이름의 태그 색을 루트 프로젝트 전체에 적용한다. 색을 바꿔도 태그 선택 상태는 바뀌지 않으며 목록·달력·간트의 칩과 필터 칩/동그라미에 함께 반영한다. 팔레트는 화면 경계를 보정하고 선택 색에 체크를 표시하며 방향키·Home/End·Enter/Space와 터치를 지원한다. Esc/뒤로가기는 팔레트 한 겹만 닫고 색 버튼으로 포커스를 복원한다. 읽기 전용에서는 색 변경을 제공하지 않는다.
- 확정된 태그는 `#` 없이 체크박스와 본문 사이의 같은 줄에 표시한다. 사용자가 지정한 색을 우선 적용하며 지정하지 않은 이름은 기존 고정 색상을 자동 지정하고 밝은/어두운 테마에 맞춰 대비를 조절하며 칩 모서리는 9px로 둥글게 표시한다. PC·모바일·읽기 전용 모두 칩 배경 높이를 20px로 맞추고 위아래 4px 여백으로 본문 첫 줄의 중심에 정렬한다. 여러 줄로 넘어가도 첫 줄 옆에 유지한다. 터치에서는 배경을 키우지 않고 버튼의 위아래 여백까지 28px 클릭 영역으로 사용한다. 태그 영역은 내용 행 너비의 최대 45%을 쓰고 본문은 나머지 공간을 사용한다. 좁은 화면의 여러 태그는 같은 줄에서 가로 스크롤한다. ×로 해당 태그만 제거한다. 읽기 전용에서는 삭제를 제공하지 않는다.
- 헤더 아래 작은 필터 아이콘에서 여러 태그를 선택한다. 선택한 태그 중 하나라도 붙은 항목을 표시하며(OR), 목록·달력의 날짜별 표시/개수·간트와 보기 전환에 같은 선택을 유지한다. 아이콘 옆의 컬러 칩으로 선택을 확인하고 칩을 눌러 개별 해제하거나 오른쪽 ×로 전체 해제한다. 칩 영역은 좁은 화면에서 가로 스크롤하며 필터 줄은 PC 33px·터치 39px다.
- 공용 `SelectField`의 다중 선택 목록은 선택 후 열린 상태를 유지한다. 방향키·Home/End·문자 검색으로 후보를 이동하고 Enter/Space로 선택을 토글한다. Tab·바깥 누름·Esc·뒤로가기로 목록만 닫는다. 선택 중에는 트리거 포커스를 유지하고 포커스된 칩 또는 전체 해제 버튼을 없애면 트리거로 복원한다. 태스크 칩의 이름은 기존 필터에 태그를 추가한다.
- 태그 필터 드롭다운은 너비 200px·안쪽 여백 4px·모서리 10px로 표시한다. 항목 높이는 PC 28px·터치 32px이며, 선택은 옅은 테마색 바탕과 오른쪽 체크로 표시한다. 활성 항목·hover는 항목 안쪽의 둥근 배경으로 구분하고 화면 경계를 넘으면 내부 스크롤한다.
- 필터 안에서 만든 새 항목에 선택 태그를 기본으로 붙이고 기존 태그와 중복을 제거한다. 항목당 100개 제한은 유지한다. 다른 태그의 항목을 편집·이동 결과로 삭제하지 않는다.
- 서버 파일의 `tags`는 사용한 이름 목록이다. 마지막 사용 항목을 지워도 이름을 보존해 자동완성에 재사용한다. 다른 루트 프로젝트의 이름은 노출하지 않는다.

## 날짜 저장과 달력

- 공용 `DateCalendar`의 날짜 표시를 눌러 연·월·일 구간을 직접 입력한다. 단일 모드는 날짜 한 칸, 기간 모드는 시작일·종료일 두 칸을 제공한다. 기존 `DateField` 마스크·자동 구간 이동·날짜 검증을 공유한다. 유효한 값은 저장하고 표시 월을 해당 날짜로 맞추며 직접 입력 뒤 달력을 유지한다. 시작일이 종료일보다 늦거나 종료일이 시작일보다 이르면 반대 끝도 같은 날짜로 맞춘다. 읽기 전용은 직접 변경할 수 없다. 핫뷰 달력의 Esc는 입력을 저장값으로 되돌리고 입력칸 밖의 Esc는 달력을 닫는다. 태스크 팝오버·간트 카드는 기존 Esc 닫기를 유지한다.

- 공용 `DateCalendar` 날짜 격자를 손가락·펜으로 왼쪽으로 40px 이상 밀면 다음 달, 오른쪽으로 밀면 이전 달을 보여준다. 세로 이동이 우세하거나 여러 손가락·취소된 제스처는 월을 바꾸지 않는다. 스와이프는 날짜/기간을 저장하지 않고 뒤따르는 날짜 클릭을 차단한다. 세로 스크롤·핀치 확대와 기존 탭·키보드 선택은 유지하며 읽기 전용에서도 월 탐색을 허용한다.

- 항목별 `startDate`는 시작일, 기존 `date`는 종료일이다. 둘 다 시간대 없는 `YYYY-MM-DD`이며 생략/null은 날짜 없음이다. 양 끝을 포함하고 하나만 지정하면 그날 하루 일정으로 표시한다. 시작일이 종료일보다 늦어지면 다른 끝도 선택한 날짜로 맞추며 서버는 역전된 기간을 거부한다. 날짜는 각 객체가 독립적으로 소유하며 이동·내용 분할에서도 원래 객체의 날짜를 유지한다. 목록의 새 항목은 날짜 없이 시작하고 달력에서 생성·분할·붙여넣은 항목은 선택 날짜의 하루 일정으로 시작한다.
- 공용 `DateField`(문서 속성 등에서 사용)는 하나의 텍스트 입력에서 `0000-00-00` 마스크를 항상 유지하고 연·월·일 구간을 각각 선택한다. 선택한 구간의 숫자만 교체하며 연 4자리·월/일 2자리를 채우면 다음 구간으로 이동한다. 모바일은 숫자 키보드(`inputMode=numeric`)와 native beforeinput을 처리한다.
- 구간 클릭, 오른쪽/아래 방향키·Tab·Enter로 연→월→일을 이동한다. 왼쪽/위 방향키·Shift+Tab은 이전 구간, Home/End는 연/일을 선택한다. 일에서 Tab은 확정 후 다음 요소로, Enter/오른쪽/아래는 확정 후 달력 버튼으로 이동한다. 한 자리 월/일은 앞에 0을 붙인다. 탐색만으로 값이 바뀌지 않는다.
- 마지막 일 두 자리 입력·일 구간 확정·blur에 실제 날짜를 검증하고 자동 저장한다. 완성 전이나 없는 날짜는 입력과 오류를 남기며 기존 저장 날짜를 유지한다. Backspace/Delete는 현재 구간을 비우고, 빈 구간의 Backspace는 이전 구간을 비운다. 전체 선택 후 삭제는 모든 구간을 비우며 확정 시 날짜를 해제한다. Esc는 입력을 현재 저장 값으로 복원한다. IME 조합 중 구간 이동·확정은 무시한다.
- 전체 날짜 붙여넣기는 네 자리 연도를 포함한 `YYYY-MM-DD`·점/슬래시 구분·`YYYYMMDD`를 받아 고정 마스크로 표시한다. 숫자만의 구간 붙여넣기는 현재 구간부터 채운다. 구분자는 직접 수정하지 않으며 문자 입력은 받지 않는다.
- 달력 버튼 또는 입력칸 Alt+아래는 공용 자체 달력을 연다. 선택일의 월 또는 오늘의 월을 보여주고 이전/다음 달, 인접 달 날짜, 오늘/내일, 날짜 지우기를 지원한다. 선택일은 액센트 원으로, 오늘은 작은 점으로 구별한다. 요일/월/전체 날짜 접근성 이름은 선택 언어의 `Intl` 형식을 쓴다.
- 달력은 `dialog`·`grid`·`gridcell`과 날짜별 접근성 이름·선택·오늘 상태를 제공한다. 열 때 선택일/오늘 버튼에 포커스하며 방향키는 일/주, Home/End는 주의 처음/끝, PageUp/Down은 월, Shift+PageUp/Down은 연도를 이동한다. 이동만으로 저장하지 않고 Enter/Space/클릭으로 확정한다.
- 선택·닫기·Esc·뒤로가기 후 달력 버튼으로 포커스를 돌린다. 외부 클릭/Tab 이탈은 달력만 닫고 다음 요소 포커스를 유지한다. `useOverlayDismiss`로 패널보다 달력이 먼저 닫힌다. 달력은 body portal과 visual viewport 배치·내부 스크롤로 작은 화면과 키보드 변화에 대응한다. 모바일에서는 텍스트 입력을 자동 포커스하지 않는다.
- 달력은 기존 밝은/어두운 테마의 surface/ink/accent 토큰을 사용한다. 월 변경의 짧은 이동은 모션 감소 설정에서 생략한다. 태스크의 목록·간트 편집에는 아래의 통합 기간 달력을 사용한다.
- 서버는 실제 달력 날짜와 네 자리 연도(0001–9999)를 검사한다. `startDate`·`date`는 각각 내용·완료·부모와 별개의 필드로 병합·충돌 검사·재시도한다. 별개 날짜 변경의 병합 결과가 역전된 기간이면 묶음 전체를 충돌로 처리한다. 날짜 저장 실패도 기존 초안/다시 저장 경로를 따른다. 유효하지 않은 텍스트 입력은 해당 입력칸의 편집 상태에만 남는다.

## 목록·달력·간트 보기

- 36px 타이틀바의 목록·달력·간트 탭으로 보기를 전환하며 같은 세션의 객체·완료 상태·기간을 편집한다. 보기 전환 시 입력 중인 새 태스크를 확정한다. 탭은 `tablist`·`tab`·`tabpanel`로 연결하고 좌우 방향키·Home/End로 선택과 포커스를 이동한다. 하단 독의 왼쪽 스와이프는 다음 보기, 오른쪽 스와이프는 이전 보기를 선택하며 양 끝에서 순환한다. App의 현재 작업 탭 전환 신호에 참여하고 패널은 열린 상태를 유지한다. 기존 날짜만 있는 목록은 변환 없이 하루 일정으로 표시한다.

- 간트의 왼쪽 고정 목록과 위쪽 고정 눈금은 본문과 함께 스크롤한다. 완료는 초록, 계획은 파랑, 종료일이 지난 미완료 일정은 빨강이다.
- 선택 모드의 막대 드래그는 기간 이동, 양 끝 손잡이는 하루 단위 길이 변경이다. 터치의 빈 공간 드래그는 스크롤이며 막대·손잡이·눈금·그리기 영역만 기본 터치 스크롤을 막는다. 그리기 모드에서는 기존 행에 기간을 설정하고 마지막 점선 행에 새 태스크를 만든다. 한 객체당 기간 하나를 유지한다. Ctrl/Cmd를 누르는 동안에는 버튼으로 선택한 모드와 별개로 그리기 모드를 임시 적용한다. 키를 놓으면 버튼으로 선택한 모드로 돌아가며 두 키를 함께 누르면 둘 다 놓을 때 해제한다. 창 포커스 상실·화면 숨김에도 임시 모드를 해제하고 읽기 전용에서는 활성화하지 않는다. 기존 Ctrl/Cmd+휠 확대는 유지한다.
- 드래그 미리보기는 화면에만 존재하고 놓을 때 최신 객체의 날짜만 저장한다. Esc·포인터 취소·캡처 해제·blur·크기 변경·화면 숨김·쓰기 권한 해제·대상 날짜의 외부 변경은 미리보기를 취소한다. 내용·완료 등 다른 필드는 보존한다.
- 막대 클릭·터치·키보드 Enter/Space 또는 왼쪽 이름을 선택하면 화면 경계 안의 편집 카드에서 내용·완료·기간을 바꾸고 일정 날짜만 지울 수 있다. 우클릭은 아이콘 메뉴를 열고 일정 편집을 선택하면 같은 카드를 연다. 키보드로 열면 카드의 닫기 버튼으로 포커스를 옮겨 터치 키보드를 자동으로 열지 않고, 닫기·Esc 후 원래 막대/이름 버튼으로 돌려준다. 기간 달력은 카드 안에 통합되며 Esc는 카드를 닫는다. 키보드 좌/우는 하루 이동, Shift+좌/우는 종료일, Alt+좌/우는 시작일 변경이다.
- 확대·축소·전체 기간·오늘 버튼과 Ctrl/Command+휠·트랙패드 핀치를 지원한다. 눈금을 좌우로 끌면 이동, 위로 끌면 축소, 아래로 끌면 확대한다. 읽기 전용은 세 뷰 모두 열람·날짜 탐색·확대만 허용한다.
- 네 언어의 라벨·월·요일·접근성 이름과 기존 밝은/어두운 테마를 사용한다. 원본 앱의 다중 기간·취소 상태·일정 분할·독립 JSON/이미지 내보내기는 Mew 태스크 모델에 추가하지 않는다.

## 저장과 동시 수정

- 태스크의 기준본은 루트 프로젝트 `docs/tasks/` 바로 아래 `.md` 파일이다. YAML 프론트매터 `title`·`done`은 필수이고 `tags`(배열)·`startDate`·`date`(ISO 날짜)는 선택 필드다. `title`이 태스크 텍스트이자 문서 제목이다. Markdown 본문과 다른 프론트매터 속성·주석은 패널 편집 때 보존하며 별도 H1을 자동 생성하지 않는다.
- 문서 속성 편집기가 문자열로 저장한 `done: "true"`/`"false"`도 완료 값으로 읽는다. 문자열 `tags`는 빈 값이면 태그 없음, 단일 이름이면 한 태그, YAML/JSON 인라인 배열 문자열이면 태그 목록으로 읽고 기존 이름·중복·개수 검증을 적용한다. 조회나 변경 없는 저장은 이 표현만으로 문서를 다시 쓰지 않는다. 다른 완료 문자열·손상된 태그 배열은 계속 거부한다.
- 생성은 `<태스크 제목>.md`를 만들고 삭제는 연결된 파일 전체를 삭제한다. 외부의 제목·태그·기간·완료 수정, 파일 생성·이름 변경·삭제도 다음 조회에서 그대로 반영한다. 프론트매터에는 `id`를 쓰지 않는다. 내부 ID와 파일 경로·파일시스템 식별자(device/inode)는 루트별 version 5 메타데이터에 보관하여 패널에서의 제목 변경과 같은 파일시스템에서의 외부 이름 변경에도 항목을 유지한다. 이전 문서의 `id`는 쓰기 가능한 조회/저장 때 메타데이터로 옮기고 본문과 사용자 속성을 보존한 채 제거한다. 메타데이터 없는 문서도 파일시스템 식별자로 읽으며, 외부에서 파일을 교체 저장해도 같은 경로의 ID를 유지한다. 메타데이터와 파일시스템 식별자가 모두 바뀌는 이동은 새 항목으로 인식할 수 있다. 손상된 YAML·중복 ID·잘못된 속성·심볼릭 링크를 오류로 처리하며 빈 목록으로 덮어쓰지 않는다.
- `DATA_DIR/task-list-<루트 절대경로 SHA-256>.json`의 버전 5는 순서(`order`), 사용한 태그 목록(`tags`), 태그 이름별 선택 색상(`tagColors`: 이름 → 팔레트 hue), 내부 ID와 파일 연결 정보(`documents`: id/path/device/inode)를 저장한다. 태스크 내용·속성은 JSON에 복제하지 않는다. 루트별로 공유하며 하위 프로젝트 탭을 바꿔도 같은 목록을 사용한다.
- 기존 버전 1·2 JSON과 버전 3의 `tasks/<ID>.md`는 쓰기 권한이 있는 계정이 패널을 조회하거나 변경할 때 `docs/tasks/<제목>.md`로 이관한다. ID·제목·완료·태그·표시 기간·순서·본문·사용자 속성을 보존하고 이동한 원본은 제거한다. 읽기 전용 조회만으로는 이관하지 않는다. 기존 버전 1·2 JSON과 Markdown이 동시에 있거나 두 위치에 중복 ID가 있으면 임의로 덮어쓰거나 지우지 않고 오류로 처리한다. 버전 4의 제목 기반 문서도 같은 방식으로 `id`를 제거하고 연결 정보를 등록한다. 이전 `project-tasks-*.json`·개인 홈 todos·공통 메모 파일은 읽거나 변경하지 않는다. [제거 전 기록](../history/project-tasks.md)은 이력으로 유지한다.
- 일반 제목은 띄어쓰기·한글을 포함해 그대로 파일명에 사용한다. 중복 제목은 `(2)`, `(3)`을 붙이며 대소문자/Unicode 정규화 차이도 충돌로 처리한다. 기존 중복 번호는 삭제·재정렬에도 유지한다. 파일명에 사용할 수 없는 문자·제어 문자는 `-`로 치환하고 앞뒤 공백/끝 마침표를 정리한다. 빈 제목은 `제목 없음`, Windows 예약 이름은 `_` 접두어, 긴 이름은 Unicode 글자를 보존해 200바이트 이내로 제한한다. 이러한 파일명 보정은 원래 `title`을 바꾸지 않는다.
- `GET /api/task-list?workspace=<현재 루트>` → `{tasks, canEdit, tags, tagColors}`. `PATCH /api/task-list`는 `{workspace, changes, tagColorChanges?, deletedTags?}`를 받으며 같은 보드 형식을 반환한다. 요청의 `X-Mew-Task-Owner`는 URL 인코딩한 로그인 이메일로 세션과 일치해야 한다.
- `deletedTags`는 중복 없는 유효 태그 이름 배열(최대 2,000개)이다. 서버의 최신 전체 목록에 삭제를 적용하며 일반 필드 변경을 검사할 때도 삭제 태그를 제외한다. 다른 창에서 추가된 태스크도 삭제 대상에 포함하고 같은 삭제의 재시도는 성공으로 처리한다. 같은 PATCH의 다른 태스크/색 변경과 함께 Markdown·메타데이터에 저장한다. 삭제 요청은 브라우저 초안과 진행 중 저장 이후 큐에 보존하고 기존 자동/명시적 재시도·전체 파일 편집 권한을 따른다.
- 색 변경은 `{tag, before, after}`이며 `before=null`은 사용자 지정 색 없음, `after`는 16색 팔레트의 hue다. 색상 메타데이터는 최대 2,000개 태그까지 저장하고 태그 이름·팔레트 값·중복 변경을 검증한다. 같은 태그의 상충하는 수정은 409, 다른 태그의 수정과 같은 값의 재시도는 병합한다. 태스크 변경과 같은 PATCH/메타데이터 쓰기로 저장하고 일반 태스크 저장·이관에서도 색을 유지한다. 색만 바꾸면 Markdown에 색상 속성을 복제하지 않는다. 기존 자동 재시도·브라우저 초안·명시적 다시 저장과 루트/계정/파일 권한 경계를 공유하며 다른 창에는 다음 주기 조회로 반영된다.
- 변경은 `{id, before, after, afterId, move?}`다. `before=null`은 생성, `after=null`은 삭제, 둘 다 객체이면 필드 변경이다. 생성 위치는 `afterId` 뒤이며 null이면 맨 앞이다. 기존 객체에 `move=true`이면 필드 변경과 별개로 해당 객체를 `afterId` 뒤로 이동한다. 객체를 재생성하지 않는다. 같은 PATCH에서 생성·삭제·이동·내용 변경을 함께 처리한다.
- 이동은 현재 서버의 객체 내용을 유지하고 앵커를 기준으로 적용한다. 다른 창의 내용·완료 수정과 병합하며 새 객체를 없애지 않는다. 동시에 순서를 바꾸면 나중에 저장된 이동의 앵커가 적용된다. 사라진 객체·앵커는 기존 충돌 경로를 따른다. 응답 유실 재시도는 같은 이동을 중복 생성하지 않는다.
- 서버는 현재 객체와 `before`를 비교한다. 다른 ID·다른 필드의 수정은 합치고, 변경할 필드가 이미 `after`이면 성공으로 취급한다. 같은 필드의 상충하는 수정·수정된 객체의 삭제·사라진 삽입 위치는 409다. 전체 변경 묶음을 검사한 뒤 각 Markdown을 임시 파일+rename으로 저장하고 순서 메타데이터를 마지막에 저장한다. 쓰기 실패는 변경 파일을 복원한다. 여러 파일의 저장 중 외부 프로세스에는 중간 상태가 보일 수 있으며 프로세스 강제 종료까지 포함한 다중 파일 트랜잭션은 제공하지 않는다. 저장 실패와 손상 파일을 빈 목록으로 덮어쓰지 않는다.
- 로그인과 루트 전체 파일 열람 권한이 필요하고, 쓰기는 전체 파일 편집 권한도 요구한다. 읽기만 허용된 계정은 목록만 볼 수 있다. 계정·현재 루트 불일치는 409, 권한 부족은 403, 잘못된 입력은 400, 저장/읽기 실패는 500이다. guest와 임시 비밀번호 계정은 기존 HTTP 인증 경계에서 차단한다.
- 최대 2,000개, 내용은 항목당 8,000자, ID는 영문·숫자·밑줄·하이픈 1–100자다. 빈 내용은 줄 나누기 도중의 독립 항목으로 허용하며 자동 생성하지 않는다. 중복 ID·형식 오류를 거부하고 패널이 관리하는 속성은 title/done/tags/startDate/date이며 다른 문서 속성은 유지한다. 변경 API는 새 parentId를 거부한다.

## 클라이언트 수명과 오류

- `useTaskList`는 App에서 루트·계정별 `TaskListSession`을 유지한다. 입력은 즉시 반영하고 마지막 입력 후 350ms 또는 기존 항목의 blur에 저장한다. 패널 닫기·도킹 재마운트는 세션과 대기 중 저장을 유지한다. 프로젝트가 바뀌면 이전 요청은 서버의 workspace 검사로 막고 이전 초안은 해당 세션에 남긴다.
- 쓰기 응답·조회 중 추가 입력은 로컬 변경으로 다시 합쳐 보존한다. `GET /api/task-list/events`의 인증된 SSE가 루트·docs·태스크 폴더의 생성/삭제 및 파일 변경을 75ms 단위로 합쳐 즉시 재조회한다. 구독은 패널·계정·루트 수명에 맞춰 해제하고 루트/권한 변경 시 종료한다. 스트림이 없거나 끊기면 3초 주기 조회와 브라우저 복귀 시 조회가 보완하며, 로컬 변경·진행 중 저장·오류가 있으면 주기 조회로 입력을 교체하지 않는다. 메모의 Yjs 공동 편집과 별개의 객체 API다.
- 미저장 변경과 마지막 입력 초안의 내용·태그는 `mew:task-draft:<이메일>:<루트>:<창 ID>`로 브라우저에 보관한다. 창 ID는 sessionStorage에 유지해 같은 계정의 다른 창이 초안 보관값을 지우지 않게 한다. 서버 저장 후 해당 변경은 정리하며 새로고침 후 초안이 남으면 서버 조회 결과에 다시 합친다. 저장 공간이 부족해도 현재 페이지의 초안은 유지한다.
- 통신 실패·HTTP 5xx 저장 오류는 처음부터 경고를 띄우지 않고 1초·3초 뒤 최대 두 번 자동 재시도한다. 응답 유실에 대비해 같은 변경 묶음을 그대로 재전송하며, 재시도 중 추가 입력은 성공 응답 뒤 별도 변경으로 저장한다. 이 동안 주기 조회로 로컬 입력을 교체하지 않는다. 자동 재시도까지 실패하면 입력과 오류·다시 저장 버튼을 유지한다. HTTP 4xx(동시 수정·계정/프로젝트 변경·권한·입력 오류)는 자동 재시도하지 않고 즉시 표시한다. 사용자가 다시 저장하면 최신 서버 목록을 읽고 로컬에서 바꾼 필드만 다시 적용한다. 같은 필드의 충돌에서 다시 저장은 확인한 로컬 내용을 적용하는 명시적 동작이다. 계정 변경 시 이전 계정의 세션 타이머를 중지한다.

- 기간 선택기는 `@mew/ui`의 `DateCalendar`를 사용한다. Markdown Hotview 날짜 속성도 같은 컴포넌트의 단일 날짜 모드를 사용한다.

### 태스크 행 날짜 표시

목록·달력의 태스크 행은 삭제 버튼 왼쪽에 날짜 상태를 표시한다. 브라우저 현지 날짜보다 `startDate`가 미래이면 회색으로 시작일까지 남은 기간을 우선 표시한다. 1–6일은 `n일 후 시작`, 7–29일은 `w주 후 시작`, 30일 이상은 `m달 후 시작`이다. 주는 7일, 달은 30일 기준으로 나누고 소수점은 버린다. 한국어·영어·중국어·일본어 UI 언어를 따른다. 시작일이 오늘·과거이거나 없으면 `date`까지 남은 날짜 수를 `D-n`, 오늘은 `D-Day`, 지난 날짜 수는 빨간색 `D+n`으로 표시한다. 완료 체크 여부는 이 날짜 계산을 바꾸지 않는다. 완료일이 없으면 회색 `날짜 설정`으로 표시한다. 일수는 시간대 없는 달력 날짜 연산으로 계산하며 열린 화면도 30초마다, 창 포커스·가시성 변경 때 오늘을 갱신한다.

날짜 상태 버튼은 클릭·Enter·Space로 일정 편집 팝오버를 연다. 목록·간트는 `TaskRangeCalendar`의 6주 달력을 팝오버 안에 직접 표시한다. 별도 달력 버튼·중첩 팝업은 제거해 기간 선택을 한곳에서 처리한다. 첫 클릭은 `startDate`를 지정하고 `date`를 비운다. 다음 클릭이 시작일과 같거나 늦으면 종료일로 저장한다. 같은 날짜를 두 번 선택하면 시작일·종료일이 같은 하루 일정이 된다. 시작일보다 이르면 시작일을 교체하고 종료일 선택을 기다린다. 종료일 선택 이후의 클릭은 새 기간을 시작한다. 매 선택은 두 필드를 한 번에 갱신하며 내용·완료·태그를 보존한다. 월 제목은 언어별 연도·월 표기로 표시하고 각각 직접 입력한다. 시작일·종료일은 두 열의 날짜 요약으로 정렬하고 다음 선택 대상의 밑줄을 테마색으로 표시한다. 선택한 양 끝은 원형으로 강조하고 사이 기간은 주별로 이어지는 옅은 테마색 띠로 연결한다. 팝오버는 테마의 `surface-deep` 바탕·12px 모서리·10px 안쪽 간격을 공통 사용한다. 오늘은 날짜 숫자를 감싸는 테마색 원형 테두리로 표시하며 선택된 날짜와 겹치면 선택 배경 위의 대비색 테두리를 사용한다. 날짜 지우기는 두 필드를 함께 비운다.

연도·월은 숫자 입력으로 클릭 시 전체 선택하며 Enter·blur에 확정한다. 연도 0001–9999, 월 1–12 범위를 벗어나면 기존 표시로 복원하며 Esc는 입력을 복원한다. 월 변경 자체는 저장 날짜를 바꾸지 않는다. 방향키·Home/End·PageUp/Down·Shift+PageUp/Down은 날짜/월/연도를 탐색하고 Enter/Space는 기간을 선택한다. 읽기 전용은 달력 탐색만 허용한다. 팝오버는 body portal로 표시하고 스크롤·크기·visual viewport 변화에 위치를 맞춘다. 입력을 자동 포커스하지 않는다. 외부 클릭·Esc·뒤로가기로 닫으며 내부 포커스는 상태 버튼에 복원한다.

### 목록 기본 정렬

목록 보기의 항목은 `D-Day → D-n → D+n → 시작 대기 → 날짜 설정` 순서로 표시한다. 같은 상태 그룹은 기존 저장 순서를 유지하고 숫자 n으로 추가 정렬하지 않는다. 완료 체크 여부는 순위를 바꾸지 않는다. 날짜 편집·현지 날짜 변경 때 표시 순서를 다시 계산하며 단순 정렬은 저장하지 않는다. 드래그·Alt+위/아래는 표시 순서를 기준으로 저장하며 같은 상태 그룹 안의 수동 순서를 유지한다. 서로 다른 상태 그룹은 기본 정렬 우선순위를 따른다. 입력칸 위/아래 이동도 표시 순서를 따른다. 달력·간트의 순서는 바꾸지 않는다.

## 문서 탐색 요약

새 태스크 문서는 YAML `description`에 `태스크: 제목`을 자동 작성한다. 제목을 바꿀 때 기존 값이 자동 기본 설명과 같으면 함께 갱신하고, 사용자가 작성한 설명과 본문·다른 속성은 보존한다. 기존 외부 문서에 설명이 없다는 이유만으로 읽기·동기화 시 원문을 재작성하지 않는다. 상세 본문을 작성할 때 [문서 규칙](../README.md)에 따라 설명을 구체화하며 MOC 등록은 필요하지 않다.
