[ADR 0133](../history/decisions/0133-mew-browser-cache-budget-and-retention.md)

`@mew/ui/browser-storage`가 서버에서 재생성할 수 있는 localStorage 캐시의 공통 예산과 수명을 관리한다. 설정·열린 탭·분할·작성 중 초안은 캐시 정리 대상이 아니다. 인증 쿠키·다른 앱의 키·서버 세션·실제 파일도 지우지 않는다. 정리는 `localStorage.clear()`를 사용하지 않는다.

일반 내부 브라우저와 바로가기 UI는 제거했다. 이전 `mew:browser-shortcuts` 저장값은 읽거나 표시하지 않으며 일괄 삭제하지 않는다. localhost 앱의 저장 경계는 [포트 프리뷰](port-preview.md)가 소유한다.

기존 바로가기 호환 유틸리티를 직접 호출해도 저장값이 없거나 손상된 경우에는 빈 목록을 반환한다. 특정 개발 주소를 기본 항목으로 만들지 않으며 사용자가 저장한 유효한 목록과 정규화·저장 동작은 유지한다.

새 에이전트 전사와 대기 큐 스냅샷은 별도 IndexedDB에 저장한다. 계정 격리·4MiB/32MiB 예산·7일 수명·구간 동기화는 [대화 저장 계약](conversation-storage.md)을 따른다. 아래 2MiB 목표는 localStorage 재생성 캐시에 적용한다. 초안·설정 저장 위치는 유지한다.

파일 본문의 새 영구 캐시는 scoped IndexedDB `mew-file-content`에 비동기로 기록한다. DB별 2MiB·256항목, 계정/루트별 40항목과 기록 후 7일 수명을 적용하며 이 예산은 아래 localStorage 합계와 별개다. 기존 `mew:content:*`는 유효한 항목만 비동기로 이관하고 성공한 원본을 지운다. 메모리 캐시·조건부 본문 조회·권한 검사·이관 실패 시 동작은 [파일 본문 조회와 캐시 복원](file-loading.md)을 따른다.

## 데모의 메모리 저장소

`setBrowserStorageScope`의 선택 옵션으로 localStorage·sessionStorage용 `Storage` backend와 영속 캐시 사용 여부를 주입할 수 있다. 일반·P2P 접속은 기존 브라우저 저장소와 IndexedDB를 유지한다. [브라우저 데모](demo.md)는 전용 메모리 backend를 앱 import 전에 선택한다. `globalBrowserStorage`를 읽는 테마·글꼴·단축키, `scopedBrowserStorage`를 읽는 설정·초안·캐시, `globalSessionStorage`를 읽는 휴식 진행·창 식별자를 모두 실제 저장소와 분리한다. 공통 캐시 예산·정리도 선택한 backend만 사용한다.

데모는 `persistentCaches: false`로 파일 본문·에이전트 이력·예약 목록·레거시 스킨 IndexedDB를 열지 않는다. 초기화·새로고침 후 새 예제 상태로 시작하며 다른 접속의 키·DB를 지우지 않는다. `src/demo/storage.test.ts`와 실제 작업 화면 브라우저 검사가 격리를 확인한다.

## 계정 테마

선택한 테마와 커스텀 목록은 `DATA_DIR/user-ui-state.json`의 계정별 `theme`가 기준본이다. 같은 Mew 인스턴스의 계정에서 프로젝트·기기·접속 주소와 무관하게 공유한다. 로그인 사용자만 `GET /api/user-ui/theme`와 `PUT /api/user-ui/theme`를 사용하며, 소유 계정은 서버 세션에서 정한다. 요청의 계정 식별자는 사용하지 않는다. GET은 `{state: ThemeSettings | null}`, PUT은 `{state: ThemeSettings, initialize?: boolean}`을 받고 저장한 `{state}`를 돌려준다. 입력은 64KiB 이내로 제한하고 공용 팔레트 정규화를 거친다. 유효하지 않은 최상위 형식·팔레트·목록과 크기 초과는 400으로 거부하며 기존 저장값을 보존한다.

첫 조회가 비어 있을 때만 `initialize: true`로 브라우저의 기존 선택을 가져온다. 이 저장은 다른 기기가 먼저 만든 계정 테마를 덮어쓰지 않고 그 값을 반환한다. 이후에는 서버 조회가 항상 기존 브라우저 사본보다 우선한다. 명시적 선택·커스텀 추가·편집·삭제는 즉시 화면에 적용하고 기기 안에서 저장 요청을 직렬화한다. 기기 간 동시 변경은 서버가 마지막으로 저장한 전체 설정을 따른다. 늦은 조회·이전 저장 응답은 새 사용자 선택을 바꾸지 않으며, 저장 후 다시 조회해 다른 기기의 변경도 확인한다. 저장 실패는 토스트로 알리고 현재 선택과 미저장 변경을 유지해 다음 변경·복귀·재접속 때 재시도한다. 계정 전환·언마운트 뒤에는 이전 응답을 적용하지 않는다.

저장 후 기존 presence 소켓으로 같은 계정에만 내용 없는 `{type:'theme'}`를 보낸다. `usePresence`는 이를 `mew:theme-changed` 이벤트로 전달하고 `useAccountTheme`가 재조회한다. 화면이 보이는 상태로 복귀하거나 bfcache에서 복원될 때, 온라인 복귀·presence 재연결의 `mew:permissions-changed` 때도 조회한다. 조회 결과를 적용하는 것만으로 서버에 다시 쓰지 않는다.

브라우저의 계정별 사본은 scoped localStorage의 `mew:themes:<JSON 계정 ID>`에 둔다. P2P에서는 기존 계정·인스턴스 범위를 추가로 따른다. 전역 `mew:themes`·`mew:theme`는 인증 전 초기 화면용 사본이며 계정의 기준값이 아니다. 전역 `mew:themes:legacy-account`는 이전 브라우저 테마를 처음 이어받은 계정을 기억해 같은 브라우저의 다른 계정에 이관하지 않게 한다. 기존 모드·테마색 이관은 [테마 계약](ui-contracts.md#테마색과-파생-액센트)을 유지한다. 이 사본·이관 표시는 사용자 설정이므로 자동 캐시 정리 대상이 아니다. 브라우저 저장 실패는 서버 동기화를 막지 않는다. 언어·글꼴·Dock 등 다른 기기 설정은 기존 저장 범위를 유지한다. 데모의 계정 상태와 캐시는 메모리에만 저장한다.

검증은 `server/account-theme.test.ts`의 실제 HTTP·계정별 WebSocket·독립 Chromium 컨텍스트, `src/utils/account-theme.test.ts`의 이관·응답 경합·저장 실패·수명 검사를 사용한다. 선택 근거는 [ADR 0030](../decisions/0030-account-themes.md)에 기록한다.

## 브랜치 기능 설정의 미저장 초안

기능 패널의 미저장 제목·작업 내용·검증·포트·경로·사용자 판정과 편집 기준은 `sessionStorage`의 `mew:branch-feature-draft:<JSON 계정·프로젝트>`에 보관한다. `src/utils/branch-feature-draft.ts`가 `globalSessionStorage`를 사용하며 원격 접속에서는 `remoteStorageName`의 계정·인스턴스 접두사를 추가한다. 직접 접속은 브라우저 origin과 명시적 계정·프로젝트 키로 구분한다. 재생성 캐시 정리 대상이 아니며 다른 계정·프로젝트의 초안을 복원하지 않는다.

같은 탭에서 프로젝트를 전환했다 돌아오거나 새로고침하면 입력과 원래 브랜치·편집 기준을 복원한다. 서버 저장 성공 또는 명시적 초안 버리기에서 삭제한다. 탭 세션용이므로 다른 기기와 동기화하지 않으며 탭을 닫은 뒤 복구는 보장하지 않는다. 저장소 접근·쓰기·삭제가 실패하면 현재 페이지의 같은 범위 메모리에 최신 상태를 남긴다. 이 대체 상태는 페이지 새로고침 후 복구를 보장하지 않으며 삭제 실패로 오래된 저장값을 다시 적용하지 않는다. 복원 시 필드 형식·길이·판정·리비전을 검사하고 잘못된 값은 사용하지 않는다.

## DB 팝업의 표시 설정

독립 DB 팝업은 scoped localStorage `mew:db-layout:<DB UUID>`에 뷰 모드와 그룹·날짜 기준 열, 카드 표시 속성을 저장한다. 계정·인스턴스 범위를 따르는 사용자 설정이므로 재생성 캐시 정리 대상이 아니다. 문서 안 DB 참조는 해당 Markdown 노드에 표시 설정을 저장하며 팝업 취향과 섞지 않는다. 데이터와 표시 설정의 경계는 [DB 기능 계약](../features/문서%20데이터베이스/문서%20데이터베이스·전체%20목록.md#뷰-설정의-저장)을 따른다.

## 관리 대상과 예산

뮤펫 스킨 목록·이미지·프레임 수·이름은 서버 전역 `DATA_DIR/mewpet/skins/`의 파일이 기준본이다. 프로젝트·워크스페이스·계정·기기와 무관하게 같은 Mew 인스턴스의 API를 읽으며 P2P도 해당 인스턴스 서버 파일을 사용한다. 브라우저에는 선택 ID를 기존 scoped localStorage `mew:mewcat-skin`에 저장한다. 크기·숨김·선택은 브라우저별 취향으로 유지한다.

기존 scoped IndexedDB `mewcat-sprite-skins`는 이관 원본으로 보존한다. owner가 정상 스킨을 서버에 저장한 뒤 `mewpetImported`를 표시하며, 업로드 실패 시 원본을 유지하고 다음 조회에 재시도한다. 서버에 같은 ID가 이미 있으면 덮어쓰지 않고 이관 처리한다. owner 이외의 계정·이관 실패에서는 기존 로컬 이미지를 표시한다. 성공 뒤 전역에서 삭제한 항목은 원본으로 다시 등록하지 않는다. 이 원본과 선택·크기는 사용자 설정이라 캐시 자동 정리 대상이 아니다. [뮤펫 스킨 계약](../features/화면·계정·운영/Mewpet%20마스코트·알림·휴식.md#스킨-선택)이 이미지 검사·저장 실패·삭제·재생 규칙을 소유한다.

뮤펫의 일반 표시 크기는 scoped localStorage `mew:mewcat-size`에 숫자로 저장한다. 계정·인스턴스별 사용자 설정이며 자동 캐시 정리 대상이 아니다. 즉시 반영·새로고침 복원·기본값·범위·저장 실패 표시는 [뮤펫 표시 계약](../features/화면·계정·운영/Mewpet%20마스코트·알림·휴식.md#상세-동작)이 소유한다.

PDF 필기 초안은 `mew:pdf-draft:<계정>:<PDF URL>`에 원본 버전·벡터 스트로크를 저장한다. 본문 캐시가 아닌 미저장 작업이므로 자동 정리하지 않는다. 저장 실패 표시·복원 충돌·저장 성공 시 제거는 [PDF 계약](pdf-viewer.md#초안과-수명)을 따른다.

태스크 미저장 변경과 마지막 입력 초안은 `mew:task-draft:<계정>:<루트>:<창 ID>`에 공통 `writeBrowserStorage`로 보관하며 자동 정리 대상에서 제외한다. 다른 창의 보관값과 분리하고 서버 저장 성공 후 해당 변경만 정리한다. [태스크 수명·복구](task-list.md#클라이언트-수명과-오류)를 따른다.

| 종류 | 키 | 항목 상한 |
| --- | --- | --- |
| 레거시 파일 본문(새 쓰기 중단) | `mew:content:*` | 256KiB (유효한 항목은 IndexedDB로 이관) |
| 레거시 에이전트 전사(새 쓰기 중단) | `mew:agent-events:*` | 512KiB |
| 에이전트 모델·권한 표시 캐시 | `mew:agent-controls:*` | 32KiB |
| 폴더 자식 목록 | `mew:tree-children:*` | 256KiB |
| 전송 성공한 입력 기록 | `mew:agent-input-histories`, `mew:tmux-input-histories` | 각 128KiB의 최신 완전한 항목 |

- 모든 루트·계정·종류를 합친 localStorage 캐시 목표는 **2MiB**, origin 전체 사용량 목표는 **4MiB**다. 키·직렬화 값의 UTF-16 크기를 계산하고 최대 64KiB의 관리 메타데이터 공간을 예약한다. 브라우저별 실제 quota와 동일한 측정값은 아니다.
- 항목 수는 최대 256개, 마지막 기록 후 보관 기간은 **7일**이다. 캐시 합계가 넘으면 오래된 것부터 제거한다. 전송 기록은 탭당 최근 100개 안에서 완전한 문자열만 남기며, 16KiB를 넘는 단일 입력은 편의용 기록에서 제외한다. 전송 전 초안에는 이 제한을 적용하지 않는다.
- 새 캐시를 쓰기 **전** 공간을 확보한다. 큰 본문을 캐시하지 않아도 메모리의 편집 내용과 서버 파일은 유지된다. 교체할 본문이 상한을 넘으면 오래된 디스크 캐시는 제거해 이전 내용이 재등장하지 않게 한다.
- 중요한 상태·초안 저장이 실패하면 명시된 재생성 캐시만 정리한 뒤 한 번 재시도한다. 중요한 데이터 자체가 공간을 채우거나 브라우저가 저장을 금지하면 저장은 실패할 수 있으며, 이를 해결하려고 초안을 자르거나 지우지 않는다.

## 실행 시점

`src/main.tsx`에서 첫 React 렌더 전에 정리한다. 이후 **5분 간격**, `visibilitychange`(숨김·복귀), `pagehide` 때 검사한다. 종료 이벤트가 누락되거나 백그라운드 타이머가 늦어져도 다음 시작과 캐시 저장 시 다시 검사한다. 종료 시 무조건 전체 캐시를 지우지는 않아 재접속의 첫 화면 복원은 유지한다.

업데이트 첫 실행에서 날짜가 없는 옛 재생성 캐시는 제거한다. 기존 에이전트 전사는 `savedAt`이 유효하고 예산 안이면 남긴다. 관리 날짜 목록도 수·크기를 제한하고 실제로 남은 캐시에 대해서만 보관한다.

에이전트 탭의 명시적 닫기에서는 자식 컴포넌트의 마지막 flush가 끝난 뒤 **그 탭의 모든 런타임·cwd 전사와 컨트롤 캐시**를 지운다. 서버 계정 원장 조회 후 사라진 탭의 전사·컨트롤 캐시도 기존 정리 경로를 사용한다. 초안 삭제는 기존의 명시적 탭 종료·전송 동작에서만 수행하며, 나이가 많거나 원장에 없다는 이유로 자동 삭제하지 않는다.

## 탐색기 복원과 가상 행

트리 계정 상태는 전체 열린 폴더 목록·하위 목록 캐시·픽셀 scrollTop과 `{tree,path,fraction}` 중앙 앵커를 저장한다. 렌더링 범위나 DOM 행은 저장하지 않는다. 가상화로 앵커 행이 아직 없으면 `mew:tree-materialize`로 같은 tree 키의 목록을 찾아 해당 행을 생성·중앙 정렬한 뒤 기존 행 기반 복원을 계속한다. 파일 탭 위치 표시도 같은 경로를 사용하며 사용자 스크롤·키 입력은 기존 복원 중단 규칙을 따른다. `server/explorer-performance-ui.test.ts`가 1,000항목의 화면 밖 중앙 앵커와 탭 위치 표시를 확인한다.

## 원격 로컬 계정 접속의 저장소 범위

내부 앱 origin의 P2P bootstrap은 Workspace App을 import하기 전에 부모의 연결된 MessagePort에서 instance ID와 현재 인증 결과를 받아 저장소 범위를 정한다. 인증 결과가 없으면 P2P `/api/auth/me`로 확인하며, 경량 인증 진입점 다운로드는 이 준비와 겹친다. 현재 인증 결과를 영속 저장하지 않는다. 연결의 난수 subject나 중앙 계정 ID는 데이터 범위가 아니다. localStorage의 물리 키와 IndexedDB 이름은 로컬 사용자 ID와 instance ID를 포함하며 미인증 상태는 별도 범위다. 기존 이메일 사용자는 이메일 ID를 그대로 쓰고 비밀번호 없는 사용자는 별도 불변 ID를 쓴다. 같은 로컬 사용자에 연결한 비밀번호·Mewlink 로그인은 같은 개인 저장소를 사용한다. 로그인·로그아웃·계정 전환 때 기존 작업과 화면을 정리하고 앱 프레임을 다시 시작해 다른 계정의 모듈 캐시·React 상태를 이어 쓰지 않는다. 범위가 바뀌면 열린 IndexedDB 연결을 닫고 새 범위의 DB를 연다. 일반 로컬 접속은 기존 키와 DB 이름을 사용한다. 계정 본문과 별개인 설치 정적 코드 사본은 [P2P 해시 재검증 캐시](remote-access.md#정적-자원-압축과-재검증-캐시)를 따른다.

중앙 런처는 **이 브라우저에서 로그인 유지 → 기억하기**에 동의한 기기의 신뢰 세션 토큰을 중앙 origin의 기기별 localStorage에 저장한다. 새 `x-mew-session`은 먼저 sessionStorage에 보관하면서 이전 영속 토큰을 제거하고, `/api/auth/me`의 `trustedDevice` 확인 또는 중앙 부모의 신뢰 요청 성공 뒤에만 localStorage로 승격한다. 동의 전 일반 세션은 sessionStorage에 남으며 기존 localStorage의 30일 토큰은 호환 재개를 유지한다. 신뢰 세션은 로컬 비밀번호 또는 승인된 외부 로그인으로 발급하되 현재 계정·인증 수단·자격증명 ID와 브라우저 키에 결합하고 90일 미사용 시 만료한다. 재개할 때 즉시 연장하며 열린 연결의 유효한 세션 검사에서도 하루 최대 한 번 연장한다. 신뢰 등록은 이전 bearer 세션을 폐기한다.

브라우저 신원용 Ed25519 CryptoKeyPair는 중앙 origin의 IndexedDB에 호스트 instance별로 생성해 저장한다. private key는 비추출이며 같은 호스트의 브라우저 탭은 키를 공유한다. 다른 호스트에는 별도 키를 사용해 방문 상관관계를 줄인다. 저장을 사용할 수 없으면 메모리 비추출 키로 연결하므로 다음 방문의 키 보존은 보장하지 않는다. 키와 토큰은 재생성 캐시 정리 대상이 아니다. 내부 앱 origin은 중앙 저장소를 읽을 수 없으며, 정확한 launch 프레임에 제공하는 앱 전송에도 private key·세션 토큰·중앙 cookie·launch 증명을 포함하지 않는다. 앱 브리지는 `/api/auth/remote-device`를 거부해 중앙 부모의 동의를 우회하지 못하게 하며 `x-mew-session`은 저장 후 앱 응답 헤더에서 제거한다. 비밀번호는 저장하지 않는다.

다음 연결의 첫 transport 인증 메시지에서 저장 세션을 재개하고 서버측 세션·계정·자격증명·키 지문을 재검증한다. 신뢰한 외부 세션은 중앙 cookie가 만료돼도 호스트의 승인 연결과 키가 유효하면 재개한다. 동의 전 일반 외부 로그인은 비밀번호 세션 토큰을 만들지 않고 중앙 세션 수명을 검사한다. 명시적 외부 로그인은 기존 로컬 세션 재개를 생략한다. 로그아웃·`access-revoked`·명시적 인증 거부는 해당 기기의 저장 토큰을 제거하고 자동 재시도를 멈춘다. 키는 회수 식별을 유지하도록 보존하며 다른 호스트의 키·토큰은 건드리지 않는다. IndexedDB 삭제·브라우저 데이터 제거로 키를 잃으면 토큰만으로 재개하지 못하며 다시 인증해야 한다.

일시적인 연결 종료의 자동 복구에서는 기존 앱 iframe과 미저장 입력을 유지한다. 새 연결의 같은 로컬 계정·인증 수단을 확인한 뒤 전송을 바꾸고, 계정·인증 수단이 다르면 기존 범위를 정리해 앱 프레임을 다시 시작한다. 이전 연결의 진행 중 요청은 취소하며 저장·명령을 재실행하지 않는다. 최초 로그인·로그아웃·명시적 계정 전환의 프레임 재시작 규칙은 유지한다. [브라우저 신뢰 결정](../decisions/0015-trusted-browser-access.md)과 [연결 수명](remote-access.md#연결-인증과-회수)을 따른다.

캐시 2MiB·origin 전체 4MiB 예산은 모든 원격 범위를 합산한다. 범위 접두사를 제거한 논리 키로 재생성 캐시를 판별하며, 범위별 기록 시각을 공통 정리 원장에 합쳐 오래된 캐시만 지운다. 여러 A에 접속해도 예산이 A마다 늘어나지 않는다. 연결 종료 시 현재 범위의 localStorage 재생성 본문·전사·입력 기록을 정리하며, 미전송 에이전트·터미널 초안, PDF 필기 초안, 열린 탭·설정은 보존한다. 자세한 연결 수명은 [계정 기반 원격 접속](remote-access.md)을 따른다.
