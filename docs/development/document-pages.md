## 저장 구조

자식 없는 문서는 `name.md`로 저장한다. 첫 하위 문서를 만들거나 이동해 넣으면 `name/`를 만들고 기존 본문을 `name/_name.md`로 옮긴다. `name/child.md`도 자식을 가질 수 있으므로 같은 규칙을 재귀적으로 적용한다. 대표 파일을 제외한 마지막 자식이 삭제되거나 다른 곳으로 이동하면 `name.md`로 돌아간다. 첨부 파일·숨김 파일도 실제 자식으로 세어 내용이 남은 폴더를 지우지 않는다. Docs 루트는 단일 파일로 전환하지 않는다.

상위 문서의 이름을 바꾸면 폴더와 대표 파일을 함께 바꾼다. `dev/_dev.md` → `development/_development.md`가 된다. 하위 문서와 본문은 보존한다. 같은 이름의 단일 문서와 폴더가 있으면 충돌로 거절하며 덮어쓰지 않는다.

기존 `MOC.md`·`_MOC.md`도 해당 폴더의 대표로 읽는다. 열기만으로 파일을 이동하지 않는다. 그 폴더의 하위 문서 생성·이름 변경·이동 때 대표 이름을 `_폴더이름.md`로 바꾼다. 실제 프로젝트 문서의 일괄 이전과 `archives/` 변경은 수행하지 않는다. Docs 루트의 기존 MOC는 **문서 홈**으로 유지한다. 대표가 없는 기존 폴더는 이름 클릭으로 하위를 펼치며, 첫 하위 문서 생성 때 대표를 만든다.

사용자에게 보이는 문서명은 파일 경로보다 대표 문서의 제목을 우선한다. 문서 파일·폴더명에는 자연어, 공백, 대문자, 한글을 사용할 수 있고, 예약 진입 파일명은 유지한다. 대표 문서의 frontmatter `title`과 첫 제목은 `문서 홈`, `개발 계약 홈`처럼 자연어로 쓴다. 기존 MOC는 목록을 나열하는 파일이 아니라 해당 상위 문서의 첫 화면 역할을 한다.

## 탐색·편집

- 하위 항목이 없는 문서는 꺾쇠 자리(기존 20px 열)에 4px 불렛을 표시한다. 단일 문서와, 조회 후 대표·MOC를 제외한 하위 항목이 없는 폴더에 적용한다. 조회하지 않은 폴더는 지연 로딩을 위해 기존 꺾쇠를 유지한다. 불렛은 `aria-hidden` 장식이며 기존 문서 열기·하위 추가를 유지한다.
- `FileTree.documentPages`가 Docs 목록을 상위·하위 문서로 표시한다. 일반 파일 보기는 기존 탐색을 유지한다.
- 이름과 화살표의 하위 목록 조회는 폴더별 캐시·Promise를 공유하며, 재검증 중 기존 행을 유지한다. 200개 이상의 연속 파일·닫힌 폴더는 화면 주변 행을 렌더링하되 펼친 상위 문서·대표 본문 판별은 유지한다. 상세 기준은 [파일·폴더 탐색](../features/프로젝트·파일·검색/파일·폴더%20탐색과%20조작.md#구현-내용)을 따른다.
- 상위 문서의 이름을 클릭하면 대표 본문을 연다. 화살표는 하위 목록만 펼치고 접는다. 대표 파일은 그 목록에서 숨긴다. 문서명과 에디터 탭 이름에는 `.md`와 대표 파일의 밑줄을 표시하지 않는다.
- Documents 트리와 에디터 탭은 저장 경로의 slug를 표시용 자연어 이름으로 바꾼다. 예를 들어 `document-pages.md`는 `Document Pages`, `api-reference.md`는 `API Reference`로 표시한다. 자연어 이름의 대소문자와 공백은 그대로 표시한다. 실제 저장 경로와 링크 대상은 바꾸지 않는다.
- 일반 클릭은 포커스된 편집 칸의 현재 탭을 바꾼다. Ctrl/Cmd+클릭은 새 탭을 유지하고, 이미 열린 문서는 해당 탭을 활성화한다. 저장되지 않은 현재 본문은 보존한다.
- 각 문서의 **+**는 하위 문서 이름을 입력한다. 상단 **새 문서**도 선택한 문서를 부모로 사용하며 선택이 없으면 Docs 루트에 만든다. 이름에서 `.md`를 생략할 수 있다. Docs에는 새 폴더 버튼을 별도로 두지 않는다.
- 프로젝트 안의 편집 가능한 Markdown은 Hotview의 `/page`에서 **하위 페이지**를 선택하면 이름 입력창을 먼저 연다. 이름을 입력하고 만들기를 누르면 하위 문서를 생성하고 부모 문서에 머무른다. 새 문서는 목록이나 링크를 눌러 연다. 빈 이름은 제출할 수 없으며 취소하면 생성하지 않는다. 이름 입력 중 다른 문서로 이동해도 생성하지 않는다. 같은 이름의 파일·상위 문서가 있으면 입력한 이름 뒤에 2부터 빈 번호를 붙인다. Documents의 **+**와 같은 구조 변경 엔진으로 `abc.md` → `abc/_abc.md` 전환·링크 보정·초안 저장·열린 탭 갱신을 처리한다. 기존 대표 문서에서는 같은 폴더에 형제를 만들고 새 하위 페이지에서도 다시 중첩 생성할 수 있다. `/page` 명령 문자열은 생성 전 본문에서 제거한다. 게스트·읽기 전용 문서·archives·프로젝트 밖 파일에는 명령을 제공하지 않는다.
- 하위 문서를 페이지에 드롭하거나 잘라내기·복사 붙여넣기로 옮길 수 있다. 목적지가 단일 문서라면 상위 문서로 전환한다. 폴더 복제 시 복제본 대표 이름도 새 폴더 이름과 맞춘다.
- Docs 루트의 **그래프 보기**는 문서 홈 위에 한 번 표시한다. 그래프의 연결은 실제 본문 하이퍼링크를 사용하며 폴더 포함 관계를 링크로 대신 만들지 않는다.

## 변경 처리

`shared/document-pages.ts`는 대표 판별, 경로 매핑, 링크 보정을 공유한다. 상대 Markdown·참조형·위키 링크와 이미지 경로를 새 위치에 맞추며 외부 URL·앵커·본문 라벨·코드·frontmatter를 보존한다. 편집 가능한 current 문서만 갱신하고, 읽기 전용 문서와 archives 본문은 고치지 않는다. 이 범위 밖의 링크는 외부 문서 이전 작업에서 별도로 확인해야 한다.

`server/document-pages.ts`는 충돌·경로 이탈·권한을 먼저 검사한다. 변경은 동기 작업 한 묶음으로 실행하고 실패하면 경로·본문·생성을 되돌린다. 삭제 대상은 같은 파일시스템의 임시 위치에 보관했다가 성공 후 지운다. 프로세스 중단 중 자동 복구를 제공하는 영구 트랜잭션은 아니다.

`POST /api/docs/pages/{create,rename,delete,move,copy}`는 로그인·`filesWrite`와 원본/목적지 파일 권한을 확인한다. 재귀 조작에는 모든 자식의 편집 권한이 필요하다. 입력은 `{path,name?,destination?,project?,unique?}`, 응답은 `{path,moves,changed,removed?}`다. `project`의 기본값은 `docs`이며 일반 프로젝트의 Markdown도 같은 엔진을 사용한다. `unique: true`는 생성 때 이름 충돌을 번호로 피하며 기본값 `false`는 기존 **+**의 충돌 거절을 유지한다. 구조 변경은 자동 Git 커밋을 만들지 않는다. 캐시·검색·감시 목록은 변경 경로의 살아 있는 부모부터 갱신한다.

`useTabs.prepareDocumentPageMutation`은 진행 중 저장을 기다리고 대상 프로젝트의 초안을 저장한다. 기본 대상은 Docs다. 구조 변경 중 대상 프로젝트의 추가 자동저장은 잠시 보류한다. 성공 응답을 받은 `applyDocumentPageMutation`은 모든 편집 칸의 해당 프로젝트 경로·본문 링크·저장 기준을 보정하고 새 경로로 다시 읽는다. 변경 중 쓴 본문은 유지하고 새 경로에 자동저장한다. 다른 프로젝트 탭과 분할 배치는 유지한다. `createChildPage`는 이 준비·적용 흐름과 생성 API를 묶으며 새 탭을 열거나 활성 문서를 바꾸지 않는다. 응답 전에 작업 폴더를 전환하면 이전 응답을 새 폴더의 탭에 적용하지 않는다. 다른 접속자의 기존 탭에 경로 이전을 전송하는 별도 협업 프로토콜은 추가하지 않았다.

자연어 경로의 링크는 공백·한글·괄호·`#`·`?`를 URL 인코딩한다. 공용 문서 검사는 인코딩된 링크와 `<공백 있는 경로>`를 읽으며, `MOC.md`·`_MOC.md` 외에 `_폴더이름.md` 대표 문서도 지도 체인으로 따라간다.

## 데이터베이스 행 하위페이지

[행 페이지 결정](../decisions/0012-database-row-pages.md)과 [표 데이터베이스 사용법](../guides/database.md)을 따른다. 대표열을 페이지로 바꾸면 DB를 넣은 문서의 바로 하위에 `<대표열 값>.md`를 만든다. `Books/_Books.md`에 있는 DB의 `송상훈` 행은 `Books/송상훈.md`로 저장한다. 원본이 `Books.md` 단일 문서이면 일반 하위 문서와 같이 `Books/_Books.md`로 전환한다. 별도의 `데이터베이스` 문서나 DB UUID 폴더는 만들지 않는다. 소유 문서가 없는 DB는 프로젝트 루트에 만든다.

파일명에는 한글·공백을 유지하고 경로 구분자·운영체제 예약 문자는 공백으로 바꾼다. 숨김·대표·예약 이름은 접두어로 피하며 긴 이름은 줄인다. 같은 이름의 파일·폴더가 있으면 2부터 번호를 붙이고 덮어쓰지 않는다. 행 UUID와 DB UUID는 프론트매터와 DB 연결 정보에 유지한다. 기존 경로는 생성 뒤 제목을 수정해도 유지하며, 프론트매터 `title`과 DB 대표열 값은 계속 동기화한다. 직접 옮긴 페이지의 경로도 보존한다.

기존 `데이터베이스/<DB UUID>/<행 UUID>.md`는 다음 일반 DB 조회·편집 때 원본 문서 아래 이름 기반 경로로 옮긴다. 본문·사용자 속성·행 연결을 보존하며 문서 링크와 DB 경로를 함께 보정한다. 소유 경로가 없거나 사라졌으면 동일 DB를 담은 원본 문서가 하나일 때만 복구한다. 비어 있는 자동 생성 DB 대표 파일과 빈 폴더만 정리하고, 추가 본문이나 다른 파일이 있으면 남긴다. 행 페이지 자동저장 중에는 경로 이관을 미뤄 저장 요청의 원래 경로를 보존한다.

DB REST 응답은 경로 변경이 있으면 `documentPageMutations`를 함께 반환한다. 호스트 DB API는 요청 전 프로젝트 초안을 저장하고 자동저장을 보류하며, 성공 응답의 변경을 `applyDocumentPageMutation`으로 열린 탭에 적용한 뒤 자동저장을 재개한다. 대기 중 작업 폴더가 바뀌면 해당 요청을 실행하지 않고, 이미 진행 중이던 응답도 새 폴더의 탭에 적용하지 않는다. 문서 생성 뒤 일반 문서 조작으로 DB 소유 문서를 옮길 때도 `owner_path`를 갱신한다.

프론트매터 `title`은 대표열과 공유하고 나머지 열은 표시명을 필드명으로 사용한다. 숫자·불리언·다중선택은 YAML 숫자·불리언·문자열 배열로 저장한다. 선택 타입과 선택지는 기존 `mew:field` 주석으로 Hotview 속성 편집기에 전달하며 일반 문서의 같은 이름 필드와 선택지를 섞지 않는다. `_mew_database`·`_mew_row`는 연결 식별자이며 속성 화면에서 숨긴다. `상위파일`은 DB 폴더 대표를 가리킨다. `description`은 기본 제목으로 시작한다. `created`·`updated`를 강제로 생성하지 않으며, DB 페이지에서는 본문 편집으로 기존 `updated`도 자동 갱신하지 않는다.

`server/db/rowPages.ts`는 `mew.row_pages`의 경로와 마지막 공유 값·열 이름을 비교해 프론트매터에서 바뀐 필드만 DB에 반영한다. DB 변경은 해당 필드를 다시 파일에 쓰고 본문·그 외 속성을 보존한다. 열 이름을 바꾸면 이전 프론트매터 키를 정리한다. 변경할 모든 값을 검증하고 DB 트랜잭션이 실패하면 먼저 쓴 파일도 되돌린다. 이 복구는 실행 중 예외를 다루며 프로세스 강제 종료를 복구하는 영구 파일 트랜잭션은 아니다.

`server/db/rowPageIntegration.ts`는 파일 자동저장과 외부 파일 감시를 연결한다. 파일 저장에도 DB 기능과 프로젝트 전체 수정 권한이 필요하다. 저장 기준인 `expectedContent`와 비교해 본문만 수정한 오래된 초안이 최신 공유 필드를 덮어쓰지 않게 하고, 같은 필드를 서로 다르게 고쳤으면 저장을 거절한다. 일반 문서 저장·이동은 Postgres의 가용성에 의존하지 않는다. 문서 이동 때 연결 경로를 보정하고, 기록한 파일이 없으면 프로젝트 안에서 두 연결 UUID가 일치하는 문서를 찾아 복구한다. 심볼릭 링크·숨김 폴더·archives·접근 차단 폴더는 이 복구 탐색에서 제외하며 같은 행의 후보가 여러 개면 자동으로 고르지 않는다.

페이지에서 텍스트로 돌아가도 연결 경로를 보관하되 필드 동기화를 중단한다. 다시 페이지로 바꾸면 같은 행의 파일과 본문을 재사용한다. 행이나 DB를 삭제해도 생성했던 페이지 본문을 자동 삭제하지 않는다. Markdown만으로 DB 정의·옵션·전체 행을 복구할 수 없으므로 Postgres와 파일을 함께 백업한다.

활성 편집 칸에서 연 행 페이지는 해당 DB 행·스키마 이벤트를 구독해 파일을 다시 읽는다. 저장하지 않은 수정이 없는 탭은 최신 프론트매터를 즉시 표시하고, 수정 중인 초안은 보존한 뒤 저장 시 공유 필드를 병합한다. 열 타입은 숫자·선택·다중선택 등 기존 속성 편집기로 표시하며, 하위페이지 Hotview에서 저장한 숫자·배열·빈 값도 YAML 숫자·배열·`null`을 유지한다.

## description 탐색과 신규 파일

AI는 [문서 규칙](../README.md)에 따라 경로·description으로 문서를 선택한다. 기존 MOC는 화면 대표와 링크 호환 용도로 유지하며 새 Markdown 파일 생성은 MOC 링크를 추가하지 않는다. 기본 Documents 문서는 제목 기반 description을 생성하고 작성자가 본문 범위에 맞춰 구체화한다. 파일 단위 커밋은 요청한 파일만 포함하며 다른 변경 MOC를 자동 포함하지 않는다.
