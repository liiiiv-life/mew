# 원격 데스크톱 화면·설정·핫키·연결 시작 개선

[작업 지도](MOC.md) · [기능](../features/remote/desktop.md) · [사용법](../guides/remote-desktop.md) · [개발 계약](../development/remote-desktop.md)

## 목표와 구현 순서

1. 기존 원격 데스크톱 전용 화면과 입력 해제 계약을 유지하면서 상단에 전체화면·90도 회전·설정 진입점을 추가한다.
2. 마우스 커서 기본 감도를 이전의 3배로 높이고, 설정에서 0.5–6배로 조절·저장한다. 직접 클릭 좌표와 wheel·pan·zoom 이득은 유지한다.
3. 왼쪽에 세로 핫키 바를 두고 마우스와 같은 핸들 이동·키보드 이동·화면 경계 제한·초기화를 제공한다.
4. 회전 후 영상·로컬 커서·직접 클릭·조이스틱 이동이 같은 좌표계를 쓰도록 공통 기하 함수를 적용한다.
5. 연결 시작의 동기 진단·중복 경로 탐색을 줄이고, 첫 영상이 없는 직접 경로에서 서버 전송으로 빠르게 넘어간다.
6. 합성 화면의 Chromium 통합 검증, 입력/좌표/서버 단위 테스트, 타입·린트와 문서 검사를 수행한다. 실제 서버 반영은 사용자가 한다.

## 반영 범위

- 기존 팔레트·마우스 모양·독립 전체 화면 portal을 유지한다. 설정은 감도·화면 선택·Ctrl/Cmd·위치 초기화·재연결을 소유한다. 핫키는 원격 Esc/Tab/Enter/Backspace/복사/붙여넣기/실행 취소/앱 전환을 제공한다.
- 감도는 브라우저 localStorage에만 저장한다. 회전·확대·핫키 보조키·컨트롤 위치는 현재 뷰어의 상태다. 원격 모니터의 OS 회전 설정은 바꾸지 않는다.
- WSL 방화벽 진단은 helper 실행 후 비동기로 진행한다. 준비 상태와 spawn에서 사용하는 실행 경로 탐색은 30초 동안 합치며, readiness·설치 버전·권한은 계속 검사한다. 두 경로 변환은 병렬 실행한다.
- 직접 연결 우선과 동일 캡처의 서버 fallback을 유지한다. offer 이후 첫 디코드 확인 대기를 4초에서 1.2초로 줄인다. 느리게 성립하는 직접 경로는 서버 전송으로 넘어갈 수 있으며, 실제 성능은 경로별로 다르다.
- 외부 서비스·상주 캡처·로그인 자동 실행·새 공개 포트를 추가하지 않는다. 기존 ADR 0139/0144/0154 범위 안의 UI·이득·시작 지연 개선이며 기존 결정 대체는 없다.

## 검증과 남은 실기 확인

- Chromium 통합 4개 시나리오(직접, 서버, native stream 모사 서버, native stream 모사 직접) 통과. 실제 WebRTC와 VP8 인코더/디코더를 쓰며 화면은 합성 canvas다.
- 3배/1배 감도, 회전 후 클릭 위치와 이동 방향, 전체화면 진입/해제, 핫키 순서·키 해제, 핫키 핸들 이동, 설정 우선 Escape·연속 뒤로가기·같은 영상 track의 해상도 변경 후 클릭 좌표, 320px 폭·390px 높이 가로 화면 경계, 설치 팝업·재접속·백그라운드 종료를 확인했다.
- 직접 경로를 막은 두 합성 시나리오의 offer→서버 전송 요청은 약 1.20초였다. 예전 고정 대기 4초에 비해 약 2.8초 줄인 구간이며, 전체 클릭→첫 화면 시간이나 실사용 망 측정은 아니다.
- 좌표 변환·입력·준비·권한/lease·경로 캐시·방화벽 진단 등 원격 데스크톱 비 UI 테스트 58개 통과, 실제 OS opt-in 3개는 미실행했다. 타입 검사와 린트는 통과했으며 린트에는 변경 범위 밖의 기존 경고가 남는다.
- 시각 검증은 기존 토큰을 사용한 모바일·데스크톱·설정 화면을 확인했다. 직접 video에 적용되던 전역 max-width가 회전된 크기를 제한하는 결함은 수정하고 4개 시나리오를 재검증했다.
- Windows/Mac 실제 cold start, 실제 외부 모바일 망, iOS Safari 전체화면·OS별 키 조합은 별도 실기 확인이 필요하다. 최초 설치·권한 승인·로그인 helper cold start는 남아 있으며 다른 원격 앱과 동등한 즉시 연결을 보장하지 않는다.
- 워크스페이스 문서 경계·링크 검사와 diff 공백 검사가 통과했다. 운영 서버 빌드·재시작·배포는 실행하지 않았다.


## 후속 개선 — 속도 비례 커서 가속

사용자 요청에 따라 같은 거리라도 빠르게 밀수록 커서 이동량이 비례해서 늘어난다. 커서/세 버튼 드래그에만 적용하며 정지 시 이동하지 않는 ADR 0154의 계약을 유지한다. 기준 속도·상한·타임스탬프·감도 결합의 기준본은 [입력과 권한](../development/remote-desktop.md#입력과-권한)이다.

100px/50ms와 100px/500ms의 10배 차이, 표본 분할 1/10/100개에서 동일한 거리, 느린 역방향 전환, 정지·새 스트로크·동일/역행 timestamp·취소를 검증했다. 입력·좌표 단위 테스트 24개와 Chromium 직접/서버/native 모사 4개 시나리오가 통과했다. 브라우저에서는 원격 상대 이동의 기존 패킷당 안전 상한 안에서 감도 1배의 200px/2000px 이동을 확인하고, 기준 속도에서 감도 1배/3배도 확인했다. 타입·변경 파일 린트·문서 검사가 통과했다. 빌드·재시작은 실행하지 않았다.

## 후속 개선 — 패널 전체 회전

회전 버튼은 영상뿐 아니라 마우스·핫키·도구 모음·설정·독을 포함한 패널 전체를 회전한다. 레이아웃·입력 좌표와 메뉴 배치의 기준본은 [뷰어 설정과 좌표](../development/remote-desktop.md#뷰어-설정과-좌표)다.

합성 WebRTC 영상의 Chromium 직접·native-direct 두 시나리오에서 네 방향의 컨트롤 경계·핸들 이동·회전된 설정 메뉴 선택과 기존 회전 클릭·조이스틱 방향·전체화면·재접속을 확인했다. 입력·좌표 단위 검사와 함께 31개 테스트가 통과했다. 실제 Windows·모바일 기기 확인은 별도이며 운영 빌드·재시작은 실행하지 않았다.
