# mew 배포 준비·보안·사용성 검토

[진행 작업 지도](MOC.md) · [기능 안내](../../README.md) · [배포 계약](../deployment/native.md)

상태: **검토·제안**. 현재 동작과 개선안을 구분한 문서이며 구현 완료나 새 정책 채택을 뜻하지 않는다. 기준은 `80c126b`와 검토 당시 작업 트리다. 기존 작업 중인 원격 데스크톱·Git·에이전트 변경도 포함했다.

## 판단과 범위

개인 또는 신뢰하는 소규모 팀이 직접 운영하는 편집기로서 기능 구성은 충분하다. 다만 새 설치의 재현성, 업로드 실행 경계, 실패 후 복구, 문서와 실제 기능의 일치가 부족해 **현재 상태를 그대로 일반 사용자에게 배포 가능한 완성본으로 안내하기는 이르다**.

불특정 다수·다중 테넌트는 기존 [지원 범위](../deployment/native.md#배포-경로와-전제) 밖이다. manager·owner의 셸 권한, member의 광범위한 파일 접근, 서버 공용 CLI 자격증명은 의도된 현재 계약이다. 앱의 역할 제한만으로 OS 격리를 보장한다고 설명하면 안 된다.

검토는 문서·현재 소스·격리 재현 중심이다. 실제 공개 서버, 로그인 세션, 사용자 파일, crontab은 변경하지 않았다. 새 OS 설치·실제 공급자 로그인·전체 UI·외부 네트워크·실물 원격 데스크톱은 이번에 검증하지 않았다. 시각 디자인 점수나 접근성 준수 판정은 포함하지 않는다.

## 유지할 장점

- 네이티브 설치·loopback 기본 바인딩·전용 OS 사용자·HTTPS·systemd를 하나의 배포 문서로 안내한다.
- 설정·상태·작업물·Postgres의 저장 경계를 구분하고, 앱 삭제와 사용자 데이터 삭제를 분리한다.
- 파일 자동저장과 커밋, 탭 종료와 패널 닫기, 예약 메시지와 독립 예약 작업을 구분했다.
- 런타임 등록표, 계정별 UI 복원, 권한 미들웨어, 선택적 브라우저·DB·데스크톱 등 공통 계약이 존재한다.
- 기능별 단위·통합 테스트가 있으며 게스트 접근·경로 검증·명령 인자·네이티브 입력의 검증 근거도 있다. 단, 테스트 존재나 일부 통과가 배포 전체의 안전성을 보장하지는 않는다.

## 배포 전에 우선 처리할 항목

P1은 대상 환경에 공개·확대하기 전 해결할 항목, P2는 운영·사용성 개선이다. 심각도는 이번 배포 검토의 우선순위이며 CVSS 점수가 아니다.

### P1 — 업로드 파일이 앱과 같은 출처에서 스크립트를 실행할 수 있음

**현재 근거:** [localAssets.ts](../../server/localAssets.ts)의 `safeExtension`은 확장자가 영숫자인지만 검사하여 `.html`·`.js`를 보존한다. [api.ts](../../server/api.ts)의 `/upload`는 로그인 사용자에게 열려 있고 `/asset`은 UUID 경로를 인증 없이 `sendFile`로 제공한다. [serve.ts](../../server/serve.ts)의 `script-src 'self'`는 같은 출처의 업로드 JS도 허용한다.

**재현:** 임시 프로젝트에서 실제 asset 저장 함수·API와 프로덕션 CSP를 적용한 격리 HTTP fixture를 사용했다. HTML 응답은 인증 없이 200, `Content-Type: text/html`, `Content-Disposition` 없음이었고, Chromium에서 그 HTML이 참조한 업로드 JS의 무해한 DOM 표식 변경이 실행됐다. 실제 사용자 API 호출·자격증명 탈취는 수행하지 않았다.

**영향:** 업로드 권한이 있는 계정이 파일을 올리고 다른 로그인 사용자가 그 URL을 열면, 그 사용자의 앱 출처에서 코드가 실행될 수 있다. HttpOnly는 쿠키 문자열 읽기를 제한하지만 해당 출처에서의 인증된 요청 자체를 막지 않는다. UUID는 경로 추측 방지이며 콘텐츠 실행 격리가 아니다.

**개선:** 본문 미디어의 인라인 허용 형식을 명시하고 HTML·JS 등 실행 가능한 파일은 다운로드로 제공한다. 렌더링이 필요한 비신뢰 문서는 쿠키를 공유하지 않는 별도 출처 또는 적절한 sandbox로 격리한다. CSP는 asset과 앱 문서에 목적별로 적용한다. [OWASP 업로드 지침](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)의 형식 검증·저장 및 제공 경계와 함께 검토한다.

**완료 기준:** 허용 이미지·문서 다운로드는 유지되며, HTML·JS·SVG 등 실행 가능한 조합이 앱 출처의 권한으로 코드를 실행하지 못하는 실제 브라우저 회귀 테스트가 통과한다.

### P1 — 설정 파일의 파싱·우선순위가 실행 방식마다 다름

**현재 근거:** [mew](../../mew)의 `set_config`는 값을 인용하지 않고 기록하고 `load_config`는 파일을 셸의 `source`로 실행한다. [server/config.ts](../../server/config.ts)는 `process.loadEnvFile`을 쓴다. [환경변수 문서](../configuration/environment.md)는 레포 `.env`가 앞선 설정을 덮는다고 설명한다.

**재현:** Node 22.22.2에서 같은 키를 두 파일로 차례로 읽으면 첫 값이 유지됐다. `/tmp/folder with spaces`라는 무해한 경로를 같은 형식으로 저장하면 Node는 읽지만 Bash는 `with: command not found`, 종료 코드 127로 실패했다. 설정을 셸로 실행하므로 `$` 등 특수문자도 단순 문자열과 다르게 처리될 수 있다.

**개선:** CLI·서버가 같은 dotenv 파서와 명시적 우선순위를 사용하고 설정 파일을 실행하지 않도록 한다. `status`에는 비밀값을 출력하지 않고 설정 출처·검증 결과만 보여준다.

**완료 기준:** 공백·한글·특수문자 경로, 환경변수·XDG 설정·레포 `.env`의 충돌, CLI·직접 Node·systemd 실행에 대해 값이 동일하고 문서와 일치한다.

### P1 — 업데이트 실패 시 이전 정상 설치를 보장하지 않음

**현재 근거:** [mew](../../mew)의 `cmd_update`는 현재 설치 경로에서 pull → `npm ci` → build → stop/start를 수행한다. [배포 문서](../deployment/native.md)는 `dist/` 변경이 실행 중인 화면에도 반영됨을 명시한다. 시작 확인은 PID 생존 확인이며 기능 준비 완료 검사가 아니다.

**영향:** 의존성 교체·빌드 중 실패하면 실행 프로세스와 디스크 산물이 달라질 수 있다. 새 서버가 시작하지 못할 때 이전 설치를 자동 복원하는 경로도 없다. [App.tsx](../../src/App.tsx)의 업데이트 폴링은 연결 실패를 계속 재시도로 처리하므로 복구 안내 없이 기다릴 수 있다.

**개선:** 별도 릴리스 디렉터리에서 의존성·빌드·검증 후 전환하고 이전 릴리스를 유지한다. 준비 상태 확인 실패 시 복귀하며 UI에는 시간 제한·실패 단계·로그·수동 복구 경로를 제공한다. 네이티브 배포 범위 안에서 설계할 수 있고 Docker 재도입은 필요하지 않다.

**완료 기준:** 설치 실패·빌드 실패·포트 충돌·새 프로세스 즉시 종료를 주입해도 이전 정상 버전으로 복구할 수 있다. 사용자 데이터의 복구 가능성은 별도 백업으로 검증한다.

### P1 — 치명적 예외 이후에도 서버가 계속 실행됨

**현재 근거:** [serve.ts](../../server/serve.ts)는 `uncaughtException`을 기록한 뒤 계속 실행한다. systemd의 `Restart=on-failure`는 프로세스가 종료되지 않으면 작동하지 않는다.

**개선:** 예상 가능한 작업 오류는 해당 세션에서 처리하고, 처리하지 못한 전역 예외는 제한된 정리 후 실패 종료해 supervisor가 복구하도록 한다. 개인용 실행의 자동 복구 방안도 함께 정해야 한다. 이는 [Node 공식 지침](https://nodejs.org/api/process.html#warning-using-uncaughtexception-correctly)의 외부 감독 프로세스 사용 권고와도 맞는다.

**완료 기준:** 격리 환경의 전역 예외 주입에서 프로세스 교체·준비 상태·파일 저장 재개가 확인된다. 사용자 에이전트 세션 유지 계약도 함께 확인한다.

### P1 — 공유 취소가 첨부 접근 취소를 뜻하지 않음

**현재 근거:** 게스트 파일 권한과 `/api/asset`은 별도 경계다. asset은 URL을 아는 방문자에게 공개되며 응답은 1년 public immutable 캐시다. 이는 버그로 몰래 생긴 동작이 아니라 [ADR 0120](../../../.mew/docs/decisions/0120-mew-project-local-assets-replace-r2.md)의 현재 선택이다.

**영향:** 문서 공유를 해제해도 이미 전달한 이미지·첨부 링크는 계속 접근 가능할 수 있다. 사적인 자료를 편집하는 사용자는 이 차이를 예상하기 어렵다. 이미 다운로드·캐시된 복사본을 사후 회수하는 것은 별개 문제다.

**개선:** 현재 공개 첨부의 의미를 공유 화면·사용법에서 명시한다. 비공개 공유가 필요하면 문서와 첨부 권한을 결합하고, 개별 공유 링크에 범위·만료·철회를 둔다. 공개 bearer-link 기본 정책을 바꾸려면 새 ADR이 먼저 필요하다.

**완료 기준:** 공유받은 사람이 볼 파일·첨부 목록을 미리 확인하고, 철회 후 서버 원본 접근이 차단되는 테스트가 있다. 공개 첨부를 유지하면 UI에서 이를 분명히 구분한다.

### P1 — 예약 작업이 겹치면 실행 중인 입력으로 새 명령을 보냄

**현재 근거:** [schedules.ts](../../server/schedules.ts)의 `buildCommand`는 기존 세션이 있으면 재사용하고 항상 `send-keys`로 다음 실행 명령을 넣는다. [명령·예약 문서](../guides/commands.md)는 주기를 실행 시간보다 짧게 잡지 말라고 안내한다.

**개선:** 작업별 잠금과 실행 상태를 두고 겹치면 건너뛰기 또는 대기 중 하나를 명시적으로 선택한다. 실행별 ID·시작/종료·오류·다음 실행 시각·시간대를 보여주고 로그 보관 상한을 정한다.

**완료 기준:** 긴 작업 중 두 번째 예약이 와도 현재 에이전트 stdin에 명령이 섞이지 않는다. 재시작·누락 시각·취소·실패를 예측 가능하게 처리한다.

### P2 — 프로덕션 보안 헤더와 미디어 기능을 함께 검증해야 함

**현재 근거:** [serve.ts](../../server/serve.ts)는 `frame-ancestors 'none'`과 `default-src 'self'`를 보낸다. PDF용 `/raw`·`/fs/raw`는 X-Frame-Options만 SAMEORIGIN으로 바꾸며, [YouTube 노드](../../packages/editor/src/MediaNodes.ts)는 외부 iframe을 만든다.

**재현·한계:** 프로덕션 헤더 조합을 적용한 격리 HTML iframe에서 같은 출처도 `frame-ancestors 'none'` 때문에 차단되는 것을 확인했다. 실제 PDF 뷰어의 기기별 동작은 별도 검증이 필요하다. YouTube 외부 프레임은 소스와 CSP의 불일치가 있으며 실제 공급자 영상 재생은 이번에 실행하지 않았다.

**PDF 후속 반영(2026-09-15):** PDF는 iframe을 제거하고 [앱 Canvas 뷰어](../development/pdf-viewer.md)로 교체했다. 실제 Chromium에 프로덕션 CSP를 적용해 열기·필기·저장·다운로드를 검증한다. `frame-ancestors 'none'`은 유지하며 로컬 디코더용 WASM 컴파일만 허용한다. 기존 `/raw` 헤더와 YouTube·기타 미디어에 대한 이 항목의 검토 범위는 남는다.

**개선:** 앱 셸의 클릭재킹 방어는 유지하면서 허용된 뷰어 응답의 조상 정책과 부모의 프레임 소스 정책을 구분한다. 미디어를 무조건 허용하는 전역 CSP 완화는 피한다.

**완료 기준:** 프로덕션 헤더를 건 실제 페이지에서 PDF·SVG·YouTube·내부 브라우저·인증 팝업의 정상 동작과 비신뢰 프레임 차단을 함께 검사한다.

| 지원하지 않는 경로 | Compose `app` 서비스와 설명은 남아 있지만 Dockerfile은 없음. setup 환영 문구도 옛 프로젝트 모델 | 미지원 프로파일 제거·명시적 실패 안내 중 선택. 환영 문구를 현재 폴더 프로젝트 모델로 정리 |
| 보안 문서 신뢰도 | SECURITY는 게스트 revert가 가능하다고 하지만 실제 라우트는 `requireAuthenticated`. 링크 미리보기·홈·계정 발급 설명도 일부 오래됨 | 코드·현재 ADR·SECURITY를 대조해 기준본을 갱신하고 역할별 API 테스트로 고정 |
| 기능 가이드 | 메뉴 조작과 내부 API·파일 형식·소스 설명이 같은 가이드에 섞임 | 사용법은 준비 → 조작 → 성공 확인 → 흔한 오류 순서. 구현 계약은 기존 development 문서로 연결 |
| 출시 증거 | `package.json` 버전은 0.0.0이고 레포 내부 `.github/workflows`는 없음. 외부 CI 유무는 미확인 | 버전·변경 기록·플랫폼 검증 결과·의존성 감사·제3자 고지와 설치/업데이트/복구 CI |

외부 사이트의 제목·설명 미리보기는 `/link-preview`가 null을 반환하므로 현재 비활성이다. 이번 검토에서 앞서 작성한 README·편집 가이드의 사용 가능 표현을 바로잡았다. 링크 편집·내부 파일 참조는 계속 제공한다.

## 기능별 instruction에서 반드시 설명할 것

| 기능 | 사용자가 알아야 할 설명 |
| --- | --- |
| 저장·Git | 자동저장은 디스크 반영, Ctrl+S는 파일 커밋, Git 패널은 전체 변경 커밋. 서버 파일과 열린 편집 내용이 다를 때 복구 방법 |
| 공유·권한 | member도 광범위한 파일을 읽음, manager·owner는 셸 권한. 게스트 규칙의 상속·공개 첨부·철회 범위 |
| 에이전트 | 실행 기계·cwd·접근 가능한 파일·승인 모드·공급자 계정·비용. 지침 텍스트는 권한 격리 수단이 아님 |
| 프로젝트 지침 | README 실행/검증 명령과 AGENTS 규칙을 찾는 방법, 런타임별 지침 파일 지원 차이. 화면에서 실제 적용되는 범위를 확인할 수 있어야 함 |
| 브라우저 | 기기의 localhost가 아닌 서버 localhost. DOM 중계의 영상·Canvas·장치 인증 한계. CLI 계정과 웹 로그인 계정의 차이 |
| 원격 데스크톱 | 서버 실제 로그인 화면 공유, OS 승인, GUI 없는 서비스의 한계, WebRTC와 HTTPS 터널의 경로 차이 |
| 예약 | 세션 예약과 독립 cron의 차이, 서버 시간대·중복 실행·실패·취소·비용과 실행 기록 |
| DB | 문서에는 참조만 저장되고 실제 행은 Postgres에 있음. Markdown/Git 백업만으로 DB가 복원되지 않음 |

에이전트 지침은 프로젝트의 목적·실행법·검증법·금지 작업·문서 위치를 담는 작은 템플릿부터 제공하는 것이 좋다. 파일·명령 권한은 별도로 강제해야 하며, 지침에 “읽지 말 것”이라고 쓰는 것으로 권한을 제한했다고 설명하지 않는다. 최소 권한·매 요청 검증의 근거는 [OWASP 인가 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)을 참고한다.

## 사용자 편의 기능 우선순위

| 순서 | 제안 | 사용자에게 생기는 변화 |
| --- | --- | --- |
| 1 | 기능 상태·진단 화면 | 브라우저·DB·런타임·데스크톱이 왜 안 되는지와 다음 조작을 한곳에서 확인 |
| 2 | 선택 파일 커밋·치환 미리보기·삭제 복구 | 다른 작업이나 비밀 파일을 함께 커밋하지 않고, 대량 변경 전 결과를 확인하며 실수를 복구 |
| 3 | 공유 관리 화면 | 공개 중인 파일·첨부·적용 규칙을 모아 보고 게스트 시점 미리보기·철회 수행 |
| 4 | 문맥 도움말·명령 팔레트 | 현재 화면의 사용법을 바로 열고 기능명으로 메뉴·명령을 검색. 전체 기능을 한꺼번에 외울 필요가 줄어듦 |
| 5 | 작업 완료·실패 알림 | 모바일에서 화면을 떠나도 에이전트·예약 작업 결과를 확인. 알림 채널·권한은 사용자 선택 |
| 6 | 프로젝트 지침 템플릿·적용 상태 | 새 프로젝트에서 어떤 명령과 규칙을 에이전트가 따라야 하는지 빠르게 설정·확인 |

선택 파일 커밋은 현재 `commitWorkingTree`의 `git add -A` 계약을 변경하는 제안이다. 현재 UI에도 전체 커밋 안내는 있으므로 숨겨진 동작이라고 보지는 않는다. 공유 정책·에이전트 권한 기본값·계정별 CLI 격리·독립 프로젝트 동시 사용 등 기존 계약을 바꾸는 기능은 관련 중앙 ADR을 먼저 검토한다. 특히 서버 활성 루트가 전역인 현재 구조는 서로 다른 프로젝트를 동시에 쓰는 팀의 확장 제약이다.

## 권장 실행 순서와 검증

1. 업로드 실행 경계, 설정 로딩 통일, 치명적 예외 처리와 안전한 업데이트/복구를 처리한다.

4. 선택 커밋·공유 관리·문맥 도움말·작업 알림을 순서대로 추가한다.
