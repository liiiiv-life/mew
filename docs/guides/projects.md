## 프로젝트 탭

mew에서 **폴더 하나가 프로젝트 하나**다. 설정된 시작 폴더도 워크스페이스가 아니라 처음 열린 프로젝트일 뿐이다. 화면 주소는 항상 `/`이고, 헤더에는 이 브라우저에서 열어 본 루트 프로젝트 경로가 탭으로 선다. 열린 경로 목록·순서·아이콘·탭 그룹은 로그인 계정에 저장되고, 브라우저에는 복원용 사본을 남긴다.

- 헤더의 `+ 탭` 또는 `Ctrl+O`는 화면 가운데 서버 폴더 브라우저를 연다. 절대경로·`~`를 주소창에 직접 넣거나 하위 폴더를 눌러 이동하고, **현재 폴더 열기**로 그 폴더를 프로젝트 탭에 추가한다(owner 전용). 주소창 아래 **새 폴더·Git 복제·Git 초기화** 버튼으로 현재 위치에서 작업한다. 이름·저장소 주소는 같은 창의 자체 폼에서 입력하며 생성 위치를 함께 표시한다. 폴더 이름 필터로 현재 목록을 좁힐 수 있고, 하단의 선택한 경로를 확인한 뒤 연다. 생성·복제·초기화 중에는 중복 실행·이동·닫기를 막으며 성공하면 목록과 완료 안내를 갱신한다. 오류가 나면 입력 내용을 보존해 다시 시도할 수 있다. 폼의 취소·Esc는 목록으로, 목록의 Esc는 창 닫기로 동작한다.
- 프로젝트 추가 창은 폴더 행을 36px, 작업 버튼·클라우드 바로가기를 최소 32px 높이로 표시한다. 헤더·주소창·필터·하단 선택 경로의 여백을 작게 유지하고, 클라우드 바로가기는 최대 96px 안에서 스크롤해 모바일에서도 폴더 목록 공간을 확보한다. 긴 폴더 이름·선택 경로는 한 줄로 줄여 표시하며 목록은 별도로 스크롤한다.
- 탭을 누르면 그 루트 프로젝트로 전환한다. 현재 서버 호환층은 활성 루트를 프로세스 전체에서 하나만 유지하므로 트리 감시자·협업 방을 정리한다. 실행 중 에이전트는 기존 프로젝트에서 계속 작업한다. 브라우저는 새로고침하지 않고 새 루트의 트리를 읽어 화면을 교체하며, 열린 탭 목록과 작은 텍스트 본문 캐시는 루트 절대경로별로 분리해 다시 돌아올 때 복원한다. 내부 이름 `WORKSPACE_ROOT`·`MEW_WORKSPACE`는 설정·경로 검증 호환용이며 사용자 개념이 아니다.
- 탭을 **1초 동안 누르면 이동 모드**가 된다(owner 전용, 마우스·터치 공통). 다른 탭의 **가로 중앙 50%**에 대면 점선 테두리와 **그룹 만들기 / 그룹에 추가** 미리보기가 보이고, 놓을 때 반영한다. 양쪽 25%는 앞·뒤 삽입선으로 순서를 바꾼다. 같은 그룹 안에서는 가장자리에 놓아 순서를 바꾸고, 다른 그룹의 탭 중앙에 놓으면 그 그룹에 들어간다.
- 그룹은 위아래 여백 없이 탭 줄 높이를 채우는 하나의 테두리로 구분하며, 모든 탭을 항상 펼쳐 표시한다. 시각적 복잡함과 불필요한 여백을 줄이기 위해 접기·펴기 토글과 별도 폴더·탭 수 표시를 제거했다. 기존에 저장된 접힘 상태도 화면에서는 무시한다. 사용자 요청 전에는 접기 UI를 다시 도입하지 않는다. 이동 중 보이는 **그룹 밖으로** 영역에 놓으면 독립 탭으로 맨 뒤에 옮긴다. 그룹 테두리 양끝 여백에 놓으면 그룹 앞·뒤의 독립 탭으로 옮긴다. 탭을 꺼내거나 닫아 그룹에 하나만 남으면 자동으로 풀린다. 그룹은 화면 정리용이며 서버 폴더를 이동하지 않는다.
- 누른 채 1초가 되기 전에 움직이면 이동을 취소하고 일반 가로 스크롤을 유지한다. 이동 중 Esc·터치 취소·화면 바깥에 놓기는 변경을 취소한다. 이동으로 프로젝트를 활성화하거나 닫지 않는다. 탭에 키보드 초점이 있으면 `Alt+←/→`로 순서 이동, `Alt+Shift+←/→`로 이웃 탭과 그룹 만들기·추가, `Alt+↓`로 그룹 밖 맨 뒤로 이동한다.
- 탭을 우클릭하거나 **0.5초 이상 누른 뒤 1초 전에 놓으면** 아이콘 선택기를 연다(owner 전용). 키보드는 `Shift+F10`으로 연다. 아이콘은 계정의 열린 루트 경로별로 기억한다. `+ 탭`은 글자 없이 `+` 아이콘만 보인다.
- 프로젝트 이름이 보이는 탭에는 `×`가 보인다. 누르면 확인 뒤 탭 목록에서만 닫으며, 파일·폴더는 지우지 않는다. 마지막 루트 프로젝트 탭은 닫을 수 없다.
- 프로젝트 탭에는 명령 버튼과 하위 폴더가 붙지 않는다. 사이드바의 하위 프로젝트를 누르면 해당 폴더가 독립된 프로젝트 탭으로 열리고 활성화된다(owner 전용). 이미 열린 경로는 기존 탭을 재사용하며 상위 프로젝트 탭은 남는다. 명령은 열린 프로젝트의 사이드바 ▶에서 실행한다.
- 절대경로 탭 추가·전환은 owner가 맡는다. manager는 셸과 같은 권한으로 현재 프로젝트 경로를 볼 수 있고, member·guest에는 절대경로 대신 일반 프로젝트 이름만 보인다.

작업 화면 상태(문서 탭·칸 배치·스크롤·트리 펼침·보조 패널)는 로그인 계정별 서버 원장에 남아 다른 기기·시크릿 창에서도 복원한다. 기존 `localStorage` 값은 계정 원장이 처음 비어 있을 때만 이관 원본으로 쓰며, 루트 프로젝트와 Documents의 내부 API 식별자 `.workspace`·`docs`는 호환을 위해 유지한다. 화면 폭·테마·언어·글꼴·작성 중 초안처럼 기기 특성이 강한 값은 브라우저에 남는다.

최근 프로젝트로 돌아갈 때는 이 로그인 세션에 남은 탭·배치·첫 폴더 목록을 먼저 복원한다. 화면 상태 캐시는 60초 동안 유지하며, 캐시가 없으면 계정 상태 조회를 서버 프로젝트 전환과 동시에 시작한다. 에이전트 탭 목록도 전환과 동시에 조회해 패널에서 같은 요청을 재사용한다. 폴더·파일 본문은 서버가 전환을 확인한 뒤 최신 내용을 읽으며, 캐시가 있는 화면을 비우고 기다리지 않는다. 새로고침·다른 기기에서는 서버 원장을 다시 읽는다. 전환 요청 중에는 화면 전체를 덮는 반투명 로딩 화면과 중앙 회전 인디케이터를 표시하고 뒤쪽 화면의 조작을 막는다. 완료·실패 시 자동으로 닫히며, 전환이 실패하면 현재 프로젝트에 머문다. 탭바의 별도 로딩 문구는 사용하지 않는다. [빠른 전환 개발 계약](../development/ui-contracts.md#루트-프로젝트-빠른-전환)을 따른다.

프로젝트·문서·터미널·에이전트·브라우저·시트 탭 줄은 항목이 폭을 넘겨도 가로 스크롤바를 표시하지 않는다. 손가락·트랙패드·Shift+휠을 통한 가로 이동은 그대로 유지한다.

### 클라우드 폴더 바로가기

프로젝트 추가 팝업은 서버에서 감지한 OneDrive·Google Drive·Dropbox와 macOS의 iCloud Drive 폴더를 주소창 아래 **클라우드 폴더 바로가기**로 표시한다. 바로가기를 누르면 그 경로로 이동할 뿐 프로젝트 탭을 추가하지 않는다. 원하는 하위 폴더까지 탐색한 뒤 **이 프로젝트 열기**로 추가한다. 감지된 폴더가 없으면 바로가기 영역을 숨긴다. 다시 찾기 버튼 또는 팝업을 다시 열어 목록을 갱신한다.

- 감지 대상은 브라우저를 사용하는 기기가 아니라 **mew 서버 프로세스의 OS 파일시스템**이다. 계정 로그인·OAuth·클라우드 API·별도 동기화 기능은 사용하지 않는다.
- macOS는 `~/Library/CloudStorage`의 OneDrive·GoogleDrive·Dropbox 폴더, `~/Library/Mobile Documents/com~apple~CloudDocs`, `/Volumes`의 알려진 서비스 이름 폴더를 확인한다. CloudStorage 경로는 [Google 안내](https://support.google.com/drive/answer/12178485?hl=en-GB)와 [Microsoft 안내](https://support.microsoft.com/en-us/onedrive/missing-files-and-autosave-issues-with-onedrive-on-macos)를 참고한다.
- 공통으로 서버 사용자의 홈 바로 아래 서비스 이름 폴더와 `OneDrive`·`OneDriveConsumer`·`OneDriveCommercial` 환경변수의 절대경로를 확인한다. WSL에서는 `/mnt/c/Users/*`의 직계 동기화 폴더도 확인한다. 계정·조직별 여러 폴더를 표시하고 이름이 같으면 경로를 함께 보여 준다. 심볼릭 링크로 같은 실제 경로를 가리키면 하나만 표시한다.
- 알려진 위치를 얕게 확인하며 서버 전체를 재귀 검색하지 않는다. 존재하고 읽기·탐색 가능한 디렉터리만 제공한다. 이름 기반 감지는 로그인·동기화 상태를 보증하지 않으며, 온라인 전용 파일의 다운로드는 OS 동기화 앱이 담당한다. 사용자 지정 경로·다른 드라이브에 있어 감지하지 못한 폴더는 기존 주소창에서 직접 연다.
- 읽기 전용 `GET /api/fs/cloud-storage`는 프로젝트 추가와 같은 owner 전용이며 `{ folders: [{ provider, name, path }] }`를 반환한다. 감지는 파일·설정·탭 목록을 쓰지 않는다. 구현은 `server/cloud-storage.ts`, UI는 `src/components/cloud-storage-locations.tsx`에서 관리한다.

## 사이드바의 프로젝트 · 하위 프로젝트 · Documents

새 파일 생성은 입력한 파일명과 확장자를 그대로 사용하며, 확장자를 생략해도 `.md`를 붙이지 않는다. `/api/new-document`는 일반 파일을 빈 내용으로 만들고, `.md` 파일에만 문서 초기 내용과 Documents의 MOC 등록을 적용한다.

사이드바 상단에는 탐색기(폴더) · 파일명 검색(돋보기, `Ctrl+P`) · 파일 내용 검색(문서 돋보기, `Ctrl+Shift+F`) · 현재 루트 프로젝트 명령(▶) 탭이 있다. 루트 명령 ▶를 누르면 파일 탐색기·Documents 없이 루트의 `.mew/cmd-button.json` 목록만 보인다. 로그인 사용자에게는 상단 오른쪽에 **새 파일**·**새 폴더** 버튼도 표시한다. 마지막으로 선택한 폴더 안에 이름 입력란을 열며, 파일을 선택했다면 그 파일의 부모 폴더를 쓴다. 선택이 없거나 루트 프로젝트를 바꾸면 현재 프로젝트 루트에 만든다. Documents 제목이나 내부 항목을 선택했다면 해당 범위에 만들고, 접혔으면 자동으로 펼친다. 하위 프로젝트 안의 파일·폴더는 그 프로젝트 탭을 연 뒤 만든다. 이름 입력 후 Enter로 생성하며 Esc로 취소한다. Git은 사이드바에 버튼을 두지 않고 헤더 햄버거 메뉴 또는 `Alt+G`로 연다.

파일 검색창 바로 아래에는 펼칠 수 있는 Documents와 직계 하위 프로젝트의 탭 열기 항목이 선다. 프로젝트 행의 오른쪽 화살표는 별도 프로젝트 탭으로 이동한다는 뜻이다. 그 뒤에는 현재 루트의 나머지 파일·폴더가 별도 Project 폴더 없이 바로 이어진다.

- **Documents** — 현재 프로젝트가 고른 docs 폴더. 펼치면 바로 아래에 내용이 보이고, owner가 우클릭하면 기존 폴더 변경·가져오기·내보내기 설정 창이 열린다. 내부 식별자와 API는 계속 `docs`다.
- 모바일에서는 사이드바의 파일·폴더를 **0.5초 이상 누른 뒤 1초가 되기 전에 손을 떼면** 데스크톱 우클릭과 같은 항목 메뉴가 열린다. 폴더 메뉴의 **Git 저장소로 만들기**는 선택한 폴더 자체에서 `git init`한다(owner·manager). 1초까지 계속 누르면 이동 모드가 되어 대상 폴더로 끌어놓을 수 있다. 그 전에 움직이면 스크롤로 처리한다([모바일 조작](editor.md#모바일과-전체화면)). 폴더 안에 실제 `.mew` 디렉터리가 있으면 깊이에 관계없이 **하위 프로젝트**다. 루트 직계 하위 프로젝트는 Documents 바로 뒤에 나타나며, 클릭·터치·Enter·Space로 해당 폴더의 프로젝트 탭을 연다. 그 행에는 내부 파일이나 명령 메뉴를 펼치지 않는다. `.mew`가 없는 루트 파일·폴더는 이 항목들 뒤에 별도 컨테이너 없이 바로 나열한다. owner·manager는 숨김 폴더도 보되 `.git`·`node_modules`·`.data`는 기존 차단·성능 규칙에 따라 제외한다. 중첩 하위 프로젝트는 실제 부모 폴더 안에서 프로젝트 아이콘과 탭 열기 화살표로 표시하고 같은 방식으로 연다. 하위 프로젝트 안의 더 깊은 프로젝트는 상위 프로젝트 탭을 연 다음 탐색한다. 일반 폴더 안에도 둘 수 있으며 중간 폴더를 자동으로 프로젝트로 바꾸지 않는다.

**MOC는 파일명으로 목록에 섞이지 않는다** — `MOC.md`·`_MOC.md`(둘은 같은 것)는 파일 목록에서 빠지고, 대신 **자기 폴더를 펼쳤을 때 맨 첫 줄**에 지도 아이콘 + `Map Of Contents`로 고정된다. 프로젝트 루트의 MOC는 담을 폴더가 없으니 트리 전체의 맨 위, 어떤 폴더보다 앞에 같은 모양으로 선다. 판별은 파일명뿐이라 프로젝트를 가리지 않는다.

프로젝트 열기는 기존 루트 전환과 같은 owner 전용 동작이다. 다른 역할에는 열기 동작이 비활성화된다. 일반 폴더와 Documents는 기존처럼 펼쳐 탐색한다. 이전에 저장된 하위 프로젝트 펼침 상태는 무시하며, 내부 파일을 자동으로 읽지 않는다. 전환 실패 시 현재 프로젝트에 머물고 오류를 표시한다. 서버의 활성 루트는 기존처럼 공유되므로 다른 접속자도 루트 변경을 받는다. 실행 중 에이전트는 기존 프로젝트에 계속 연결된다([ADR 0158](../../../.mew/docs/decisions/0158-mew-subprojects-open-root-tabs.md)).

### 폴더를 하위 프로젝트로 지정

쓰기 가능한 폴더를 우클릭(모바일은 길게 누른 뒤 놓기)하고 **하위 프로젝트로 만들기**를 누른다. 선택한 폴더에 빈 `.mew` 디렉터리를 생성하고 트리에 바로 반영한다. 기존 파일과 `.mew` 설정은 보존하며 Git 초기화나 루트 프로젝트 전환은 하지 않는다.

- `liiiiv`를 열면 `abc/def`도 그 위치에서 하위 프로젝트가 된다. `abc`도 프로젝트라면 그 안의 중첩 프로젝트이고, 일반 폴더여도 `def`를 지정할 수 있다. `abc` 자체를 루트로 열면 `def`는 직계 프로젝트로 보인다.
- 루트·이미 지정된 프로젝트·파일·읽기 전용 폴더·`.mew` 설정 내부에는 생성 메뉴가 없다. 로그인 계정의 파일 읽기·쓰기 권한과 대상 폴더 및 `.mew` 경로의 편집 권한이 필요하다.
- `.mew`라는 **파일이나 링크**는 표식으로 인정하지 않는다. 같은 이름의 파일·링크가 있으면 내용을 보존하고 오류를 표시한다. 심볼릭 링크 경로로 생성할 수 없다.
- 중첩 프로젝트의 ▶는 해당 폴더의 `.mew/cmd-button.json`을 사용하고 그 폴더에서 실행한다. 다른 경로에 이름이 같은 프로젝트가 있어도 명령과 세션이 섞이지 않는다. 터미널 권한이 있는 계정에게만 ▶를 표시한다.
- 검색의 `@` 범위 선택은 기존 Documents·직계 하위 프로젝트를 유지한다. 중첩 프로젝트 내용은 이를 포함하는 기존 범위에서 검색된다.

개발 계약: `POST /api/subprojects?project=`에 `{path}`(현재 트리 기준 상대경로)를 보낸다. 생성은 멱등이며 표식과 부모 행의 catalog를 갱신한다. 명령 API(`/api/cmd-buttons`, `/api/cmd-buttons/run`)는 선택적 `path`로 중첩 실행 폴더를 받는다. 편집·협업의 기존 프로젝트 식별자는 바뀌지 않는다. 결정 근거는 [ADR 0151](../../../.mew/docs/decisions/0151-mew-nested-subprojects.md)이다.

## 파일·폴더 관리

프로젝트 작업, 서버 파일 탐색기의 이름 변경·삭제·프로젝트 열기, 사이드바 Git 초기화, Git 커밋 작업, 검색의 일괄 치환은 앱 자체 입력·확인 컴포넌트를 사용한다. 브라우저 `prompt`·`confirm` 대신 앱 테마를 따르는 대화상자를 사용하며, Tab 포커스를 창 안에 유지하고 닫으면 호출한 컨트롤로 복원한다. 삭제 등 위험 작업은 취소 버튼에 먼저 포커스한다.

사이드바의 파일·폴더를 우클릭하거나 모바일에서 길게 눌러 항목 메뉴를 연다. 로그인 사용자에게 생성·이름 변경·복제·복사·잘라내기·붙여넣기·삭제 등의 작업을 제공한다. 선택한 항목과 역할에 따라 가능한 메뉴만 표시한다.

- `F2`는 이름 변경, `Delete`는 삭제, `Insert`는 새 파일, `Shift+Insert`는 새 폴더다. `Ctrl+C`·`Ctrl+X`로 복사·잘라내기 후 대상 폴더에서 `Ctrl+V`로 붙여넣는다.
- 새 파일은 확장자까지 입력한다. 확장자를 생략하면 확장자 없는 파일을 만든다.
- 파일 메뉴의 다운로드로 원본을 받는다. 파일·폴더를 다른 폴더에 끌어놓으면 이동하고, 기기의 파일을 사이드바에 끌어놓으면 업로드한다([드롭 위치별 동작](editor.md#사이드바-항목-끌어놓기)).
- 파일 이동·잘라내기 붙여넣기 후 Git 이력을 기록할 때, 아직 Git이 추적하지 않던 원래 경로가 사라져도 이동은 정상 완료된다. 기존에 추적하던 파일·폴더는 원래 경로의 삭제와 새 경로를 함께 기록한다.
- manager·owner는 폴더 메뉴의 **Git 저장소로 만들기**로 그 폴더 자체를 초기화할 수 있다. 서버의 임의 경로에 새 프로젝트를 만드는 것은 owner의 [프로젝트 선택 창](#프로젝트-탭)에서 한다.
- 파일 권한은 owner의 계정 관리에서 [각 계정과 guest별로 설정](../configuration/environment.md#내-계정과-계정-관리)한다. 사이드바는 허용된 파일과 읽기 전용 상태를 반영한다.

## Documents 폴더 계약

Documents의 에이전트 안내·문서 초기화 GUI와 CLI는 [프로젝트 문서 설정](project-setup.md)을 따른다. 프로젝트별 `.mew/agent-context.json`의 경로가 기존 `MEW_DOCS`와 기본 경로보다 우선한다.

Documents는 탭이 아니라 사이드바의 가상 폴더다. 실제 폴더는 현재 루트 프로젝트 안에서 owner가 고르며 기본은 `docs`다. 설정이 없고 옛 `.mew/docs`만 있으면 그 위치를 그대로 쓴다. 폴더가 없으면 빈 Documents 폴더를 만든다.

- 내부 식별자 `docs`는 유지한다. 문서·트리·검색·협업 방·git·저장 키가 이 이름을 공유하므로 UI 배치와 함께 바꾸지 않는다.
- 현재 Documents의 실제 최상위 폴더는 루트 프로젝트 트리에서 중복 표시하지 않는다.
- owner가 사이드바의 Documents를 우클릭하면 `DocsSettingsModal`이 열린다. 폴더 변경은 현재 루트 프로젝트 안에서만 허용하고, 가져오기는 기존 내용을 지운 뒤 교체하며, 내보내기는 대상 아래 `docs`로 복사한다.
- 폴더 선택은 서버 파일시스템을 읽는 `GET /api/fs/dirs`를 쓰며 owner 전용이다.

| 라우트 | 역할 | 하는 일 |
| --- | --- | --- |
| `GET /api/fs/dirs?path=` | **owner** | 그 폴더의 하위 폴더 목록 |
| `POST /api/docs/root` `{path}` | **owner** | 현재 루트 프로젝트 안에서 Documents 폴더 변경 |
| `POST /api/docs/import` `{path}` | **owner** | Documents를 통째로 교체(되돌릴 수 없음) |
| `POST /api/docs/export` `{path}` | **owner** | `{path}/docs`로 복사 |

## 서버 파일 탐색기

헤더 메뉴에서 여는 프로젝트 독립 팝업(`components/ServerFileExplorer.tsx`). 기본 경로는 서버 사용자의 홈이고, 주소 입력·드롭다운으로 `~` 또는 절대경로를 연다. 폴더는 펼칠 때 한 단계씩 읽으므로 홈 전체를 미리 재귀 스캔하지 않는다. 숨김 항목을 포함해 mew 서버의 OS 사용자가 읽을 수 있는 모든 파일·폴더가 대상이다.

- 파일을 누르면 현재 프로젝트는 그대로 둔 채 포커스된 편집 칸의 **미리보기 탭**으로 열린다. 외부 탭은 자동저장할 수 있지만 협업·댓글·git 이력·프로젝트 규칙을 쓰지 않고, 새로고침 탭 복원에도 남지 않는다.
- 우클릭 메뉴는 파일·폴더 이름 변경, 복사·잘라내기·폴더에 붙여넣기, 삭제를 제공한다. 파일은 다운로드할 수 있다. **모바일에서 브라우저가 셀룰러 연결을 확인하고 파일이 100MiB를 넘으면**, 실제 내려받기 전에 데이터 요금 안내와 계속 다운로드 확인을 띄운다. Wi‑Fi·데스크톱·연결 종류를 알 수 없는 브라우저는 바로 내려받는다.
- 폴더의 **프로젝트로 열기**는 그 폴더 자체를 루트 프로젝트 탭에 추가하고 활성 프로젝트로 연다. owner 전용이며 활성 루트 전환 계약에 따라 현재 화면을 새 루트로 교체한다.
- 탐색·읽기·쓰기 API는 **서버 파일 탐색기 기능이 허용된 로그인 계정**이 사용한다(기본 manager·owner). 워크스페이스 경계나 `.git`·`node_modules` 차단 규칙을 적용하지 않으며 셸과 동일한 OS 권한 범위다. 공개 서버의 권한 의미는 [SECURITY.md](../../SECURITY.md)를 따른다.

| 라우트 | 역할 | 하는 일 |
| --- | --- | --- |
| `GET /api/fs/entries?path=` | manager·owner | 절대경로 폴더의 파일·하위 폴더 한 단계 |
| `GET/PUT /api/fs/file` | manager·owner | 외부 텍스트 파일 읽기·저장(텍스트 열기는 10MB 이하) |
| `POST /api/fs/rename` · `DELETE /api/fs/path` · `POST /api/fs/paste` | manager·owner | 이름 변경·재귀 삭제·복사/이동 |
| `GET /api/fs/raw` · `GET /api/fs/download` | manager·owner | 외부 미디어 스트리밍·파일 다운로드 |
| `POST /api/fs/open-project` | owner | 선택 폴더 자체를 루트 프로젝트로 열고 활성화 |
| `POST /api/fs/folder` · `POST /api/fs/git/init` · `POST /api/fs/git/clone` | owner | 현재 폴더 안 생성·Git 초기화·저장소 clone |

## Git 작업 패널

헤더 햄버거 메뉴의 **Git** 또는 `Alt+G`로 현재 프로젝트 루트의 Git 패널을 바로 열고 접는다. 하위 프로젝트는 해당 프로젝트 탭으로 전환한 뒤 Git을 연다. Documents·중첩 저장소 선택 목록이나 새 저장소 탭 버튼은 없다. 현재 루트 자체에 Git 저장소가 없으면 빈 상태를 표시하며 상위·하위 저장소를 대신 열지 않는다.

다른 작업 패널과 같은 탭바·닫기 버튼을 사용한다. 손잡이나 현재 프로젝트 탭을 끌어 패널을 옮기고 경계를 조절한다. 패널 닫기·탭의 `×`·포커스된 Git 화면의 `Ctrl+W`는 패널을 접는다. 다시 열면 상세 화면과 작성 중인 커밋을 이어 쓴다. 다른 영역을 클릭해도 닫히지 않으며 모바일 전면 전환·Esc·뒤로가기는 공통 패널 규칙을 따른다.

계정의 프로젝트별 작업 상태에 열림 상태·배치를 저장한다. 예전 Documents·하위 저장소 탭 저장분은 현재 프로젝트 루트 하나로 정리하며 다시 열지 않는다. 상세 화면과 커밋 초안은 현재 패널 메모리에만 유지하며 프로젝트 전환·새로고침 때 초기화한다. 편집기의 파일 탭은 별개이며 기존 `mew:git:` 가상 파일 탭은 계속 복원하지 않는다([ADR 0160](../../../.mew/docs/decisions/0160-mew-git-current-project-only.md)). 통합 저장소 선택기를 제거한 이유는 프로젝트 탭과 Git 작업 범위를 일치시키기 위해서며, 같은 선택기의 재도입에는 후속 결정이 필요하다.

- 첫 화면은 모든 ref의 최근 커밋 최대 300개를 topo-order로 표시한다. 맨 위 첫 항목은 항상 **커밋되지 않은 변경사항**이고, 그 아래에 그래프 레인과 커밋 제목·ref·작성자·시간·짧은 해시가 선다.
- 저장소 탭 안 화면은 `그래프 → 커밋 또는 작업트리 상세 → 파일 diff`의 세 단계다. 상세·diff 화면 왼쪽 위의 뒤로가기로 바로 전 단계에 돌아가며 탭바 오른쪽 `×`는 어느 단계에서든 해당 패널을 접는다.
- 커밋 상세는 본문과 변경 파일을 표시한다. 작업트리 상세는 수정·추가·삭제·미추적 파일 전체를 먼저 표시하고, 패널 맨 아래 고정 작성 영역에서 커밋 제목·선택 설명을 입력한다. `커밋`은 이 변경을 모두 stage해 한 커밋으로 만든다.
- **AI Commit** → 기존 에이전트셋 선택 또는 **새 에이전트셋 추가** → **초안 생성**으로 제목·설명을 만든다. 새로 만든 셋은 바로 선택되며 에이전트 창에서도 재사용한다. 선택한 런타임의 설치·로그인이 필요하다. Git·에이전트 기능 권한을 모두 가진 계정이 사용할 수 있다.
- 생성은 전용 tmux 안의 독립 ACP 세션에서 실행한다. 기존 에이전트 대화에 섞이지 않는다. 창을 닫거나 새로고침해도 작업은 계속되며, 같은 프로젝트에서 AI Commit을 다시 열면 마지막 작업·진행 로그·결과를 확인한다. 실행 중에는 **생성 취소**, 실패·취소 뒤에는 에이전트셋을 선택해 **다시 생성**할 수 있다.
- 생성된 결과를 읽고 **초안 적용**을 누르면 작성 영역의 제목·설명을 교체한다. 실패·취소·완료 알림만으로 기존 초안을 덮어쓰지 않는다. 생성 후 변경사항이 달라지면 적용을 거절하고 재생성을 안내한다. 적용 이후에도 파일을 수정했다면 커밋 전에 메시지를 다시 확인한다. 실제 stage·commit은 기존 **커밋** 버튼으로 확정한다.
- AI에는 생성 시점의 변경 파일·diff 스냅샷을 제공한다. 변경량이 크면 일부 diff가 생략됐다는 안내를 표시한다. 충돌 중에는 생성하지 않으며, 10분 시간 초과·모델/로그인 오류·응답 형식 오류는 실패로 표시한다. 도구 승인이 필요한 요청은 거절하고 에이전트셋 역할 조정을 안내한다. 상세 실행·저장 계약은 [에이전트 세션](../development/agent-sessions.md#git-ai-commit-초안-작업)을 따른다.
- 상세의 변경 파일을 누르면 같은 탭이 파일 diff 화면으로 바뀌고 이전·이후 줄 번호와 추가·삭제 줄을 표시한다. 파일을 누를 때만 patch를 읽으므로 전체 diff가 첫 응답을 막지 않는다.
- 커밋 우클릭은 해시 복사, branch/tag 생성, detached checkout, cherry-pick, revert를 제공한다. checkout·cherry-pick·revert는 확인 뒤 실행하며 강제 checkout·reset·clean은 제공하지 않는다. 작업 트리 변경이나 충돌 때문에 Git이 거부하면 오류를 그대로 표시한다.
- API는 저장소 상대경로와 구조화된 작업 인자만 받으며 임의 셸 문자열을 받지 않는다. 지정한 폴더 자체에 `.git`이 있어야 하고 상위 저장소를 암묵적으로 찾아가지 않는다.

| 라우트 | 역할 | 하는 일 |
| --- | --- | --- |
| `GET /api/git/repository` · `GET /api/git/log` | manager·owner | 저장소 상태와 커밋 그래프 원본 |
| `GET /api/git/repositories` | manager·owner | 요청한 프로젝트 스코프 루트만 확인(재귀 탐색 없음) |
| `GET /api/git/commit` · `GET /api/git/diff` | manager·owner | 과거 커밋 메타데이터·변경 파일과 선택 파일 patch |
| `GET /api/git/working-tree` · `GET /api/git/working-tree/diff` | manager·owner | 현재 작업트리 변경 파일과 선택 파일 patch |
| `POST /api/git/commit` · `POST /api/git/action` | manager·owner | 작업트리 전체 커밋과 과거 커밋 대상 허용 작업 |
| `POST /api/git/init` | manager·owner | 프로젝트 안 폴더 Git 초기화 |
| `POST /api/fs/folder` · `POST /api/fs/git/init` · `POST /api/fs/git/clone` | owner | 프로젝트 브라우저의 임의 OS 경로 생성·초기화·clone |

## 현재 제공하지 않는 홈 화면

워크스페이스 스코프 홈 고정 탭과 최상위 하위 폴더 전체를 나열하던 프로젝트 격자 진입점은 없다. 예전 홈의 할 일·달력 위젯도 현재 화면에서 열 수 없다. 문서 본문의 체크박스와 [에이전트 예약 작업](commands.md)은 각각 계속 제공한다. 할 일·달력 위젯을 다시 노출할 때는 워크스페이스 홈 탭을 되살리지 않고 프로젝트 스코프 배치를 별도로 결정한다.

## 숨김 목록 (.data/ignore.json)

파일 목록·검색·트리 감시에서 통째로 건너뛸 **이름** 목록. 경로가 아니라 이름이라 어느 깊이에 있든 그 이름의 폴더·파일이 사라진다(`dist` → 모든 프로젝트의 모든 `dist/`). 설정 창 → **숨김 목록**에서 고친다(owner/manager). 파일이 없으면 `server/ignoreList.ts`의 `DEFAULT_IGNORE`를 쓴다.

```json
{ "names": ["dist", ".next", "node_modules", ".git", ".data"] }
```

- 목록은 **전역 하나**다 — 프로젝트마다 다르지 않다. 그래서 `.data/`에 서버가 저장한다.
- `.git`·`node_modules`·`.data`는 `paths.ts`의 `DENY_SEGMENTS`가 API 계층에서 따로 막는다. 목록에서 빼도 계속 안 보이므로, 저장할 때 서버가 도로 넣고 UI는 **고정**으로 표시한다 — 지울 수 있는 것처럼 보이면 "지웠는데 왜 그대로냐"가 된다.
- 저장하면 서버가 감시자를 전부 접고(`resetTreeWatchers`) `tree` 신호를 보낸다. 살아 있는 감시자는 옛 규칙으로 만든 트리 서명을 들고 있어 새 규칙을 "변화 없음"으로 흘려버리기 때문 — 접어두면 클라이언트가 새 트리를 받아 갈 때(`GET /api/tree`) 새 규칙으로 다시 등록된다.
- `build/`는 기본 숨김이 **아니다**. 트리는 안의 APK/AAB만 노출하고 나머지·빈 폴더는 접으며 (`tree.ts`의 `DOWNLOAD_ONLY_DIRS`), 감시는 숨김 목록과 별개로 `build`에 내려가지 않는다.
- **owner·manager의 트리에는 이 목록도 확장자 필터도 적용되지 않는다** — 있는 그대로 다 보인다. 목록은 계속 살아서 member 이하의 트리와, 역할과 무관하게 **검색·트리 감시**에 적용된다.
- 사이드바는 `GET /api/tree?path=<폴더>`로 해당 폴더의 **직접 자식만** 읽는다. 프로젝트 전환 때는 계정에서 복원한 펼침 상태와 자식 스냅샷을 먼저 그리고 열린 경로의 직접 자식만 갱신한다. 접힌 조상 아래와 닫힌 최상위 폴더는 펼칠 때 읽고, 받은 목록·진행 중 요청은 재사용한다. Documents·프로젝트 진입점을 포함한 사이드바 스크롤은 계정에 중앙 항목의 트리 식별자·경로·항목 내 비율로 저장하며, 지연 로딩 중에도 같은 항목을 중앙에 복원한다. 사용자가 조작하면 초기 보정을 끝낸다([ADR 0125](../../../.mew/docs/decisions/0125-mew-sidebar-center-anchor-and-visible-loading.md)). `path` 없는 API 호출은 기존 서버 도구 호환을 위해 전체 재귀 트리를 유지한다. 정책 기준본은 [SECURITY.md](../../SECURITY.md)이고, 표시 필터는 `server/tree.ts`의 `isPathVisible`과 `server/reqAuth.ts`의 `seesEveryFile`, 실제 접근은 `server/access-policy.ts`가 판정한다. 부분 파일 제한이 있으면 허용된 하위 경로를 찾기 위해 트리를 필터링한다.
- 서버: `server/ignoreList.ts` + `GET/PUT /api/ignore`(owner/manager). 클라이언트: `src/components/SettingsModal.tsx`의 `IgnorePanel`.
