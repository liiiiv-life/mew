# 프로젝트와 파일 탐색

## 프로젝트 탭

mew에서 **폴더 하나가 프로젝트 하나**다. 설정된 시작 폴더도 워크스페이스가 아니라 처음 열린 프로젝트일 뿐이다. 화면 주소는 항상 `/`이고, 헤더에는 이 브라우저에서 열어 본 루트 프로젝트 경로가 탭으로 선다. 열린 경로 목록·순서·탭 그룹은 로그인 계정에 저장되고, 브라우저에는 복원용 사본을 남긴다. 아이콘은 각 프로젝트의 `.mew/project-icon.json`을 기준으로 사이드바와 프로젝트탭이 함께 사용한다.

- 헤더의 `+ 탭` 또는 `Ctrl+O`는 화면 가운데 서버 폴더 브라우저를 연다. 처음 열면 제목에 포커스가 놓이고 주소창은 직접 눌러 입력한다. 절대경로·`~`를 주소창에 직접 넣거나 하위 폴더를 눌러 이동하고, **현재 폴더 열기**로 그 폴더를 프로젝트 탭에 추가한다(owner 전용). 주소창 아래 **새 폴더·Git 복제·Git 초기화** 버튼으로 현재 위치에서 작업한다. 이름·저장소 주소는 같은 창의 자체 폼에서 입력하며 생성 위치를 함께 표시한다. 폴더 이름 필터로 현재 목록을 좁힐 수 있고, 하단의 선택한 경로를 확인한 뒤 연다. 생성·복제·초기화 중에는 중복 실행·이동·닫기를 막으며 성공하면 목록과 완료 안내를 갱신한다. 오류가 나면 입력 내용을 보존해 다시 시도할 수 있다. 폼의 취소·Esc는 목록으로, 목록의 Esc는 창 닫기로 동작한다.
- 프로젝트 추가와 서버 파일 탐색기는 프로젝트 추가 창에서 추출한 공통 `FileBrowser`를 사용한다. 헤더·주소창·홈/상위 이동·이름 필터·목록 행·하단 경로·오류 재시도 UI가 같고, 폴더/파일 행을 36px, 작업 버튼·즐겨찾기를 최소 32px 높이로 표시한다. 헤더·주소창·필터·하단 선택 경로의 여백을 작게 유지하고, 맨 위 즐겨찾기는 접힌 드롭다운으로 표시해 폴더 목록 공간을 확보한다. 펼친 항목은 44px 이상 높이이며 화면 경계 안에서 최대 280px 높이로 스크롤한다. 긴 폴더 이름·선택 경로는 한 줄로 줄여 표시하며 목록은 별도로 스크롤한다.
- 탭을 누르면 그 루트 프로젝트로 전환한다. 현재 서버 호환층은 활성 루트를 프로세스 전체에서 하나만 유지하므로 트리 감시자·협업 방을 정리한다. 실행 중 에이전트는 기존 프로젝트에서 계속 작업한다. 브라우저는 새로고침하지 않고 새 루트의 트리를 읽어 화면을 교체하며, 열린 탭 목록과 작은 텍스트 본문 캐시는 루트 절대경로별로 분리해 다시 돌아올 때 복원한다. 내부 이름 `WORKSPACE_ROOT`·`MEW_WORKSPACE`는 설정·경로 검증 호환용이며 사용자 개념이 아니다.
- 탭을 **1초 동안 누르면 이동 모드**가 된다(owner 전용, 마우스·터치 공통). 다른 탭의 **가로 중앙 50%**에 대면 점선 테두리와 **그룹 만들기 / 그룹에 추가** 미리보기가 보이고, 놓을 때 반영한다. 양쪽 25%는 앞·뒤 삽입선으로 순서를 바꾼다. 같은 그룹 안에서는 가장자리에 놓아 순서를 바꾸고, 다른 그룹의 탭 중앙에 놓으면 그 그룹에 들어간다.
- 그룹은 위아래 여백 없이 탭 줄 높이를 채우는 하나의 테두리로 구분하며, 모든 탭을 항상 펼쳐 표시한다. 시각적 복잡함과 불필요한 여백을 줄이기 위해 접기·펴기 토글과 별도 폴더·탭 수 표시를 제거했다. 기존에 저장된 접힘 상태도 화면에서는 무시한다. 사용자 요청 전에는 접기 UI를 다시 도입하지 않는다. 이동 중 보이는 **그룹 밖으로** 영역에 놓으면 독립 탭으로 맨 뒤에 옮긴다. 그룹 테두리 양끝 여백에 놓으면 그룹 앞·뒤의 독립 탭으로 옮긴다. 탭을 꺼내거나 닫아 그룹에 하나만 남으면 자동으로 풀린다. 그룹은 화면 정리용이며 서버 폴더를 이동하지 않는다.
- 누른 채 1초가 되기 전에 움직이면 이동을 취소하고 일반 가로 스크롤을 유지한다. 이동 중 Esc·터치 취소·화면 바깥에 놓기는 변경을 취소한다. 이동으로 프로젝트를 활성화하거나 닫지 않는다. 탭에 키보드 초점이 있으면 `Alt+←/→`로 순서 이동, `Alt+Shift+←/→`로 이웃 탭과 그룹 만들기·추가, `Alt+↓`로 그룹 밖 맨 뒤로 이동한다.
- 탭을 우클릭하거나 **0.5초 이상 누른 뒤 1초 전에 놓으면** 아이콘 선택기를 연다(owner 전용). 키보드는 `Shift+F10`으로 연다. 아이콘은 해당 프로젝트의 `.mew/project-icon.json`에 저장해 모든 계정과 사이드바·프로젝트탭이 공유한다. SVG·이모지·라인 아이콘 선택값을 지원하며, 초기화하면 두 곳 모두 기본 폴더 아이콘을 표시한다. `+ 탭`은 글자 없이 `+` 아이콘만 보인다.
- 프로젝트 이름이 보이는 탭에는 `×`가 보인다. 누르면 확인 뒤 탭 목록에서만 닫으며, 파일·폴더는 지우지 않는다. 마지막 루트 프로젝트 탭은 닫을 수 없다.
- 프로젝트 탭에는 명령 버튼과 하위 폴더가 붙지 않는다. 사이드바의 하위 프로젝트를 누르면 해당 폴더가 독립된 프로젝트 탭으로 열리고 활성화된다(owner 전용). 이미 열린 경로는 기존 탭을 재사용하며 상위 프로젝트 탭은 남는다. 명령은 열린 프로젝트의 사이드바 ▶에서 실행한다.
- 절대경로 탭 추가·전환은 owner가 맡는다. manager는 셸과 같은 권한으로 현재 프로젝트 경로를 볼 수 있고, member·guest에는 절대경로 대신 일반 프로젝트 이름만 보인다.

작업 화면 상태(문서 탭·칸 배치·스크롤·트리 펼침·보조 패널)는 로그인 계정별 서버 원장에 남아 다른 기기·시크릿 창에서도 복원한다. 기존 `localStorage` 값은 계정 원장이 처음 비어 있을 때만 이관 원본으로 쓰며, 루트 프로젝트와 Documents의 내부 API 식별자 `.workspace`·`docs`는 호환을 위해 유지한다. 화면 폭·테마·언어·글꼴·작성 중 초안처럼 기기 특성이 강한 값은 브라우저에 남는다.

최근 프로젝트로 돌아갈 때는 이 로그인 세션에 남은 탭·배치·첫 폴더 목록을 먼저 복원한다. 화면 상태 캐시는 60초 동안 유지하며, 캐시가 없으면 계정 상태 조회를 서버 프로젝트 전환과 동시에 시작한다. 에이전트 탭 목록도 전환과 동시에 조회해 패널에서 같은 요청을 재사용한다. 폴더·파일 본문은 서버가 전환을 확인한 뒤 최신 내용을 읽으며, 캐시가 있는 화면을 비우고 기다리지 않는다. 새로고침·다른 기기에서는 서버 원장을 다시 읽는다. 전환과 뒤이은 복원 조회 중에는 화면 중앙에 로딩 인디케이터만 표시하며, 화면을 어둡게 덮거나 클릭·터치·키보드 조작을 막지 않는다. 모든 복원 요청이 완료·실패하면 자동으로 닫히며, 전환이 실패하면 현재 프로젝트에 머문다. 탭바의 별도 로딩 문구는 사용하지 않는다. [빠른 전환 개발 계약](../development/ui-contracts.md#루트-프로젝트-빠른-전환)을 따른다.

앱을 다시 열거나 다른 앱·브라우저 탭에서 돌아와 세션을 갱신할 때도 같은 전체 화면 로딩을 표시한다. 기존 화면은 계속 조작할 수 있으며 계정·프로젝트·목록·파일 권한 등 진행 중인 복원 조회가 모두 끝나면 인디케이터가 사라진다. 평소 파일 변경 알림과 자동저장에는 이 인디케이터를 띄우지 않는다.

프로젝트·문서·터미널·에이전트·브라우저·시트 탭 줄은 항목이 폭을 넘겨도 가로 스크롤바를 표시하지 않는다. 손가락·트랙패드·Shift+휠을 통한 가로 이동은 그대로 유지한다.

에디터의 파일 탭을 한 번 클릭하면 사이드바의 파일 보기에서 해당 파일 위치를 갱신한다. PC에서는 닫힌 사이드바도 연다. 모바일에서는 다른 파일 탭을 선택하면 에디터를 유지하고, 현재 보고 있는 탭을 다시 누를 때만 사이드바로 전환한다. 해당 문서/파일 보기로 전환하고 부모 폴더를 펼쳐, 파일 목록을 불러온 뒤 사이드바가 보일 때 해당 행으로 스크롤한다. 프로젝트 밖에서 연 파일은 제외한다.

### 없는 프로젝트 경로 만들기

프로젝트 추가 창에서 없는 경로로 이동하면 **「{존재하는 경로}에 {없는 경로 첫번째}가 없습니다. 경로를 생성할까요?」** 확인창이 열린다. 예를 들어 `/work`가 있고 `/work/new/project`가 없다면 `/work`에 `new`가 없다고 안내하고, 생성할 전체 경로 `/work/new/project`를 함께 보여준다. **경로 생성**을 누르면 중간 폴더까지 만든 뒤 해당 위치로 이동한다. 프로젝트 탭 추가는 **이 프로젝트 열기**로 따로 실행한다. 취소·Esc·뒤로가기는 확인창만 닫고 입력한 경로를 유지한다. 확인 문구·생성 버튼·전체 경로 안내는 한국어·영어·중국어·일본어로 표시한다.

권한 부족, 파일 경로, 깨진 심볼릭 링크는 생성 확인 대신 기존 탐색 오류로 표시한다. 생성 실패 시 주소를 유지하며 다시 시도할 수 있다. 경로 생성은 기존 새 폴더 작업과 같이 owner 전용이다.

### 파일 탐색기 즐겨찾기

프로젝트 추가와 서버 파일 탐색기 모두 **제목 바로 아래, 주소창 위**에 즐겨찾기 드롭다운을 표시한다. 버튼을 눌러 펼친 다음 항목을 누르면 그 폴더로 이동한다. **현재 폴더 추가**로 지금 보고 있는 경로를 저장하고, 드롭다운 항목의 × 또는 현재 폴더의 별 버튼으로 제거한다. Tab·방향키·Home/End로 목록 안의 이동·제거 버튼을 탐색하고 Enter/Space로 실행한다. Esc·뒤로가기·바깥 누름은 드롭다운만 닫는다. 목록의 폴더를 우클릭(모바일은 길게 누르기)해 **즐겨찾기로 추가**를 눌러도 상단 목록에 바로 반영된다. 파일에는 이 항목이 없다. 폴더를 삭제하는 작업은 아니다. 추가·제거는 로그인 계정별로 서버에 저장되어 다른 프로젝트·브라우저에서도 이어진다. 기본 항목을 제거해도 다시 열기·새로고침으로 되살아나지 않는다. 다시 추가하려면 주소창으로 해당 경로를 열고 **현재 폴더 추가**를 누른다.

- macOS: 서버 사용자 홈·바탕화면·다운로드·문서·사진·음악·동영상과 iCloud Drive를 기본으로 제공한다.
- WSL: WSL 홈, `/mnt/c` C 드라이브, 접근 가능한 Windows 사용자 프로필의 바탕화면·다운로드·문서를 제공한다. OneDrive 안으로 옮겨진 바탕화면·다운로드·문서도 확인하며 프로필/동기화 폴더 이름으로 구별한다.
- 공통: 홈의 기본 폴더와 감지된 OneDrive·Google Drive·Dropbox를 추가한다. 실제 존재하고 읽기·탐색 가능한 폴더만 자동으로 넣으며 같은 실제 경로의 별칭은 하나로 합친다.
- 새로고침은 자동 감지 결과와 계정의 저장값을 다시 읽는다. 저장 실패 시 기존 목록을 유지하고 오류를 표시한다. 저장했던 사용자 지정 폴더가 나중에 사라져도 즐겨찾기 제거는 가능하다.

### 클라우드 폴더 바로가기

클라우드 폴더 바로가기는 별도 영역 대신 두 탐색기 맨 위의 **즐겨찾기**에 통합했다. 바로가기를 누르면 경로로 이동할 뿐 프로젝트 탭을 추가하지 않는다. 프로젝트 추가 창에서는 원하는 하위 폴더까지 탐색한 뒤 **이 프로젝트 열기**로 연다.

- 감지 대상은 브라우저를 사용하는 기기가 아니라 **mew 서버 프로세스의 OS 파일시스템**이다. 계정 로그인·OAuth·클라우드 API·별도 동기화 기능은 사용하지 않는다.
- macOS는 `~/Library/CloudStorage`의 OneDrive·GoogleDrive·Dropbox 폴더, `~/Library/Mobile Documents/com~apple~CloudDocs`, `/Volumes`의 알려진 서비스 이름 폴더를 확인한다. CloudStorage 경로는 [Google 안내](https://support.google.com/drive/answer/12178485?hl=en-GB)와 [Microsoft 안내](https://support.microsoft.com/en-us/onedrive/missing-files-and-autosave-issues-with-onedrive-on-macos)를 참고한다.
- 공통으로 서버 사용자의 홈 바로 아래 서비스 이름 폴더와 `OneDrive`·`OneDriveConsumer`·`OneDriveCommercial` 환경변수의 절대경로를 확인한다. WSL에서는 `/mnt/c/Users/*`의 직계 동기화 폴더도 확인한다. 계정·조직별 여러 폴더를 표시하고 이름이 같으면 경로를 함께 보여 준다. 심볼릭 링크로 같은 실제 경로를 가리키면 하나만 표시한다.
- 알려진 위치를 얕게 확인하며 서버 전체를 재귀 검색하지 않는다. 존재하고 읽기·탐색 가능한 디렉터리만 제공한다. 이름 기반 감지는 로그인·동기화 상태를 보증하지 않으며, 온라인 전용 파일의 다운로드는 OS 동기화 앱이 담당한다. 사용자 지정 경로·다른 드라이브에 있어 감지하지 못한 폴더는 기존 주소창에서 직접 연다.
- 클라우드 감지는 `server/cloud-storage.ts`, 기본 즐겨찾기 조합은 `server/file-favorites.ts`, 공통 UI는 `src/components/file-browser-favorites.tsx`에서 관리한다. 기존 owner 전용 `GET /api/fs/cloud-storage`는 호환용으로 유지하며 새 UI는 서버 파일 탐색 권한의 `/api/fs/favorites`를 사용한다. 감지 자체는 파일·설정·탭 목록을 쓰지 않는다.

## 사이드바의 프로젝트 · 하위 프로젝트 · Documents

파일 탐색기 맨 위의 전체 너비 **문서 / 파일** 토글로 목록을 전환한다(영어: **Documents / Files**). 문서 보기에는 연결된 Documents 폴더만, 파일 보기에는 일반 파일·폴더와 하위 프로젝트, 문서 폴더 진입점을 표시한다. 문서 폴더 진입점은 연결된 폴더 이름(`docs` 등)으로 보이며, 클릭하면 펼치는 대신 문서 보기로 전환한다. 실제 경로가 `.mew/docs`여도 파일 보기의 맨 위에 표시한다. 선택한 보기는 계정·프로젝트별로 기억하며 각 목록의 펼침·스크롤을 따로 보존한다. 기존 Documents 펼침 상태는 문서 보기 선택으로 이관하고 저장값이 없으면 파일 보기로 시작한다. 토글은 목록과 겹치지 않는 독립 행을 차지하며 두 버튼이 너비를 나눠 사용한다. 에이전트 패널 + 탭의 토글과 같은 둥근 사각형·표면 색상을 사용하고 선택한 항목의 배경만 강조한다. 스크롤해도 위에 남고 검색·명령 화면에서는 숨긴다. 좌우 방향키·Home/End로도 전환할 수 있다. 게스트는 기존 문서 탐색 범위를 유지한다.

Docs 루트의 **그래프 보기** 버튼은 **문서 홈**보다 위에 표시된다. 내부 문서 링크를 그래프로 보고, 휠·두 손가락·확대/축소 버튼으로 크기를 바꾸거나 빈 영역을 끌어 이동한다. 노드를 선택하면 연결이 강조되고, 더블클릭 또는 **문서 열기**로 해당 문서를 연다. 검색·목록에서도 문서를 찾고 열 수 있다. 하위 폴더에는 그래프 버튼을 반복하지 않으며, 읽을 수 있는 Docs 내부 Markdown 문서만 연결한다.

Documents는 문서를 모아 보여 주는 탐색 영역이며 별도 에디터가 아니다. Documents 파일과 일반 파일은 같은 에디터 탭 목록에 함께 남고, 전환해도 편집 칸과 도킹 위치를 유지한다.

문서 목록은 상위 문서가 하위 문서를 갖는 형태다. `development` 이름을 누르면 `development/_development.md`를 열고, 왼쪽 화살표는 하위 목록만 펼친다. 대표 파일은 하위에 중복 표시하지 않는다. 기존 `development/MOC.md`도 같은 방식으로 열며 수정 없이 호환한다. 대표 문서는 그 영역의 홈처럼 제목과 첫 안내를 자연어로 적고, 실제 파일·폴더명도 자연어, 공백, 대문자, 한글을 사용할 수 있다. 이름을 바꾸면 기존 링크도 함께 갱신한다. 일반 클릭은 현재 탭에서 문서를 바꾸고, Ctrl/Cmd+클릭은 별도 탭으로 연다. 저장되지 않은 본문은 보존한다.

각 문서 오른쪽 **+**로 하위를 만든다. `dev.md`에 처음 자식을 추가하면 본문이 `dev/_dev.md`로 이동하고 자식은 `dev/child.md`가 된다. 마지막 자식을 삭제하거나 다른 곳으로 옮기면 `dev.md`로 돌아간다. 이름 변경은 폴더와 대표 파일에 함께 적용한다. 기존 MOC의 일괄 이전은 하지 않으며 해당 폴더의 하위 생성·이름 변경·이동 때 새 이름으로 전환한다. 상세 저장·링크 보정 계약은 [Documents 페이지](../development/document-pages.md)를 따른다.

파일 목록 맨 아래에는 PC·모바일 모두 300px의 스크롤 여백을 둬 마지막 항목도 화면 위쪽으로 올려 볼 수 있다. 문서와 파일 보기 각각에 적용해 마지막 항목을 화면 위쪽으로 올려 볼 수 있다.

파일 보기의 새 파일 생성은 입력한 파일명과 확장자를 그대로 사용하며, 확장자를 생략해도 `.md`를 붙이지 않는다. `/api/new-document`는 일반 파일을 빈 내용으로 만들고, `.md` 파일에만 문서 초기 내용과 Documents의 MOC 등록을 적용한다. 문서 보기의 **새 문서**는 `.md`를 자동으로 붙이고 상위·하위 구조를 적용하는 별도 페이지 API를 사용한다.

사이드바 상단에는 탐색기(폴더) · 파일명 검색(돋보기, `Ctrl+P`) · 파일 내용 검색(문서 돋보기, `Ctrl+Shift+F`) · 현재 루트 프로젝트 명령(▶) 탭이 있다. 루트 명령 ▶를 누르면 파일 탐색기·Documents 없이 루트의 `.mew/cmd-button.json` 목록만 보인다. 로그인 사용자에게 파일 보기의 **새 파일**·**새 폴더**, 문서 보기의 **새 문서**를 표시한다. 파일 보기에서는 선택한 폴더 또는 파일의 부모 폴더를 사용한다. 문서 보기에서는 선택한 문서에 하위를 추가한다. 선택이 없으면 현재 보기의 루트에 만든다. 파일 탭에서 위치 표시·새 파일 만들기를 요청하면 그 파일에 맞는 보기로 전환한다. 하위 프로젝트 안의 파일·폴더는 그 프로젝트 탭을 연 뒤 만든다. 이름 입력 후 Enter로 생성하며 Esc로 취소한다. Git은 사이드바에 버튼을 두지 않고 헤더 햄버거 메뉴 또는 `Alt+G`로 연다.

파일 보기 위쪽에는 직계 하위 프로젝트의 탭 열기 항목이 선다. 프로젝트 행의 오른쪽 화살표는 별도 프로젝트 탭으로 이동한다는 뜻이다. 그 뒤에는 현재 루트의 나머지 파일·폴더가 별도 Project 폴더 없이 바로 이어진다. Documents를 감싸던 상단 펼침 행은 표시하지 않는다.

- **Documents** — 현재 프로젝트가 고른 docs 폴더. 상단 문서 토글을 선택하면 내용이 보이고, owner가 해당 토글을 우클릭하면 기존 폴더 변경·가져오기·내보내기 설정 창이 열린다. 내부 식별자와 API는 계속 `docs`다.
- 모바일에서는 사이드바의 파일·폴더를 **0.5초 이상 누른 뒤 1초가 되기 전에 손을 떼면** 데스크톱 우클릭과 같은 항목 메뉴가 열린다. 폴더 메뉴의 **Git 저장소로 만들기**는 선택한 폴더 자체에서 `git init`한다(owner·manager). 1초까지 계속 누르면 이동 모드가 되어 대상 폴더로 끌어놓을 수 있다. 그 전에 움직이면 스크롤로 처리한다([모바일 조작](editor.md#모바일과-전체화면)). 폴더 안에 실제 `.mew` 디렉터리가 있으면 깊이에 관계없이 **하위 프로젝트**다. 루트 직계 하위 프로젝트는 파일 보기 위쪽에 나타나며, 클릭·터치·Enter·Space로 해당 폴더의 프로젝트 탭을 연다. 그 행에는 내부 파일이나 명령 메뉴를 펼치지 않는다. `.mew`가 없는 루트 파일·폴더는 이 항목들 뒤에 별도 컨테이너 없이 바로 나열한다. owner·manager는 숨김 폴더도 보되 `.git`·`node_modules`·`.data`는 기존 차단·성능 규칙에 따라 제외한다. 중첩 하위 프로젝트는 실제 부모 폴더 안에서 프로젝트 아이콘과 탭 열기 화살표로 표시하고 같은 방식으로 연다. 하위 프로젝트 안의 더 깊은 프로젝트는 상위 프로젝트 탭을 연 다음 탐색한다. 일반 폴더 안에도 둘 수 있으며 중간 폴더를 자동으로 프로젝트로 바꾸지 않는다.

문서 보기에서는 `_폴더이름.md`·기존 MOC를 폴더 대표 본문으로 열고 자식 목록에서 숨긴다. Docs 루트의 MOC는 **문서 홈**으로 표시한다. 일반 파일 보기의 `MOC.md`·`_MOC.md`는 기존대로 폴더를 펼쳤을 때 첫 줄의 지도 아이콘 + `Map Of Contents`로 표시한다.

프로젝트 열기는 기존 루트 전환과 같은 owner 전용 동작이다. 다른 역할에는 열기 동작이 비활성화된다. 일반 폴더는 펼쳐 탐색하고 Documents는 상단 토글로 선택한다. 이전에 저장된 하위 프로젝트 펼침 상태는 무시하며, 내부 파일을 자동으로 읽지 않는다. 전환 실패 시 현재 프로젝트에 머물고 오류를 표시한다. 서버의 활성 루트는 기존처럼 공유되므로 다른 접속자도 루트 변경을 받는다. 실행 중 에이전트는 기존 프로젝트에 계속 연결된다([ADR 0158](../../../.mew/docs/decisions/0158-mew-subprojects-open-root-tabs.md)).

### 폴더를 하위 프로젝트로 지정

쓰기 가능한 폴더를 우클릭(모바일은 길게 누른 뒤 놓기)하고 **하위 프로젝트로 만들기**를 누른다. 선택한 폴더에 빈 `.mew` 디렉터리를 생성하고 트리에 바로 반영한다. 기존 파일과 `.mew` 설정은 보존하며 Git 초기화나 루트 프로젝트 전환은 하지 않는다.

- `liiiiv`를 열면 `abc/def`도 그 위치에서 하위 프로젝트가 된다. `abc`도 프로젝트라면 그 안의 중첩 프로젝트이고, 일반 폴더여도 `def`를 지정할 수 있다. `abc` 자체를 루트로 열면 `def`는 직계 프로젝트로 보인다.
- 루트·이미 지정된 프로젝트·파일·읽기 전용 폴더·`.mew` 설정 내부에는 생성 메뉴가 없다. 로그인 계정의 파일 읽기·쓰기 권한과 대상 폴더 및 `.mew` 경로의 편집 권한이 필요하다.
- `.mew`라는 **파일이나 링크**는 표식으로 인정하지 않는다. 같은 이름의 파일·링크가 있으면 내용을 보존하고 오류를 표시한다. 심볼릭 링크 경로로 생성할 수 없다.
- 중첩 프로젝트의 ▶는 해당 폴더의 `.mew/cmd-button.json`을 사용하고 그 폴더에서 실행한다. 다른 경로에 이름이 같은 프로젝트가 있어도 명령과 세션이 섞이지 않는다. 터미널 권한이 있는 계정에게만 ▶를 표시한다.
- 검색의 `@` 범위 선택은 기존 Documents·직계 하위 프로젝트를 유지한다. 중첩 프로젝트 내용은 이를 포함하는 기존 범위에서 검색된다.

개발 계약: `POST /api/subprojects?project=`에 `{path}`(현재 트리 기준 상대경로)를 보낸다. 생성은 멱등이며 표식과 부모 행의 catalog를 갱신한다. 명령 API(`/api/cmd-buttons`, `/api/cmd-buttons/run`)는 선택적 `path`로 중첩 실행 폴더를 받는다. 편집·협업의 기존 프로젝트 식별자는 바뀌지 않는다. 결정 근거는 [ADR 0151](../../../.mew/docs/decisions/0151-mew-nested-subprojects.md)이다.

## 파일·폴더 관리

사이드바에서 선택한 파일·폴더·문서·하위 프로젝트는 배경으로 구분하며 테마 색 테두리를 표시하지 않는다.

프로젝트 작업, 서버 파일 탐색기의 이름 변경·삭제·프로젝트 열기, 사이드바 Git 초기화, Git 커밋 작업, 검색의 일괄 치환은 앱 자체 입력·확인 컴포넌트를 사용한다. 브라우저 `prompt`·`confirm` 대신 앱 테마를 따르는 대화상자를 사용하며, Tab 포커스를 창 안에 유지하고 닫으면 호출한 컨트롤로 복원한다. 삭제 등 위험 작업은 취소 버튼에 먼저 포커스한다.

사이드바의 파일·폴더를 우클릭하거나 모바일에서 길게 눌러 항목 메뉴를 연다. 로그인 사용자에게 생성·이름 변경·복제·복사·잘라내기·붙여넣기·삭제 등의 작업을 제공한다. 선택한 항목과 역할에 따라 가능한 메뉴만 표시한다.

- `F2`는 이름 변경, `Delete`는 삭제, `Insert`는 새 파일, `Shift+Insert`는 새 폴더다. `Ctrl+C`·`Ctrl+X`로 복사·잘라내기 후 대상 폴더에서 `Ctrl+V`로 붙여넣는다.
- 새 파일은 확장자까지 입력한다. 확장자를 생략하면 확장자 없는 파일을 만든다.
- 파일 메뉴의 다운로드로 원본을 받는다. 파일·폴더를 다른 폴더에 끌어놓으면 이동하고, 기기의 파일을 사이드바에 끌어놓으면 업로드한다([드롭 위치별 동작](editor.md#사이드바-항목-끌어놓기)).
- 파일 이동·잘라내기 붙여넣기 후 Git 이력을 기록할 때, 아직 Git이 추적하지 않던 원래 경로가 사라져도 이동은 정상 완료된다. 기존에 추적하던 파일·폴더는 원래 경로의 삭제와 새 경로를 함께 기록한다.
- manager·owner는 폴더 메뉴의 **Git 저장소로 만들기**로 그 폴더 자체를 초기화할 수 있다. 서버의 임의 경로에 새 프로젝트를 만드는 것은 owner의 [프로젝트 선택 창](#프로젝트-탭)에서 한다.
- 파일 권한은 owner의 계정 관리에서 [각 계정과 guest별로 설정](../configuration/environment.md#내-계정과-계정-관리)한다. 사이드바는 허용된 파일과 읽기 전용 상태를 반영한다.

## Documents 폴더 계약

Documents의 에이전트 안내·문서 초기화 GUI와 CLI는 [프로젝트 문서 설정](project-setup.md)을 따른다. 프로젝트별 `.mew/agent-context.json`의 경로가 기존 `MEW_DOCS`와 기본 경로보다 우선한다.

Documents는 탭이 아니라 사이드바의 가상 폴더다. 실제 폴더는 현재 루트 프로젝트 안에서 owner가 고르며 기본은 `docs`다. 설정이 없고 옛 `.mew/docs`만 있으면 그 위치를 그대로 쓴다. 폴더가 없으면 빈 Documents 폴더를 만든다.

- 내부 식별자 `docs`는 유지한다. 문서·트리·검색·협업 방·git·저장 키가 이 이름을 공유하므로 UI 배치와 함께 바꾸지 않는다.
- 현재 Documents의 실제 최상위 폴더는 루트 프로젝트 트리에서 중복 표시하지 않는다.
- owner가 사이드바의 Documents를 우클릭하면 `DocsSettingsModal`이 열린다. 폴더 변경은 현재 루트 프로젝트 안에서만 허용하고, 가져오기는 기존 내용을 지운 뒤 교체하며, 내보내기는 대상 아래 `docs`로 복사한다.
- 폴더 선택은 서버 파일시스템을 읽는 `GET /api/fs/dirs`를 쓰며 owner 전용이다.

| 라우트 | 역할 | 하는 일 |
| --- | --- | --- |
| `GET /api/fs/dirs?path=` | **owner** | 그 폴더의 하위 폴더 목록 |
| `POST /api/docs/root` `{path}` | **owner** | 현재 루트 프로젝트 안에서 Documents 폴더 변경 |
| `POST /api/docs/import` `{path}` | **owner** | Documents를 통째로 교체(되돌릴 수 없음) |
| `POST /api/docs/export` `{path}` | **owner** | `{path}/docs`로 복사 |
| `POST /api/docs/pages/{create,rename,delete,move,copy}` | 로그인·파일 쓰기 권한 | 상위·하위 문서의 생성·전환·이동·이름 변경·삭제·복사 |

## 서버 파일 탐색기

헤더 메뉴에서 여는 프로젝트 독립 팝업(`components/ServerFileExplorer.tsx`). 기본 경로는 서버 사용자의 홈이고, 주소 입력·드롭다운으로 `~` 또는 절대경로를 연다. 폴더는 펼칠 때 한 단계씩 읽으므로 홈 전체를 미리 재귀 스캔하지 않는다. 숨김 항목을 포함해 mew 서버의 OS 사용자가 읽을 수 있는 모든 파일·폴더가 대상이다. 프로젝트 추가와 같은 공통 탐색 UI를 쓰며, 이름 필터는 현재 경로의 최상위 목록을 좁힌다. 폴더 펼침과 하위 항목 우클릭은 유지한다. Tab 포커스는 창 안에 머물고, 닫으면 호출한 버튼으로 돌아간다. 즐겨찾기와 클라우드 폴더는 두 창이 공유하고, 새 폴더·Git 작업·프로젝트 열기 확인 버튼은 프로젝트 추가 창에서 제공한다.

- 파일을 누르면 현재 프로젝트는 그대로 둔 채 포커스된 편집 칸의 **미리보기 탭**으로 열린다. 외부 탭은 자동저장할 수 있지만 협업·댓글·git 이력·프로젝트 규칙을 쓰지 않고, 새로고침 탭 복원에도 남지 않는다.
- 프로젝트 추가 창과 서버 파일 탐색기의 우클릭 메뉴는 사이드바와 같은 공통 컴포넌트를 사용한다. 이름 변경·복사·잘라내기·붙여넣기·삭제를 제공하며, 폴더에는 **즐겨찾기로 추가**도 표시한다. 붙여넣기는 우클릭한 폴더 안으로, 파일을 우클릭했다면 그 파일이 있는 폴더 안으로 실행한다. 복사하거나 잘라낸 항목이 없으면 붙여넣기는 비활성화된다. 모바일에서는 길게 눌러 같은 메뉴를 연다. 잘라내기 성공 후 원본과 대상 목록 및 열린 외부 파일 경로를 갱신한다. 파일은 다운로드할 수 있다. **모바일에서 브라우저가 셀룰러 연결을 확인하고 파일이 100MiB를 넘으면**, 실제 내려받기 전에 데이터 요금 안내와 계속 다운로드 확인을 띄운다. Wi‑Fi·데스크톱·연결 종류를 알 수 없는 브라우저는 바로 내려받는다.
- 폴더의 **프로젝트로 열기**는 그 폴더 자체를 루트 프로젝트 탭에 추가하고 활성 프로젝트로 연다. owner 전용이며 활성 루트 전환 계약에 따라 현재 화면을 새 루트로 교체한다.
- 탐색·읽기·쓰기 API는 **서버 파일 탐색기 기능이 허용된 로그인 계정**이 사용한다(기본 manager·owner). 워크스페이스 경계나 `.git`·`node_modules` 차단 규칙을 적용하지 않으며 셸과 동일한 OS 권한 범위다. 공개 서버의 권한 의미는 [SECURITY.md](../../SECURITY.md)를 따른다.

| 라우트 | 역할 | 하는 일 |
| --- | --- | --- |
| `GET /api/fs/favorites` · `PUT /api/fs/favorites` `{path, favorite}` | 서버 파일 탐색 기능이 허용된 로그인 계정 | OS/클라우드 기본 폴더와 계정별 즐겨찾기 조회·추가·제거 |
| `GET /api/fs/entries?path=` | manager·owner | 절대경로 폴더의 파일·하위 폴더 한 단계 |
| `GET/PUT /api/fs/file` | manager·owner | 외부 텍스트 파일 읽기·저장(텍스트 열기는 10MB 이하) |
| `POST /api/fs/rename` · `DELETE /api/fs/path` · `POST /api/fs/paste` | manager·owner | 이름 변경·재귀 삭제·복사/이동 |
| `GET /api/fs/raw` · `GET /api/fs/download` | manager·owner | 외부 미디어 스트리밍·파일 다운로드 |
| `POST /api/fs/directory` `{path}` | owner | 확인한 전체 경로의 없는 중간 폴더까지 생성(기존 폴더는 유지) |
| `POST /api/fs/open-project` | owner | 선택 폴더 자체를 루트 프로젝트로 열고 활성화 |
| `POST /api/fs/folder` · `POST /api/fs/git/init` · `POST /api/fs/git/clone` | owner | 현재 폴더 안 생성·Git 초기화·저장소 clone |

## Git 작업 패널

변경 파일의 체크박스 영역에서 터치하거나 마우스를 누른 채 위아래로 드래그하면 시작 파일이 미선택이면 지나간 파일까지 모두 선택하고, 체크된 파일에서 시작하면 모두 해제한다. 단일 탭·클릭은 해당 파일의 선택을 켜거나 끈다. 드래그 중 목록 위·아래 가장자리에 머무르면 자동으로 스크롤하며 선택·해제가 이어지고, 손을 떼면 멈춘다.

**변경사항** 바 맨 오른쪽의 커밋 아이콘과 로봇 아이콘은 각각 **커밋**, **AI 자동 커밋** 버튼이다. 커밋 아이콘을 처음 누르면 하단에 제목·설명 입력란이 열리고 제목에 초점이 놓인다. 제목을 작성하고 파일을 선택한 뒤 같은 아이콘을 다시 누르거나 제목 입력란에서 Enter를 누르면 커밋한다. 성공하면 입력란을 비우고 숨기며 실패·로그인 취소 시 초안을 유지한다. 로봇 아이콘은 입력란이 닫혀 있어도 AI 자동 커밋을 연다. 마우스를 올리면 기존 번역 문구를 툴팁으로 표시한다.

독의 **Git** 또는 `Alt+G`로 현재 프로젝트 루트의 Git 패널을 바로 열고 접는다. 하위 프로젝트는 해당 프로젝트 탭으로 전환한 뒤 Git을 연다. Documents·중첩 저장소 선택 목록이나 새 저장소 탭 버튼은 없다. 현재 루트 자체에 Git 저장소가 없으면 빈 상태를 표시하며 상위·하위 저장소를 대신 열지 않는다.

Git 패널 상단에는 다른 패널 탭 바와 같은 36px 높이의 바에 Git 아이콘과 **Git** 제목, 오른쪽 닫기 버튼을 표시한다. 데스크톱에서는 왼쪽 손잡이로 패널을 옮기며, 모바일에서는 다른 패널처럼 손잡이를 숨긴다. 경계선으로 크기를 조절한다. 상단 바는 상세·diff·로딩·저장소 없음 상태에서도 유지한다. GitHub 로그인 버튼·연결 계정 정보는 패널 헤더의 닫기 버튼 왼쪽에 표시하며 모든 본문 상태에서 같은 위치를 유지한다. 닫기 `×`·포커스된 Git 화면의 `Ctrl+W`는 패널을 접는다. 다시 열면 상세 화면과 작성 중인 커밋을 이어 쓴다. 다른 영역을 클릭해도 닫히지 않으며 모바일 전면 전환·Esc·뒤로가기는 공통 패널 규칙을 따른다.

계정의 프로젝트별 작업 상태에 열림 상태·배치를 저장한다. 예전 Documents·하위 저장소 탭 저장분은 현재 프로젝트 루트 하나로 정리하며 다시 열지 않는다. 상세 화면과 커밋 초안은 현재 패널 메모리에만 유지하며 프로젝트 전환·새로고침 때 초기화한다. 편집기의 파일 탭은 별개이며 기존 `mew:git:` 가상 파일 탭은 계속 복원하지 않는다([ADR 0160](../../../.mew/docs/decisions/0160-mew-git-current-project-only.md)). 통합 저장소 선택기를 제거한 이유는 프로젝트 탭과 Git 작업 범위를 일치시키기 위해서며, 같은 선택기의 재도입에는 후속 결정이 필요하다.

- 첫 화면은 위에서부터 **커밋 기록**, **변경사항** 파일 목록 순서이며 **커밋 작성** 영역은 기본으로 숨긴다. 변경사항 바의 새로고침 버튼은 제거하고 자동 갱신을 유지한다. 커밋 입력란을 열면 아래의 원래 위치에 제목·설명만 표시하며 기본 높이는 약 20:55:25이다. 입력 영역은 터미널·에이전트 본문의 `surface-deep`, 입력칸은 에이전트 입력창의 `surface` 색상을 사용해 밝은·어두운 테마를 따른다. 제목 입력칸 높이와 변경사항 바의 두 아이콘 버튼 크기는 28px이다. 작성 영역 위쪽 경계선을 마우스·터치로 위로 끌면 설명 공간이 늘어나고 아래로 끌면 줄어든다. 경계선에 포커스 후 위·아래 화살표 키로 12px씩 조절하고 Home·End로 최소·최대 높이를 선택한다. 두 목록은 따로 스크롤한다. 가운데 경계선을 드래그하거나 포커스 후 위·아래 화살표 키로 높이를 조절한다(Home·End는 최소·최대). 기록과 변경사항·작성의 기본 비율은 20:80이며 조절값과 목록 스크롤은 상세 이동·패널 닫기/재열기 동안 유지하고 프로젝트 전환·새로고침 때 초기화한다. 본문은 Git 상단 바 아래에서 시작하며 중복된 프로젝트 루트 문구는 표시하지 않는다.
- 커밋 기록은 모든 ref의 최근 최대 300개를 topo-order로 표시한다. 28px 한 줄에 가는 그래프 레인과 제목·상대 시간·7자리 해시·작성자를 표시한다. 시간은 `0분 전`, `59분 전`, `1시간 전`, `2일 전`처럼 분·시간·일 중 가장 큰 단위 하나만 쓰며 분마다 갱신한다. 넓은 패널에서는 ref도 표시하고 긴 제목·작성자는 말줄임한다. 작성자 칸은 짧은 이름에 불필요한 고정 너비를 예약하지 않으며 행 오른쪽 여백은 8px이다. 행 툴팁과 상세에서 전체 정보를 확인한다.
- Git 패널 너비가 400px 미만이면 Git 아이콘·제목을 숨기고 브랜치·Pull·Push 등 메뉴 공간을 확보한다.
- 타이틀바의 Pull·Push 오른쪽 **origin** 아이콘으로 원격 저장소를 새 탭에서 연다. GitHub 저장소는 GitHub 아이콘, 다른 호스트는 외부 링크 아이콘을 표시한다. origin이 없거나 웹 링크로 변환할 수 없는 주소는 버튼을 표시하지 않는다. GitHub 로그인 없이 사용할 수 있다.
- 타이틀바의 **브랜치 드롭다운**에서 로컬·이미 조회된 원격 브랜치를 검색하고 선택해 전환한다. **새 브랜치**에서 이름과 기준 브랜치·태그·커밋을 지정하면 생성 후 바로 전환한다. 기본 base는 현재 HEAD이며 커밋 해시도 직접 입력할 수 있다. 원격 브랜치를 직접 선택하면 추적 로컬 브랜치를 만든다. 별도 이름으로 생성한 브랜치는 upstream을 자동 설정하지 않는다. GitHub 로그인이나 자동 fetch 없이 로컬에서 실행하며, 변경사항이 덮어써질 경우 Git이 거부하고 오류를 표시한다. 강제 전환·자동 stash는 하지 않는다.
- 타이틀바의 GitHub 계정 왼쪽 **↓ Pull**, **↑ Push** 버튼은 현재 브랜치의 upstream과 동기화한다. 원격 추적 브랜치가 없으면 먼저 Git에서 upstream을 설정한다. Pull은 fast-forward만 허용하고 자동 merge·rebase·stash를 하지 않는다. Push는 현재 브랜치만 보내며 강제 push·태그·하위 모듈 전송을 하지 않는다. 실행 중에는 버튼을 비활성화하고 완료 후 변경 파일·기록을 갱신한다. 커밋 초안과 여전히 변경된 파일의 선택은 유지한다. 실행한 버튼 안에 `압축 42%`·`전송 68%`처럼 실제 단계별 진행률을 짧게 표시한다. 전송 100% 뒤 원격 확인을 기다리고, 성공하면 체크 아이콘과 **완료**가 3초간 표시된 뒤 원래 버튼으로 돌아온다. 별도 하단 토스트는 띄우지 않는다. 인증·연결 오류와 분기된 이력은 패널 오류 영역에서 확인한다. 진행 연결이 끊기면 저장소 상태를 확인하고 다시 판단하며 자동 재전송하지 않는다.
- 기본 화면의 변경 파일을 누르면 바로 diff를 열고 뒤로가기로 기본 화면에 돌아온다. 파일 앞 체크박스는 커밋 포함 여부만 바꾸며 diff를 열지 않는다. 전체 선택 체크박스 오른쪽에 **선택 파일 수 / 전체 변경 파일 수**, **변경사항** 제목 순서로 표시한다. 좁은 폭에서도 숫자는 유지하고 제목을 말줄임한다. 과거 커밋은 `커밋 기록 → 커밋 상세 → 파일 diff`로 이동한다. 상세·diff의 왼쪽 위 뒤로가기는 직전 단계로 돌아가며 Git 닫기 `×`는 어느 단계에서든 패널을 접는다([ADR 0170](../../../.mew/docs/decisions/0170-mew-git-selected-files-and-composer.md)).
- **커밋 기록·브랜치 정보·커밋되지 않은 변경사항**과 열린 작업트리 diff는 패널을 보는 동안 조회 완료 후 2초 간격으로 자동 갱신된다. 외부 편집기·터미널·에이전트의 파일 추가·수정·삭제·stage 변경도 반영한다. 커밋 초안과 스크롤, 여전히 변경된 파일의 선택은 유지하고 새 파일은 체크하지 않는다. 변경이 사라진 파일은 목록·선택에서 빠지고 열린 diff는 빈 상태가 된다. 패널이나 브라우저 탭이 숨겨지면 조회를 멈추며 다시 보거나 창으로 돌아오면 곧바로 확인한다. 느린 조회는 겹치지 않고 실패 시 기존 내용을 유지한 채 오류를 표시하며 다음 주기에 재시도한다. 외부 터미널·에이전트에서 만든 새 커밋과 브랜치 변경도 수동 새로고침 없이 반영한다.
- 커밋 상세는 본문과 변경 파일을 표시한다. 현재 변경 목록은 수정·추가·삭제·미추적 파일을 각각 표시한다. 파일별 체크박스나 **변경 파일 전체 선택**으로 범위를 정한 뒤 `커밋`을 누른다. 패널 초기 진입·프로젝트 전환 시 처음 불러온 변경 파일은 모두 선택한다. 이후 새로 발견된 파일은 자동 선택하지 않으며 선택이 없거나 제목이 비어 있으면 커밋할 수 없다. 선택한 파일의 현재 작업트리 내용을 커밋하고, 선택하지 않은 파일은 기존 stage 상태와 작업 내용을 유지한다. 이름 변경은 이전·이후 경로를 함께 포함한다. 새로고침은 여전히 변경된 파일의 선택을 유지한다.
- **AI 자동 커밋** → 기존 에이전트셋 선택 또는 **새 에이전트셋 추가** → **자동 커밋 실행**으로 선택 파일을 작업 단위로 나눠 실제 커밋을 만든다. 한 작업이면 하나, 독립적인 작업이 섞이면 여러 커밋을 만든다. 초기 구현은 파일 단위 분리이며 한 파일 내부 hunk는 나누지 않는다. 새로 만든 셋은 바로 선택되며 에이전트 창에서도 재사용한다. 런타임 설치·로그인과 Git·에이전트 기능 권한이 필요하다.
- 모든 런타임과 Git 패널은 서버 데이터 폴더의 `skills/commit/SKILL.md` 하나를 사용한다. **Skills 관리 → Mew → commit → 수정**으로 지침 파일을 편집한다. 다음 자동 커밋 작업과 `/commit`에 반영되며 런타임 전역·프로젝트 폴더에 복사하지 않는다.
- 작업은 전용 tmux·독립 ACP 세션에서 실행한다. 창을 닫거나 새로고침해도 계속되며 같은 프로젝트에서 다시 열면 진행 로그·만든 커밋의 해시·제목·포함 파일·남긴 파일과 이유를 확인한다. **작업 중단**은 진행 중인 Git 명령이 끝난 뒤 다음 커밋부터 막는다. 이미 만들어진 커밋은 실패·중단 때도 보존하고 결과에 남긴다. 재실행은 새로 남은 변경을 선택한 뒤 한다.
- AI가 계획을 반환하면 Mew가 선택 범위·중복·누락과 HEAD·브랜치·작업 내용·stage 변경을 검사하고 순서대로 커밋한다. 선택 밖 파일과 stage, 수동 작성 영역의 제목·설명은 보존한다. 분석한 Git 트리를 사용하므로 실행 중 새로 편집된 내용은 커밋에 섞이지 않는다. push하지 않는다. 이전 버전의 메시지 초안을 자동 실행하지 않는다.
- 선택 파일 전체를 분석할 수 없을 만큼 크면 파일 수를 줄이도록 안내하며 부분 diff로 자동 커밋하지 않는다. 충돌, 10분 분석 시간 초과, 로그인·모델·응답 형식·Git 오류는 실패로 표시한다. AI의 도구 승인 요청은 거절하고 Mew가 Git 실행을 담당한다. 기존 Git hook·서명 설정은 적용된다. 상세 계약은 [에이전트 세션](../development/agent-sessions.md#git-ai-commit-작업)을 따른다.
- 상세의 변경 파일을 누르면 패널이 파일 diff 화면으로 바뀌고 이전·이후 줄 번호와 추가·삭제 줄을 표시한다. 파일을 누를 때만 patch를 읽으므로 전체 diff가 첫 응답을 막지 않는다.
- 커밋 우클릭은 해시 복사, branch/tag 생성, detached checkout, cherry-pick, revert를 제공한다. checkout·cherry-pick·revert는 확인 뒤 실행하며 강제 checkout·reset·clean은 제공하지 않는다. 작업 트리 변경이나 충돌 때문에 Git이 거부하면 오류를 그대로 표시한다.
- API는 저장소 상대경로와 구조화된 작업 인자만 받으며 임의 셸 문자열을 받지 않는다. 지정한 폴더 자체에 `.git`이 있어야 하고 상위 저장소를 암묵적으로 찾아가지 않는다.

| 라우트 | 역할 | 하는 일 |
| --- | --- | --- |
| `GET /api/git/repository` · `GET /api/git/log` | manager·owner | 저장소 상태와 커밋 그래프 원본 |
| `GET /api/git/repositories` | manager·owner | 요청한 프로젝트 스코프 루트만 확인(재귀 탐색 없음) |
| `GET /api/git/commit` · `GET /api/git/diff` | manager·owner | 과거 커밋 메타데이터·변경 파일과 선택 파일 patch |
| `GET /api/git/working-tree` · `GET /api/git/working-tree/diff` | manager·owner | 현재 작업트리 변경 파일과 선택 파일 patch |
| `POST /api/git/commit` · `POST /api/git/action` | manager·owner | 선택 파일 커밋과 과거 커밋 대상 허용 작업 |
| `GET /api/git/branches` · `POST /api/git/branches` | Git 기능 + 프로젝트 전체 파일 접근 | 브랜치·태그 조회와 base 지정 생성/브랜치 전환. 쓰기 요청의 workspace 검증 |
| `POST /api/git/remote` | Git 기능 + 프로젝트 전체 파일 접근 | 현재 workspace를 검증한 뒤 `pull` 또는 `push` 실행 |

### GitHub 로그인

로그인 팝업은 오른쪽 위 X로 닫는다. 코드 옆 복사·외부 승인, 하단 새로고침·로그인 취소·연결 해제는 아이콘 버튼으로 표시하며 마우스를 올리면 조작 이름이 나온다. **로그인 계속하기**는 팝업 안에서 승인 화면을 열고 외부 승인 아이콘은 GitHub를 새 탭으로 연다.


Git 연결은 **Mew 로그인 계정마다 별도**다. 처음에는 미연결이며 서버의 기존 `gh`·SSH 인증을 가져오지 않는다. 커밋·AI 자동 커밋·Pull/Push를 시도했을 때 연결이 없으면 로그인 창을 연다. 로그인 완료 후 작성 내용과 선택 파일을 유지해 원래 요청을 한 번 실행한다. 닫거나 취소하면 작업을 실행하지 않는다.

Git 패널 헤더의 **GitHub 로그인**에서도 연결할 수 있다. 로그인 시작 → **코드 복사** → **GitHub에서 승인**으로 공식 GitHub 화면에 로그인하고 코드를 입력한다. 브라우저 기능이 허용되어 있으면 **로그인 계속하기**로 Mew 내부 브라우저를 사용할 수도 있다. 승인할 GitHub 계정을 확인한다. 완료되면 헤더에 연결된 계정이 표시된다.

- 연결은 Mew 재로그인·새로고침·서버 재시작 뒤에도 유지한다. **연결 해제** 후 다시 로그인하면 계정을 바꿀 수 있다. 해제는 자기 Mew 연결에만 적용되고 GitHub 웹 로그인이나 다른 사용자의 연결을 끊지 않는다.
- 기본 Mew OAuth 앱이 포함되어 별도 서버 설정 없이 연결한다. 자체 앱을 쓰는 운영자만 `MEW_GITHUB_CLIENT_ID`를 [환경 설정](../configuration/environment.md#github-oauth-연결)에 지정한다. gh 설치와 client secret은 필요하지 않다.
- 계정 연결에는 Mew 로그인과 Git 또는 파일 쓰기 기능이 필요하다. Git 작업 자체는 기존 기능·파일 접근 권한을 확인한다. 내부 승인 화면에만 browser 기능과 Chromium이 필요하다.
- 커밋 작성자·커미터는 연결한 계정의 이름과 GitHub 비공개용 이메일로 기록한다. 저장소의 공용 Git 작성자 설정은 바꾸지 않는다. cherry-pick 원저자는 유지한다.
- 파일 자동저장·생성·복사 등은 미연결 상태에서도 사용할 수 있다. 이때 부수적인 자동 커밋은 생략하며 명시적으로 커밋할 때 연결한다.
- 최초 제공자는 github.com이다. GitHub SSH remote는 저장된 주소를 바꾸지 않고 전송할 때 HTTPS로 사용한다. 저장소 접근 권한·조직 SSO 승인·브랜치 보호는 GitHub에서 정한다. GitLab·Enterprise는 확장 가능한 제공자 계약만 마련했으며 아직 지원하지 않는다.
- 승인 코드는 만료될 수 있으며 토큰 만료·승인 철회 시 다시 로그인한다. 서버 재시작 전 진행하던 승인은 새로 시작한다. 로그인만으로 Push를 실행하지 않는다. 대기 중이던 Push가 있는 경우에만 로그인 성공 후 이어서 실행한다.
- 이 연결은 Mew가 관리하는 커밋·원격 작업에 적용한다. 터미널·일반 에이전트의 셸 명령과 외부 폴더 clone은 기존 OS 환경을 사용한다.

API·토큰 저장·테스트와 실행 경계는 [계정별 Git 연결 계약](../development/git-connections.md), 결정 변경은 [ADR 0179](../../../.mew/docs/decisions/0179-mew-account-git-connections.md)를 따른다.

## 현재 제공하지 않는 홈 화면

워크스페이스 스코프 홈 고정 탭과 최상위 하위 폴더 전체를 나열하던 프로젝트 격자 진입점은 없다. 예전 홈의 할 일·달력 위젯도 현재 화면에서 열 수 없다. 문서 본문의 체크박스와 [에이전트 예약 작업](commands.md)은 각각 계속 제공한다. 할 일·달력 위젯을 다시 노출할 때는 워크스페이스 홈 탭을 되살리지 않고 프로젝트 스코프 배치를 별도로 결정한다.

## 숨김 목록 (.data/ignore.json)

파일 목록·검색·트리 감시에서 통째로 건너뛸 **이름** 목록. 경로가 아니라 이름이라 어느 깊이에 있든 그 이름의 폴더·파일이 사라진다(`dist` → 모든 프로젝트의 모든 `dist/`). 설정 창 → **숨김 목록**에서 고친다(owner/manager). 파일이 없으면 `server/ignoreList.ts`의 `DEFAULT_IGNORE`를 쓴다.

```json
{ "names": ["dist", ".next", "node_modules", ".git", ".data"] }
```

- 목록은 **전역 하나**다 — 프로젝트마다 다르지 않다. 그래서 `.data/`에 서버가 저장한다.
- `.git`·`node_modules`·`.data`는 `paths.ts`의 `DENY_SEGMENTS`가 API 계층에서 따로 막는다. 목록에서 빼도 계속 안 보이므로, 저장할 때 서버가 도로 넣고 UI는 **고정**으로 표시한다 — 지울 수 있는 것처럼 보이면 "지웠는데 왜 그대로냐"가 된다.
- 저장하면 서버가 감시자를 전부 접고(`resetTreeWatchers`) `tree` 신호를 보낸다. 살아 있는 감시자는 옛 규칙으로 만든 트리 서명을 들고 있어 새 규칙을 "변화 없음"으로 흘려버리기 때문 — 접어두면 클라이언트가 새 트리를 받아 갈 때(`GET /api/tree`) 새 규칙으로 다시 등록된다.
- `build/`는 기본 숨김이 **아니다**. 트리는 안의 APK/AAB만 노출하고 나머지·빈 폴더는 접으며 (`tree.ts`의 `DOWNLOAD_ONLY_DIRS`), 감시는 숨김 목록과 별개로 `build`에 내려가지 않는다.
- **owner·manager의 트리에는 이 목록도 확장자 필터도 적용되지 않는다** — 있는 그대로 다 보인다. 목록은 계속 살아서 member 이하의 트리와, 역할과 무관하게 **검색·트리 감시**에 적용된다.
- 사이드바는 `GET /api/tree?path=<폴더>`로 해당 폴더의 **직접 자식만** 읽는다. 프로젝트 전환 때는 계정에서 복원한 펼침 상태와 자식 스냅샷을 먼저 그리고 열린 경로의 직접 자식만 갱신한다. 접힌 조상 아래와 닫힌 최상위 폴더는 펼칠 때 읽고, 받은 목록·진행 중 요청은 재사용한다. Documents·프로젝트 진입점을 포함한 사이드바 스크롤은 계정에 중앙 항목의 트리 식별자·경로·항목 내 비율로 저장하며, 지연 로딩 중에도 같은 항목을 중앙에 복원한다. 사용자가 조작하면 초기 보정을 끝낸다([ADR 0125](../../../.mew/docs/decisions/0125-mew-sidebar-center-anchor-and-visible-loading.md)). `path` 없는 API 호출은 기존 서버 도구 호환을 위해 전체 재귀 트리를 유지한다. 정책 기준본은 [SECURITY.md](../../SECURITY.md)이고, 표시 필터는 `server/tree.ts`의 `isPathVisible`과 `server/reqAuth.ts`의 `seesEveryFile`, 실제 접근은 `server/access-policy.ts`가 판정한다. 부분 파일 제한이 있으면 허용된 하위 경로를 찾기 위해 트리를 필터링한다.
- 서버: `server/ignoreList.ts` + `GET/PUT /api/ignore`(owner/manager). 클라이언트: `src/components/SettingsModal.tsx`의 `IgnorePanel`.

## 태스크

타이틀바의 **목록·달력·간트** 탭으로 보기를 전환한다. 하단 독을 왼쪽으로 스와이프하면 다음 보기, 오른쪽으로 스와이프하면 이전 보기로 순환한다. 태스크마다 시작일과 종료일을 지정하며, 날짜가 하나만 있으면 그날 하루 일정이다. 시작일과 종료일을 모두 지정하면 양 끝을 포함하는 기간이다.

**달력**은 위쪽에서 날짜를 고르고 아래쪽에서 그날의 일정들을 보고 수정한다. 기간이 걸친 일정과 완료된 일정도 표시한다. 아래쪽의 새 태스크는 선택한 날짜의 일정으로 추가된다.

**간트**는 왼쪽의 태스크와 오른쪽의 기간 막대를 함께 보여준다. 막대를 끌어 이동하고 양 끝을 잡아 기간을 바꾼다. 연필 버튼을 켜고 행을 가로로 그으면 기간을 설정하며, 맨 아래 점선 행에서는 새 태스크를 만든다. 막대나 왼쪽 이름을 누르면 편집 카드에서 내용·완료·시작일·종료일을 바꾼다. 초록은 완료, 파랑은 계획, 빨강은 종료일이 지난 미완료 일정이다.

간트의 오늘·전체·확대/축소 버튼으로 기간을 탐색한다. 날짜 눈금을 좌우로 끌면 이동하고 위로 끌면 축소, 아래로 끌면 확대한다. Ctrl/Command+휠과 트랙패드 핀치도 된다. 드래그는 놓을 때 저장하며 Esc로 취소한다. 막대에 키보드 포커스를 두고 좌/우로 하루 이동하거나 Shift+좌/우로 종료일, Alt+좌/우로 시작일을 바꿀 수 있다.

날짜칸은 `0000-00-00` 형태다. 연·월·일 부분을 눌러 각각 입력한다. 연도 4자리, 월·일 2자리를 채우면 다음 부분으로 넘어가며 방향키·Tab·Enter로도 이동할 수 있다. 달력 버튼으로 날짜를 고르거나 오늘·내일을 선택할 수도 있다. 날짜 전체를 선택해 삭제하거나 달력의 지우기 버튼으로 날짜를 해제한다.

태스크는 프로젝트의 `tasks/<ID>.md` 파일로 저장된다. 태스크 제목이 글의 프론트매터 `title`이고, 태그·완료·시작일·종료일도 프론트매터 속성이다. 날짜 왼쪽 문서 아이콘으로 실제 Markdown을 열어 본문을 작성할 수 있다. 파일에서 속성을 고치면 태스크에도 반영된다. 새 태스크는 새 파일을 만들고 태스크 삭제는 해당 문서 전체를 삭제한다. 기존 목록은 쓰기 권한으로 패널을 열면 자동 이관된다.

태스크는 상위·하위 구분 없는 평면 목록이다. 제목 왼쪽 태그 영역의 +를 눌러 이름을 검색하고 여러 태그를 선택하거나 새 이름을 만든다. 선택 후에도 팝업이 유지되며 칩의 ×로 태그를 지운다. 색상은 이름별로 자동 지정된다. 제목에 입력한 `@`·`#`는 제목에 그대로 남는다.

헤더 아래 작은 **태그 필터** 아이콘에서 여러 태그를 고를 수 있다. 선택한 태그 중 하나라도 붙은 태스크를 목록·달력·간트에 표시한다. 아이콘 옆의 컬러 칩을 누르면 해당 필터를 해제하고, 오른쪽 ×는 전체 필터를 해제한다. 필터 안에서 새 태스크를 만들면 선택한 태그들이 자동으로 붙는다. 태그 이름은 같은 루트 프로젝트의 입력칸들이 공유하며 마지막 사용 항목을 지워도 자동완성에 남는다.

독의 캘린더 모양 **태스크** 아이콘으로 메모와 별도의 태스크 패널을 연다. 마지막 **새 태스크** 입력칸에 바로 쓰고 Enter로 다음 항목을 이어 작성한다. 다른 곳을 눌러도 작성한 항목은 추가된다. 각 항목은 독립 Markdown 파일로 자동 저장되며 체크박스로 완료를 표시한다.

기존 내용에 커서를 놓고 바로 수정한다. Enter로 현재 항목을 나누거나 여러 줄을 붙여넣어 항목을 한꺼번에 만들 수 있다. Shift+Enter는 항목 안의 줄바꿈이다. 빈 항목에서 Backspace를 누르면 앞 항목으로 이동하며 빈 항목을 삭제한다. 삭제 아이콘으로도 지울 수 있다.

체크박스를 잡아 끌면 항목을 이동한다. 끌고 있는 동안 주변 항목이 탭·독처럼 애니메이션으로 즉시 자리를 바꾼다. 손을 놓으면 순서가 자동 저장되며 취소하면 원래 순서로 돌아간다. 짧게 누르면 기존처럼 완료를 체크하며 이동 중에는 완료 상태가 바뀌지 않는다. Esc로 이동을 취소할 수 있고, 체크박스에 키보드 포커스를 둔 뒤 Alt+위/아래로도 순서를 바꾼다.

목록은 현재 루트 프로젝트별로 공유하고 하위 프로젝트 탭에서는 같은 목록을 쓴다. 계층과 날짜 외에 우선순위 같은 추가 속성은 없다. 패널의 도킹·크기 조절·확대·모바일 전환은 다른 작업 패널과 같다. 입력과 마지막 초안은 닫기·다시 열기와 프로젝트 전환에도 유지된다.

다른 창의 변경은 주기적으로 반영한다. 저장 실패·같은 내용의 동시 수정은 입력을 유지하고 오류를 표시한다. 내용을 확인한 뒤 다시 저장 버튼으로 재시도한다. 같은 내용이 충돌한 경우 다시 저장은 현재 입력한 내용을 적용한다. 로그인과 프로젝트 전체 열람 권한이 필요하며 읽기만 허용된 계정에는 작성 기능을 제공하지 않는다. [저장·API 계약](../development/task-list.md)을 따른다.
