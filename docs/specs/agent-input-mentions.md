기능 항목: [에이전트 입력](../features/%ED%84%B0%EB%AF%B8%EB%84%90%C2%B7%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%C2%B7%EC%9E%90%EB%8F%99%ED%99%94/%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%20%EC%9E%85%EB%A0%A5%C2%B7%EB%A9%98%EC%85%98%C2%B7%EC%8A%A4%ED%82%AC%C2%B7%EC%B2%A8%EB%B6%80.md). 이 문서는 해당 기능의 세부 동작·표시 계약을 소유한다.

에이전트 창의 입력칸은 토큰 앞글자를 입력하면 자동완성 목록을 보여 준다. 선택하면 뒤에 공백 하나를 붙여 계속 쓸 수 있다.

| 입력 | 목록 | 선택 결과 |
| --- | --- | --- |
| `@` | 역할에 맞는 워크스페이스 하위 프로젝트, 현재 프로젝트의 폴더·파일과 Documents 내부 폴더·파일 | 프로젝트는 `[프로젝트명]` 뒤 줄바꿈, 폴더·파일은 멘션 토큰(프로젝트·상대경로) 뒤 공백 |
| `/` | 로컬 스킬 | `/스킬명` |

`/` 후보는 현재 에이전트의 cwd·런타임에 맞는 전용/공통 스킬이다. 가까운 프로젝트를 우선하고 전역을 합치며 하위·형제 프로젝트는 제외한다. 관리창에서 수정·이동·삭제하면 후보를 다시 읽는다. 저장 위치와 우선순위·예약 메시지 적용은 [스킬·MCP 관리](../configuration/agent-harness.md#입력창과-api)를 따른다.

에이전트 자동완성은 후보를 8개에서 자르지 않고 스크롤로 모두 보여 준다. 하위 프로젝트가 많아도 그 아래 폴더·파일을 선택할 수 있으며, 방향키로 이동하면 선택 항목이 보이도록 목록이 스크롤된다. 폴더는 경로 끝의 `/`로 파일과 구분한다. 현재 프로젝트 후보는 기존에 로드된 트리를 사용한다. Documents는 별도 `docs` 스코프로 합치며, `@`를 열 때만 권한 필터가 적용된 전체 트리(`GET /api/tree?project=docs`, `path` 생략)를 읽어 사이드바에서 접힌 폴더의 하위 문서도 표시한다. 선택한 편집기 파일의 범위가 루트 프로젝트여도 Documents 후보는 함께 보인다. 항목의 경로 힌트는 `Documents/상대경로`이고 선택 토큰은 `[[docs:상대경로]]`다. 실제 Documents 위치가 `docs`가 아닌 사용자 지정 폴더여도 같은 스코프를 사용한다. 현재 프로젝트의 동명·동일 상대경로 파일과 구분하며, Documents 자체를 편집 중이면 중복 후보를 합치고 포커스 파일 우선순위를 유지한다.

Documents 조회는 입력창의 `@`가 열려 있는 동안만 수행한다. 조회 중에도 기존 후보를 선택할 수 있고, 조회 실패 시 기존 후보를 유지하며 다음 `@` 열기에서 다시 시도한다. 메뉴 닫기·탭 전환·루트 프로젝트 전환 시 진행 중 조회를 취소하고 늦은 응답을 반영하지 않는다. 권한 변경 시 Documents 후보를 비운 뒤 다시 읽는다. 일반 입력·`/` 스킬·CLI 명령 모드에서는 Documents 전체 조회를 하지 않는다.

`@` 결과는 입력한 문자열로 **시작하는** 항목만 보인다. 마지막으로 포커스한 편집기 파일이 있으면 그것을 가장 먼저 보이고, 없을 때는 **하위 프로젝트 → 폴더 → 파일** 우선순위이며 각 종류 안에서는 가나다 오름차순이다. 하위 프로젝트는 `GET /api/projects`의 역할별 목록과 현재 트리에서 발견한 하위 프로젝트를 합친다. 따라서 게스트에게는 그 역할이 볼 수 있는 프로젝트만 보이고, 에이전트 창을 쓸 수 있는 manager·owner에게는 워크스페이스의 프로젝트 전체가 보인다. 프로젝트를 선택하면 `[프로젝트명]`을 넣은 뒤 다음 줄에 커서를 놓고, 현재 에이전트 탭 이름은 대괄호 없는 `프로젝트명`으로 바꾼다. 이미 같은 이름의 탭이 있으면 `프로젝트명 (1)`처럼 가장 작은 빈 번호를 붙인다. 폴더·파일을 직접 참조할 때는 `@`를 쓴다.

입력 영역은 두 열이다. 왼쪽 열은 모델·추론 정도·권한 드롭다운과 입력칸을 쌓고, 오른쪽 열은 저장 버튼 위와 첨부·예약·전송 버튼 아래를 둔다. 아래 버튼은 `gap-1.5` 간격으로 모은다. 드롭다운의 기본 화살표는 위쪽을 향하고, 모델 드롭다운만 화살표를 맨 오른쪽에 둔다. 모델 드롭다운만 왼쪽 설정 줄의 남는 폭을 채우며, 추론 정도·권한 드롭다운은 내용 폭을 유지한다. 높이 조절의 최소값은 오른쪽 버튼 열의 실제 콘텐츠 높이와 입력 영역의 계산된 패딩·테두리를 합친 hug 높이다. ResizeObserver로 버튼 행의 크기 변화를 감지해 최소값·리사이즈 하한·키보드 가용 높이에 반영한다. 현재 스타일에서는 137px이며 이 수치를 UI 하한으로 하드코딩하지 않는다. 최소 높이와 확장한 높이 모두 전송 버튼과 입력칸의 아래 경계를 같은 y좌표에 맞춘다. 저장된 높이가 측정한 최소값보다 작으면 표시 높이만 올린다. 최대값은 에이전트 창의 90%다. 모바일 소프트 키보드나 브라우저 UI가 화면 아래를 덮으면 `visualViewport`에서 실제로 가려진 높이를 구해 입력 영역 전체를 그만큼 위로 띄우고, 표시 높이의 상한에서도 같은 값을 뺀다. 모바일에서는 측정 경계보다 8px 더 위를 하단 한계로 삼아 최대 높이에서도 키보드와 겹치지 않게 한다. 키보드가 닫히면 사용자가 정한 높이로 되돌린다. 고른 파일, OS에서 입력칸으로 끌어놓은 파일, 또는 이미지 클립보드를 붙여넣은 파일은 현재 열어 둔 루트 프로젝트의 `.mew/assets/`에 원본 바이트 그대로 저장되고, 이름이 겹치면 서버가 비켜 쓴다. 저장하는 동안 입력칸 위에는 회전 표시와 `첨부 중…` 태그가 보이고 전송은 완료될 때까지 비활성화된다. 저장을 마치면 입력칸 위에 확장자만 보이는 태그가 생기며, 각 태그의 ×로 전송 전 첨부를 뺄 수 있다. 태그 너비는 확장자와 × 내용에 맞추며 고정 최소 너비로 생기는 빈 공간을 두지 않는다. 확장자와 × 버튼을 감싸는 컨테이너의 상하좌우 패딩은 모두 4px(`p-1`)로 같게 둔다. 사진 태그 본문을 누르면 큰 미리보기 팝업이 열리고, ×와 팝업 바깥 클릭 또는 Escape로 닫는다. 실제 프로젝트·`.mew/assets/` 경로 참조 토큰은 입력칸에 노출하지 않고 전송할 때만 프롬프트에 넣는다.

첨부 업로드와 참조 토큰은 루트 프로젝트 스코프(`.workspace`)를 사용한다. 편집 중인 파일이 Documents(`docs`)에 있거나 다른 파일 스코프로 바뀌어도 저장 위치는 `<프로젝트>/.mew/assets/`로 유지한다. Documents가 `.mew/docs`여도 그 아래에 `.mew/files` 또는 `.mew/assets`를 만들지 않는다. 새 메시지·대기 큐 편집에 같은 규칙을 적용하며, 기존 대화·큐에 저장된 과거 첨부 참조는 그대로 읽는다.

대기 큐에서도 첨부 확장자 태그를 본문 옆에 표시한다. 항목 오른쪽의 연필 편집 버튼을 누르면 기존 하단 입력칸에 본문과 첨부 태그를 표시하며, 같은 파일 첨부 버튼으로 파일을 추가하고 태그의 ×로 제거할 수 있다. 사진 태그는 기존 큰 미리보기를 사용하고 Escape로 미리보기만 닫아 편집을 유지한다. 큐 편집과 새 메시지는 하단 입력 UI를 공유하되 본문·첨부 상태는 독립적이다. 저장·취소하면 보존한 새 메시지 초안과 첨부가 다시 표시된다. 첨부 업로드 중에는 저장 버튼과 단축키 저장을 막으며, 본문이 없어도 첨부가 있으면 저장한다. 저장은 본문과 첨부를 함께 반영하고 취소는 원래 첨부를 유지한다. 취소한 편집의 업로드가 늦게 끝나도 다음 편집이나 새 메시지에 붙이지 않는다. 파일 제거·편집 취소는 업로드된 원본 파일을 디스크에서 삭제하지 않는다.

에이전트 입력은 CodeMirror의 `contenteditable="true"` 호스트를 사용한다. 모바일 키보드가 이미지 클립보드를 받을 수 있는 입력으로 인식하도록 하며, `paste`와 키보드의 `beforeinput(insertFromPaste)`에서 제공되는 이미지 파일을 위 첨부 경로로 보낸다. 외부 파일 드롭은 캡처 단계에서 편집기보다 먼저 받아 여러 파일을 각각 첨부하며 파일 내용을 본문에 삽입하지 않는다. 텍스트 드래그는 편집기의 기본 동작을 유지한다. 파일 목록이 비어 있으면 클립보드 항목의 파일을 사용하고, 사진은 본문에 `<img>`로 삽입하지 않는다. 텍스트·HTML 클립보드는 서식 없는 텍스트로 붙여넣고 한글 조합 중 Enter로 전송하지 않는다. OS·키보드·브라우저가 웹에 이미지 파일을 전달하지 않는 조합은 지원을 보장하지 않으며, 이때는 파일 첨부를 사용할 수 있다. 클립보드 이력 전체를 읽거나 별도 클립보드 권한을 요청하지 않는다. CLI 모드는 같은 텍스트 편집 호스트를 유지하되 이미지 첨부를 받지 않는다. 채팅·댓글 입력은 기존 textarea를 유지한다.

전송에 성공한 입력은 탭별로 브라우저에 최근 100개까지 보관한다. 입력칸의 첫 줄에서 ↑를 누르면 이전 입력, 마지막 줄에서 ↓를 누르면 다음 입력을 불러온다. ↑로 불러온 입력은 커서를 끝에, ↓로 불러온 다음 입력이나 복원한 미전송 초안은 커서를 시작에 둔다. 여러 줄 안에서의 방향키는 커서 이동을 유지한다. 빈 줄·공백만 있는 줄도 한 줄로 세며, 커서 위·아래에 명시적 줄바꿈이 남아 있으면 해당 방향의 히스토리를 불러오지 않는다. 화면 폭에 따라 자동으로 접힌 줄도 커서 이동을 우선한다.

긴 입력과 자동 줄바꿈은 사용자가 정한 입력 영역의 높이를 늘리지 않고 CodeMirror 내부에서 세로 스크롤한다. 이미지 지원 입력의 멘션 래퍼는 `min-height: 0`으로 내용의 최소 높이가 flex 가용 높이를 넘지 않게 한다. 자동완성 목록은 래퍼 바깥 위쪽에 계속 표시한다. 모바일 독의 예약 공간과 키보드 보정은 기존 패널 배치를 따르며, 키보드가 닫히면 입력 높이와 독 위 위치를 복원한다.

검증: `src/utils/agentInputMentions.test.ts`는 스코프·동명 파일 구분·중첩 Documents·중복 제거·포커스 우선순위를, `server/agent-command-ui.test.ts`는 실제 AgentPanel의 데스크톱/모바일에서 지연 조회·필터·선택·전송 토큰·조회 실패·닫기 후 응답 무시와 재시도를 검사한다. 같은 격리 Chromium 테스트에서 이미지 `paste`·`beforeinput`의 첨부/전송, 서식 제거·한글 조합 전송 차단·여러 줄 입력 기록 탐색, 긴 입력·자동 줄바꿈의 내부 스크롤과 높이 유지, 모바일 독 예약 공간·키보드 viewport 축소·복원 시 입력 영역 경계도 검증한다. 모바일 검증은 브라우저 화면 크기와 합성 이벤트 기준이며 실제 OS 키보드 클립보드와 키보드 애니메이션의 실기기 검증을 대신하지 않는다.

입력 맨 앞에 새로 입력된 `! `는 두 문자를 제거하고 일반/CLI 모드를 양방향 전환한다. 나머지 본문과 커서를 보존한다. 본문 중간에서는 전환하지 않으며 대기 큐 편집·터미널 권한 없음·첨부 존재/업로드·명령 전송 중에는 문자 그대로 유지한다. 기존 CLI 버튼·Ctrl+Tab과 같은 전환 제한을 적용한다.

CodeMirror가 React 렌더 전에 같은 입력의 문서·커서 변경을 중복 통지해도 모드는 한 번만 전환한다. 접두사 처리 시 현재 모드의 반대 값을 지정하며 알림마다 모드를 다시 뒤집지 않는다.
