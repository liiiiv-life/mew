# 기능 기반 개발

상위: [제품 스펙](MOC.md). 결정: [ADR 0159 — 실행](../../../.mew/docs/decisions/0159-mew-feature-driven-development.md) · [ADR 0161 — Markdown 기준본](../../../.mew/docs/decisions/0161-mew-feature-markdown-source.md) · [ADR 0173 — 인라인 편집과 작업 접수](../../../.mew/docs/decisions/0173-mew-inline-feature-edit-dispatch.md). 실행 기반: [에이전트 세션](../development/agent-sessions.md).

## 사용 흐름

1. 작업할 프로젝트 탭에서 PC·모바일 독의 **기능** 버튼을 누른다. 독 버튼은 현재 프로젝트와 에이전트 권한이 있을 때 표시하며 기본 위치는 원격 데스크톱 바로 왼쪽이다. 하위 프로젝트도 자기 탭에서 별도 목록을 사용한다.
2. 기능 화면 맨 위에서 **에이전트셋**을 고른다. 목록 맨 위 **+ 기능 요청**을 누르면 목록 안에 3줄 높이의 입력칸이 펼쳐진다. 제목 입력 없이 원하는 기능 내용만 적고 **맡기기**를 누른다. Enter는 줄바꿈이며, 빈 내용은 보낼 수 없다. 셋이 없으면 에이전트 패널에서 먼저 등록한다.
3. 기능 제목 왼쪽 **접기/펼치기 아이콘**으로 요구사항·구현 내용·검증을 펼친다. 본문은 Markdown 서식을 적용한 목록으로 읽고, 관련 파일·커밋·작업 이력을 함께 확인한다. 원본 문서는 기능 제목 오른쪽 문서 아이콘으로 연다. 저장된 화면 상태가 없으면 기능과 내부 섹션은 모두 접힌 상태로 시작하며 **모두 접기/펼치기**도 사용할 수 있다. 제목 클릭은 펼침 상태를 바꾸지 않는다.
4. 트리의 기능 제목을 누르면 그 자리에서 제목을 수정한다. 본문의 텍스트 항목을 누르면 해당 항목의 Markdown 원문 편집기가 열린다. 내용을 바꾸고 **적용·작업 시작** 또는 `Ctrl/⌘+Enter`를 누르면 Markdown 저장과 선택한 에이전트셋의 구현 요청을 함께 접수한다. 별도로 요구사항을 저장하거나 다시 위임할 필요가 없다. 제목 입력의 `Enter`는 적용, 본문 입력의 `Enter`는 줄바꿈이며 `Esc`·**취소**는 해당 편집을 취소한다. 각 섹션의 `+`로 새 기술 특성을 추가할 수 있다.
5. 에이전트는 전체 명세와 편집 전후를 읽고 같은 기능 ID에 연결해 다시 구현한다. 구현 내용·검증 문구 수정도 사용자가 원하는 동작·확인 기준으로 전달하며, 완료 보고는 실제 수행 결과로 갱신한다. 파일·커밋 증거와 과거 실행 보고는 보존한다.
6. 결과가 맞으면 **확인 완료**, 보완이 필요하면 **수정 필요**를 누른다. 파일은 편집기에서, 커밋은 메시지·변경 파일 창에서 연다. 삭제된 파일은 연결된 커밋에서 확인한다. 실행 중 상태·중단·대화 열기는 기능 안의 작업 이력에서 제공한다.

새 요청과 **하위 기능 추가**, **에이전트에게 맡기기**, 실패 요청의 **다시 요청**은 목록 위의 인라인 입력칸을 사용한다. **하위 기능 추가**는 선택 항목을 부모로 고정한다. 펼친 본문의 중복 제목·상위 기능 표시와 부모 선택기는 트리와 중복된다는 사용자 요청으로 제거했으며 요청 전 재도입하지 않는다. 부모 관계는 문서의 `parent`로 관리하고 자기 자신이나 자손 아래로는 이동할 수 없다. 화면 상단의 셋 선택은 모든 요청에 사용하며, 처음에는 최근 요청의 유효한 셋 또는 첫 셋을 제안하고 이후 선택을 유지한다. 셋·정렬은 공용 자체 선택기를 사용한다. 에이전트셋 아래에 작업 방식·단축키를 반복 설명하는 상시 안내 문구는 두지 않는다. 셋이 없을 때만 등록 안내를 표시한다.

일반 `+` 요청은 에이전트가 새 기능·기존 수정·하위 기능으로 분류한다. 하나의 요청은 한 기능에 연결하며 모호한 범위는 대화에서 확인한다. 결과 보고 없이 질문으로 턴을 끝내면 완료로 처리하지 않는다. 답을 정리해 다시 요청한다.

요청 제목 입력은 사용자 지시에 따라 제거했다. 내부 요청에는 첫 줄을 최대 300자로 줄인 미리보기 제목을 사용하고 본문 전체를 에이전트에게 전달한다. 에이전트는 분류 시 기능 이름을 정한다. 기존 기능 재위임에는 해당 제목을 유지한다. 별도 요청 팝업은 사용하지 않으며 자동 재도입하지 않는다. 요청 전송 실패 시 내용과 셋을 유지하고, 미전송 입력을 버리는 이동·닫기는 확인한다.

기능 화면은 작업 영역에 붙는 패널이다. 모바일에서는 독 위의 본문을 채우며, 독 버튼·좌우 스와이프로 다른 패널과 오간다. 같은 프로젝트에서 패널만 전환하면 펼침 상태·에이전트셋·편집 및 요청 초안을 유지한다. 데스크톱에서는 공통 `DockWorkspace` 안의 오른쪽 칸으로 처음 열리고, 상단 `DockGrip`으로 다른 패널의 좌우·상하에 옮긴다. 브라우저 옆에서는 공통 좌우 배치 제한을 따른다. 경계선 드래그·키보드 화살표로 폭과 높이를 조절하며 배치·비율은 `workspaceUi.dock`에 저장한다. 닫힌 동안에도 패널 등록을 유지해 다른 칸을 조절해도 저장된 기능 패널 위치를 잃지 않는다. 이동·크기 조절·모바일 전환으로 본문을 다시 마운트하지 않는다. 타이틀바 제목 앞에는 독과 같은 기능 아이콘을 14px로 표시하며 장식용 SVG는 접근성 트리에서 제외한다. 타이틀바는 다른 작업 패널과 같은 36px 높이·`surface-deep` 배경·하단 구분선·작은 제목과 아이콘 버튼을 사용하며 모바일에서는 손잡이와 해당 여백을 제거한다. 모든 폭에서 하나의 스크롤 계층 안에 기능과 명세를 표시하며 별도 상세 화면으로 전환하지 않는다. 닫기·Esc·뒤로가기는 미저장 확인을 거치고, 확인창·커밋 상세만 모달을 사용한다. 기능 화면 전체 팝업은 사용자 요청으로 제거했으며 요청 전 재도입하지 않는다.

기능·섹션의 펼침 상태, 정렬 기준, 목록 스크롤 위치는 사이드바와 같은 계정별·프로젝트별 서버 화면 상태(`workspaceUi.features`)에 저장한다. 패널을 닫았다 열거나 프로젝트를 오가거나 새로고침해도 복원한다. 계정 상태를 읽은 뒤 패널을 만들고, 기능 목록을 받은 뒤 스크롤을 한 번 복원하므로 주기적인 조회가 사용자의 스크롤을 되돌리지 않는다. 저장된 위치가 현재 목록 범위를 벗어나면 스크롤 가능한 범위로 제한한다. 편집·요청 초안은 이 저장 대상에 포함하지 않는다.

## 목록·상태·편집

- 요구사항·구현 내용·검증·관련 파일·관련 커밋은 제목 다음 줄에 내용을 배치한다. 데스크톱·모바일 모두 한 열을 사용하며 제목용 왼쪽 컬럼을 따로 예약하지 않는다. 항목 추가 버튼은 해당 제목 옆에 둔다. 섹션 사이에는 별도 세로 여백을 넣지 않고 32px 제목 행을 이어 배치한다. 펼친 기능 아래 여백은 4px로 둔다.
- 요구사항·구현 내용·검증·하위 기능·관련 파일·관련 커밋은 제목 옆 화살표가 있는 버튼으로 각각 접고 펼친다. 처음에는 접어 두며 펼침 상태는 기능 ID·섹션별로 구분한다. 조회 갱신·정렬·부모 기능 접기/재열기에도 유지하고, 나중에 추가된 기능과 섹션도 기본적으로 접힌다. 읽기 전용에서도 접을 수 있다. 접힌 섹션의 `+`는 섹션을 펼쳐 새 항목을 편집한다. 현재 편집 중인 항목이나 자식의 초안을 숨기는 접기는 미저장 확인을 거치며, 다른 섹션 접기는 초안을 유지한다. 기능 링크로 이동할 때는 조상의 하위 기능 묶음도 펼친다. 상단 모두 접기/펼치기는 기능 가지에 적용하며 개별 섹션의 상태는 보존한다.
- 하위 기능은 부모의 펼친 내용 안에서 요구사항 다음의 **하위 기능** 묶음에 실제 기능 행으로 표시한다. `parent` 관계와 현재 정렬을 사용하고, 각 자식의 상태·아이콘 접기·제목 및 본문 편집·작업 이력을 같은 GUI에서 제공한다. 부모를 접으면 자식도 숨긴다. 본문의 자식 문서 링크만 있는 목록 항목과 중복 하위 기능 제목은 패널에서 생략하며 원문은 보존한다. 자식은 별도 목록에 중복 표시하지 않는다. 등록된 다른 기능을 가리키는 본문 링크도 파일 대신 해당 기능의 조상을 펼치고 그 행으로 이동한다. 일반 문서 링크와 등록되지 않은 링크는 기존 파일 열기를 유지한다.
- 문서 열기는 기능 제목 오른쪽의 문서 아이콘 버튼으로 제공한다. 접힌 상태에서도 사용할 수 있고 본문에는 중복 버튼을 두지 않는다. 문서 경로를 툴팁과 접근성 이름에 포함하며 미저장 편집 확인을 유지한다.
- 기능 제목 행은 읽을 때 32px 높이이며 왼쪽에 상태 동그라미·펼침 버튼을 둔다. 펼침 버튼만 해당 가지를 접고 펼친다. 제목 클릭은 같은 행을 한 줄 제목 입력으로 바꾸며 접힌 상태에서도 바로 편집한다. 읽기 전용에서는 제목 편집을 막고 접기·펼치기는 허용한다. 상태명은 제목 옆 동그라미의 접근 가능한 이름·툴팁으로 제공한다. 펼친 본문 맨 위의 중복 상태 동그라미·상태 설명·수정 날짜 행은 사용자 요청으로 제거했으며 요청 전 재도입하지 않는다.
- 명세는 Markdown의 제목·목록 항목·문단·코드 블록·표 경계로 나눈다. 읽을 때 제목·불렛·강조·코드·링크·표를 렌더링하고 원문 문법은 편집 중에만 노출한다. 들여쓴 불렛의 깊이를 유지하며 raw HTML과 실행 가능한 링크는 허용하지 않는다. 링크는 항목 편집을 시작하지 않고, 문서 상대 파일 링크는 해당 기능 문서 기준으로 편집기에서, 외부 링크는 새 탭에서 연다.
- 기능 제목·섹션명과 같은 본문 제목, `상위:`·`상위 기능:`으로 시작하는 탐색 링크는 패널에서 중복 표시하지 않는다. 원본 문서에서는 삭제하지 않는다. 항목 하나의 원문 범위만 치환하여 숨긴 탐색 정보·다른 항목·줄바꿈을 보존한다. 한 번에 한 항목을 편집하며 이동·닫기·접기로 미저장 초안을 버릴 때 확인한다. 연결된 다른 소유 문서의 본문은 자동 복제하지 않는다.
- 최근 변경순은 최신 우선, 이름순은 오름차순, 최초 생성순은 오래된 항목 우선이다. 형제끼리 정렬해 계층을 유지하며 하위 변경은 상위 묶음 정렬에도 반영한다. 열람·접기는 변경 시각을 바꾸지 않는다.
- 부모 동그라미는 부모 기능 자체의 상태다. 자식의 승인을 자동 전파하지 않는다.

| 색 | 의미 | 전환 |
| --- | --- | --- |
| 파랑 | 구현 중 | 에이전트가 분류·연결을 완료 |
| 민트 | 구현 완료·확인 전 | 검증된 결과 보고와 정상 턴 종료를 모두 확인 |
| 초록 | 사용자 확인 완료 | 사용자가 확인 완료 선택 |
| 빨강 | 사용자 수정 필요 판정 | 사용자가 수정 필요 선택 |
| 주황 | 요구사항 변경·재위임 필요 | 제목·내용·상위 기능 변경 저장, 또는 연결된 작업 실패·중단 |

같은 내용은 작업을 접수하지 않는다. GUI 항목 편집은 적용할 때 명세 저장과 작업 접수를 함께 수행한다. 일반 Markdown 편집과 기존 편집 API는 자동 실행하지 않는다. 주황에서 직접 초록으로 바꾸거나 재위임할 수 있다. 실패·중단은 이력에 이유를 표시하며 사용자 판정인 빨강으로 바꾸지 않는다.

버전으로 동시 편집을 검사한다. 충돌하면 초안을 보존하고 최신 내용 다시 불러오기를 제공한다. 요청 당시 대상 버전도 고정하므로 대기 중 바뀐 기능을 이전 요청으로 덮어쓸 수 없다. 실행 시작 뒤 사용자가 저장·판정한 기능은 이전 실행의 종료가 색이나 내용을 덮어쓰지 않는다. 실행 결과는 이력에 남는다.

## 실행과 복원

- 같은 기능에 대기·실행 중 요청이 있으면 새 인라인 초안 작성은 가능하지만 **적용**은 비활성화한다. 현재 작업 완료 또는 중단 후 적용한다. 실행 중 문서가 바뀌었다면 최신 내용을 확인하고 편집을 다시 시작한다.
- 프로젝트별 FIFO 큐로 한 요청씩 실행한다. 다른 프로젝트 큐는 독립이다. 같은 기능의 명시적 재위임이 대기·실행 중이면 중복 요청을 막는다. 대기·실행 합계 50개, 기능 항목 2,000개까지 받는다.
- 요청은 셋의 런타임·모델·역할과 프로젝트·Documents 연결을 캡처한다. 셋 편집·프로젝트 전환은 접수한 요청을 바꾸지 않는다. 실행 직전에 요청 계정의 에이전트·프로젝트 전체 수정 권한을 재검사한다.
- `feature_<request UUID>` 탭의 기존 독립 감독을 사용한다. 세션 준비와 모델 적용을 확인한 뒤 프롬프트를 보낸다. 로그인·승인 대기는 이력에 표시하며 **대화 열기**에서 처리한다. 대화를 열 때 같은 탭에 연결하고 구현 프롬프트를 추가 전송하지 않는다.
- 전달 직전에 `dispatchedAt`을 저장한다. 복원은 기존 감독에만 연결하며 전송 의도를 기록한 요청은 자동 재전송하지 않는다. 아직 전송하지 않은 요청은 세션 준비 후 전달할 수 있다. 복원 불가나 전송 경계의 불확실성은 대화 확인 후 사용자가 재요청한다.
- 브라우저 닫기·프로젝트 전환은 작업을 계속 둔다. **중단**은 큐에서 제거하거나 실행 취소를 보내고 완료 확인까지 다음 요청을 막는다. 전송 전 취소는 즉시 끝낸다. 서버 종료 시 감시 연결만 닫고 감독을 죽이지 않는다.
- 유효한 보고와 정상 턴 종료가 모두 있어야 민트색이다. 보고 누락·비정상 종료·복원 불가에서는 실패 이유와 재요청 경로를 제공한다. 감독까지 사라진 작업은 성공을 추정하지 않는다.

## 공통 에이전트 인터페이스와 저장

`server/feature-agent-instructions.ts`가 모든 셋에 같은 분류·구현·결과 보고 지침을 붙인다. 셋은 실행 프리셋이며 원장이나 분류 규칙을 소유하지 않는다. 에이전트는 지침에 들어 있는 절대 경로 명령을 사용한다.

```text
node <feature-cli.ts> <feature store directory> <workspace> <request UUID> list
node <feature-cli.ts> <feature store directory> <workspace> <request UUID> assign
node <feature-cli.ts> <feature store directory> <workspace> <request UUID> report
```

`assign`·`report`는 JSON 한 개를 표준 입력으로 받는다. `assign`은 new/update/child 분류·전체 요구사항·분류 이유·대상 ID/버전을 검사한다. `report`는 구현 설명·검증·프로젝트 상대 파일·저장소 상대 경로와 실제 커밋 해시를 받는다. 경로 이탈·symlink 외부 연결·없는 파일·허위 커밋을 거부한다. 삭제 파일은 연결한 커밋에서 삭제를 확인할 때만 연결한다. 커밋 없는 결과도 유효하며 자동 커밋을 지시하지 않는다.

## Markdown 기준본과 실행 기록

기능의 기준본은 **현재 프로젝트에 설정한 Documents 폴더의 `features/` 아래 Markdown**이다. 기본 Documents가 `docs`이면 `docs/features/`, 이 워크스페이스처럼 `.mew/docs`이면 `.mew/docs/features/`다. 별도 설정은 프로젝트의 Documents 연결을 따른다. 새로운 기능은 `<고정 UUID>.md`로 만들며, 파일을 소문자 영문 케밥 케이스 이름으로 바꾸거나 내부 폴더로 옮겨도 `id`가 같으면 같은 기능이다. 계층은 경로 대신 `parent` ID로 정한다.

직접 작성할 수 있는 최소 예:

```markdown
---
id: email-login
title: 이메일 로그인
parent: null
status: changed
created: 2026-09-17
updated: 2026-09-17
files: []
commits: []
---

## 요구사항

이메일과 비밀번호로 로그인한다.
```

| 위치 | 관리하는 내용 |
| --- | --- |
| 프론트매터 | 고정 `id`, `title`, `parent`, `status`, `created`·`updated`, `status_hash`, `files`·`commits` |
| Markdown 본문 | 요구사항, 구현 내용, 검증 결과. 추가 설명·하위 제목도 사용 가능 |
| `DATA_DIR/features/<sha256(workspace)>.json` | 저장 형식 2: 요청 큐·담당 셋 스냅샷·대화 연결·실행 상태·요청별 결과 이력·저장 복구 정보 |

`id`·`title`은 필수다. ID는 영문·숫자·밑줄·하이픈 1~128자, 제목은 300자까지다. `parent` 생략/null은 최상위다. 날짜는 ISO 문자열이며 생략 시 파일 시각을 사용하므로 Git 복제 후에도 날짜를 유지하려면 기록한다. 관련 파일은 프로젝트 상대 경로다. 커밋은 `{ repository: "", hash: "실제 해시", subject: "제목" }` 형태이며 빈 repository는 프로젝트 루트다. 문서 읽기에서는 경로와 해시 형식을 검사하고, CLI 결과 보고에서는 실제 파일과 커밋도 검증한다. 다른 clone에서 아직 없는 파일·커밋 때문에 전체 기능 목록을 막지는 않는다.

지속 상태는 `changed`·`implemented`·`verified`·`needs-fix`다. 파랑(`implementing`)은 서버 실행과 문서 버전이 일치할 때만 표시하며 파일에는 저장하지 않는다. `status_hash`는 mew가 저장하는 요구사항 해시다. 제목·본문 요구사항·부모 ID가 외부에서 달라지거나 해시가 없으면 주황으로 표시한다. 원본 상태를 자동으로 고쳐 쓰지는 않는다. GUI에서 확인 완료를 누르면 현재 내용의 해시와 판정을 함께 기록한다. 줄바꿈 형식·파일 시각만 바뀌는 checkout, 추가 메타데이터 수정은 승인을 해제하지 않는다. 이는 변경 감지용이며 외부 편집자의 판정을 인증하는 서명은 아니다.

구현 결과는 `## 구현 내용`·`## 검증` 섹션으로 저장한다. mew가 기록할 때는 각 섹션을 `<!-- mew:implementation:start -->` / `<!-- mew:implementation:end -->`, `<!-- mew:validation:start -->` / `<!-- mew:validation:end -->`로 감싸 결과 안의 Markdown 제목·코드 블록도 보존한다. 구분자는 유지하고 내부 문장을 편집할 수 있다. 직접 쓴 문서는 구분자 없이 해당 2단계 제목을 각각 한 번 사용하는 것도 허용한다. 이 경우 다음 2단계 제목까지를 결과로 읽는다. 요구사항에서 같은 제목을 설명용으로 쓸 때는 `###`를 사용한다. 나머지 본문은 요구사항이며, GUI 저장 시 사용자 추가 프론트매터·주석과 기존 결과를 보존한다.

새 결과가 현재 버전에 대해 완료되면 구현·검증 설명을 갱신하고 관련 파일·커밋을 합친다. 실행 중 문서가 편집되면 이전 실행 결과는 요청 이력에만 남기고 최신 문서에 덮어쓰지 않는다. 직접 편집한 기능 문서는 별도 스펙 문서에 복제하지 않는다. 설치·운영·공통 지침·ADR은 기존 소유 문서에 둔다. 기존 docs 전체를 자동 변환하거나 삭제하지 않는다.

### 외부 편집과 Git

- GUI·일반 편집기·공통 CLI가 같은 파일을 사용한다. 조회 시 문서를 읽으므로 외부 추가·수정·rename·삭제는 다음 갱신에 반영한다. 외부 파일 추가는 주황으로 나타나며 에이전트를 자동 실행하지 않는다.
- 동시 편집은 파일 전체 내용에서 만든 불투명 버전으로 검사한다. 버전의 크기를 시간순으로 해석하지 않는다. GUI 초안이 있으면 외부 수정으로 덮어쓰지 않고 최신 내용 불러오기를 제공한다. 삭제된 문서의 미저장 초안도 복사할 수 있게 남긴다.
- `features/MOC.md`·`README.md`와 숨김 파일은 기능으로 읽지 않는다. 중복 ID·잘못된 YAML·없는 부모·순환·심볼릭 링크는 오류로 알리고 덮어쓰지 않는다. 부모 파일 삭제 전에는 자식을 이동하거나 함께 정리한다. 문서당 512KB, 요구사항/구현 설명 각각 40,000자, 검증 20,000자, 폴더 깊이 16, 기능 2,000개까지다.
- mew가 기능 문서를 저장할 때 `features/MOC.md`의 관리 블록과 Documents `MOC.md`의 진입 링크도 갱신한다. 사용자 작성한 나머지 인덱스 내용은 유지한다. 외부에서만 rename·삭제했다면 다음 mew 문서 저장 전까지는 일반 문서 규칙에 따라 MOC 링크도 직접 고친다.
- Documents와 프로젝트의 Documents 설정을 Git으로 공유하면 새 clone에서도 기능·계층·결과·사용자 판정을 읽을 수 있다. 실행 중 상태·대화·요청 이력은 서버 데이터에 남으며 clone에 따라가지 않는다. 자동 Git 커밋은 하지 않는다.

### 기존 데이터 이전과 복구

서버에 변경을 반영한 뒤, 수정 권한이 있는 기능 조회·CLI 접근 또는 실행 서비스 복구 시 기존 형식 1 JSON을 감지해 이전한다. 기존 ID·계층·상태·완료 결과를 Markdown으로 쓰고, 큐의 버전 연결과 실행 이력을 보존한다. 원본은 같은 서버 파일 옆 `<sha256(workspace)>.json.v1-backup`에 보관한다. 동일 ID의 기존 Markdown이 있으면 원본 확인이 필요하므로 이전을 중단하고 덮어쓰지 않는다. 읽기 전용 조회만으로 이전을 수행하지 않는다.

API와 CLI는 같은 프로세스 간 잠금을 사용한다. 문서·MOC 쓰기 계획을 서버 JSON의 `pendingWrites`에 먼저 기록하고 파일별 원자적 교체를 마친 뒤 계획을 지운다. 중간 종료 시 이미 적용한 내용은 인정하고 남은 쓰기를 복구한다. 외부 편집이 감지되면 해당 파일과 계획을 보존한 채 오류를 표시한다. 잠금을 사용하지 않는 외부 편집기와의 완전한 트랜잭션 격리를 보장하지는 않는다.

복구 충돌은 표시된 문서와 실행 JSON을 먼저 별도 백업하고 처리한다. `pendingWrites`의 해당 경로·예정 내용(`content`)과 외부 변경을 비교한다. 예상 이전 내용(`before`의 SHA-256)으로 복원하거나 예정 내용과 동일하게 맞추면 다음 조회/CLI에서 복구가 진행된다. 보관한 외부 변경은 복구 후 다시 합친다. 원인을 확인하지 않고 `pendingWrites`나 서버 파일을 삭제하지 않는다. 일반 편집에는 JSON을 직접 수정하지 않으며, 백업에는 프로젝트 Documents와 서버 features 디렉터리를 함께 포함한다.

API는 `/api/features` 아래 조회·요청·편집·판정·취소 경로다. `POST /requests`의 선택적 `edit`는 `{title, content, parentId, summary, validation}` 전체 명세이며 `targetId`·`expectedVersion`과 함께 보낸다. 저장·큐 생성은 같은 프로세스 간 잠금과 `pendingWrites` 복구 단위로 처리하며, 저장 후 문서 버전으로 요청의 대상 버전을 고정한다. 기존 큐·버전·계층·크기 검증 실패 시 명세와 요청을 둘 다 변경하지 않는다. 서버는 편집 전후·원본 버전을 실행 이력에 캡처하고 같은 요청 ID 재전송의 본문을 비교한다. 응답 실패 후 같은 내용을 다시 적용하면 동일 ID를 사용하므로 중복 실행하지 않는다. 현재 프로젝트와 요청 workspace가 다르면 409다. 조회에는 agent 기능과 전체 파일 열람, 변경에는 전체 파일 수정 권한이 필요하다. 부분 파일 제한이 있는 계정에는 원장을 노출하지 않는다. 파일 열기에는 기존 파일 API 권한, 커밋 상세에는 Git 권한을 적용한다. CLI는 에이전트 셸과 같은 OS 신뢰 경계 안에서 사용한다.

## 검증과 현재 한계

`server/feature-documents.test.ts`는 Markdown 왕복·외부 편집·복제·이전·복구 충돌을, `server/features.test.ts`는 수명주기·동시 수정·계층·경로/Git·CLI를, `server/feature-service.test.ts`는 큐·로그인/모델 대기·취소·권한·복원을 검사한다. `server/feature-host.test.ts`는 실제 독립 감독과 ACP 테스트 에이전트로 모델 적용·CLI 보고·같은 대화 복원을 확인한다. `server/feature-ui.test.ts`는 실제 React·격리 Chromium에서 인라인 항목 편집→실제 요청 API→테스트 에이전트 연결, 셋 선택, 충돌·실패 초안 보존·재시도, 실행 중 중복 방지, 파일/커밋, 하위 기능·정렬·모바일·편집 폐기·권한을 검사한다. `src/utils/feature-specification.test.ts`는 Markdown 항목 분리와 원문 범위 치환을 검사한다. 실제 유료 AI의 구현 품질이나 모바일 실기기 동작을 보증하는 검사는 아니다.

목록은 2초 주기로 갱신한다. GUI 삭제 버튼·일괄 분리·의존성 그래프·프로젝트 간 기능 이동·자동 커밋은 이번 범위에 포함하지 않는다. 빌드와 서버 반영은 [실행·검증 규칙](../development/getting-started.md)에 따라 사용자가 수행한다.
