기능 항목: [파일 검색](../features/projects/search.md). 이 문서는 해당 기능의 세부 동작·표시 계약을 소유한다.

사이드바 탭은 탐색기 다음에 **파일명 검색(돋보기)**, **파일 내용 검색(문서 돋보기)**을 나란히 둔다.
Ctrl+P는 파일명 검색, Ctrl+Shift+F는 내용 검색을 연다. 두 검색 모두 로그인 사용자에게 현재 루트 프로젝트의 Documents와
직계 `.mew` 하위 프로젝트를 함께 검색 대상으로 보인다. 검색어 입력줄에서 `@`를 누르면 Documents와
하위 프로젝트 목록이 열리고, 하나 이상을 고르면 태그로 남는다. 여러 태그는 OR다. 태그가 없으면 루트
내용·모든 직계 하위 프로젝트·Documents를 검색한다. 파일명 모드는 250ms 입력 디바운스 뒤 서버의 증분
파일 카탈로그를 검색하고 상위 50개만 받는다. 전체 후보 트리를 브라우저로 전송하지 않으며 평상시 사이드바의
폴더 단위 지연 로드는 유지한다([ADR 0105](../../../.mew/docs/decisions/0105-mew-incremental-file-catalog-and-exact-search-index.md)).
두 검색 모두 대소문자 구분과 정규식 옵션을 제공한다. 파일명 정규식은 전체 상대 경로에 적용하며, 의미 검색과
History / raw 확장 검색은 이 화면에 두지 않는다.

검색 요청이 진행되는 동안에는 `검색 중…`을 보인다. 파일 내용 검색은 3글자 이상 리터럴에서 로컬 SQLite
trigram 색인으로 후보를 좁힌 뒤 원문에서 매치를 검증한다. 짧은 질의·정규식·색인 구축/장애 중에는 기존
원문 scanner로 정확성을 유지한다. SSE는 매치 파일을 `result` 이벤트로 보내고, `done`은 잘림·색인 상태·
dirty 보완 파일 수를 함께 보낸다.

탐색기에는 별도 파일명 검색·정렬 도구 줄을 두지 않는다. 파일명 검색은 전용 탭이 맡고, 탐색기 목록은 서버가 정한 기본 순서를 그대로 보인다.

Documents와 일반 폴더를 펼칠 때 내부 폴더는 기억된 펼침 상태가 있으면 복원하고, 없으면 모두 접힌 상태로 시작한다. 하위 프로젝트 항목은 펼치지 않고 해당 프로젝트 탭을 연다.
처음 표시할 때 활성 문서의 경로를 자동으로 펼쳐 이 상태를 덮어쓰지 않는다. 이후 문서 탭 선택에 따른 경로 펼침은 유지한다.

탐색기의 새 파일은 입력한 확장자를 유지하며, 확장자를 생략해도 `.md`를 자동으로 붙이지 않는다.
이전 자동 보정은 코드 파일·확장자 없는 파일을 원하는 이름으로 만들 수 없어 제거했으며 재도입하지 않는다.
마크다운 파일만 기존 문서 초기 내용과 Documents의 MOC 등록을 적용하고, 나머지는 빈 파일로 만든다.

결과는 프로젝트별로 묶지 않는다. 각 파일 행의 맨 왼쪽에는 Documents 또는 그 파일을 포함한 프로젝트의
아이콘을 보이고, hover 경로 패널은 `프로젝트 → 폴더 … → 파일`을 세로 들여쓰기로 보여 준다. 검색의 범위 태그는 Documents와 직계 하위 프로젝트를 사용한다. 중첩 `.mew`
폴더는 이를 포함한 범위에서 검색하며, 탐색기에서는 별도 프로젝트 탭으로 여는 항목이다([프로젝트 사용법](../guides/projects.md)).
