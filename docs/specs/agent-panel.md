기능 항목: [에이전트 대화](../features/agents/conversations.md). 이 문서는 해당 기능의 세부 동작·표시 계약을 소유한다.

## 상태버블

에이전트 대화 헤더의 `i` 오른쪽에 책 모양 **Skills 관리**와 플러그 모양 **MCP 관리** 버튼을 둔다. 전역·프로젝트·하위 프로젝트를 런타임별로 탐색하고 원문 조회·추가·수정·이동·삭제한다. 기존 정보 팝업과 별개의 공통 전체 화면 모달이며 세부 동작·지원 범위는 [스킬·MCP 관리](../configuration/agent-harness.md)를 따른다. 그 오른쪽 톱니 버튼은 **에이전트 기본 지침** 설정을 연다(`serverFiles` 권한). 커밋 방식·응답 언어·답변 길이와 파일 보기 동작은 [공통 지침 설정](../guides/project-setup.md#공통-안내-파일-편집)을 따른다.

**에이전트**와 **터미널**은 별도 패널이다. 에이전트에는 ACP 채팅과 공식 에이전트 TUI를, 터미널에는 일반 셸 탭을 둔다. 에이전트의 `+`는 런타임 선택기를 열고 터미널의 `+`는 셸을 추가한다. 기존 `tmux` 탭은 ID·cwd를 유지한 채 터미널에 표시한다.

패널 이동과 탭 분리는 [ADR 0134](../../../.mew/docs/decisions/0134-mew-dockable-workspace-panels.md)와 [UI 계약](../development/ui-contracts.md#작업-패널-배치)을 따른다. 패널을 접거나 이동해도 세션은 종료하지 않는다. 패널의 닫기 버튼은 누른 칸만 닫고 탭을 같은 종류의 남은 패널로 모은다. 마지막 패널의 탭은 다시 열 때를 위해 보존한다. 남은 패널은 빈자리를 채우며 닫은 분할은 복원하지 않는다. 탭의 `×`만 해당 세션을 끝낸다.

## 새 에이전트 선택

`+` 런타임 목록에서 설치된 에이전트는 행 전체를 누르거나 키보드 Enter·Space로 연다. 행 클릭으로 열 수 있어 중복되는 `사용` 버튼은 제거했으며, 사용자 요청 전에는 다시 추가하지 않는다. 미설치·설치 중인 항목의 열기 동작은 비활성화한다. 미설치 항목의 `설치` 버튼은 맨 오른쪽 톱니 아이콘 바로 왼쪽에 둔다. 설치·설정은 행 선택과 독립적으로 동작하며, 설치 성공 후 해당 에이전트를 여는 기존 흐름은 유지한다.

## 모델·노력도 선택

입력칸의 기본값 저장 버튼은 모델·노력·권한 드롭다운과 같은 20px 높이의 투명 컨테이너에 넣고 아이콘을 가로·세로 중앙에 배치한다. 28px 설정 행 안에서도 중앙 정렬하며 음수 여백으로 위치를 보정하지 않는다.

Codex 모델 드롭다운은 노력도별 항목을 기본 모델 하나로 합친다. 예를 들어 `Astra (low)`·`Astra (medium)`·`Astra (high)`는 `Astra` 하나로 표시하고, 노력도는 바로 옆 사고 드롭다운에서 고른다. 모델 이름의 다른 괄호 설명은 유지한다. 기본 모델이 하나뿐이면 모델 선택만 비활성화하며, 지원 노력도가 여러 개면 사고 선택은 계속 사용할 수 있다.

모델을 바꿀 때 현재 노력도를 지원하면 유지하고, 지원하지 않으면 `medium` → 첫 지원 항목 순으로 선택한다. 사고 목록은 선택 모델이 광고한 지원 값으로 갱신한다. 노력도 변경 시 Codex의 실제 복합 모델 ID도 함께 동기화하여 기본값 저장·재접속과 표시가 어긋나지 않게 한다. 설정 실패 시 이전 값을 유지한다. 다른 런타임의 모델 목록과 기존 셋의 정확한 모델 ID는 유지한다. 실행·기본값 계약은 [런타임 설정](../configuration/agent-runtimes.md#모델권한-기본값과-런타임-선택)을 따른다.

## 로그인 화면

제목은 `<에이전트 이름> 로그인`으로 표시한다. 로그인 방식은 설명 카드 대신 행 전체를 누르는 버튼으로 제공하며, Kimi의 `.com`·`.ai`처럼 선택에 필요한 구분은 이름에 남긴다. API 키는 이름이 연결된 입력란과 `연결` 버튼을 사용한다.

서버 실행 위치, CLI 자격증명 관리, 세션 재연결, 인증 코드 저장 방식 같은 내부 동작 설명은 화면에 표시하지 않는다. 인증 브라우저의 `SERVER OAUTH` 배지와 반복되는 하단 안내도 제거한다. 이 설명 문구는 다시 추가하지 않는다. 구현 정보는 [런타임 설정](../configuration/agent-runtimes.md)에서 관리한다.

진행 상태, 승인 코드·복사, `로그인 계속하기`, 코드 입력, 오류와 재시도 안내는 필요한 상태에서만 표시한다. 로그인 사이트의 호스트와 공급자가 요청한 안내는 유지하며, 긴 OAuth URL은 본문에 나열하지 않는다. Prime의 `/login` 입력처럼 사용자가 직접 해야 하는 단계는 짧게 안내한다. 로그인 방식·인증 작업·브라우저 연결 계약은 유지한다.

내용은 최대 24rem 폭으로 배치하고, 짧은 패널에서는 위쪽으로 스크롤해 뒤로가기와 입력란에 접근할 수 있어야 한다. 버튼과 입력란은 키보드 포커스를 표시하며, 진행 상태는 `status`, 오류는 `alert`로 알린다.

## 빈 대화

연결·초기 준비·히스토리 로딩이 끝난 ACP 채팅에서 표시할 대화 버블이 없으면 본문 가로·세로 중앙에 `채팅을 시작하세요`를 보조 글자색으로 표시한다. 앱 언어에 따라 한국어·영어·일본어·중국어 간체로 번역하며, 메시지·명령·오류 버블이 생기면 숨긴다. 로그인 화면과 로딩 말풍선에는 이 문구를 겹쳐 표시하지 않는다.

## 연결 대기와 재연결

ACP 세션 연결·재연결, 인증 화면을 제외한 초기 준비, 히스토리 전환·현재 대화 새로고침 동안 대화 영역에 크기가 다른 빈 말풍선 네 개를 표시한다. 말풍선에는 빛이 순차적으로 좌우를 왕복하는 shimmer를 적용한다. 말풍선 너비 40%의 빛 띠가 각 방향 1.4초로 내부에서 왕복하며, 바깥으로 사라지거나 끝에서 처음으로 건너뛰지 않는다. 첫 프레임부터 띠를 표시하고 각 말풍선의 위상을 200ms씩 달리한다. 빛 띠는 수평 90도 그라데이션이며 0/25/50/75/100% 위치에 상대 강도 0/50/100/50/0(본문색 불투명도 0/11/22/11/0%)를 적용한다. 기울어진 그라데이션이 사각 레이어의 좌우 경계에서 잘리지 않도록 모든 높이에서 끝을 완전히 투명하게 연결한다. 히스토리 목록 조회에도 같은 컴포넌트의 작은 말풍선 세 개를 사용한다. 테마의 표면색·본문색을 사용하며, 로딩이 끝나면 실제 대화를 즉시 표시한다. 전체 mew 세션 인디케이터와 중복되던 패널 중앙 스피너·검정 덮개·상시 연결 문구는 제거했으며 사용자 요청 전 재도입하지 않는다.

대화·입력 초안은 유지한다. 로딩 중 기존 대화 DOM은 숨기고 `inert`로 조작을 막되 스크롤 위치와 버블 상태를 보존한다. 연결이 끊기면 세션 도구 바도 `inert`로 잠근다. 입력 영역·탭 바·패널 닫기·다른 패널은 가리지 않으며 초안 작성·수정·첨부·높이 조절을 계속할 수 있다. 연결 끊김과 히스토리 전환 동안 버튼·`Ctrl+Enter` 전송은 막고 초안을 유지한다. 초기 준비 중 메시지를 서버 큐에 보내는 동작과 첨부·CLI 모드의 기존 제한은 유지한다.

기존 1초 간격 재연결을 유지한다. 소켓이 열려도 초기 세션 준비 중에는 말풍선을 유지하며, 인증 화면·초기 오류는 숨기지 않는다. 히스토리는 기존 `replay`·`reset`·`error` 수신 시 로딩을 해제한다. 대화 영역은 `aria-busy`, 말풍선은 번역된 접근성 이름이 있는 `status`로 알린다. 모션 감소 설정에서는 띠를 중앙에 고정하고 2초마다 불투명도만 0.35~0.8로 부드럽게 왕복한다. 숨긴 탭에서는 두 애니메이션 모두 멈춘다. 표시 여부와 입력 포커스를 분리하여 다른 패널에 포커스가 있어도 화면에 보이는 말풍선은 계속 움직인다. 연결 끊김 뮤캣 알림은 사용자 요청 전 재도입하지 않으며 실제 작업 오류·완료·승인 알림은 유지한다.

검증: `server/agent-connection-ui.test.ts`는 실제 AgentPanel과 격리 Chromium에서 탭 원장 조회 중 캐시 줄글 미노출·소켓 미연결, 포커스 없는 복원 도킹 패널에서 빛의 실제 위치 변화·좌우 왕복과 양 끝 시점 스크린샷의 픽셀 대비(최소 25/255), 초기 연결·소켓 연결 후 준비 대기·장기 재연결의 알림 없음, 말풍선 영역과 입력칸의 비겹침, 초안 편집·높이 조절·전송 차단·복구, 탭별 격리, 모션 감소, 히스토리 목록·대화 로딩 및 replay/reset/error 후 해제를 데스크톱/모바일 양 테마로 검사한다. 소켓 전송은 fixture로 대체한다.

## 연결 계정·구독·사용량 제한

로그인에 성공해도 구독 권한이나 남은 사용량이 없을 수 있다. Claude·Kimi·Codex·Cursor의 ACP 채팅에서는
로그인 안내가 없는 상태에서 에이전트창의 **i(세션 정보)** 팝업을 열면 `연결 계정 · 구독`의 계정과 공급자 플랜을 바로 보여 준다. 화면의 항목명은 `계정`이며, 조회 방식에 대한 설명은 붙이지 않는다. 계정 조회는 팝업을 열 때 수행하며, 별도의 본문 카드와 추가 펼치기 단계는 두지 않는다. 지원 런타임 설정에서도 같은 계정 정보를 확인할 수 있다. Antigravity는 ACP 채팅·공식 Google 인증을 제공하지만 계정·플랜 정보 카드에는 포함하지 않는다. 공식 서버가 반환하지 않는 계정 정보는 추정하지 않는다.

구독 필요·사용량 소진·크레딧 부족은 인증 만료와 구분한다. 공급자가 Authentication required로 감싸 보내더라도
명시적 한도 오류이면 기존 대화와 로그인 상태를 유지한다. 대기 메시지를 보존하고 자동 전송은 멈춘다.
계정 재조회·패널 재연결·대기 메시지 편집은 실행 재개 신호가 아니다. 사용자가 새 메시지를 보내면 대기 순서대로 재개한다.

무료·미구독과 현재 요청 불가를 같은 상태로 보지 않는다. 무료 한도를 쓸 수 있는 상품은 구독 없이도 사용할 수 있다.
플랜 코드나 조회 실패만으로 미구독을 추정하지 않으며, Kimi의 VIP10처럼 유료 여부를 확인하지 못한 값은 그대로 표시하고 판단을 유보한다.

사용량 확인은 i 팝업의 기존 컨텍스트·입출력·캐시·전체 토큰·API 환산 비용 표시를 사용한다. 중복된 `구독 · 사용량 확인` 동선은 제거하고 `구독 관리`(무료 플랜 또는 구독 필요 시 `구독하기`) 버튼으로 내부 DOM 브라우저의 공식 페이지를 연다. 이 UI 통합은 재시도 금지 결정이 아니다. 팝업은 좁은 패널 폭에 맞추고 내용이 길면 내부에서 스크롤한다. 서버 CLI 계정과 웹 구독 페이지의 계정은 별개로 로그인되어 있을 수 있으므로
구독 창 안에서 같은 계정인지 확인하도록 안내한다. 계정 요약에는 무료 플랜 설명과 공급자 조회 메모를 반복 표시하지 않으며, API 키 연결은 별도 요금임을 표시한다. 구독 창을 닫으면 상태만 재조회하고 결제나 프롬프트 전송은 자동 수행하지 않는다.
계정 정보는 잠시 표시하며 대화 전사·브라우저 저장소에 남기지 않는다. 결정은 [ADR 0130](../../../.mew/docs/decisions/0130-mew-agent-account-entitlement.md),
공급자별 조회 기능·실행 계약·API는 [런타임 설정](../configuration/agent-runtimes.md)에 둔다.

## 새 탭 생성

런타임이나 에이전트셋의 `사용`을 누르면 현재 루트 프로젝트 경로를 서버의 `agent-cwd` 검증에 통과시킨 뒤 탭을 만든다. 검증 중에는 선택기를 그대로 두고 `여는 중…`을 표시한다. 검증 실패 시 이유를 같은 화면에 표시하고 탭은 만들지 않는다. 복원 호환 데이터의 cwd는 비어 있을 수 있지만 새 탭 생성 함수는 빈 cwd를 허용하지 않는다.

탭 목록의 SSoT는 계정 서버 원장이고 `localStorage`는 첫 화면용 fallback이다. 따라서 전사·본문 캐시가 브라우저 저장 한도를 채워 fallback 갱신이 `QuotaExceededError`로 실패해도 새 탭 렌더와 서버 원장 저장을 계속한다. 활성 탭과 최근 런타임·선택기 보기 저장도 같은 원칙으로 best effort 처리한다.

[브라우저 저장 계약](../development/browser-storage.md)에 따라 로컬 전사 캐시는 탭당 512KiB, 다른 재생성 캐시와 합쳐 전체 2MiB를 넘기지 않는다. 긴 대화는 상한 안에 들어가는 최근 이벤트 꼬리를 로컬에 남겨 먼저 보여 주고, 서버 transcript/replay가 도착하면 원본으로 보정한다. 캐시 저장 전에 오래된 캐시부터 정리해 공간을 확보한다. 이벤트 하나 자체가 상한을 넘으면 그 이벤트는 로컬에 담지 않고 서버 복원을 기다린다. 계정 탭 원장 동기화가 끝나면 원장에 없는 닫힌 탭의 `mew:agent-events:*`와 `mew:agent-controls:*`도 제거한다. 2026-09-08 실제 계측에서는 전체 약 10.49MB 중 닫힌 Codex 탭 세 개의 전사 캐시가 6.41MB·1.91MB·1.05MB로 약 89%를 차지해 quota를 소진했다.

서버 탭 원장 조회 단계부터 동일한 빈 말풍선 로딩을 표시한다. 처음 진입할 때 줄글이 먼저 노출되지 않도록 캐시 텍스트 미리보기는 제거했으며 사용자 요청 전 재도입하지 않는다. 캐시 유무와 관계없이 원장 확인 전에는 세션 연결·서버 원장 갱신을 하지 않는다. 원장 확인 뒤 세션 준비가 끝나면 보존된 캐시와 서버 전사를 실제 대화 버블로 표시한다.

ACP 에이전트 대화에서 사용자 메시지 바로 위에 보이는 `모델 · 노력 · 권한` 구분선을 **상태버블**이라 부른다.

- 첫 사용자 메시지에는 항상 보인다.
- 이후에는 직전 사용자 메시지와 모델·노력·권한 중 하나라도 달라진 경우에만 다시 보인다.
- 같은 대화를 한 시간 뒤 이어 가거나 유휴 종료 후 복원해도 조합이 같으면 새 상태버블을 추가하지 않는다. 복원된 답변의 표현·청크가 달라져도 같은 질문에 저장된 설정은 유지한다.
- 전송 시점의 값을 대화 전사에 남기므로, 재접속·세션 복원 뒤에도 당시 상태버블을 보인다.
- 상태버블은 사용자 메시지가 아니라 작업 버블과 같은 전체 폭을 쓴다. 사용자 메시지만 오른쪽으로 들여쓴다.

## 대기 큐 편집

대기 큐 순서 변경은 각 항목 맨 왼쪽의 전용 드래그 핸들로만 시작한다. 마우스·터치 모두 길게 누르지 않고 바로 끌며 핸들에만 `touch-action: none`을 적용한다. 핸들의 위·아래 방향키로도 인접 항목으로 이동한다. 항목이 하나뿐이거나 큐 편집 중이면 핸들을 비활성화한다. 본문 길게 누르기로 이동하는 동작은 제거한다.

대기·예약 큐 컨테이너는 대화 영역보다 위 레이어에 표시하고 높이가 눌리지 않도록 유지한다. 대화 내부 레이어는 분리해 버블이나 새 메시지 표시가 큐의 상단 경계와 내용을 덮지 않도록 한다.

대기 큐 항목을 누르면 목록 안에 편집칸을 만들지 않고 기존 하단 메시지 입력칸에서 본문과 첨부를 편집한다. 편집 중인 큐 행은 배경으로 구분하며 큐 순서 변경·삭제·다른 항목 편집을 막는다. 하단 입력칸의 멘션·스킬·첨부·이미지 붙여넣기·높이 조절을 그대로 사용한다.

편집 중에는 전송 버튼을 저장 아이콘으로 바꾸고, 예약 버튼 자리에 취소 X를 두어 저장 바로 위에 표시한다. 두 버튼은 번역된 `취소`·`저장` 접근성 이름과 툴팁을 제공한다. CLI 모드 전환·새 메시지 예약·전송 기록 탐색은 편집 중 사용하지 않는다.

작성 중이던 새 메시지 본문·첨부·CLI 모드는 큐 편집 상태와 분리해 보존하고 저장·취소 후 복원한다. 모델·노력도·권한도 큐 등록 시점의 표시 이름과 실제 설정 ID를 항목별로 저장한다. 큐 편집을 열면 해당 스냅샷을 드롭다운에 불러오고 변경은 편집 중인 항목에만 보관한다. 저장하면 본문·첨부와 함께 반영하며, 저장·취소 후에는 편집 직전 새 메시지용 모델·노력도·권한으로 돌아간다. 큐를 등록한 뒤 바꾼 설정을 과거 큐 설정으로 덮어쓰지 않는다. 편집 중 기본값 저장은 비활성화한다. 취소는 큐 원본을 유지하며 Esc로도 취소한다. 멘션 후보·사진 미리보기가 열렸으면 Esc는 해당 화면부터 닫는다. Ctrl/Cmd+Enter는 새 메시지를 보내지 않고 수정한 큐 항목을 저장한다. 연결 끊김·첨부 업로드 중·본문과 첨부가 모두 빈 항목은 저장하지 않는다.

## 작업 버블 상태

사용자 채팅 버블은 오른쪽 위, 에이전트 답변 작업 버블은 왼쪽 위 모서리의 라운딩을 0으로 표시한다. 나머지 모서리는 기존 라운딩을 유지하며 접힘·펼침 상태에 동일하게 적용한다.

작업 버블의 점 색은 실행 상태를 뜻한다: 파랑은 진행 중, 초록은 완료, 회색은 중단, 빨강은 실패다. ACP 히스토리에 마지막 종료 이벤트가 없더라도 현재 세션이 유휴면 마지막 작업은 완료로 본다.

완료된 작업은 종료 순간의 전체 전사를 보존한다. 따라서 감독 프로세스가 유휴 종료된 뒤에도 다시 불러온 화면에는 사용자 질문, 답변과 작업 내역 전체, 완료 상태와 경과 시간이 남는다. 이벤트 수가 많다는 이유로 한 턴의 앞부분을 자르지 않는다.
