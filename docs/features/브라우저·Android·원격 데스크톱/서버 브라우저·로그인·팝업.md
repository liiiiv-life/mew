## 요구사항

- 서버에서 웹페이지를 열어 프로젝트 웹앱과 외부 사이트를 사용한다.

### 범위

- URL·탭·뒤로/앞으로·폼·업로드/다운로드·로그인 팝업과 계정별 프로필을 제공한다.

### 경계와 제한

- 사용자의 개인 Chrome을 연결하지 않는다.
- 열린 본인 계정의 일반 탭은 [디버거의 Chromium 분석](../터미널·에이전트·자동화/외부%20DAP%20디버거.md#chromium-분석과-외부-분석-파일)에서 명시적으로 선택할 수 있다. 디버거·브라우저 권한을 함께 요구하고 OAuth 로그인 전용 탭은 제외한다. 디버거가 탭을 자동 생성하거나 브라우저의 입력·탐색·소유권을 가져오지 않는다.
- 사이트 로그인 지원과 DOM 입력·렌더링 한계, 프로필·쿠키 경계는 브라우저 사용법을 따른다.

### 상세 계약

- [서버 브라우저 계약](../../guides/browser.md)

## 구현 내용

- 주소 입력·시작 화면·탭 줄·페이지 iframe에 포커스가 있으면 Ctrl/Cmd+N·T와 기존 새 탭 키는 그 그룹의 빈 내부 탭을 만든다. 주소를 제출하기 전에는 서버 페이지를 열지 않는다. Ctrl/Cmd+W·Shift+W는 현재 내부 탭 하나를 닫으며 마지막 빈 탭 뒤의 시작 화면도 새 탭을 만들 수 있다. iframe은 생성·닫기·번호·순환 키를 앱에 전달하고 앱이 소비하면 서버 페이지 키로 보내지 않는다. 브라우저 예약키를 받는 조건은 [공통 단축키 계약](../../development/ui-contracts.md#포커스-기반-탭-단축키)을 따른다.

- PC·모바일 햄버거 메뉴에서 권한에 따라 열며 Dock에는 표시하지 않는다.

- URL·탭·뒤로/앞으로·폼·업로드/다운로드·로그인 팝업과 계정별 프로필을 제공한다.

- Linux/WSL 창 모드는 전용 가상 화면에서 실행하여 서버 데스크톱의 포커스를 빼앗지 않는다.
- 표시 모드·준비·예외는 [브라우저 계약](../../guides/browser.md#브라우저-창)을 따른다.

- 관리되지 않는 Chromium 시작용 빈 탭 생성을 막고, 생성 도중 닫은 탭도 실제 서버 탭까지 정리한다.
- 정상 로그인 빈 팝업은 유지한다.
