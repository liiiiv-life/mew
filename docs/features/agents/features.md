## 요구사항

- 기능 단위로 요구사항을 관리하고 에이전트 구현과 사용자 검토를 연결한다.

### 범위

- 기능 계층 안에서 요구사항·구현 내용·검증을 목록 항목으로 보고 인라인 편집한다.
- 제목 왼쪽 아이콘으로만 해당 가지를 접고 펼치며, 제목 클릭은 같은 자리에서 제목을 편집한다.
- 원본 문서는 제목 오른쪽 문서 아이콘으로 열며, 접힌 상태에서도 제공하고 본문의 문서 열기 버튼은 제거한다.
- 본문은 Markdown 서식을 적용해 읽고 편집할 때만 원문을 표시한다. 중복 제목·상위 기능 표시는 생략한다.
- 요구사항·구현 내용·검증·관련 파일·커밋은 제목 다음 줄부터 내용을 표시하는 한 열 배치를 사용한다. 섹션 사이의 별도 세로 여백 없이 32px 제목 행을 촘촘하게 배치하고 펼친 기능 아래에는 4px 여백을 둔다.
- 기능 상태는 제목 옆 색상 표시와 접근성 이름·툴팁으로 제공하고, 펼친 본문에는 중복 상태 설명·수정 날짜를 표시하지 않는다.
- 하위 기능은 파일 링크 대신 부모 안의 실제 기능 행으로 표시하며, 같은 패널에서 상태 확인·접기·제목과 본문 편집을 제공한다.
- 요구사항·구현 내용·검증·하위 기능·관련 파일·커밋은 섹션별로 독립적으로 접고 펼친다. 초안을 숨길 때는 미저장 확인을 거치며 다른 섹션을 접어도 편집 내용은 유지한다.
- 처음에는 기능과 내부 섹션을 모두 접어 두고, 이후에는 계정·프로젝트별 펼침 상태·정렬·스크롤 위치를 저장해 다시 연다. 새로 추가된 항목은 접힌 상태로 시작한다.
- 적용하면 선택한 에이전트셋에 즉시 작업을 요청한다.
- 에이전트셋 아래의 작업 방식·단축키 상시 설명은 표시하지 않으며, 셋 미등록처럼 필요한 상태에서만 안내한다.
- 제목·부모 관계·관련 파일·커밋·상태·작업 이력과 새 기능 요청·재위임도 같은 계층에서 제공한다.
- Markdown 프론트매터와 본문을 기준본으로 사용하고 관련 파일·커밋·구현 결과를 연결한다.

### 경계와 제한

- 실행 큐·대화·요청 이력은 서버 소유다.
- 외부 문서 편집만으로 작업을 실행하지 않으며 사용자 승인 상태를 에이전트가 임의 설정하지 않는다.

## 구현 내용

- 메뉴와 모바일 하단 독의 기능 버튼으로 같은 작업 패널을 연다.
- 펼침 상태와 스크롤은 사이드바와 같은 계정의 프로젝트 화면 상태에 저장하고, 기능 목록을 불러온 뒤 복원한다.
- 독 전환 시 펼침 상태와 초안을 유지하며 닫기·Esc·뒤로가기는 미저장 내용을 확인한다.
- 현재 프로젝트·에이전트 권한을 따르고 모바일도 동일한 인라인 계층을 사용한다.
- 기능 전체 팝업은 사용자 요청으로 제거했으며 요청 전 재도입하지 않는다.

- 텍스트 항목을 수정하고 적용하면 명세 저장·작업 접수를 한 번에 수행한다.
- Markdown 원문 범위 치환, 버전 충돌 초안 보존, 동일 요청 재시도, 실행 중 중복 방지를 제공한다.
- 관련 파일·커밋과 과거 실행 결과는 보존한다.
- 제목 편집은 접힌 상태에서도 가능하며 펼침 상태를 바꾸지 않는다. 중복된 제목·부모 편집 행은 사용자 요청으로 제거했고 요청 전 재도입하지 않는다.
- 본문의 제목·불렛·강조·코드·링크·표를 렌더링하고, 문서의 중복 제목·상위 탐색 링크는 원문을 보존한 채 패널에서 숨긴다.
- 파일 링크는 기능 문서 기준으로 열며 링크 클릭은 편집을 시작하지 않는다. 셋·정렬은 공용 자체 선택기를 사용한다.
- `parent`로 연결된 자식은 요구사항 다음의 하위 기능 묶음에 한 번만 표시한다. 본문의 자식 링크 목록은 원문을 보존한 채 생략하고, 등록된 기능으로 향하는 링크는 GUI의 해당 기능으로 이동한다.
