## 요구사항

- 에이전트가 현재 프로젝트의 문서와 지침부터 찾아 읽도록 안내한다.

### 범위

- 에이전트 패널 Skills·MCP 옆 기본 지침에서 Git 브랜치 전략과 세부 동작·커밋 방식·응답 언어·답변 길이·서브에이전트 위임·디버거 활용을 설정하고 파일 보기로 MD를 직접 편집한다.
- 저장은 로그인한 Mew 계정의 모든 프로젝트에서 다음 ACP 요청에 반영하며 다른 계정에는 영향을 주지 않는다.
- Documents 설정에서 자동 안내·진입 문서·추가 지침을 편집하고 미리 본다.
- 없는 문서를 생성하는 프로젝트 초기화 GUI와 CLI를 제공한다.

### 경계와 제한

- 공통 자동 안내는 사용자 요청이나 프로젝트 지침을 대체하지 않는다.
- 서브에이전트 위임 설정은 런타임 기능 활성화나 강제 차단이 아니며 상위 지침·지원 범위 안에서 적용한다.
- 브랜치·Git 자동 처리는 다음 요청에서 AI에게 전달하는 지침이다. 설정 저장만으로 Git 명령을 실행하지 않는다. 수동 모드는 기존 커밋 설정을 따르며, 자동 모드를 선택하면 작업 커밋·검증·병합과 선택한 원격·정리 범위의 권한도 전달한다. 사용자 요청·프로젝트 지침·직접 편집한 제약과 브랜치 보호는 유지한다.
- 문서 진입점·description 탐색 안내를 전달하며 새 문서의 MOC 등록 의무를 두지 않는다. 제거된 RAG 검색 명령은 전달하지 않는다.
- 초기화는 기존 문서·사용자 설정을 보존하는 계약을 따른다.

## 구현 내용

- 에이전트 패널의 기본 지침 설정은 MD 원문에서 선택값을 읽고 변경한 항목만 저장한다.
- 기본 지침 창은 공용 `DialogFrame`의 `size="settings"`로 [전체 설정과 같은 크기](../../development/ui-contracts.md#설정-창-레이어)를 사용한다. 일반·Git 그룹을 구분하고 제목과 드롭다운·입력을 같은 행에 둔다. 긴 내용은 본문 안에서 스크롤한다. 브랜치 전략 설명은 기본으로 접힌 **브랜치 세부 설정**에 두고, Git 자동 처리·커밋 설명은 해당 행 아래에 표시한다. 드롭다운·입력의 최소 높이는 PC에서 32px, 터치 환경에서 44px다. 하단에는 파일 보기·저장 상태·새로고침을 두며 새로고침·닫기는 접근성 이름과 툴팁을 갖춘 아이콘 버튼을 쓴다.
- 파일 보기로 기존 에디터에서 직접 수정한다.
- 기존 TXT와 자유 지침을 보존하며 동시 수정 충돌을 알린다.
- 세션 시작 계정의 원문을 모든 프로젝트의 다음 ACP 요청에서 다시 읽는다. 기존 공용 원문·모델 기본값·런타임 설정은 최초 owner 계정에만 한 번 이전하며 다른 계정에는 복제하지 않는다.
- 서브에이전트 위임은 별도 지정 안 함·필요할 때 자동 위임·요청할 때만 위임·사용 안 함을 제공한다. 기존 지침은 선택을 강제하지 않으며 지원 런타임에 전달할 문장만 저장한다.
- 자동 위임은 독립적인 작업에 한정하고 공유 파일 수정 조율·결과 검토 및 통합을 지시한다.
- 디버거 활용은 활성화·비활성화를 제공하며 기본값은 활성화다. 설정 구간 없는 기존 지침에는 읽을 때만 영어 안내를 보충하고 저장 원문을 보존한다. 직접 편집한 구간과 명시적인 비활성화는 덮어쓰지 않는다.
- 활성화는 로그·테스트로 설명이 부족할 때 디버거 활용과 변수·호출 스택 확인, 기존 실행·권한 제한 준수 및 임시 연결·프로세스 정리를 지시한다. 비활성화는 사용자 명시 요청 시에만 사용하도록 안내하며, 어느 값도 디버거를 자동 설치·실행하지 않는다.

- 브랜치 전략은 GitHub Flow를 기본으로 Git Flow·Trunk 기반·프로젝트 지침에 따름을 제공한다. GitHub Flow는 통합 브랜치에서 짧은 작업 브랜치를 만들고 검토·검증 뒤 통합하는 흐름이며, 기존에 적절한 작업 브랜치가 있으면 재사용한다. Git Flow는 개발·배포 브랜치를 구분하고, Trunk 기반은 작은 변경을 빠르게 통합하도록 안내한다.
- Git 그룹 안에 브랜치 전략·자동 처리 범위·커밋 방식·세부 설정·저장 버튼을 모으고 응답 언어·답변 길이·위임·디버거 같은 일반 지침과 구분한다. Git 자동 처리는 기존 커밋 설정 사용·로컬 병합까지 자동·원격 반영까지 자동을 제공한다. 기본값은 로컬 병합까지 자동이며, 원격 반영은 포함하지 않는다. 자동 모드는 각 Git 단계마다 다시 묻지 않고 이번 작업의 커밋·검증·diff 검토·통합을 마무리하도록 지시한다. 원격 모드만 기존 upstream의 fetch·일반 push 또는 기존 PR 흐름을 허용하며 보호 규칙·필수 검토·CI를 우회하지 않는다.
- 자동 모드에서는 표준 커밋 구간을 요청에서만 생략해 커밋 시점·push 제한과의 충돌을 피한다. 저장 원문과 수동 커밋 선택값은 유지하며 직접 편집한 커밋 제약은 제거하지 않는다. 일반 커밋 선택기는 자동 모드에서 비활성화하고 수동 모드로 돌아오면 저장값을 다시 적용한다.
- 정리를 켠 자동 모드는 이번 작업의 통합된 로컬 브랜치·임시 worktree 삭제도 허용한다. squash 후에는 단순 조상 관계 대신 실제 변경 통합을 확인하며 미커밋·고유 변경, 다른 작업·실행 중인 세션의 worktree와 원격 브랜치는 보존한다. 검사 실패·대상 모호함·기존 변경 보존 때문에 진행할 수 없으면 구체적인 원인을 알린다.
- 기본으로 접힌 브랜치 세부 설정에서 기본 브랜치의 자동 감지 또는 직접 지정, Git Flow의 개발 브랜치, 작업 브랜치 접두사, 작업 폴더의 worktree 사용 방식, 승인된 병합 방식과 통합 후 로컬 브랜치 정리를 다룬다. **브랜치 세부 설정**과 **Git 설정 저장**은 같은 줄에 두고 펼친 입력은 본문 전체 너비를 사용한다. 브랜치 설정은 **Git 설정 저장**으로 전략과 세부 값을 함께 저장하며 다른 일반 지침은 기존처럼 즉시 저장한다. 사용법과 기본값은 [브랜치 지침 설정](../../guides/project-setup.md#git-브랜치-지침)을 따른다.
- worktree 자동은 공유 체크아웃이나 기존 변경과의 충돌 위험이 있을 때 별도 작업 폴더를 권한다. 기존 미커밋·스테이징 변경은 보존하고 자동 stash·reset을 하지 않는다. 새 worktree에 기존 미커밋 변경이 자동으로 옮겨지는 것으로 가정하지 않는다. Git 저장소가 아니면 브랜치 지침을 건너뛴다.
- 새 worktree는 기본 체크아웃의 `.worktrees/<브랜치 슬러그>`를 사용하도록 안내한다. 브랜치의 `/`는 `-`로 바꾸고, 공용 Git 디렉터리·등록 목록으로 기본 체크아웃을 찾아 중첩 생성을 막는다. 생성 전 기본 체크아웃의 `/.worktrees/` ignore를 확인하고 명시적인 사용자·프로젝트 경로는 우선한다. 기존 worktree 이전은 요청받은 경우에만 프로세스·세션의 경로 의존성을 확인한 뒤 `git worktree move`로 수행한다. [결정 0054](../../decisions/0054-internal-worktrees.md)를 따른다.
- 브랜치 설정 구간이 없는 기존 MD·TXT에는 읽을 때만 기본 지침을 보충한다. v1·v2 구간은 고정된 이전 렌더러와 정확히 대조해 정상 선택값을 인식하고 저장 원문·전략·세부 값을 보존한다. v1은 로컬 병합 기본값으로 읽고 v2의 명시적 수동·원격 선택은 유지한다. 실제 요청에서는 정상 v1·v2 구간을 현재 v3 생성문으로 바꾸며 직접 저장할 때 v3 형식을 사용한다. 자유 지침과 직접 편집한 구간은 유지하고 GUI에서 **직접 편집한 지침**으로 표시한다. 프로젝트 지침에 따름을 명시하면 자동 처리 지침도 추가하지 않는다.
- 기본 전략의 선택 근거는 [결정 0045](../../decisions/0045-agent-branch-guidance.md), 선택한 자동 처리의 권한과 이전 설정 보존은 [결정 0046](../../decisions/0046-agent-git-automation.md)에 둔다.

- Documents 설정에서 자동 안내·진입 문서·추가 지침을 편집하고 미리 본다.

- 로컬 RAG CLI·설정 조회와 자동 검색 안내를 제거했다.
