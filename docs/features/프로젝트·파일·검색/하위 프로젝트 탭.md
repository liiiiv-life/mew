## 요구사항

- 폴더 안의 프로젝트를 현재 트리에서 탐색하고 필요할 때 독립 작업 루트로 선택한다.

### 범위

- 프로젝트의 `.mew/project-icon.json` 하나를 사이드바·프로젝트 선택기의 공통 아이콘으로 사용한다.

- 실제 `.mew` 디렉터리를 가진 하위 프로젝트도 일반 폴더와 같은 위치·정렬로 표시하며, 폴더 행은 펼침·접기와 내부 파일 탐색·조작을 제공한다.
- 폴더를 하위 프로젝트로 지정하고 별도 화살표로 작업 루트를 전환한다. 이미 등록된 경로는 프로젝트 목록에서 재사용한다.

### 경계와 제한

- 하위 프로젝트의 파일 탐색·조작은 현재 프로젝트의 파일 권한을 따른다.
- 지정은 Git 초기화나 자동 루트 전환을 하지 않으며 화살표를 통한 프로젝트 전환은 owner 권한을 따른다.

### 상세 계약

## 구현 내용

- `server/projectIcons.ts`가 프로젝트별 아이콘 읽기·저장·기존 값 이관을 맡는다. 직계·중첩 트리와 프로젝트 선택기는 같은 값을 표시하고, 선택기에서 변경하면 프로젝트 파일을 갱신한다.

- [ADR 0004](../../decisions/0004-subproject-folder-exploration.md)에 따라 폴더 행은 펼침만 바꾸고 별도 `SubprojectLink` 화살표가 프로젝트 전환을 실행한다. 서버는 owner·출발 루트·실제 하위 경로·`.mew`·파일 열람 권한을 검사한다. 헤더는 [프로젝트 선택기](../../decisions/0019-project-selector.md)를 사용하며 상위 프로젝트 경로도 목록에 남는다.

## 검증

- `projectIcons.test.ts`·`project-icons-api.test.ts`: 공통 SVG·중첩 아이콘·이관 우선순위·초기화·이름 변경·손상/링크 보호·owner 권한·계정 사본 배제를 검증한다.

- 아래 항목은 이번 정리에서 실행한 테스트 결과가 아닌 사용자 확인 기준이다:
  - 직계·중첩 프로젝트 폴더를 현재 트리에서 펼치고 내부 파일을 열 수 있는지 확인한다.
  - 화살표를 누르면 해당 루트로 전환하고, 상위 프로젝트와 이미 등록된 하위 프로젝트를 헤더 목록에서 다시 선택할 수 있는지 확인한다.
