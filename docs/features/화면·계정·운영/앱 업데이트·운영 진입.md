## 요구사항

- 접속마다 설치된 Mew 관련 의존성·에이전트 런타임의 업데이트를 확인하고 뮤캣이 알린다.
- 햄버거 메뉴의 **업데이트**에서 현재·최신 버전, 항목별 실행·세션 보기와 일괄 업데이트를 제공한다.
- `system` 권한이 있으면 **Ctrl/Cmd+U**로도 같은 화면을 연다. 편집기·입력란·터미널에 포커스가 있어도 동작하며 키 반복·IME 조합 중에는 다시 열지 않는다. 원격 데스크톱 등 전용 키보드 입력이 활성화된 화면은 해당 입력을 우선한다.

### 범위

- 통합 업데이트 화면에 Mew·설치된 독립 에이전트 CLI·시스템 도구를 표시한다.
- 독립 에이전트는 개별 업데이트만 허용하고 실행 중에는 차단한다. 시스템 도구는 일괄 순차 실행하며 진행 상태·실패 이유와 재시도 버튼을 제공한다.
- 자동 갱신이 불가능한 설치 방식은 사유를 표시하고 일괄 업데이트에서 제외한다.
- 의존성 작업이 모두 성공하면 Mew 업데이트를 마지막에 실행한다.

- Mew·에이전트·도구 업데이트는 전용 tmux 세션에서 실행하고 출력과 결과를 세션에 남긴다. 업데이트 화면을 닫아도 작업은 계속되며 항목의 터미널 아이콘으로 세션을 다시 연다.
- Mew 업데이트는 pull·의존성 설치·빌드·재시작을 순서대로 실행한다. 빌드 실패 시 서버를 재시작하지 않고 실패·로그·재시도를 제공한다.
- pull 이후 실패해도 Git 커밋이 최신이라는 이유로 재시도를 차단하지 않는다. 페이지를 다시 열면 작업 상태와 세션 진입을 복원한다.

### 경계와 제한

- 앱 npm 의존성과 번들 ACP 어댑터는 최신 조회·알림·개별·일괄 업데이트에서 제외한다. Mew 업데이트에서 커밋의 lockfile 조합을 설치하며 이전 `npm:*` API 요청도 거절한다.

- 실행·설정·HTTPS·백업의 상세 기준본은 배포 문서다.
- 이 기능 문서 정리에서는 업데이트·빌드·재시작을 실행하지 않는다.

### 실행과 세션 보기

- 업데이트 화면·실행은 기존 `system` 권한을 따른다. 세션 보기에는 `terminal` 권한도 필요하며 이 권한이 없으면 터미널 아이콘을 표시하지 않는다.
- 각 항목의 업데이트 버튼은 작업을 시작한다. 옆의 터미널 아이콘은 세션이 생기면 활성화되며 **항목명 터미널 세션**이라는 접근 가능한 이름을 제공한다. 명령 버튼과 같은 터미널 팝업에서 실시간 출력과 남은 로그를 확인한다.
- 개별 업데이트는 항목별 세션을 사용한다. 시스템 도구의 일괄 업데이트는 하나의 세션에서 순차 실행하며 해당 큐의 각 행이 같은 세션을 연다.
- 터미널 팝업이나 업데이트 화면을 닫는 동작은 세션을 종료하지 않는다. 업데이트 터미널 팝업에는 강제 종료 버튼을 두지 않는다. 실행 중 여부와 세션 존재 여부를 구분하므로 성공·실패 뒤에도 세션을 다시 열어 출력과 종료 결과를 확인한다.
- 같은 항목을 다시 업데이트하면 이전 완료 세션을 교체한다. 시스템 도구 일괄 업데이트도 다음 일괄 실행이 이전 일괄 세션을 교체하므로 이전 출력은 새 실행 전까지 확인할 수 있다.
- Mew가 재시작하면 브라우저의 터미널 연결은 끊길 수 있다. 업데이트 작업과 세션은 서버 프로세스 밖에서 계속되며, Mew에 다시 연결한 뒤 같은 세션을 연다.
- Mew 업데이트 성공이 확인되면 업데이트 화면 헤더와 Mew 터미널 팝업에 **새로고침** 아이콘을 제공한다. 사용자가 눌러 브라우저를 다시 불러오며 자동 새로고침은 하지 않는다. 이 버튼은 업데이트 작업이나 서버 재시작을 새로 실행하지 않는다.

## 구현 내용

- 통합 업데이트 화면에 Mew·설치된 독립 에이전트 CLI·시스템 도구를 표시한다.
- 독립 에이전트는 개별 업데이트만 허용하고 실행 중에는 차단한다. 시스템 도구는 일괄 순차 실행하며 진행 상태·실패 이유와 재시도 버튼을 제공한다.
- 자동 갱신이 불가능한 설치 방식은 사유를 표시하고 일괄 업데이트에서 제외한다.
- 의존성 작업이 모두 성공하면 Mew 업데이트를 마지막에 실행한다.

- 전용 tmux 작업을 로그인 셸 없이 직접 시작하고 기존 세션 터미널 팝업으로 출력을 연다. 작업이 끝나도 출력 확인을 위해 세션을 보존한다.
- 에이전트·도구 큐와 항목별 세션 연결은 `dependency-update-job.json`에 저장하며 별도 worker가 실행한다. Mew 서버 종료·재시작 뒤에도 상태를 복원하고, 실행 중이던 worker가 사라졌으면 남은 대기·실행 항목을 실패로 바꾼다.
- 시작 실패·작업 중단을 실패 상태로 기록하며 화면에 오류 로그와 재시도를 제공한다. pull 뒤 실패한 작업도 전체 업데이트를 다시 수행할 수 있다.

### 실행 Node와 알림 종료 (2026-10-06)

업데이트 작업은 서버의 `process.execPath`를 사용하며 Bash로 스크립트를 실행한다. 설치·빌드의 PATH 앞과 재시작의 `MEW_NODE`에도 같은 런타임을 전달하여 tmux의 다른 Node 버전·스크립트 실행 권한에 영향받지 않는다. 실제 업데이트 적용은 사용자가 실행한다.

뮤캣 업데이트 알림의 X·전체 지우기·업데이트 열기는 표시된 앱 remote hash와 도구 최신 버전을 브라우저에 기억한다. 다시 접속해도 같은 버전은 알리지 않고, 아직 닫지 않은 새 버전이 발견되면 다시 알린다. 일부 항목을 업데이트해 목록이 줄어드는 것은 새 업데이트로 취급하지 않는다. 업데이트 화면은 메뉴에서 계속 열 수 있다.

검증 (2026-10-06): 관련 서버·격리 Chromium 테스트와 TypeScript·대상 lint를 실행했다. 실제 업데이트 설치·빌드·서버 재시작은 실행하지 않았다.

### 사전 빌드 CLI의 운영 경계 (2026-10-14)

`MEW_DISTRIBUTION=release`에서는 Mew 상태 조회가 Git 또는 source 업데이트 작업 파일을 읽거나 변경하지 않는다. 앱 빌드·재시작·pull 작업과 번들 tmux 개별 업데이트는 서버에서 거절하고 CLI 종료 후 `npx @liiiiv/mew-cli@latest` 재실행을 안내한다. 외부 독립 에이전트는 기존 개별 업데이트·실행 중 차단 규칙을 유지한다. [CLI 배포 계약](../../development/cli-distribution.md)을 따른다. 격리 API·업데이트 검증으로 source 명령이 호출되지 않는 것을 확인했으며 실제 업데이트·빌드·재시작은 실행하지 않았다.
