## 요구사항

- 상단바의 업로드·다운로드 누적량·속도 버튼과 별도 네트워크 팝업을 제거하고 시스템 자원 팝업에 통합한다.
- CPU·메모리·GPU 아래, 프로세스 목록 위에서 누적량과 초당 속도를 확인한다. 업로드·다운로드 열은 화살표 아이콘으로 구분한다.

## 상세 동작

- 현재 Mew 탭을 연 뒤의 업로드·다운로드 누적량을 각각 소수점 한 자리와 B·KB·MB·GB·TB 단위로 표시한다. 속도 표시는 같은 형태에 `/s`를 붙인다.
- 시스템 자원 팝업은 누적 사용량·네트워크 속도 표를 제공한다. 각 표에는 원격 데스크톱·그 외·전체 행과 업로드·다운로드 열이 있다. 네트워크 표는 팝업이 열린 동안 약 1초마다 갱신하고, 실제 표본 간 경과 시간으로 속도를 계산한다. 통신이 멈추면 속도는 0으로 돌아가며 누적량은 보존한다.
- 원격 연결을 종료하거나 다른 프로젝트로 이동해도 합계를 유지한다. 원격 세션의 상단 표시는 접속별 값이며 시스템 자원 팝업은 모든 원격 세션을 합산한다.
- 새로고침하면 초기화하며 다른 탭·기기·계정의 트래픽을 합치지 않는다. 팝업에 현재 탭의 추정치라는 범위를 표시한다.
- 기본 0.0 B·0.0 B/s에서도 표를 표시하고 PC·모바일·양 테마·네 언어를 지원한다. 닫기·바깥 클릭·Esc·뒤로가기와 포커스 복원은 시스템 자원 팝업을 따른다. 서버 자원 조회 실패·로딩 중에도 네트워크 표는 표시한다.
- 일반 Mew HTTP·협업·터미널·에이전트 등의 WebSocket과 원격 영상·입력을 포함한다. 전송 계층 헤더·브라우저가 제공하지 않는 바이트 등은 제외하며 OS·통신사의 청구량과 다를 수 있다. [집계·중복 방지와 한계](../../development/network-usage.md)를 따른다.

## 구현 진입점

`main.tsx`의 공통 추적기가 저장소를 갱신하고 `NetworkUsagePanel`이 시스템 자원 팝업 안에서 구독한다. 팝업을 닫으면 속도 표본 타이머를 정리하지만 누적량은 계속 집계한다. 다시 열면 첫 새 표본부터 현재 속도를 표시한다. 원격 연결은 접속별 집계의 증분만 같은 저장소에 추가한다. 네트워크 표를 위한 추가 서버 요청·새 권한·영구 데이터 파일은 없다.

## 확인 기준

- 일반 통신과 원격 연결이 각각 올바른 행에 반영되고 전체의 업로드·다운로드 누적량과 속도가 각 범주의 합과 일치한다.
- 여러 원격 세션을 열고 닫아도 이전 사용량이 남고 같은 표본은 중복 집계되지 않는다. 표본 지연·유휴·재구독에서도 속도가 실제 경과 시간과 현재 트래픽을 반영한다.
- 업로드·WebSocket·지속 SSE 데이터가 갱신되고 정상 응답·입력·취소 동작이 유지된다.
- 320px 모바일과 데스크톱에서 시스템 자원 팝업의 표가 넘치지 않으며 언어 전환·키보드·뒤로가기·포커스 복원을 확인한다.

2026-10-07: 관련 단위·공용 번역 검사 10개와 격리 Chromium의 네트워크 팝업 1개·WebRTC 뷰어 2개 시나리오를 통과했다. 실제 HTTP·WebSocket·SSE와 취소·clone·중복 집계 방지, 원격 뷰어 종료 후 합계 보존, 320/390/1100px·양 테마·네 언어·Esc·포커스 복원을 확인했고 PC·모바일 캡처를 검토했다. 대상 린트·문서 description·문서 경계 검사가 통과했다. 프런트엔드 타입 검사는 초기에 통과했으나 최종 재확인에서 작업 밖 Git UI 변경의 타입 오류가 발생했고 전체 타입 검사는 작업 밖 `server/remote-access-agent.ts` 오류로 실패했다. 운영 빌드·서버 재시작·실제 원격 기기 검증은 수행하지 않았다.
