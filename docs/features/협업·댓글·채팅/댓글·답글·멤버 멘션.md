## 요구사항

- 본문 선택 위치에 의견을 남기고 스레드로 대화한다.

### 범위

- 선택 위치 댓글·답글·멘션·수정·삭제와 댓글 목록을 제공한다.

### 경계와 제한

- 댓글은 본문과 별도로 관리한다.
- 목록 조회에는 파일 열람 권한, 등록·수정·삭제에는 파일 수정 권한도 필요하다.
- 읽기 전용·보관된 파일에서는 기존 댓글 조회만 제공한다. 본문을 불러오는 동안에도 댓글을 새로 작성하거나 변경하지 않는다.
- 원문이 바뀌어 앵커를 못 찾는 댓글도 목록에 남기며 작성자·owner의 관리 권한을 구분한다.
- 로그인과 협업 기능 권한이 있는 프로젝트 안의 텍스트 편집 화면에 제공한다. 게스트·미디어·diff·프로젝트 밖 파일·앵커 미리보기와 파일 재검증 중에는 댓글을 시작하지 않는다.

### 댓글 시작과 단축키

Markdown의 Hotview·Plain이나 코드·텍스트에서 글자를 선택하고 기본 단축키 `Ctrl+Shift+C`(macOS는 `Cmd+Shift+C`)를 누르면 선택한 부분을 인용한 댓글 입력 팝업을 연다. 단축키는 선택이 비어 있으면 새 댓글을 만들지 않는다. 모바일에서는 선택 후 키보드 보조키 바의 댓글 아이콘으로 같은 입력창을 연다. 단축키는 설정에서 바꿀 수 있으며 기존 사용자 지정 조합은 유지한다.

본문 우클릭 메뉴의 **댓글 달기**는 기존 선택을 사용하며, 선택이 없으면 우클릭한 Hotview 문단 또는 Plain·코드의 줄을 자동 선택해 댓글을 시작한다. 텍스트가 없거나 댓글 작성 권한이 없으면 항목을 비활성화한다. 생성 후 앵커·저장·작성자 권한은 기존 댓글과 같다.

앱에 전달된 댓글 단축키는 실제 텍스트 편집기에 포커스나 선택이 있을 때 capture 단계에서 브라우저 기본 동작을 막고 해당 편집 칸에 전달한다. 유효한 편집기에서는 선택이 없거나 반복·IME 입력이어도 키를 소비하며 댓글은 만들지 않는다. 터미널·에이전트·원격 화면·모달의 키를 댓글 단축키로 가로채지 않는다. 브라우저 예약키와 원격 입력 우선권은 [공용 입력 계약](../../development/ui-contracts.md#포커스-기반-탭-단축키)을 따른다.

### 작성·스레드·목록 화면

작성 팝업은 작은 제목 줄과 선택한 구절의 인용, 멤버 멘션을 지원하는 입력칸, 닫기·등록 아이콘 버튼으로 구성한다. 빈 내용은 등록하지 않는다. Enter로 등록하고 Shift+Enter로 줄을 바꾸며, 멘션 후보가 열려 있으면 Enter는 후보를 먼저 선택한다.

스레드는 작성자 아바타·작성 시각·본문을 묶어 보여 주고 아래에 답글 입력칸을 둔다. 수정 가능한 파일에서 작성자와 owner에게만 수정·삭제 도구를 표시하며 키보드와 터치에서도 사용할 수 있다. 수정 중에는 저장·취소를 구분한다. 작성·답글·수정 요청이 실패하면 내용을 지우거나 입력창을 닫지 않고 오류와 초안을 유지한다. 요청 중에는 같은 내용을 중복 전송하지 않는다.

워크스페이스·파일·계정·보기 모드나 댓글 권한이 바뀌면 이전 팝업과 목록을 닫고, 이전 조회·등록·수정·삭제의 늦은 응답을 새 화면에 적용하지 않는다.

댓글 목록은 제목·스레드 수·닫기 버튼을 위에 두고, 각 항목에 인용 구절·첫 댓글·작성자·시각·답글 수를 표시한다. 댓글이 없으면 빈 상태를 표시한다. 항목을 고르면 본문 위치로 이동하고 스레드를 연다. 위치를 찾지 못해도 스레드를 열고 그 이유를 표시한다.

팝업은 모바일 키보드를 제외한 보이는 화면 안에 배치하고 긴 스레드·목록은 내부에서 스크롤한다. 닫기·Esc·뒤로가기로 닫으며, 스레드 안의 입력과 메뉴를 키보드로 조작할 수 있다.

## 구현 내용

- 선택 위치 댓글·답글·멘션·수정·삭제와 댓글 목록을 제공한다.
- 댓글 단축키는 capture 단계에서 처리하고, 작성·스레드·목록에 작은 인용 영역과 아이콘 도구를 사용한다.

## 검증

- 아래 항목은 실행 결과가 아닌 사용자 확인 기준이다:
  - 댓글 앵커·답글·멘션과 원문 변경 후 목록 접근, 타인 댓글 수정 권한을 확인한다.
  - 텍스트 선택 후 `Ctrl+Shift+C`가 댓글 작성창을 열고, 선택이 없거나 댓글을 지원하지 않는 화면에서는 댓글을 만들지 않는지 확인한다.
  - 키보드·터치로 닫기·등록·수정·삭제·목록 선택을 조작하고, 작은 화면과 키보드가 열린 상태에서 입력칸과 버튼에 접근할 수 있는지 확인한다.
  - 작성·답글·수정 요청이 실패했을 때 초안을 유지하고 재시도할 수 있는지 확인한다.
