## 요구사항

- 프로젝트 작업 중 멤버와 메시지·파일 참조를 주고받는다.

### 범위

- 단체방·DM·읽지 않은 대화·메시지별 읽음 상태와 파일 참조 열기를 제공한다.

### 경계와 제한

- 채팅 기능을 허용한 로그인 사용자만 사용한다.
- 기록 삭제는 관리자(owner)만 할 수 있다. manager·member·guest에는 삭제 버튼이 없으며 API도 거부한다.
- DM은 앱의 당사자 전달 범위이며 서버 관리자에게 숨기는 암호화 비밀 대화가 아니다.

### 기록 삭제

- 채팅 헤더의 휴지통 버튼으로 현재 단체방 또는 본인이 참여한 DM의 기록을 삭제한다. 빈 대화와 삭제 중에는 버튼을 비활성화한다.
- 확인창은 대상 대화와 모든 참여자에게서 영구 삭제되는 결과를 안내한다. 취소하면 기록을 유지한다.
- 삭제는 서버 원장의 해당 메시지를 제거한다. 다른 대화와 남의 DM은 유지한다. 여러 수신자가 있는 멘션 DM은 메시지 전체가 삭제되므로 그 메시지의 다른 수신자 화면에서도 사라진다.
- 삭제 후 presence 신호로 참여자의 기록·읽지 않은 수를 다시 조회한다. 실패하면 오류를 표시하고 재시도할 수 있다.

## 구현 내용

- `DELETE /api/chat`에 owner·chat 권한을 함께 검사하고, 대화 키를 기준으로 원장을 삭제한다. 읽음 포인터를 보존하며 새 메시지의 시각은 보존된 읽음 시각보다 크게 생성한다.

- 단체방·DM·읽지 않은 대화·메시지별 읽음 상태와 파일 참조 열기를 제공한다.

## 검증

- 자동 검증: `server/chat-history.test.ts`는 owner 전용 API·잘못된 입력·대화별 삭제·남의 DM 보존·재삭제·삭제 직후 읽음 계산·다중 수신자 삭제를 확인한다. `server/chat-history-ui.test.ts`는 실제 채팅 패널의 1100/390px 확인창·취소 포커스·취소·삭제·빈 대화 비활성화·오류와 재시도·presence 재조회·관리자 외 버튼 비노출을 확인한다. 기존 채팅 테스트도 통과했다.

- 아래 항목은 이번 정리에서 실행한 테스트 결과가 아닌 사용자 확인 기준이다:
  - 단체방·DM의 수신 범위와 읽음 상태, 파일 참조 열기를 확인한다.
  - owner의 단체방·DM 삭제 확인/취소·오류·실시간 갱신과 다른 역할의 버튼 비노출·API 거부를 확인한다.
