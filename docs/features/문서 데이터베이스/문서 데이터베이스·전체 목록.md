## 요구사항

- 문서 안에 표 데이터베이스를 넣고 프로젝트의 데이터를 편집한다.

### 범위

- 문서 DB 삽입, 표·카드·보드·캘린더·간트 뷰, 제목·텍스트/숫자/체크박스/날짜/단일선택/다중선택/페이지 열과 행·셀 편집, 실시간 갱신을 제공한다.
- 독립 [태스크 패널](../프로젝트·파일·검색/태스크%20패널·목록·달력·간트.md)과 함께 제공한다. 태스크 Markdown과 DB 행을 자동 이관하거나 동기화하지 않는다.
- 같은 DB의 뷰를 전환해도 행·열 데이터를 복제하지 않는다. 카드·일정에서 항목 상세를 열어 기존 속성 편집기를 사용하고 연결된 행 페이지로 이동한다.
- 보드는 단일선택·체크박스 열로 그룹을 나누며, 캘린더는 종료일과 선택적인 시작일 날짜 열로 월별 단일 날짜·기간 일정을 표시한다. 필요한 열이 없으면 편집 가능한 DB에서 해당 열 추가를 제공한다.
- 메뉴의 데이터베이스 목록에서 현재 프로젝트 DB를 열람·편집한다.
- Plain에서 DB 참조를 Ctrl/Cmd+클릭하면 해당 DB를 선택한 팝업을 연다.
- 각 열 제목 오른쪽의 정렬 버튼으로 오름차순 → 내림차순 → 해제를 전환한다. 읽기 전용 표도 정렬할 수 있다.
- 셀을 우클릭해 해당 열의 타입을 바꾼다. 타입 변경은 클릭한 셀 하나가 아니라 열 전체에 적용한다.
- 첫 데이터 열은 각 행의 대표열이며, 비어 있지 않은 유일한 제목을 갖는다. 기본 타입은 텍스트이며 페이지로 전환할 수 있다.
- 새 DB는 `제목` 대표열과 일반 `텍스트` 열, 예시 값이 입력된 2개 행으로 시작한다.
- 대표열을 페이지로 전환하면 DB가 있는 문서의 바로 하위에 각 행의 제목을 파일명으로 하위페이지를 만들고, 나머지 열 값과 페이지 프론트매터 필드를 양방향으로 공유한다.

### 경계와 제한

- DB를 넣은 Markdown 본문에는 참조 ID와 문서별 표시 설정을 저장하며, 실제 행·열 데이터는 Postgres가 소유한다. 페이지로 연결한 행의 필드는 하위페이지 프론트매터에도 동기화한다.
- Postgres 연결이 없으면 DB API를 사용할 수 없다.
- DB 기능·프로젝트 전체 접근 권한을 확인한다.
- 연결한 하위페이지의 파일 저장에도 DB 편집과 같은 기능·프로젝트 전체 수정 권한을 적용한다.

## 구현 내용

### Markdown 표와 전환

- 편집 가능한 Hotview 문서에서 DB를 우클릭하면 `표로 전환`을 제공한다. 편집 가능한 셀의 기존 열 타입 메뉴에도 같은 항목을 추가한다. 제목·카드·보드·캘린더에서도 DB 전체를 전환하며 독립 DB 팝업에는 표시하지 않는다. 읽기 전용 DB 참조·외부 테이블도 문서를 편집할 수 있으면 스냅샷 표로 전환한다. 문서 자체가 읽기 전용이면 양방향 전환을 제공하지 않는다.
- DB→표는 `getView(id, {allRows: true})`로 검색·정렬·뷰 설정과 무관한 전체 행·열을 읽어 문서 본문의 일반 표로 만든다. 기본 조회의 1,000행 제한을 적용하지 않는다. 열 이름은 헤더가 되고 숫자·체크박스·날짜·페이지 제목은 텍스트, 다중선택은 쉼표로 이은 텍스트, 빈 값은 빈 셀이 된다. 줄바꿈을 유지한다. DB 타입·선택 색상·행 페이지 본문은 일반 표에 복제하지 않는다.
- 표→DB는 `TableCopyMenu`의 `데이터베이스로 전환`으로 표의 셀 텍스트를 새 DB에 저장한다. `POST /api/db`의 선택적인 `table: {columns: string[], rows: string[][]}`를 검증하고, 모든 열을 텍스트로 만들어 열 정의와 행을 한 트랜잭션에 저장한다. 기본 `/db` 삽입은 기존 예시 2행을 유지하며, `table`을 보낸 가져오기는 예시 행을 만들지 않는다. 가져오기는 최대 200열·10,000행이다. 브라우저 데모도 같은 정규화를 사용한다.
- 첫 열에 비어 있지 않은 유일한 값이 있으면 그 열을 대표열로 사용한다. 빈 값·중복 값이 있으면 원본 셀을 유지한 채 `항목 1`부터 채운 별도 텍스트 대표열을 앞에 추가한다. 빈 이름·중복 이름·예약된 열 이름은 구분되는 이름으로 바꾼다. 헤더 없는 표와 병합 셀의 규칙은 [Markdown 표 계약](../문서·코드·미디어%20편집/Markdown%20표%20편집·복사.md#상세-계약)을 따른다.
- 양방향 교체는 일반 ProseMirror·협업 Yjs 이력에서 각각 한 단계다. 실행 취소·다시 실행은 원래 노드의 DB UUID·읽기 전용·뷰 설정 또는 표 서식을 복원하며 DB를 재생성·삭제하지 않는다. DB→표 후 원본 DB와 연결된 행 페이지는 유지되고, 표→DB 후 실행 취소한 DB도 목록에 남아 다시 실행에 사용된다. 표를 나중에 다시 DB로 전환하는 것은 새 DB 생성이며 기존 타입을 복원하지 않는다.
- 요청 대기 중 원본 노드의 위치는 이후 트랜잭션으로 추적한다. 다른 위치의 편집은 유지하고, 원본 수정·삭제·문서 읽기 전용 전환 뒤에는 덮어쓰지 않는다. 같은 노드의 중복 요청을 막고, 문서에 삽입하지 못한 새 DB는 제거를 요청한다. API 실패 시 기존 문서 블록을 보존하고 오류를 표시한다. [전환 결정](../../decisions/0035-table-database-conversion.md)을 따른다.

### 여러 뷰와 항목 상세

- `DatabaseCollection`이 공통 제목·뷰 전환·검색을 제공하고 기존 `DatabaseTable`과 카드·보드·캘린더를 연결한다. 에디터 노드와 전체 DB 팝업이 같은 컴포넌트를 사용하며 브라우저 데모도 같은 UI를 사용한다. 기본 뷰는 기존 표다. 좁은 화면에서는 뷰 이름 대신 아이콘·접근성 이름·공통 툴팁을 유지하고, 열이 하나뿐인 표도 모든 전환 버튼을 표시할 최소 너비를 확보한다. 뷰 탭은 방향키·Home·End·Enter·Space·터치를 지원한다.
- 카드는 대표열 제목·첫 텍스트 속성의 미리보기와 선택한 속성을 표시한다. `표시 속성`에서 표시할 열을 고르며 선택 항목 색상·날짜·숫자·체크 상태는 기존 필드 타입을 따른다. 연결된 행 페이지가 있으면 별도 페이지 열기 버튼을 제공한다. 모바일은 한 열로 쌓고 넓은 화면에서는 가용 너비에 맞춰 카드 수를 정한다.
- 보드는 선택한 단일선택·체크박스 열로 그룹을 나눈다. 설정한 선택 항목의 빈 그룹과 미분류 그룹을 유지하며 각 행을 한 번만 표시한다. 데스크톱에서 카드를 다른 그룹으로 끌어놓으면 그 행의 그룹 열 값을 변경한다. 다른 DB의 드래그는 무시한다. 터치·키보드에서는 카드 상세의 같은 속성을 편집해 이동한다. 그룹의 추가 버튼은 해당 값을 채운 행을 만든다. 가로 스크롤은 보드 내부로 제한한다.
- 캘린더는 종료일 날짜 열과 선택적인 시작일 날짜 열을 지정하고 일요일 시작 6주 격자로 표시한다. 시작일 선택의 `열 추가`는 새 날짜 열을 만들고 바로 연결한다. 같은 열을 양 끝에 연결하지 않으며, 시작일을 지정하지 않으면 기존 단일 날짜 일정을 유지한다. 기간은 양 끝을 포함한 모든 날짜에 표시하고 선택 날짜 목록에 기간을 함께 쓴다. 한쪽 날짜만 유효하면 그 날짜에 표시하며, 순서가 뒤집힌 기존 값은 두 날짜 사이에 표시하되 원본 값을 바꾸지 않는다. 두 날짜가 모두 없거나 잘못된 항목은 별도 `날짜 없음` 목록에 남긴다. 긴 기간도 현재 보이는 42일만 계산한다.
- 월 이동·오늘 복귀·날짜 선택·날짜별 행 추가를 제공하며 날짜 값은 시간대 변환 없이 원래 달력 날짜로 사용한다. 날짜별 새 행은 연결한 시작일·종료일을 모두 선택한 날짜로 채운다. 기본으로 오늘의 전체 일정 목록을 표시하고 월 이동 뒤에는 해당 월의 첫날(이번 달은 오늘)을 선택한다. 각 날짜의 최대 3개 항목 뒤에 더 보기 버튼을 두며 선택한 날짜 목록에서는 전체 제목을 읽고 모든 항목을 연다.
- 캘린더·간트의 항목 상세는 공용 `DateCalendar`로 연결한 날짜를 편집한다. 시작일 열이 있으면 시작일·종료일 입력과 두 날짜 선택·기간 강조·일정 지우기를 제공하며, 없으면 단일 날짜 편집을 제공한다. 값은 기존 셀 API로 해당 열에 저장한다. 읽기 전용에서는 날짜 열 선택·기간 열람만 가능하고 날짜 변경·열 추가는 제공하지 않는다.
- 검색은 현재 DB의 셀 값을 대상으로 모든 검색어가 일치하는 행을 표시한다. 결과는 모든 뷰에 공통 적용하며 서버의 행 순서와 다른 표시 위치를 변경하지 않는다. 표의 열별 정렬은 기존 표 상태로 유지한다.
- 카드·일정을 누르면 공용 `DialogFrame`의 항목 상세를 연다. 대표열·텍스트·숫자·날짜·체크박스·선택 속성을 기존 셀 컴포넌트로 편집하며, 저장 실패는 상세와 DB 블록에서 표시하고 서버 값을 다시 읽는다. 행 삭제는 상세 창에서 확인한 뒤 실행한다. 보드·날짜별 새 행은 생성 뒤 초기 속성을 저장하고 상세를 연다. 초기 속성 저장에 실패하면 이미 만든 행은 보존하고 오류를 표시한다.
- 읽기 전용 참조·외부 DB도 뷰 전환·검색·상세 열람을 제공하지만 속성 변경·그룹 이동·행/열 추가·삭제는 제공하지 않는다. 데이터 접근·수정은 기존 DB API의 프로젝트·기능·파일 권한을 유지한다.

### 간트

- 간트는 같은 DB 행과 캘린더의 `dateColumn`·`startDateColumn`을 공유한다. 시작일이 없으면 하루 막대를 표시한다. 역순·한쪽 날짜·잘못된 날짜는 캘린더의 기간 정규화를 따른다. 날짜 없는 행도 제목과 상세 열기를 유지한다.
- 이번 달의 날짜 축, 이전·다음 달·오늘, 확대·축소·전체 기간 보기를 제공한다. 가로 스크롤은 DB 내부에 제한하며 왼쪽 제목은 고정한다. 검색 결과만 표시하고 조회·행·열·셀 저장은 기존 컨트롤러를 사용한다.
- 월 보기에서는 막대 이동, 시작일 열이 있을 때 양 끝 크기 조절, 빈 행의 시간축 그리기를 기존 날짜 셀에 반영한다. 포인터 취소는 저장하지 않는다. 막대의 좌우 방향키는 하루 이동, Shift는 종료일, Alt는 시작일 변경이다. 전체 기간 보기에서는 포인터 편집 대신 상세 창·키보드를 사용한다. 읽기 전용은 이동·기간 변경·그리기를 차단한다.
- 제목·막대에서 공용 항목 상세를 열어 날짜와 다른 속성을 편집한다. 태스크 패널 전용 완료 색상·태그·담당자·자동 생성 기능은 가져오지 않는다. 기존 태스크 Markdown을 DB로 자동 이관하거나 삭제하지 않는다. [통합 결정](../../decisions/0051-database-gantt.md)을 따른다.

### 뷰 설정의 저장

- 문서 노드의 `layout`은 `{mode, groupColumn?, dateColumn?, startDateColumn?, visibleFields?}`이며 모드는 `table`·`cards`·`board`·`calendar`다. `dateColumn`은 종료일 또는 단일 날짜 열, `startDateColumn`은 선택적인 시작일 열이다. `data-mew-db-layout`에 정규화한 JSON을 URL 인코딩해 저장한다. 기본 표 설정은 속성을 생략해 기존 Markdown 표현을 유지한다. 서버 협업 스키마와 클라이언트가 같은 파서·직렬화기를 사용한다.
- 문서를 편집할 수 있으면 해당 참조의 뷰·그룹/날짜 기준·표시 속성을 Markdown에 저장한다. 같은 DB를 다른 문서에서 참조해도 표시 설정은 독립적이다. 문서가 읽기 전용이면 현재 화면에서만 바꾼다. DB의 행·열 정의는 Postgres에 유지하며 표시 설정을 저장해도 DB 데이터가 Markdown으로 복제되지는 않는다.
- 독립 DB 팝업은 scoped localStorage `mew:db-layout:<DB UUID>`에 표시 설정을 보관하고 같은 DB를 다시 열면 복원한다. 저장소를 사용할 수 없으면 현재 화면의 선택은 유지한다. 검색어·선택한 행·캘린더 월은 영구 저장하지 않는다. 삭제되거나 타입이 바뀐 그룹·종료일 기준 열은 같은 타입의 첫 사용 가능한 열로 대체하고, 없으면 열 추가/빈 상태를 표시한다. 선택한 시작일 열이 사라지거나 날짜 타입이 아니면 시작일 없이 표시한다. [표시 설정 결정](../../decisions/0028-database-multiple-views.md)을 따른다.

### 기존 표와 데이터 동기화

- Plain의 Markdown HTML 블록에서 유효한 `data-mew-db` UUID를 가진 `div`를 링크로 표시한다. Ctrl+클릭 또는 Cmd+클릭하면 그 DB를 선택한 전체 목록 팝업을 연다. 일반 클릭은 원문 편집을 유지하며, 코드 블록·인라인 코드·HTML 주석·잘못된 UUID는 링크로 처리하지 않는다. 링크 열기는 Markdown 본문을 바꾸지 않는다.

- 팝업 요청과 행 페이지 탐색은 참조를 연 문서의 프로젝트 범위를 사용한다. `data-mew-db-readonly="true"`인 참조는 해당 DB를 읽기 전용으로 연다. 게스트·외부 파일·파일 재검증 중에는 DB 링크를 활성화하지 않으며 서버의 기존 DB 권한 검사도 유지한다. 문서·프로젝트 전환 시 편집 칸의 DB 팝업을 닫는다.

- 전체 목록과 Plain에서 여는 DB 팝업은 공용 `DialogFrame`을 사용한다. 공용 테마의 배경·블러·테두리를 따르고, 안쪽 패널 배경이 바깥 블러를 가리지 않게 한다. 닫기 버튼·바깥 누름·Esc로 닫고 이전 포커스를 복원하며 Tab 포커스는 팝업 안에 유지한다.

- 에디터와 전체 DB 팝업의 표는 첫 데이터 열부터 표시하며, 왼쪽의 행 삭제 버튼 전용 열은 두지 않는다. 빈 표 안내는 데이터 열과 편집 시 오른쪽 열 추가 칸을 합친 너비에 걸쳐 표시한다.

- DB 전체 블록·제목·뷰 전환·표시 설정·행 추가에는 테두리를 두지 않고 문서 배경을 그대로 사용한다. 표의 필드 격자만 6px 모서리의 테두리로 감싸며 셀 구분선은 일반 Markdown 표와 같은 `edge-strong`을 사용한다. 표 본문은 `surface-deep`, 열 헤더는 `surface-raised` 배경을 20% 불투명도로 적용한다. 카드·빈 보드·캘린더의 날짜 칸과 일정에도 테두리를 두지 않으며 배경과 간격으로 구분한다. 전체 DB 팝업도 같은 스타일을 재사용한다. 일반 Markdown 표의 셀 패딩은 DB 표에 적용하지 않아 기존 밀도를 유지한다.

- DB 생성 트랜잭션에서 `제목`·`텍스트` 열과 `항목 1` / `첫 번째 내용`, `항목 2` / `두 번째 내용`의 2개 행을 함께 저장하고 생성 응답에 반환한다. 브라우저 데모도 같은 초기값을 사용한다. 기존 DB와 외부 읽기 전용 참조에는 예시 행·열을 추가하지 않는다.

- 각 열 제목 오른쪽에 항상 보이는 정렬 아이콘 버튼을 둔다. 클릭·Enter·Space·터치로 오름차순 → 내림차순 → 해제를 전환하며 다른 열을 누르면 그 열의 오름차순으로 바꾼다. 활성 열에 방향 화살표와 강조색, `aria-sort`를 표시하고 버튼 이름·툴팁으로 다음 동작을 안내한다.
- 정렬은 표시 중인 표에만 적용한다. 에디터·팝업·읽기 전용 참조에서 사용하며 DB의 저장 순서와 다른 표의 정렬은 바꾸지 않는다. 해제하면 서버에서 받은 원래 행 순서를 표시한다. 숫자는 수치, 날짜는 시간, 체크박스는 미체크 → 체크, 텍스트·페이지·선택 항목은 화면 언어의 자연 정렬을 따른다. 다중선택은 항목 이름을 이어 비교한다. 빈 값은 양방향 모두 마지막에 두고 같은 값은 원래 순서를 유지한다. 셀·행 갱신 시 현재 정렬을 다시 적용하며 없어진 열의 정렬은 적용하지 않는다.

- DB 전체 블록과 각 열의 가로 너비는 표 내용에 맞춘다(hug). 제목 영역의 내용은 블록 너비를 늘리지 않으며, 긴 제목은 주어진 너비 안에서 표시한다. 편집 중 셀 입력값·선택 항목·페이지 제목도 열 너비에 반영하며, 짧은 DB 블록을 화면 너비로 강제 확장하지 않는다. 화면보다 넓은 표는 블록을 부모 너비로 제한한 뒤 DB 내부에서 가로 스크롤하고 문서 전체 너비를 늘리지 않는다. 읽기 전용 표와 전체 DB 팝업도 같은 규칙을 사용한다.

- 단일선택은 문자열 하나, 다중선택은 문자열 배열로 저장한다. 선택지는 열별로 관리하며 셀 편집 중 새 선택지를 추가할 수 있다.

- 선택 목록의 각 항목은 태스크 태그와 같은 16색 팔레트와 기본 색상 계산을 사용한다. 색상 원으로 색을 고르고, 연필로 이름을 바꾸며, X로 항목을 삭제한다. 고른 색은 열별 항목 메타데이터에 저장해 다른 셀·세션·행 페이지에도 같은 색으로 표시한다.

- 이름 변경은 그 항목을 쓰는 모든 행의 단일·다중선택 값과 하위페이지 속성을 함께 바꾼다. 삭제는 선택지·색상과 해당 선택값을 함께 제거한다. 단일선택은 빈 값이 되고, 다중선택은 다른 선택값을 유지한다. 중복 이름·빈 이름·지원하지 않는 색상은 저장하지 않는다.

- 셀 우클릭 메뉴에서 해당 열 전체의 타입을 변경한다. 대표열은 텍스트↔페이지만 허용하고, 일반 열에는 페이지 타입을 적용하지 않는다. 대표열의 내부 값은 페이지 모드에서도 제목 문자열이며 행 UUID가 기본키다.

- 새 행의 대표값은 중복되지 않는 `제목 없음`으로 시작한다. 기존 DB에 대표열 제약을 처음 적용할 때 빈 값은 기본 제목으로 채우고, 중복 값에는 번호를 붙여 구분한다. 이후 빈 값·중복 값 저장과 대표열 삭제를 거부한다.

- 타입 변경은 열의 모든 값을 먼저 검증하고 적용한다. 변환할 수 없는 값이 있으면 변경하지 않는다. 다중선택에 값이 둘 이상인 행은 단일 값 타입으로 바꿀 수 없다. 사용 중인 항목을 X로 삭제할 때는 행 값도 같은 트랜잭션에서 정리하며, 단순 옵션 목록 교체로 사용 중인 값을 유실시키지는 않는다.

- 대표열을 페이지로 바꾸면 행마다 원본 문서의 바로 하위에 `<대표열 값>.md`를 생성한다. 원본이 단일 파일이면 일반 하위 문서 규칙으로 대표 파일로 전환한다. 별도 DB 문서·UUID 폴더는 만들지 않는다. 기존 UUID 파일도 본문과 행 연결을 유지해 이관한다. 이름 충돌·예약 문자·열린 탭과 초안 처리 및 생성 후 경로 유지 규칙은 [문서 페이지 계약](../../development/document-pages.md#데이터베이스-행-하위페이지)을 따른다. 대표열 값은 프론트매터 `title`, 다른 열 값은 열 표시명을 필드명으로 공유한다. 숫자·체크박스·다중선택은 각각 YAML 숫자·불리언·배열을 유지한다. `title`·`_mew_database`·`_mew_row`·`상위파일`은 일반 열 이름으로 사용하지 않는다.

- 하위페이지를 편집하거나 표의 셀을 바꾸면 연결한 필드가 반대쪽에도 반영된다. 본문과 DB에 연결하지 않은 프론트매터 필드는 보존한다. `created`·`updated`를 자동 생성하지 않으며, 같은 이름의 DB 열을 직접 정의한 경우에만 그 값을 공유한다. 바인딩 페이지의 본문을 편집해도 `updated` 값을 오늘 날짜로 자동 갱신하지 않는다.

- 페이지를 텍스트로 전환하거나 행·DB를 삭제하면 공유를 중단한다. 기존 페이지의 본문을 자동 삭제하지 않으며, 같은 행을 다시 페이지로 전환하면 기존 본문을 보존한다. 페이지 경로·연결 메타데이터와 문서 수명은 [문서 페이지 계약](../../development/document-pages.md)을 따른다.
