# 0028 — 같은 DB를 여러 문서별 뷰로 표시

상태: 승인

## 배경

문서 DB가 표만 제공해 상태별 작업이나 날짜별 일정을 탐색하기 어려웠다. 같은 데이터를 복제하지 않고 카드·보드·캘린더로 볼 수 있어야 하며, 한 DB를 여러 문서에서 서로 다른 방식으로 표시할 수 있어야 한다.

## 결정

- 표·카드·보드·캘린더는 같은 DB 조회와 변경 컨트롤러를 공유한다. 기존 표의 셀·선택 항목 편집기를 항목 상세에서 재사용한다.
- 보드 그룹은 단일선택·체크박스 열, 캘린더는 날짜 열을 사용한다. 그룹 이동과 날짜별 생성은 기존 행·셀 API로 처리한다. 읽기 전용 뷰는 표시 기능만 제공한다.
- 2026-10-21 확장: 캘린더의 기존 `dateColumn`을 종료일 또는 단일 날짜로 유지하고 선택적인 `startDateColumn`에 별도 날짜 열을 연결한다. 기간 값은 기존 날짜 셀에 저장하며 DB 스키마에 별도 기간 타입을 추가하지 않는다. 시작일 열이 없는 기존 문서는 단일 날짜 동작을 유지한다.
- 문서별 뷰 모드·그룹/날짜 기준·표시 속성은 DB 참조 노드의 속성으로 저장하고 Markdown의 `data-mew-db-layout`으로 직렬화한다. 기본 표는 기존 표현을 유지한다.
- 서버 협업 스키마와 클라이언트가 같은 설정 파서·직렬화기를 사용한다. 문서 편집 권한이 없으면 선택은 현재 화면에만 적용한다.
- 독립 팝업은 DB UUID를 키로 scoped 브라우저 설정에 저장한다. 문서의 설정과 팝업 취향을 서로 덮어쓰지 않는다.
- 행·열 데이터와 DB 정의는 계속 Postgres가 소유한다. 표시 설정을 위해 DB 스키마나 데이터 사본을 추가하지 않는다.

## 근거와 영향

문서마다 다른 뷰를 사용할 수 있고, 표시 설정을 문서와 함께 협업·이동·Git으로 관리할 수 있다. 브라우저 팝업의 개인 취향은 문서 내용을 변경하지 않는다. 기존 문서와 DB API는 그대로 사용하며, 기준 열이 없어지면 해당 타입의 사용 가능한 열이나 빈 상태로 복구한다.

자세한 동작·확인 기준은 [DB 기능 계약](../features/문서%20데이터베이스/문서%20데이터베이스·전체%20목록.md), 사용자 조작은 [DB 안내](../guides/database.md#뷰-바꾸기), 개인 저장 범위는 [브라우저 저장 계약](../development/browser-storage.md#db-팝업의-표시-설정)을 따른다.
