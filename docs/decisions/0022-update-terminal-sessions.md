# 0022 — 업데이트 실행을 보존되는 터미널 세션으로 제공

상태: 채택.

## 배경

업데이트 화면에서 실행하면 단계별 출력을 확인하기 어렵고 Mew 재시작 시 브라우저 연결이 끊긴다. 사용자는 프로젝트 명령 버튼이나 직접 연 터미널처럼 실행 중인 출력과 재시작 이후의 결과를 같은 세션에서 확인할 수 있어야 한다.

## 결정

1. Mew·독립 에이전트 CLI·시스템 도구 업데이트를 전용 tmux 세션에서 실행한다. 각 항목에 실행과 세션 보기 진입을 제공하며 기존 터미널 팝업을 재사용한다. 개별 업데이트는 항목별 세션을, 시스템 도구의 일괄 실행은 큐 전체가 공유하는 세션을 사용한다.
2. 화면이나 팝업을 닫아도 업데이트를 계속한다. 성공·실패 뒤에도 출력을 다시 볼 수 있도록 세션을 보존한다.
3. Mew 업데이트 작업과 터미널 세션은 Mew 서버 재시작을 견딘다. 브라우저가 다시 연결한 뒤 같은 세션을 연다. 성공 확인 뒤 사용자가 새로고침 버튼으로 브라우저에 새 화면을 적용하며 자동 새로고침은 하지 않는다.
4. 에이전트의 개별 업데이트·실행 중 차단, 시스템 도구 순차 실행, 의존성 작업 성공 뒤 Mew 실행, 빌드 성공 뒤 재시작과 사전 빌드 CLI의 운영 경계는 유지한다.

## 근거와 영향

명령 버튼에서 익숙한 실행·출력 확인 동작을 업데이트에도 적용한다. 브라우저 연결과 작업 수명을 분리해 서버 재시작 뒤에도 결과를 확인하고 실패 원인을 살필 수 있다. 세션 저장·재실행·복원과 새로고침의 구체적인 현재 계약은 [앱 업데이트·운영 진입](../features/화면·계정·운영/앱%20업데이트·운영%20진입.md)이 소유한다.
