# 0035 — 일반 표와 문서 DB 전환의 저장·이력 경계

상태: 승인

## 배경

Markdown 표는 본문에 저장되고 문서 DB의 행·열은 Postgres에 저장된다. 두 형식을 우클릭 메뉴로 전환하면서 실행 취소·다시 실행을 지원하려면 문서 이력과 DB 수명을 구분해야 한다. 일반 표의 빈 값·중복 값은 DB의 필수·유일 대표열 제약과 충돌할 수 있다.

## 결정

- 전환을 문서 노드 교체 한 번으로 기록한다. 일반 ProseMirror 이력과 Yjs 협업 이력 모두 앞뒤 입력과 분리한 한 단계로 실행 취소·다시 실행한다.
- DB→표는 전체 행·열의 텍스트 스냅샷을 본문에 넣고 원본 DB·행 페이지를 유지한다. 표시용 검색·정렬·행 수 제한을 스냅샷에 적용하지 않는다.
- 표→DB는 모든 열을 텍스트로 가져오고 DB 생성·열 정의·행 저장을 한 트랜잭션으로 처리한다. 기존 생성 API의 선택적 초기 표 입력을 사용하며 일반 `/db` 삽입의 예시 값은 유지한다.
- 첫 열의 값이 필수·유일 조건을 만족하지 않으면 별도 텍스트 대표열을 추가해 원본 셀을 보존한다. [대표열 결정](0012-database-row-pages.md)의 필수·유일 규칙은 유지한다.
- 실행 취소·다시 실행은 DB를 생성하거나 삭제하지 않는다. 새 DB는 실행 취소 후에도 목록에 남기고 다시 실행에서 같은 UUID를 참조한다. 요청 대기 중 원본이 달라져 문서에 삽입하지 못한 새 DB는 제거를 요청한다.

## 근거와 영향

원본 DB를 유지하면 다른 문서의 참조와 연결된 페이지를 훼손하지 않고 문서 이력만 복원할 수 있다. 실행 취소 후 사용하지 않는 DB가 목록에 남을 수 있으며 필요하면 사용자가 별도로 삭제한다. DB 셀 편집의 이력까지 문서 undo/redo에 포함하지는 않는다. 표를 다시 새 DB로 전환할 때는 텍스트 타입을 사용한다.

현재 동작과 검증은 [DB 기능 계약](../features/문서%20데이터베이스/문서%20데이터베이스·전체%20목록.md#markdown-표와-전환), 조작 방법은 [DB 사용법](../guides/database.md#일반-표와-전환하기)을 따른다.
