## 상태

채택. 코드·격리 회귀 검증을 완료했다. 앱 빌드와 서버 적용은 사용자가 수행한다.

## 배경

서버 검색은 사용자 정규식을 Node.js의 native RegExp로 동기 실행했다. 검색어 길이와 결과 개수만 제한하면 한 번의 패턴 매칭에서 발생하는 과도한 backtracking을 막을 수 없다. 읽기 공유를 받은 guest의 검색도 서버 전체의 응답을 지연시킬 수 있다.

## 결정

내용 검색·SSE 검색·치환·파일명 정규식에 순수 JavaScript RE2 포트인 `re2js`를 사용한다. 본문 검색의 기본 와일드카드도 같은 엔진으로 처리한다. 지원하지 않는 전후방 탐색·패턴 역참조는 오류로 거부하며 native RegExp로 되돌아가지 않는다. 패턴은 2,000자, 컴파일된 명령은 10,000개로 제한한다.

현재 구문·치환 계약은 [검색 설정](../configuration/search.md)과 [검색 기능](../features/프로젝트·파일·검색/파일명·내용%20검색과%20치환.md)이 소유한다.

## 근거와 영향

네이티브 모듈 빌드와 비동기 API 전환 없이 기존 검색 흐름에서 비선형 backtracking을 제거한다. 캡처 치환·유니코드 결과 위치는 유지하되 JavaScript의 모든 정규식 구문을 지원하지는 않는다. 파일 읽기량과 결과 개수 제한은 계속 적용하며, 선형 시간 실행이 모든 크기의 문서에 대한 즉시 응답을 보장하는 것은 아니다.

격리 회귀는 중첩 반복 패턴의 완료, 미지원 구문의 거부, 캡처 치환과 HTTP 오류 응답을 확인한다. 실제 운영 요청이나 외부 시스템을 대상으로 공격 재현은 수행하지 않는다.
