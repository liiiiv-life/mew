## 상태

채택. 구현·격리 검증을 마쳤으며 운영 빌드·서버 재시작은 사용자가 적용한다.

## 배경

[결정 0031](0031-agent-display-events.md)로 원시 도구 결과를 제외했지만 최근 20턴의 생각·도구 호출은 접힌 상태에서도 전송·조합했다. 감독은 이미 가진 이벤트를 SQLite에서 다시 파싱하고 내부 IPC에는 큰 원본을 보낸 뒤 WS에서야 표시용으로 줄였다.

질문·답변을 읽기 전에 상세를 기다릴 필요가 없다. 다만 이벤트를 단순 삭제하면 재접속 커서·캐시·버블 키가 바뀌고 늦은 도구 상태를 놓칠 수 있다.

## 결정

새 화면은 최근 3턴부터 표시하고 이전 구간은 스크롤할 때 읽는다. 감독 capability를 확인한 연결에서만 생각·도구 호출의 연속 구간을 원래 이벤트 수를 가진 marker로 보낸다. 브라우저는 순번 슬롯을 유지하며 상세의 위치만 조합한다. 작은 도구 상태 갱신과 실시간 이벤트는 표시용으로 즉시 전달한다.

첫 표시 뒤 보이는 탭의 상세를 제한된 동시성으로 미리 읽고 펼친 턴을 우선한다. 백그라운드 결과는 메모리에 두며 펼칠 때 해당 marker를 채운다. 조회는 기존 인증된 탭의 WS·감독 IPC 안에서 현재 세대를 확인하며, 구간·바이트·시간 상한과 재시도를 둔다. 연결·세대 교체는 오래된 조회를 무효화한다.

감독은 메모리 구간을 표시용으로 변환하고 IPC 송신 전에 원본 도구 결과를 제거한다. 구 감독은 기존 경로를 유지한다. SQLite·ACP 원본과 실행 컨텍스트는 보존하며 별도 DB 스키마·원시 도구 결과 조회 API는 추가하지 않는다. 구체 계약과 수치는 [대화 저장](../development/conversation-storage.md#접힌-작업-상세의-지연-조회)이 소유한다.

## 근거와 영향

첫 화면에서 보이지 않는 생각·도구 내용을 제외해 조회·전송·파싱·조합 비용을 줄인다. 상세만 펼칠 때 읽는 방식에 제한된 미리 읽기를 더해 사용자가 펼친 직후의 대기도 줄인다. 숨긴 탭은 새 요청을 멈춰 다른 작업과 통신을 경쟁하지 않게 한다.

합성 비교와 격리 서버·브라우저 검사로 전송 축소·순번·중복·늦은 응답·오류 복구를 확인했다. 실제 Mewlink 접속 시간과 공급자 ACP 복원 시간은 측정하지 않았다. 한 질문·답변 자체가 큰 경우, preview Worker의 원본 읽기와 감독의 전체 메모리 사용량은 이번 변경의 상한 보장 대상이 아니다.
