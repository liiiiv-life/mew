## 상태

채택. 구현·격리 검증과 운영 적용은 구분한다. 로컬 서버 변경은 해당 실행본을 업데이트한 뒤 적용된다.

[후속 결정 0043](0043-agent-work-details-loading.md)은 투영 시점을 감독 IPC 이전으로 옮기고 표시용 작업 상세를 지연 조회한다. 아래의 별도 상세 조회 불필요 판단은 그 범위에서 대체하며 원본 보존과 표시 필드 제한은 유지한다.

## 배경

에이전트 패널은 도구 실행의 ID·제목·상태를 표시하지만 ACP가 보내는 원시 입출력도 대화 이벤트에 포함해 브라우저로 전송했다. 최근 저장 전사 20개를 읽기 전용으로 조사했을 때 도구 이벤트는 전체 바이트의 약 91%였다. 최근 20개 질문을 보내는 정책은 질문 하나에 포함되는 도구 결과의 크기를 제한하지 않는다.

대화의 순번은 재접속·앞선 구간 조회·기기 캐시의 기준이다. 이벤트를 삭제하거나 합치면 이 계약과 기존 브라우저의 복원을 깨뜨린다. ACP 원본을 줄이면 공급자 문맥이나 서버 복원에도 영향을 준다.

## 결정

공유 순수 함수에서 `tool_call`과 `tool_call_update`의 `update`를 `sessionUpdate`·`toolCallId`·`title`·`status`·`kind`로 투영한다. 외부 이벤트 필드와 사용자·답변·생각·승인·설정 등 다른 이벤트는 유지한다. 원본 객체·SQLite·감독의 ACP 이벤트는 변경하지 않는다.

브라우저 WebSocket의 단일 송신 경계에서 구간 이력·선표시·실시간 이벤트·레거시 replay에 같은 투영을 적용한다. 이벤트 개수·순서·세대·전역 순번·구간 경계는 보존한다. 기존 브라우저도 이미 사용하던 표시 필드로 같은 화면을 구성한다.

선표시 Worker도 원본 행을 읽은 뒤 즉시 투영하고 투영본만 누적한다. 출력 바이트 한도와 원본 읽기·단일 행 한도는 별도로 적용한다. 원본에 큰 도구 결과가 있어도 표시할 구간이 작으면 선표시할 수 있으며, 시간·메모리·읽기 예산을 넘으면 기존 ACP 복원으로 돌아간다. 구체 한도와 저장·복원 계약은 [대화 저장](../development/conversation-storage.md)이 소유한다.

## 근거와 영향

읽기 전용 표본에서 표시 필드만 남긴 결과는 원본 약 62.2MB에서 약 7.36MB로 줄었고, 20개 모두 대화 조합 결과가 같았다. 실제 계정의 화면 전체 로딩시간이나 외부망 개선율을 측정한 수치는 아니다.

현재 화면은 원시 도구 입출력을 표시하지 않으므로 별도 상세 조회 API를 추가하지 않는다. 앞으로 원시 결과를 표시하는 기능을 만들 때는 기존 전송에 원본을 다시 끼워 넣기 전에 별도의 권한·조회·용량 계약을 정한다.
