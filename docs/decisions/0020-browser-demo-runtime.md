# 0020 — 공통 UI와 교체 가능한 데모 실행 환경

상태: 채택

## 배경

설치·로그인 없이 `mew.run/demo`에서 Mew를 직접 체험할 수 있어야 한다. 체험용 화면을 복사하면 UI 변경과 버그 수정을 이중으로 관리하게 된다. 고정 API 응답만 반환하면 편집·자동저장·에이전트 수정·Git 변경 사이의 상태가 어긋나며 실시간 기능도 처리할 수 없다.

## 결정

별도 HTML 진입점에서 데모 실행 환경을 선택한 뒤 실제 Mew 앱·편집기·패널을 그대로 사용한다. 전송·협업·초기 인증·기준 경로를 공통 runtime 계약으로 제공하고, 데모 여부에 따른 UI 분기를 기능마다 추가하지 않는다. 실제 P2P 접속 상태와 데모 실행 환경은 별개다.

데모의 기준 상태는 방문자별 `DemoWorkspaceStore` 하나다. HTTP·실시간 이벤트·편집기·가상 에이전트·Git이 같은 파일을 읽고 수정한다. 문서 편집은 실제 Yjs와 공통 편집기 스키마를 사용하며 서버의 동기화 프로토콜을 복제하지 않는다. 외부 명령·모델·호스트에 필요한 동작만 가상 구현으로 교체한다.

설정·초안·캐시도 메모리에 격리하고 실제 사용자의 브라우저 저장소와 영속 캐시를 사용하지 않는다. 미지원 작업은 실제 서버로 넘기지 않는다. 중앙의 `/demo`는 별도 앱 origin의 데모를 열며 사용자 이름 예약과 기존 점유 검사를 적용한다.

UI 변경은 다음 데모 빌드에 포함한다. 중앙 배포에서 소스·산출물 일치를 검증하고 데모를 함께 반영한다. 새 서버 기능은 필요한 가상 동작과 계약 검증도 함께 갱신한다.

## 근거와 영향

공통 UI의 개선을 한 번만 구현할 수 있고, 데모 상태와 실행 수명이 제품 서버와 분리된다. 기존 `EditorApi`·`EditorCollab`·전송 계약을 활용해 모든 기능을 새 추상화로 옮기는 비용도 줄인다.

데모 구현과 fixture는 별도로 유지해야 한다. 공통 인터페이스 변경을 타입·동작 테스트에서 확인하며, 공개 데모가 갱신되는 시점은 배포 완료 후다. 실제 멀티테넌트 서버나 자유로운 OS 명령 실행을 제공하는 결정은 아니다.

구체적인 현재 계약과 사용자 적용 절차는 [브라우저 데모](../development/demo.md)가 소유한다.

후속 [ADR 0027](0027-demo-lazy-repository.md)은 파일 준비 방식을 전체 공개 파일 목록·작은 초기 사본·요청 시 본문 로딩으로 확장한다. 공통 UI·방문자별 가상 상태·외부 연결과 메모리 저장소의 경계는 유지한다.
