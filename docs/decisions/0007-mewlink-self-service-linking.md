# Mewlink 즉시 승인과 본인 계정 연결

상태: 승인됨. 이전 계정을 보존하던 범위는 [0041 — 병합된 이전 계정 삭제](0041-mewlink-merged-account-removal.md)가 대체한다.

## 배경

기존 승인 화면은 관리자에게 새 사용자 생성과 기존 이메일 사용자 연결을 선택하도록 했다. 사용자는 Mewlink 사용자를 바로 승인하고, 두 로그인 수단을 가진 사람은 본인이 이메일로 로그인한 뒤 연결하는 흐름을 요청했다.

## 결정

- 관리자의 **승인**은 비밀번호 없는 member를 즉시 등록하고 승인된 Mewlink 목록에 표시한다. 역할은 기존 계정 관리에서 변경한다. 관리자 API의 기존 명시적 연결·역할 선택은 호환을 위해 유지한다.
- 기존 이메일 사용자는 **설정 → 계정 → Mewlink 계정 연결**에서 직접 연결한다. 같은 살아 있는 P2P 접속의 중앙 서명으로 검증한 Mewlink 신원과 완료된 로컬 비밀번호 로그인을 함께 요구한다. 연결 대상은 현재 비밀번호 세션의 사용자다.
- 이미 로컬 계정의 사용 권한을 증명했으므로 본인 연결에는 추가 관리자 승인을 요구하지 않는다. 외부 로그인만으로 다른 로컬 계정에 연결하거나 새 계정·역할을 만들 수 없다.
- 기존 Mewlink 연결을 옮길 수 있다. 화면에서 확인한 이전 연결과 실제 상태가 다르면 거부하며, 같은 대상에 대한 재시도는 기존 연결을 반환한다. 옮길 때는 연결 ID를 교체하여 이전 외부 세션이 대상 계정의 권한을 이어받지 않도록 한다.
- 기존 로컬 계정과 그 계정의 개인 데이터·설정·권한·비밀번호는 보존한다. 이 작업은 로그인 수단을 연결하며 두 계정의 데이터를 합치지 않는다.

## 근거와 영향

관리자는 외부 사용자의 접근과 역할을 관리하고, 사용자는 두 로그인 수단의 소유를 증명해 본인 계정에 연결한다. 이메일 문자열 일치나 기기 등록자로 신원을 추정하지 않는다. 이메일 계정의 기존 권한을 사용하므로 본인 연결 자체로 권한을 늘리지 않는다.

이 결정은 [이전 승인 신원 결정](../history/decisions/0208-mewlink-approved-login-identities.md)의 관리자 중심 연결 UI와 owner만 연결할 수 있던 범위를 확장한다. 중앙 신원 검증·로컬 권한·외부 세션 고정 원칙은 유지한다. 구현 계약은 [원격 접속](../development/remote-access.md#승인된-mewlink-계정-로그인), 사용 순서는 [계정 설정](../configuration/accounts.md#mewlink를-기존-이메일-계정에-연결하기)이 소유한다. 적용에는 사용자의 로컬 업데이트와 새 API 경로를 허용하는 Mewlink 중앙 배포가 필요하다.
