## 상태

채택. [이전 결정 0194](../history/decisions/0194-mew-readonly-feature-panel.md)·[0196](../history/decisions/0196-mew-file-backed-feature-tree.md)·[0198](../history/decisions/0198-mew-inline-feature-title.md)의 기능 패널 표시·편집 범위를 대체한다. Markdown 문서와 기존 API·CLI·실행 큐·이력의 보존 계약은 유지한다.

## 배경

여러 에이전트가 브랜치와 worktree에서 병렬로 작업하면 기능 문서 목록만으로는 어느 작업을 직접 써볼 수 있는지 알기 어렵다. 작업마다 현재 폴더의 브랜치를 바꾸지 않고, 실행 중인 앱과 확인 결과를 한곳에서 찾을 수 있어야 한다. Mew의 기존 `/포트번호` 앱 접속을 브랜치별 진입점으로 사용할 수 있다.

## 결정

기능 패널을 현재 프로젝트의 로컬 Git 브랜치별 작업 목록으로 바꾼다. 실제 브랜치·worktree·최근 커밋·미커밋 변경을 읽고 제목·작업 내용·검증 기록·사용자 판정·미리보기 포트와 경로를 별도로 저장한다. 설정은 Git 공통 디렉터리에 두어 같은 저장소의 worktree들이 공유한다. 원격 조회와 `feat/` 이름 규칙을 필수로 하지 않는다.

사용자가 **미리보기 열기**를 누르면 현재 Mew 접속 주소의 `/포트번호` 진입점을 새 브라우저 탭으로 연다. 기존 프리뷰 인증·권한·출처 분리를 재사용한다. 포트의 연결 상태, 실제 수행한 검사 기록, 직접 사용한 결과의 판정은 서로 구분한다. 커밋이나 worktree 변경 상태가 바뀐 판정은 확인 대기로 표시한다.

패널은 worktree·실행 프로세스·테스트 데이터를 만들거나 관리하지 않는다. 빌드·서버 실행·중지·브랜치 전환·병합을 자동 실행하지 않으며 [에이전트 Git 자동 처리 결정](0046-agent-git-automation.md)과 저장소 실행 제한을 바꾸지 않는다. 판정 저장도 에이전트 병합을 강제로 차단하거나 허용하는 장치가 아니다.

기존 `Documents/features/`와 Markdown 기능 API·CLI·실행 큐·보고 이력을 그대로 보존한다. 문서는 Documents에서 읽고 편집하며 새 브랜치 원장으로 자동 변환하거나 삭제하지 않는다. 세부 화면·저장·사용법은 [소유 기능 계약](../features/터미널·에이전트·자동화/기능%20기반%20개발·Markdown%20문서.md)과 [사용법](../guides/projects.md#기능-패널에서-작업-브랜치-확인)에 둔다.

## 근거와 영향

사용자는 작업 브랜치를 전환하는 대신 해당 작업의 미리보기를 열어 직접 확인할 수 있다. 포트 응답을 검사 통과로 표시하지 않아 자동 검사와 실제 사용 결과를 구분한다. 앱을 별도 포트에서 실행하고 DB·업로드·설정을 분리하는 준비는 여전히 필요하며, 연결 가능한 포트가 해당 worktree의 앱인지는 실행 담당자가 맞춰야 한다.
